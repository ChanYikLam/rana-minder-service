# config · 配置加载与启动前校验

> 更新日期：2026-08-12
> 目录位置：src/config/
> 权威依据：ADR-010、部署运维手册 §7/§8（OPS-CFG-001~006、OPS-DEP-001、§8.4）

## 核心职责

统一配置读取边界：负责单文件外置配置的加载、结构校验、环境判定与版本化秘密引用解析，是启动入口与一切外部适配器（数据库、Casdoor、对象存储、邮件等）的配置唯一来源。不属于单一业务分层，作为平台策略层与适配执行层之间的基础设施边界。

- **单文件外置配置**：官方部署为部署项目目录内本地 `config.yaml` 或等效单文件，Docker 以只读方式挂载到容器内固定受控位置；应用只读，不覆盖、不补写、不提供下载（ADR-010）。
- **统一读取边界**：所有配置由本目录加载并校验，业务模块不得各自扫描任意路径、重复解析秘密或把原值写入错误信息（ADR-010 §2.7）。
- **启动前校验**：结构、环境标识、必需引用、版本兼容与互斥条件全部先行校验（OPS-CFG-001）；未知字段、缺失必需项不得被框架默认值静默接受；正式环境学校硬编码与开发策略误用不得放行。
- **秘密与传输策略**：秘密经数据库外版本化引用解析（服务端 AES-256-GCM、版本化 AAD、强类型引用与版本化密钥环，OPS-CFG-002）；正式环境 HTTPS 强制，非 HTTPS 明确阻止或警告并保持受保护能力关闭（OPS-CFG-006）。

关键不变量：

- 真实配置绝不进入源码仓库、容器镜像、发布物、示例、截图、日志或公开诊断材料（OPS-CFG-001）。
- 解析、校验或秘密引用失败按 §8.4 启动判定分类处理，不伪造健康。
- 日志、启动摘要与错误只说明配置项是否存在、是否合法及来自哪个受控入口，绝不输出密码、令牌、私钥、访问密钥或可还原秘密的派生值（ADR-010 §2.8）。

## 关键组件

| 组件 | 类型 | 职责 |
|---|---|---|
| `ConfigLoader` | 配置加载器 | 从只读挂载的受控位置读取单文件、基础解析与结构校验；未知字段/缺失必需项失败关闭 |
| `ConfigSchema` | 结构定义 | 配置结构声明、必填条件、正式/开发环境差异、无效占位符识别与兼容版本 |
| `EnvironmentValidator` | 环境校验器 | 环境标识、声明环境一致性、必需引用、版本兼容与互斥条件检查（OPS-CFG-001） |
| `SecretReferenceResolver` | 秘密引用解析 | 数据库外版本化密钥环引用解析（AES-256-GCM、版本化 AAD、强类型秘密引用；OPS-CFG-002/003），值不落日志 |
| `TlsPolicyGuard` | 传输策略 | 正式环境 HTTPS 强制；非 HTTPS 阻止或警告并关闭受保护能力（OPS-CFG-006） |
| `ConfigRedactor` | 脱敏摘要 | 生成仅含秘密引用及其版本的脱敏配置摘要，供启动证据基线使用（OPS-DEP-001） |

## 使用与准入规则

- **使用**：仅启动入口（HTTP 与后台任务）与统一装配在初始化阶段调用；适配器与模块只消费已校验的配置对象，不再解析文件或环境。
- **可以放进来**：结构声明、加载与校验、版本化秘密引用解析、脱敏摘要、传输策略判定、升级兼容检查入口。
- **禁止放进来**：任何业务领域逻辑；业务模块自行读取文件路径或扫描配置目录；配置原值进入错误、日志、追踪、状态页或审计；以默认值或热加载静默替代缺失项（是否热加载不提前决定）。
- 升级约束：发布说明列出新增、废弃、重命名与默认值变化；升级前保留受保护的现行配置副本并执行兼容检查（ADR-010 §2.9）。

## 核心逻辑摘要

- **校验顺序**：结构 → 环境标识 → 必需引用 → 版本兼容 → 互斥条件；任一步失败记录脱敏失败证据，按 §8.4 分类处理，不得以半配置状态继续提供业务服务。
- **启动分类衔接**：配置无法解析→启动阻断，不启动业务服务；能力相关秘密缺失或不可解析→能力阻断，应用可运行但对应能力按 SRS 关闭；结果未知→按风险失败关闭，状态页显示未知。
- **秘密语义**：秘密可集中存放于单文件但必须按秘密字段声明；日志采用字段允许清单，疑似秘密在落盘前拒绝或移除（OPS-CFG-005）；根密钥只通过外置版本化引用提供，不随密文进入数据库备份、仓库或镜像（OPS-CFG-003）；根密钥丢失、引用不可解析或版本被撤销时受影响能力失败关闭并进入恢复，不得把旧明文写回普通配置、日志或数据库（OPS-CFG-004）。
- **HTTPS**：传输保护必须覆盖认证证据、业务数据、文件访问、外部回调和运维入口（OPS-CFG-006）。
- **升级与回滚**：镜像升级无需把真实配置复制进镜像层；配置变更生效方式、凭据轮换顺序与回滚限制由运维规格决定，本目录不提前承诺热加载。

配置文件 Schema 顶层段（YAML）：
- database:
  - host, port, database, username, passwordRef, sslMode, poolMax, poolMin, poolIdleTimeoutMs
- casdoor:
  - baseUrl, clientId, clientSecretRef, organization, applicationName, groupPrefix, webhookSecretRef
- storage:
  - endpoint, region, accessKeyRef, secretKeyRef, bucketPublic, bucketPrivate, bucketTemp, forcePathStyle
- mail:
  - host, port, username, passwordRef, fromAddress, fromName, tlsRequired
- tls:
  - enabled, certPath, keyPath
- app:
  - port, corsOrigins, trustProxy, logLevel, environment（development|staging|production）
- secrets:
  - encryptionKeyRef（AES-256-GCM 根密钥引用）

字段以 `Ref` 结尾的为秘密引用（指向外置密钥文件路径或密钥管理器标识），不以明文出现在配置文件中。

## 典型调用链

`main.ts / worker.ts 启动` → `ConfigLoader` 读取只读挂载单文件并解析 → `ConfigSchema`/`EnvironmentValidator` 完成结构、环境、引用、版本与互斥校验（失败→启动阻断，保留脱敏证据）→ `SecretReferenceResolver` 解析版本化秘密引用（值不落日志）→ `TlsPolicyGuard` 判定传输策略（正式环境非 HTTPS 阻止或警告且受保护能力关闭）→ `ConfigRedactor` 生成脱敏摘要进入启动证据基线 → 装配各模块与适配器 → 依赖就绪后开放 HTTP/任务入口。
