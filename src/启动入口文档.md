# 启动入口 · HTTP 应用与后台任务开发指导

> 更新日期：2026-08-12
> 对应文件：`src/main.ts`（HTTP 应用入口）、`src/worker.ts`（后台任务入口）、`src/app.module.ts`（根装配）
> 权威依据：ADR-001、ADR-004、ADR-010、ADR-011、ADR-013；[部署运维与恢复手册](../docs/operations/部署运维与恢复手册-v1.0.md) §8~§10

## 核心职责

首版后端提供两个独立启动入口，共用同一编译产物、同一领域规则与同一数据库结构，不构成微服务（ADR-013 §2.3、OPS-TOPO-003）：

- **`main.ts`（HTTP 应用）**：承载页面交互接入、命令/查询、逐请求授权、同步本地事务与提交后任务意图登记。
- **`worker.ts`（后台任务）**：承载 Casdoor 写入与回读、邮件投递、文件检查/预览、导出生成、到期任务、正式删除、派生重算和对账；不监听 HTTP。

关键不变量：

- 后台入口不得假定 HTTP Guard / Pipe / Interceptor / 请求上下文自动生效；每个任务取得租约和提交结果时重新校验状态、版本、权限与业务前置条件（ADR-013 §2.7、ADR-004 §2.6）。
- 任务权威为 PostgreSQL 持久任务/事务发件箱，至少一次执行；内存回调、进程内队列或外部回调不能成为业务权威（OPS-JOB-001、ADR-004 §2.1）。
- 两个入口的启动状态、最近异常与关联追踪进入 ops 模块内置状态页与脱敏日志（ADR-011）。
- 文件检查、预览生成等 CPU/内存密集或处理不可信内容的工作不得塞入 API 请求事件循环（ADR-013 §2.9）。

## 关键组件

| 组件（建议命名） | 类型 | 职责 |
|---|---|---|
| `main.ts` | 启动入口 | 配置校验 → 创建 NestJS 应用 → 注册全局管道/过滤器/中间件 → 启动 HTTP 监听 → 上报启动状态 |
| `worker.ts` | 启动入口 | 以 NestJS 应用上下文（不监听 HTTP）启动 → 注册任务处理器 → 启动调度循环与租约领取 → 优雅停止 |
| `AppModule` | 根装配（src/app.module.ts） | 按 12＋3 逻辑模块装配各 FeatureModule；跨模块能力只经应用命令与查询边界暴露 |
| `ConfigLoader` | 配置基础设施 | 加载单文件外置配置（ADR-010，只读挂载），启动前结构校验；未知字段、缺失必需项失败关闭 |
| `DbConnectionManager` | DB 适配（src/adapters/db） | PostgreSQL 连接池、RLS/连接上下文建立与清理（OPS-DB-002/003） |
| `AuthMiddleware`（HTTP） | 入口组件 | 认证与作用域解析、请求追踪编号、RLS 上下文绑定（仅 HTTP 入口生效） |
| `TaskLeaseWorker` | job 编排 | 按业务意图领取任务、取得有期限租约、版本/权限复核、执行、按回读收口 |
| `GracefulShutdown` | 公共能力 | 停止接收新请求/新领取 → 等待进行中事务与外部回读 → 清理连接上下文 → 置状态为停止 |

## 对外接口

- HTTP：受保护 HTTPS 监听（正式环境强制），对外提供认证接入、命令/查询、文件访问与内置状态页；具体端口与路由以传输适配评审为准，本入口不自行决定协议细节。
- 配置：单文件外置配置以只读方式挂载（ADR-010）；启动前校验配置结构、环境标识、必需引用、版本兼容与互斥条件（OPS-CFG-001）；秘密不进入仓库或镜像。
- 外部依赖：PostgreSQL（权威库＋持久任务）、Casdoor（账号/Group 回读）、S3 兼容对象存储、文件检查/预览、邮件；均通过 src/adapters 适配边界接入。
- 依赖就绪与启动状态：两入口向 ops 内置状态页上报应用版本/启动状态与最近异常（ADR-011）；依赖不可用时按 §8.4 分类处理，不伪造健康。

## 核心逻辑摘要

- **启动前置证据（OPS-DEP-001~003）**：版本化证据基线（构建指纹、配置脱敏摘要、DB/Casdoor/存储能力结论）；PostgreSQL 18.x、uuidv7/UTF-8/pg_unicode_fast/pg_trgm/btree_gist 与统一 Schema 就绪；Casdoor 实例能力按实际证据判定，无法证明的置"未知"并按风险失败关闭；Webhook 不属启动前置。
- **启动结果分类（§8.4）**：启动阻断（配置无法解析、迁移/发布不兼容、数据库权威无法建立、基础安全证据不成立）→ 不启动业务服务，保留脱敏失败证据；能力阻断 → 应用可运行但对应能力关闭；明确降级 → 仅开放降级目录（如 Casdoor 15 分钟最小白名单）；未知 → 按风险失败关闭，状态页显示未知。
- **HTTP 入口顺序**：认证与作用域 → 逐请求授权 → 目标对象/状态/版本校验 → 本地事务提交（业务＋历史＋关键审计＋必要通知事实与任务意图同成同败）→ 提交后触发外部任务/派生刷新；响应按事务类别返回已完成或处理中（IFC-CMD-001/002）。
- **后台执行语义**：任务至少一次执行；每次尝试取得有期限租约，重复领取/租约过期/续租失败/对象版本变化/作用域扩大时旧持有者不得提交；外部结果不确定时先可信回读再决定成功/重试/补偿/异常（OPS-JOB-003、ADR-004 §2.5/§2.7）；幂等键与追踪编号分离，不得混同。
- **RLS 与连接上下文**：每个受保护数据库操作在事务边界内重建并验证最小单目标/集合只读上下文，成功/回滚/异常/超时/取消后清理，归还池前证明无跨请求残留；集合只读上下文不可写入（OPS-DB-002/003）；迁移/特权连接与普通流量隔离（OPS-DB-004）。
- **优雅停止**：先停止新请求接收与新任务领取，等待进行中事务与外部回读收口，清理连接上下文后退出；突然终止不得在外部副作用未收口时自行判定成功。

## 典型调用链

- **HTTP**：`main.ts 接收请求` → `AuthMiddleware` 认证＋作用域＋追踪编号 → 应用命令用例组装授权上下文 → 领域校验（状态/版本/前置条件）→ 本地原子提交（业务＋历史＋关键审计＋通知事实＋任务意图）→ 提交后登记任务到 job / 触发派生刷新 → 按事务类别返回结果。
- **后台**：`worker.ts 调度循环轮询持久任务` → `TaskLeaseWorker` 原子领取并取得租约 → 复核任务类型对应状态/版本/权限/安全开关（不因任务存在授权）→ 外部写入（Casdoor/邮件/存储/文件检查/导出）→ 可信回读收口 → 幂等更新任务状态（成功/可重试失败/结果不确定/人工处置/完成）→ 继续下一任务；应用关闭时先停止领取再等待在途任务。
