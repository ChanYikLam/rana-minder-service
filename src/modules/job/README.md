# 平台支撑 · 后台任务与批量编排

> 模块定位：平台支撑模块之一（ADR-002 §2.2）
> 职责：到期、重试、对账、通知投递、导出、删除、重算和受控批量执行的领取、租约、调度与编排
> 上游权威：[系统架构总览 v1.0](../../../docs/architecture/系统架构总览-v1.0.md)、[ADR-001](../../../docs/architecture/ADR-001-首版应用形态与后台任务运行单元.md)、[ADR-004](../../../docs/architecture/ADR-004-后台任务与可靠投递机制.md)、[ADR-013](../../../docs/architecture/ADR-013-Vue与NestJS首版应用技术栈.md)、[SRS-SM-ORG-004（受控批量操作，8 条转换；IFC-SM-007）](../../../docs/specification/SRS-状态机转换明细-v1.0.md)

## 事务边界对照（IFC-TX-001~008）

对照[接口契约 v1.0](../../../docs/specification/接口契约-v1.0.md)事务边界定义，标注本模块参与情况（✓=参与，--=不参与）。

| 边界         | 名称               | 本模块参与                         |
| ------------ | ------------------ | ---------------------------------- |
| `IFC-TX-001` | 本地业务状态转换   | --                                 |
| `IFC-TX-002` | 直接权益与通知     | --                                 |
| `IFC-TX-003` | Casdoor 外部写入   | ✓ Casdoor 写入与回读任务编排       |
| `IFC-TX-004` | 文件上传/检查/绑定 | ✓ 文件检查/预览任务编排            |
| `IFC-TX-005` | 通知渠道投递       | ✓ 通知投递任务编排                 |
| `IFC-TX-006` | 受控批量           | ✓ 受控批量编排（逐项调用领域命令） |
| `IFC-TX-007` | 正式删除           | ✓ 正式删除步骤执行任务             |
| `IFC-TX-008` | 派生刷新与重建     | ✓ 派生重算/对账任务                |

注：本模块只提供任务执行机制，各任务的事务归属与业务决定由责任领域模块拥有。

## 1. 定位与责任

本模块为系统提供后台执行能力：任务领取、租约竞争、调度、重试策略和受控批量编排（`SRS-SM-ORG-004（IFC-SM-007）`）。

本模块**只提供执行机制**，不拥有任何领域状态，不代替领域模块作出业务决定。每类业务意图的最终业务解释、状态机和事务归属继续遵守 ADR-002；每个批量单项仍调用责任领域模块的应用命令。

承接的工作类型（由各领域模块发起）：Casdoor 写入与回读、通知投递、文件检查/预览、导出生成、到期任务、正式删除执行、派生重算、对账。

## 2. 关键组件

| 组件                         | 类型                             | 职责                                                                                                                           |
| ---------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `TaskProcessorRegistry`      | 接口适配（interfaces）           | 任务类型->处理器映射注册；处理器薄壳，不含业务决策；平台支撑模块 interfaces 层例外：无 HTTP 入口，承载任务类型注册与处理器装配 |
| `JobController`              | Controller（interfaces）         | 任务管理端点（积压查询、手动重试入口，仅超管）                                                                                 |
| `ClaimAndExecuteTaskUseCase` | 应用命令（application/commands） | 取租约->复核前置条件->调用领域命令->回读收口->更新任务状态                                                                     |
| `BatchOrchestrationUseCase`  | 应用命令（application/commands） | 受控批量编排：冻结批次输入->逐项调度->汇总结果                                                                                 |
| `RetryPolicyUseCase`         | 应用命令（application/commands） | 重试策略判定：退避计算、上限判定、人工处置触发                                                                                 |
| `TaskStateMachine`           | 状态机（domain/state-machines）  | 任务状态转换规则（SRS-SM-ORG-004（IFC-SM-007））：待执行/执行中/可重试失败/结果不确定/需人工处置/已完成                        |
| `LeaseAndIdempotencyRules`   | 领域服务·规则（domain/services） | 租约竞争规则、幂等键派生、重试判定（纯规则，不依赖存储或 SDK）                                                                 |
| `BatchAggregationRules`      | 领域服务·规则（domain/services） | 批次汇总规则：成功项保留、失败项隔离、批次级审计                                                                               |
| `TaskRepository`             | 基础设施适配（infrastructure）   | 任务表访问（含租约竞争原子条件更新）、任务状态持久化                                                                           |
| `ExternalCallAdapter`        | 基础设施适配（infrastructure）   | 外部适配调用编排：路由至 `src/adapters/` 的 Casdoor/S3/邮件/文件检查适配器，按任务类型分发；不直接持有外部 SDK                 |

## 3. 权威与边界

| 本模块可以                                     | 本模块禁止                                   |
| ---------------------------------------------- | -------------------------------------------- |
| 领取、租约、调度、执行、重试、汇总持久任务     | 反向拥有其他模块的领域状态                   |
| 在批量中逐项调用领域应用命令                   | 自行决定录取、任免、成员、权限或归档结果     |
| 保存任务意图、租约、尝试、失败与收口的技术权威 | 用任务存在绕过状态、版本、权限或业务前置条件 |
| 按任务类型和积压独立扩展执行单元               | 把外部成功直接当成本地业务成功               |

核心不变量（ADR-004）：

1. 待执行意图必须先可靠持久化；业务事实与执行意图要求同成同败时，必须在同一本地事务持久化（事务发件箱）。
2. 以租约竞争领取任务，按**至少一次执行**设计：并发、崩溃、租约过期、恢复重放都可能重复领取，不得假设"恰好一次"。
3. 每份业务意图和每个外部操作使用稳定幂等依据；重复领取、客户端重试、人工重试、外部回调和恢复重放必须汇聚到同一业务意图，最终至多一份有效业务结果。
4. 执行前必须重新检查对象状态、版本、当前权限/系统任务授权、安全开关和业务前置条件；过期、失权、已取消、已替换、已删除或版本落后的任务不得复活旧业务。
5. 外部结果不确定时必须先可信回读或查询，再决定成功、重试、补偿或异常收口。
6. 任务状态必须能区分：待执行、执行中、可重试失败、结果不确定、不可自动重试/需人工处置、已完成（命名与实现由下游规格决定）。

## 4. 运行形态（ADR-001、ADR-013）

- 后台任务通过 `src/main.worker.ts` 独立启动入口运行（NestJS 应用上下文，不监听 HTTP），与 HTTP 应用复用同一套应用层、领域层和基础设施适配。
- 后台入口不得假定 HTTP Guard/Pipe/Interceptor 生效；每个任务在应用能力边界重新校验授权、状态、版本、租约、幂等和外部结果收口条件。
- 单机部署可同主机独立进程/容器运行；拆分部署按任务类型和积压独立扩展。
- 文件检查、预览生成等 CPU/内存密集或处理不可信内容的工作不得塞入 API 请求事件循环（ADR-013 §2.9）。
- 首版不强制独立消息队列；未来引入时只能作为唤醒/分发/削峰，消费者仍回到持久任务领取并核验，队列确认不能替代业务完成状态。

## 5. 分层落位

```
interfaces/     启动器与任务注册：声明任务处理器（无 HTTP 入口）
application/    执行编排：领取、重试策略、对账流程、批量逐项调用领域命令
domain/         任务状态机规则（SRS-SM-ORG-004（IFC-SM-007））、租约/幂等规则、重试判定（纯规则）
infrastructure/ 任务持久化访问、租约锁、外部适配调用（Casdoor/S3/邮件/文件检查）
```

- **interfaces**：注册"任务类型 → 处理器"映射；处理器本身是薄壳。
- **application**：编排执行流程——取租约 → 复核前置条件 → 调用领域命令 → 回读收口 → 更新任务状态。
- **domain**：任务状态转换、幂等键派生、重试上限/退避判定、批次汇总规则，不依赖具体存储或外部 SDK。
- **infrastructure**：任务表访问（含租约竞争语句）、事务辅助、外部调用客户端。

## 6. 开发必须遵守的规则

### 6.1 任务写入与提交

- 业务事实与任务意图同成同败时，**同一本地数据库事务**内写入；不得先提交业务再靠内存回调/进程内队列补建任务。
- 任务记录须携带：与来源业务意图的稳定关联、适用作用域、源对象及版本、幂等依据、租约信息、尝试次数、可执行时间、脱敏失败信息和最终结果引用。
- 失败信息必须脱敏，不得写入业务正文、内部评语、附件内容、完整联系方式、令牌或密钥。

### 6.2 领取与执行

- 所有领取/竞争使用数据库级原子条件更新（租约版本比较），双执行单元并发只允许一个成功。
- 执行成功必须回读或查询外部结果后再收口；不得盲目重复调用换取表面成功。
- 迟到响应、重复回调、人工重试与恢复重放共享同一业务意图和收口规则，不得各自产生一份结果。
- 对任务执行使用唯一追踪编号，并与业务幂等键区分开（两者不得混同）。

### 6.3 受控批量（SRS-SM-ORG-004（IFC-SM-007））

- 批量前提：固定一个社团、一个操作类型和一个业务/邀请类型；跨社团、跨操作类型或任意字段通用修改一律拒绝。
- 预览阶段原子保存筛选条件、固定对象 ID、对象版本、操作参数和影响范围；预览版本唯一，修改选择后旧预览失效并重新预览。
- 确认执行时原子冻结批次输入，不得重新查询筛选结果；执行启动幂等，只允许一个执行器。
- 每个单项独立本地事务提交，单项失败不终止整批、不回滚成功项；成功项即使被伪造传入也拒绝重复执行。
- 失败项重试必须关联原批次、仅含失败项、沿用原业务幂等键；成功项不得复制或再次执行。
- 批次级审计与单项审计并存，单项通知不能被批次摘要替代。

### 6.4 任务状态枚举（TaskStatus）

```
任务状态枚举（TaskStatus）：
- PENDING（待执行）
- LEASED（执行中）
- RETRYABLE_FAILED（可重试失败）
- UNCERTAIN（结果不确定，需读回）
- MANUAL_INTERVENTION（不可自动重试/需人工处置）
- COMPLETED（已完成）
```

TaskStatus 为任务持久状态枚举，与适配层 ExternalStatus（外部调用结果枚举，见 src/adapters/基础设施适配文档.md）语义不同：UNCERTAIN 在 TaskStatus 指任务结果不确定需读回，在 ExternalStatus 指外部调用结果不确定；二者位于不同枚举体系，不得混用。

## 7. 与相邻模块协作

| 协作对象                                                                                         | 关系                                                                                                        |
| ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| 各领域模块（identity/organization/invitation/membership/stat-export/audit/notification/file 等） | job 逐项调用其应用命令编排到后台执行，不直接写领域表；取得租约与提交结果时仍复核状态/版本/权限/业务前置条件 |
| ops 模块                                                                                         | 任务积压、最近异常与各任务类型最近结果流向 ops 内置状态页；job 不改变 ops 观测结论                          |
| adapters（Casdoor/S3/邮件/文件检查）                                                             | 经 `ExternalCallAdapter` 按任务类型路由分发，不直接持有外部 SDK                                             |

任务类型的业务归属详见 §6.5 任务类型与处理器映射表；每类业务意图的最终解释与状态机归属仍由领域模块负责（ADR-002）。

## 8. 测试要求

- 业务提交前崩溃、提交后崩溃（外部未执行）、外部成功但本地记录前崩溃、迟到响应；
- 双执行单元竞争、租约过期、恢复重放——全部场景不得产生第二份业务结果；
- 任务执行前的状态/版本/权限/开关复核（过期、失权、已取消任务不得复活）；
- 批量：越权单项、状态变化、容量失败只记该项失败；伪造成功项重试被拒绝；
- 消息加速层（未来引入时）丢失任务不得丢业务意图；
- 幂等键重复提交返回原结果；追踪编号与幂等键分离；
- 任务失败信息脱敏断言。
