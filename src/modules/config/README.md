# 领域模块 · 配置与发布

> 更新日期：2026-08-12
> 状态机：无（配置版本发布语义，SRS-FAIL-013）

## 核心职责

平台/社团默认值、活动配置快照、学年/届次、模板与安全开关的不可变版本发布与生效范围管理。关键不变量（ADR-002 §2.1）：已发布版本不可原地覆盖（CFG-005）；发布失败时旧版本完整有效、不得混合生效（SRS-FAIL-013）；活动发布冻结快照，后续默认值变化不影响已发布活动（CFG-005）；本模块不拥有使用配置的领域状态。

## 关键组件

| 组件（建议命名） | 类型 | 职责 |
|---|---|---|
| `ConfigController`、`ConfigPublishController` | Controller | 配置查看/修改/预览/发布/回滚入口与授权上下文（含高风险重认证） |
| `PublishConfigCommand`、`RollbackConfigCommand`、`SnapshotConfigCommand` | 应用命令·查询用例 | 基于旧版本创建新版本、影响预览与差异校验、原子发布、活动快照冻结 |
| `ConfigVersionAggregate`、`ConfigScopeResolver` | 领域模型·状态机 | 版本不可变性、平台→社团→活动快照三级范围解析、安全开关版本规则 |
| `ConfigRepository`、`CacheInvalidationClient` | 基础设施适配 | 版本、当前指针与发布记录持久化（PostgreSQL）；权限模板/安全开关发布后缓存立即失效 |

## 对外接口

- HTTP 路由前缀：平台侧 `/admin/config/*` 与社团侧 `/org/:clubId/config/*` 两组前缀（具体路径以接口契约落位为准）。
- 外部适配：PostgreSQL（不可变版本＋当前指针＋发布记录同事务）；缓存（权限模板/安全开关发布后立即失效，CFG-008）；job 模块（可选：发布后派生刷新/对账触发）。
- 关键外部调用：发布权限模板、字段映射等高风险配置前展示影响对象并二次确认；影响学生权益或管理员权限时通知（CFG-005）。
- 查询要点：配置查看与影响预览走版本化服务端目录（IFC-QRY-002）；预览基于发布前固定版本，确认执行时不重新查询宽范围，防止预览与生效范围不一致。

## 核心逻辑摘要

- 版本语义：修改/回滚=基于旧版本创建新版本并发布，不删除中间历史；邮件密钥不能通过普通回滚恢复旧明文，只能重新填写或轮换（CFG-005）。
- 发布原子性：原子切换当前发布指针并使缓存失效；任一对象失败时所有对象继续使用旧版本，不得部分对象使用新版本（SRS-FAIL-013、IFC-GEN-007）；重试前重新预览影响并校验当前状态。
- 三级范围解析：平台默认值与允许范围 → 社团覆盖（限于允许范围内）→ 活动配置快照；活动发布时冻结快照，之后模板回滚与默认值变化不影响已发布活动；已发布活动只能在业务状态允许时单独修改配置。
- 学年/届次：平台初始化时区与学年分界日，系统自动生成学年并切换当前学年；切换当前学年不自动创建届次、结束招新或改变成员关系；已被正式业务引用的历史学年不得因规则变化被自动重写。
- 展示资料：社团展示名称/Logo/简介等修改立即生效且无需审批，不进入完整发布流程，但仍保留修改历史与审计；修改不改变 Casdoor Group、成员关系或权限。
- 安全开关：紧急开关（如 GOV-004 类）立即生效并优先于活动快照；权限模板发布后立即统一作用于关联职位 Group 的全部当前成员，权限缓存立即失效，已登录用户下一次受保护请求按新版本鉴权（CFG-008）。
- 作用域与审计：所有配置修改显示作用域和生效时间，记录旧值、新值、修改人并审计；发布、失败、缓存失效与回滚均审计。
- 高风险发布：权限模板、字段映射发布要求最近 10 分钟重新认证、实时确认当前 Group、填写原因、影响预览与二次确认（GOV-007、CFG-008）；映射不存在、类型不兼容或可能造成批量数据丢失时禁止发布。
- 新社团接入：启用前必须存在负责人职位 Group 且至少一名有效负责人；检查重复绑定、层级关系、负责人连续性与权限越界，任一步骤失败保持未启用，不产生部分生效的权限。
- 字段映射：学号/账号与姓名是必需映射，真实数据启用后不得随意删除；学院、年级、邮箱等仅能从固定同步白名单映射，动态表单字段不能映射到 Casdoor；映射只决定外部字段位置，不改变只读/可编辑/双向同步规则；新映射发布后执行一次受控对账。

## 典型调用链

`ConfigController 发布配置` → 基于当前发布版本创建新版本 → 影响预览与差异校验 → 高风险配置先重认证（10 分钟 proof）＋二次确认 → 原子提交：新版本＋发布记录＋旧值/新值/修改人审计（第 1 类事务）→ 提交后信号触发缓存立即失效（权限模板/安全开关）→ 影响方通知；任一失败则当前指针与缓存保持旧版本，重新预览后重试。
