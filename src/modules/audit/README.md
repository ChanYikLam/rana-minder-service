# 领域模块 · 纠错、审计与数据生命周期

> 更新日期：2026-08-12
> 状态机：`SRS-SM-AUD-001`（纠错，8 条转换；IFC-SM-028）

## 核心职责

事实纠错（申请/批准/驳回/撤回/逾期）、不可变业务审计写入器、数据保留策略与正式删除执行清单。关键不变量（ADR-002 §2.1）：不通过覆盖历史实现纠错或删除完成假象；关键审计与业务结果同一提交边界，审计失败业务不得成功（AUD-003）；正式删除部分失败不得宣称完成，恢复后重放清单（AUD-009）。

## 关键组件

| 组件 | 类型 | 职责 |
|---|---|---|
| `CorrectionController`、`CorrectionAdminController` | Controller（interfaces） | 纠错提交/决定/撤回、正式删除、保留策略、审计查询入口与授权上下文 |
| `SubmitCorrection`、`DecideCorrection`、`WithdrawCorrection` | 应用命令·查询用例（application/commands、application/queries） | 推进 `SRS-SM-AUD-001` 各转换；携带申请版本与幂等键 |
| `AuditWriter` | 应用命令·查询用例（application/commands、application/queries） | 关键审计写入器：与业务同事务提交；敏感字段脱敏 |
| `FormalDeleteCommand`、`RetentionPolicyCommand` | 应用命令·查询用例（application/commands、application/queries） | 删除执行清单编排、保留策略发布/执行（高风险门） |
| `CorrectionAggregate`、`CorrectionStateMachine` | 领域模型·状态机（domain/models、domain/state-machines） | 纠错状态、客观错误判定、作者回避与联合边界 |
| `AuditEvent`、`DeletionChecklist` | 领域模型·状态机（domain/models、domain/state-machines） | 审计事件目录；删除清单步骤、恢复重放与最小删除审计 |
| `AuditRepository`、`DeletionStepExecutor` | 基础设施适配（infrastructure） | 审计/清单持久化（PostgreSQL）；跨数据库/对象存储/缓存/索引/导出副本逐项执行 |

## 对外接口

- HTTP 路由前缀：社团侧 `/org/:clubId/audit/*`，平台侧 `/admin/audit/*`、`/admin/delete/*`、`/admin/retention/*`；路径以接口契约为准，不得临时编造。
- 外部适配：PostgreSQL（纠错链、审计、删除清单同库原子提交）；对象存储/搜索缓存/导出副本（删除清单跨存储步骤）；job 模块（逾期截止任务、删除步骤执行、临时清理）。
- 关键外部调用：删除与清理执行器、站内通知（纠错决定/删除结果）；高风险操作先重认证再执行。

## 核心逻辑摘要

- 状态机链路：`新建（NEW） -> 草稿（DRAFT） -> 待处理（PENDING） ->（已批准（APPROVED）/ 已驳回（REJECTED））`；`待处理 -> 逾期待处理（OVERDUE_PENDING）`（系统截止任务仅置逾期标志，不自动决定）；`待处理或逾期待处理 -> 已撤回（WITHDRAWN）`（仅原提交人，与批准/驳回按同一申请版本竞争）；终态（已批准/已驳回/已撤回）不可覆盖（AUD-002、AUD-010）。
- 拒绝条件：单纯主观评价争议（IFC-ERR-006 业务前置条件失败 / IFC-ERR-007 状态冲突）、作者自批（IFC-ERR-003 当前无权）、跨社团改写他人记录（IFC-ERR-003 当前无权 / IFC-ERR-004 作用域不匹配 / IFC-ERR-015 结果不可见）、证据越权（IFC-ERR-003 当前无权）、驳回缺原因（IFC-ERR-005 输入无效）--拒绝并保持实际状态。
- 事务边界：纠错决定与审计=第 1 类纯本地领域命令同事务提交（IFC-TX-001）；正式删除=第 7 类（先撤权、步骤核验、部分失败不得宣称完成、恢复后重放清单，IFC-TX-007）；保留清理任务失败按退避重试直至收敛（AUD-014）。
- 审计写入器：排队写审计视为失败，不得异步补写关键审计（AUD-003、GOV-006 至 009）；密码/密钥/令牌/验证码/附件正文不入审计，只记脱敏差异；应用内任何管理员不能修改或删除审计。
- 归档访问：活动完成后自动只读归档；面试官结束后失去档案访问权；历史负责人/部长不因过去职位保留访问权，访问按当前角色重新鉴权（IFC-ERR-003 当前无权）；超管特权查看每次审计（AUD 归档规则）。
- 普通编辑边界：业务开放期间走业务状态下的普通编辑，锁定/归档后关闭普通编辑、只允许纠错；纠错只追加新记录，原值、原附件与历史继续保留。
- 高风险重认证 proof：模拟前端 `governance.ts::assertHighRisk`--命令登记、10 分钟内重新认证 proof 一次性消费、原因必填、二次确认；18 类高风险命令目录（保留策略发布/执行、正式删除、权限模板发布、批量执行、导出下载、成员移除、换届执行等）；真实数据开关开启同样为高风险命令（GOV-007、GOV-002）。
- 保留策略：临时/技术数据分层清理；先撤访问再物理清理；延期立即生效、缩短对已有数据至少 7 天缓冲（AUD-014）。
- 删除后最小审计：仅保留内部标识、执行时间、执行超管与删除类型，不保留被删正文（AUD-007）。

## 典型调用链

`CorrectionController 提交纠错` -> 授权上下文（客观错误、作者回避、联合作者归属）-> 领域校验 -> 原子提交：正式申请＋证据引用＋关键审计＋通知事实（第 1 类事务）-> 站内通知处理人。`处理人批准` -> 申请版本 CAS 竞争 -> 同事务追加原值/新值/原因/处理人/时间＋审计 -> 影响权益时通知本人；需改变当前关系时另走成员流程。`正式删除`：重认证 proof＋原因 -> 影响预览二次确认 -> 第 7 类事务持久化删除清单 -> job 跨存储逐项执行并核验 -> 全部核验完成才宣称完成；恢复备份后重放清单防复现。
