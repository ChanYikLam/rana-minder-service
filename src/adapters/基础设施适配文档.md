# 基础设施适配 · 外部依赖统一适配边界开发指导

> 更新日期：2026-08-12
> 目录位置：src/adapters/
> 权威依据：[系统架构总览 v1.0](../../docs/architecture/系统架构总览-v1.0.md)（§4.2、§5.1、§5.4、§9）、ADR-004 §2.7、ADR-005、ADR-008、ADR-009、ADR-014；[部署运维与恢复手册](../../docs/operations/部署运维与恢复手册-v1.0.md) §8~§12

## 核心职责

本目录是 RanaMinder 与全部外部基础设施交互的唯一适配边界，位于架构分层"适配与执行层"（§5.1）：Casdoor 统一认证与 Group（casdoor/）、PostgreSQL 访问（db/）、邮件渠道（mail/）、S3 兼容对象存储（storage/），以及文件检查/预览、搜索/缓存类适配。领域规则不得依赖供应商专有对象，业务模块不得直接依赖具体 SDK、端点或响应结构（§5.4）。

关键不变量：

- 适配层不拥有产品状态，不从派生数据授予权限，不自行决定录取、任免、成员、权限或归档结果；故障处理的业务所有者始终是拥有业务意图或状态机的模块（§9）。
- 外部结果不确定时必须先可信回读或查询，再决定成功、重试、补偿或异常（ADR-004 §2.7）；不得以 HTTP 成功、事件到达或本地期望值替代可信回读。
- 适配器返回规范化结果、当前值、版本/时间依据和错误分类；具体是否推进状态由领域模块决定（ADR-009 §2.4，该语义适用于全部适配器）。
- 服务账号凭据只保留在服务端；超时、限流、重试、熔断、错误脱敏、追踪与审计关联由适配层统一处理（ADR-009 §2.9）。

## 关键组件

| 组件                                | 类型         | 职责                                                                                                                                                                         |
| ----------------------------------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CasdoorAdapter`（casdoor/）        | 基础设施适配 | 账号与 Group 查询与写入、写后定向读回、周期对账；规范化结果与错误分类（ADR-009）。浏览器登录/回调之外唯一应用边界，登录令牌/Claims 核验由身份模块承接（见 Casdoor 适配文档） |
| `DbConnectionManager`（db/）        | 基础设施适配 | PostgreSQL 连接池、事务辅助；RLS/连接上下文建立与清理由 `ConnectionContextBuilder`/`ContextGuard` 承担（详见 db 目录文档）                                                   |
| `ObjectStoreAdapter`（storage/）    | 基础设施适配 | S3 兼容对象存储字节读写、只写一次定位、短时地址、删除与核验；不决定业务归属或访问权限（ADR-008）                                                                             |
| `MailChannelAdapter`（mail/）       | 基础设施适配 | 邮件渠道投递、邮箱验证邮件、退信与重试；投递结果非业务或通知事实权威                                                                                                         |
| `FileCheckAdapter`                  | 基础设施适配 | 文件检查/安全预览服务适配；只提供检查结果与派生物，不授予访问权                                                                                                              |
| `ExternalResult` 与 `ExternalError` | 公共类型     | 规范化结果（当前值、版本/时间依据）与错误分类（可重试/结果不确定/明确失败/限流），全部适配器共用                                                                             |

## 使用与准入规则

- 业务模块经本目录暴露的适配边界访问外部依赖；领域层与供应商专有对象解耦（§5.4）。
- 适配器只执行外部操作并报告规范化结果；是否推进本地状态、创建角色或业务结论由调用方领域模块决定（ADR-009 §2.4）。
- 适配器必须统一处理超时、限流、重试、熔断、错误脱敏、追踪与审计关联；凭据只保留在服务端。
- 禁止：把 HTTP 成功、事件到达或本地期望值当作可信回读；把适配器错误冒充业务拒绝或成功；在日志、错误或任务载荷中暴露秘密或完整外部响应（OPS-CFG-005）。

## 核心逻辑摘要

- **写后可信回读收口**：外部写入超时、断连或响应丢失时先定向读回或查询，再按结果分类决定成功、重试、补偿或异常；不盲目重放（ADR-004 §2.7、OPS-JOB-004）。
- **事件与对账边界**：Casdoor 事件只触发可信刷新或对账，不直接作为当前值最终权威；周期对账兜底，Webhook 默认关闭（ADR-009 §2.5、§9）。
- **数据与字节分离**：元数据、版本、检查状态与业务引用在 PostgreSQL，字节在对象存储；不伪装跨系统原子事务，部分失败不得返回假成功（ADR-008 §2.7）。
- **失败分类与失败关闭**：结果区分明确成功、结果不确定、可重试失败与不可自动重试；未知状态按风险失败关闭，不伪造健康（§8.4、OPS-DEP-004）。

ExternalResult<T>（外部调用统一结果类型）：

- status: ExternalStatus 枚举
  - SUCCESS（明确成功）
  - UNCERTAIN（结果不确定，需读回）
  - RETRYABLE_FAILURE（可重试失败）
  - NON_RETRYABLE（不可自动重试/需人工处置）
  - RATE_LIMITED（限流）
  - NOT_FOUND（目标不存在）
  - CONFLICT（不唯一/冲突）
  - PARTIAL（部分结果）
  - UNAVAILABLE（依赖不可用：超时、连接中断或服务不可达，对应 IFC-ERR-012）
- data: T | null（成功时的返回数据）
- error: ExternalError | null（失败时的错误信息）
- attemptId: string（本次尝试的唯一标识）
- timestamp: Date（结果时间）

ExternalError（外部调用错误信息）：

- code: string（稳定错误分类，脱敏）
- message: string（脱敏错误摘要，不含业务正文/密钥/令牌）
- retryable: boolean（是否建议重试）
- rawStatusCode: number | null（原始 HTTP 状态码，仅用于诊断）

## 典型调用链

Group 关系写入（后台）：领域事务持久化业务意图与任务 → job 领取并复核状态/版本/权限 → `CasdoorAdapter` 执行写入 → 写后定向读回 → 规范化结果返回领域模块 → 领域模块按规则收口（成功/重试/异常）→ 更新任务状态。附件下载：文件模块按当前授权实时鉴权 → `ObjectStoreAdapter` 生成短时最小范围地址 → 访问写审计。
