# 对象存储适配 · S3 兼容对象存储字节读写开发指导

> 更新日期：2026-08-12
> 目录位置：src/adapters/storage/
> 权威依据：[ADR-008](../../../docs/architecture/ADR-008-S3兼容对象存储与文件可恢复提交.md)、[接口契约-v1.0](../../../docs/specification/接口契约-v1.0.md)（IFC-TX-004/007、§10）、SRS-FAIL-006/011/012、[部署运维与恢复手册](../../../docs/operations/部署运维与恢复手册-v1.0.md)（§8.1、§11）

## 核心职责

以 S3 兼容对象存储承载附件原件、安全预览、水印/转码派生物与临时导出等文件字节；元数据、不可变版本、业务引用与检查/处理状态权威在 PostgreSQL（ADR-008 §2）。对象存储对字节负责，但不能决定业务归属、可见性或访问权限；授权始终由 RanaMinder 元数据与对象关系决定（ADR-008 §2.2、§2.6）。

关键不变量：

- 未检查文件不可预览、下载或正式绑定（GOV-008、SRS-INV-013、ADR-008 §2.4）；字节进入对象存储不等于检查通过或正式绑定。
- 数据库事务与对象存储操作不伪装成跨系统原子事务；上传/检查/绑定/删除以可查询状态、持久任务、幂等定位、补偿和对账形成可恢复提交（ADR-008 §2.7）。
- 每次访问重新鉴权后只生成短时、最小范围访问地址，敏感预览加水印；对象键、历史地址、缓存命中与旧短链均不是授权依据（ADR-008 §2.6、OPS-FIL-005）。
- 旧任务不得恢复已替换、删除、隔离或失权文件（SRS-FAIL-006）；应用级不可变版本是唯一业务版本（OPS-FIL-003）。

## 关键组件

| 组件                      | 类型         | 职责                                                                                                            |
| ------------------------- | ------------ | --------------------------------------------------------------------------------------------------------------- |
| `ObjectStoreAdapter`      | 基础设施适配 | S3 兼容接口字节写入/读取/晋升/删除与核验；统一超时、限流、重试与错误脱敏                                        |
| `ObjectKeyGenerator`      | 基础设施适配 | 服务端生成高熵随机定位符：只写一次、不覆盖、不复用，不编码用户/文件名/摘要（OPS-FIL-002）                       |
| `StorageIsolationManager` | 基础设施适配 | 待检查隔离区、权威原件区、临时派生区三区定位与跨区晋升（OPS-FIL-001）                                           |
| `SignedUrlProvider`       | 基础设施适配 | 短时、最小范围访问地址生成与校验；配合敏感预览水印                                                              |
| `StorageTaskExecutor`     | 后台任务     | 孤儿清理；检查回调与正式删除清单调用文件模块命令/清单用例并回传规范化结果（不直接收口文件状态机，见 file 模块） |
| `StorageRecoveryVerifier` | 后台任务     | 恢复备份后的数据库—对象一致性核对与删除清单重放支持                                                             |

## 核心接口

ObjectStorageAdapter 核心接口：

- putObject(bucket: string, key: string, body: Buffer, contentType: string): Promise<ExternalResult<void>>
- getObject(bucket: string, key: string): Promise<ExternalResult<Buffer>>
- deleteObject(bucket: string, key: string): Promise<ExternalResult<void>>
- generateSignedUrl(bucket: string, key: string, expiresIn: number): Promise<ExternalResult<string>>
- headObject(bucket: string, key: string): Promise<ExternalResult<ObjectMetadata>>

## 使用与准入规则

- 字节与元数据分离：调用方在 PostgreSQL 保存文件版本、检查状态、引用与对象定位，本适配只读写字节；对象地址不是授权（IFC-DATA-009）。
- 上传只进入隔离区；检查未可信确认前不得晋升、绑定、预览或下载（OPS-FIL-004）；客户端不得自行宣布检查通过或决定对象键（IFC-FIL-001/002）。
- 每次预览/下载由文件模块实时鉴权后经本适配生成短时地址；失权、停用、隔离、删除后旧地址立即失效，不缓存授权（OPS-FIL-005）。
- 删除必须走删除清单：先撤销访问，再逐项核验数据库、对象存储、缓存、索引与未过期导出；任一步失败保持未完成并重试，不得宣称完成（AUD-007 至 009、SRS-FAIL-011）。
- 禁止：把应用本地磁盘当正式唯一权威副本、覆盖旧原件、把业务信息编码进对象键、绕过检查直接开放访问。

## 核心逻辑摘要

- **三区与键设计（OPS-FIL-001/002）**：每个环境三个私有 Bucket（待检查隔离区、权威原件区、临时派生区），环境间不共享；对象键由服务端生成不少于 128 位随机熵、只写一次、不覆盖、不复用；在线 Bucket 不启用原生 Versioning/Object Lock，应用级不可变版本为唯一业务版本（OPS-FIL-003）。
- **版本化可恢复提交（第 4 类，IFC-TX-004）**：上传初始化只创建指向隔离区的限时会话 → 字节完成进入检查中并创建权威检查任务 → 检查通过后以新键晋升、核对大小与可信哈希，PostgreSQL 原子收口定位与版本状态 → 绑定与提交修订同事务建立；检查服务不可用不超时放行，保持不可访问（OPS-FIL-004、SRS-FAIL-006）。
- **短时访问与水印（IFC-FIL-005）**：每次访问按当前用户、对象、字段、任务、社团/联合关系与业务状态实时鉴权；只发放时效受控、最小范围的访问地址，敏感内容加水印并写访问审计。
- **清理与正式删除（第 7 类，IFC-TX-007）**：草稿孤儿、扫描失败、无有效引用与临时导出按期限异步清理，执行前重查引用；正式删除按清单跨数据库/对象存储/缓存/索引/未过期导出逐项执行并核验，任一步失败保持未完成；恢复备份后重放删除清单并核对一致性，未收口不得宣称文件恢复完成（AUD-007/009、SRS-FAIL-011/012、IFC-FIL-008/009）。
- **证据基线（OPS-DEP-001）**：Bucket 私有性、版本控制/Object Lock、防覆盖、检查/预览与删除能力结论进入每次部署的版本化证据基线；无法证明的能力按风险失败关闭。

## 典型调用链

上传绑定：`FileController` 初始化上传 → 元数据＋不可变版本＋隔离区定位与检查任务同事务保存（第 4 类）→ 字节进入隔离区 → 检查通过后 `ObjectStoreAdapter` 以新键晋升并核验 → 绑定与表单提交修订同事务原子提交。访问：文件模块实时鉴权 → `SignedUrlProvider` 生成短时最小范围地址＋水印 → 敏感访问审计。正式删除：审计模块删除命令 → 撤销访问 → 删除清单逐项执行核验 → 全部完成进入终态；备份恢复后重放清单并对账后再开放普通写入。
