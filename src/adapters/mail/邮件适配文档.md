# 邮件渠道适配 · 邮箱验证与通知邮件投递开发指导

> 更新日期：2026-08-12
> 目录位置：src/adapters/mail/
> 权威依据：[系统架构总览](../../docs/architecture/系统架构总览-v1.0.md)（§4.1）、[接口契约-v1.0](../../docs/specification/接口契约-v1.0.md)（IFC-TX-005）、SRS-FAIL-007、[需求发现记录 08](../../docs/requirements/08-站内信与权益通知需求发现记录.md)（NTF-004 至 009）

## 核心职责

邮件只承载"邮箱验证"与"符合资格的附加通知渠道"，不是业务或通知事实权威；通知事实、已读状态与业务结论的权威始终在 RanaMinder（§4.1、NTF-001）。本适配只负责外部投递、结果查询与退信处理，不决定投递资格、不创建通知事实、不把投递成功当作用户已知晓（NTF-004、NTF-007）。

关键不变量：

- 邮件任务属于第 5 类事务边界：对应通知事实、邮件渠道任务与安全摘要先本地保存，外部投递在提交后执行；邮件失败不回滚普通权益业务（IFC-TX-005、SRS-FAIL-007）。
- 邮箱验证不能绕过：验证邮件不可退订、24 小时有效、重发限频，只发当前待验证或当前已验证邮箱（SRS-FAIL-007、IDN-011、NTF-005）。
- 平台运维异常不创建外部邮件任务，只进站内信与内置状态（NTF-004、PRD-OPT-055）。
- 投递结果不确定时按提供商结果或消息 ID 查询后再收口，不得以发送响应宣称成功（NTF-008/009、IFC-TX-005）。

## 关键组件

| 组件（建议命名） | 类型 | 职责 |
|---|---|---|
| `MailChannelAdapter` | 基础设施适配 | 渠道意图对应的外部投递、按消息 ID 的结果查询与退信处理；返回规范化结果与错误分类 |
| `MailSender` | 基础设施适配 | 具体 SMTP/供应商客户端封装，统一超时、重试与熔断 |
| `SenderAccountResolver` | 基础设施适配 | 按事件类型与范围选择平台级或社团级发信账号；不借用其他社团账号（NTF-006） |
| `MailEligibilityChecker` | 基础设施适配 | 事件、配置、退订、验证与账号有效性五条件资格判定及执行前复核（NTF-004 至 007） |
| `SenderAccountManager` | 基础设施适配 | 社团/平台发信账号配置、测试邮件、轮换与失效暂停；密钥不明文回显（需求发现 08） |
| `TemplateSnapshotProvider` | 基础设施适配 | 发送时冻结模板版本与发件身份；HTML 安全校验失败自动回退平台默认模板 |

## 使用与准入规则

- 只投递已登记的渠道意图：调用方先本地保存渠道任务、模板/目标地址快照与安全摘要；本适配不创建业务、通知事实或已读状态。
- 每次发送前复核渠道资格（五条件）与通知事实状态；失权、已永久失败或事件不允许邮件时不得创建或执行外部投递。
- 正文遵守最少信息原则：不得包含内部评分/评语、非公开原因、完整报名表、附件、其他学生数据或免登录令牌；业务链接只进正常登录页（NTF-002/007、需求发现 08）。
- 结果不确定必须回读/查询：按提供商结果或消息 ID 核实后再收口，禁止以 HTTP 成功或本地期望值替代（NTF-008/009）。
- 禁止：密钥明文回显或入日志、模板覆盖发件身份、设置任意 Reply-To、以邮件成功宣称用户已知晓（NTF-008/009、需求发现 08）。

## 核心逻辑摘要

- **资格判定（NTF-004 至 007）**：事件允许邮件、本次/活动配置未关闭、用户未退订普通邮件、邮箱已验证、发信账号有效——五条件全满足才创建邮件任务；未验证邮箱、关闭普通邮件或无有效密钥时只投站内信。
- **第 5 类事务边界（IFC-TX-005）**：通知事实（第 2 类）提交后，渠道意图＋模板/目标快照独立原子保存；外部投递失败不回滚已提交权益，只重试渠道。
- **失败与收口（SRS-FAIL-007、NTF-007）**：临时失败自动重试；明确退信或连续失败 24 小时进入永久失败并保留投递证据，通过站内信提示用户并通知管理员；人工重发创建新尝试，只重发通知、不重执行业务。
- **结果不确定**：先按提供商结果/消息 ID 查询再决定成功、重试或异常；消息 ID 幂等，重复回调不得生成第二份投递结果。
- **发件身份与模板**：社团独立事件用社团账号，联合共同事件与超管平台操作用平台账号，账号无效降级为站内信；发送时冻结模板版本与发件身份，历史投递保留原身份；回复地址固定为实际发信账号（NTF-006、NTF-009、需求发现 08）。
- **邮箱验证**：单次令牌、24 小时有效、重发限频；新邮箱验证成功前旧邮箱保持有效；验证链路不可退订、不含免登录业务访问（IDN-011、NTF-005）。

## 典型调用链

权益领域命令（第 2 类）同事务保存业务结果＋通知事实＋收件人快照 → 资格判定五条件通过后保存邮件渠道任务＋模板快照＋安全摘要（第 5 类）→ job 执行前复核事实状态与资格 → `MailChannelAdapter` 按解析出的发信账号投递 → 结果不确定时按消息 ID 查询收口 → 临时失败重试 / 退信或连续失败 24 小时转永久失败并站内信提示、通知管理员 / 人工重发新建尝试。邮箱验证：`EmailVerificationUseCase` 登记验证意图 → 发送验证邮件（单次令牌、24 小时）→ 消费链接单次生效，旧邮箱保持有效至新邮箱验证成功。
