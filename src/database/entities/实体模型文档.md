# entities · 实体模型开发指导

> 更新日期：2026-08-12
> 目录位置：src/database/entities/
> 权威依据：ADR-006、ADR-013；[系统架构总览](../../../docs/architecture/系统架构总览-v1.0.md) §6/§7.3；数据模型与约束 v1.0 §2、§9

## 核心职责

本目录承载持久化映射：关系骨架与 JSONB 动态答案的混合存储（ADR-006）、对象标识/作用域/状态/版本/时间的统一表达，以及平台运行数据映射。关键不变量：

- 动态字段不能替代身份、组织、状态、审批、邀请、权限或时间等固定业务骨架；骨架必须强类型关系建模，不得埋入 JSONB 失去引用完整性或状态机约束（ADR-006 §2.2）。
- 每个本地业务对象必须表达：稳定对象标识（uuidv7）、所属作用域（普通社团作用域；联合协作域使用独立模型）、当前状态、状态版本、创建/更新时间及必要历史关联（架构总览 §6）。
- 乐观版本/版本列是并发控制基础：每个命令声明期望状态或对象版本，提交时不匹配拒绝（架构总览 §7.3）。
- JSONB 校验不得只依赖 TypeScript 编译期类型（ADR-013 §2.6、§4.1）；跨信任边界数据使用前必须运行时校验。
- ORM 实体不是领域模型：Controller、Guard、Pipe、ORM 模型与框架适配属于入口或基础设施，不携带业务结论（ADR-013 §2.5）。

## 关键组件

| 组件 | 类型 | 职责 |
|---|---|---|
| 权威业务实体映射 | ORM 实体 | 当前行：标识/作用域/状态/状态版本/时间的强类型关系映射 |
| 不可变版本与快照映射 | ORM 实体 | 发布版本、提交修订等可还原事实；普通编辑不得覆盖 |
| 追加式历史映射 | ORM 实体 | 状态转换、必要差异、操作者与结果；与业务提交同事务追加 |
| JSONB 答案快照映射 | 类型映射 | 稳定字段 UUID 键控的动态答案、重复组 `item_id` 引用（DATA-Q-007） |
| `EntityValidator`（由 `src/shared/` 提供） | 实体校验组合 | 按不可变表单版本执行结构/类型/范围/必填/条件/对象引用/附件检查（DATA-FRM-003）；校验原语来自 `common/RuntimeValidators` |
| 任务与租约映射 | ORM 实体 | 持久任务、租约、幂等依据、尝试与结果等平台运行数据（OPS-JOB-002） |
| 搜索规范化载体 | 派生载体 | 版本化规范化函数与按表证据门控的表达式索引/投影（ADR-007 §8） |

## 使用与准入规则

- 允许：稳定标识（PostgreSQL 内置 `uuidv7()` 生成）、作用域一致引用、版本列、时间列、JSONB 动态答案快照、不可变版本与追加式历史映射。
- 禁止：客户端或应用侧生成权威 UUID；把身份/状态/审批/邀请/权限/时间埋入 JSONB；只凭 TypeScript 类型或 DTO 通过 JSONB 校验；把 ORM 实体当领域模型承载业务规则；把联合协作关系伪装为普通社团作用域字段。
- 强关联必须同时证明对象标识与作用域一致；只按全局标识建外键、再依赖应用代码检查作用域，不足以保证隔离（DATA-GEN-004）。
- 标识不得使用数据库行位置、名称、学号、Group 名称、对象存储键或客户端工作空间提示替代（DATA-GEN-002）。

## 核心逻辑摘要

- **三层数据分层（DATA-GEN-003）**：当前行服务命令与查询；不可变业务版本或快照保存可还原事实；追加式历史保存变更轨迹；三层同事务写入，普通编辑不得覆盖不可变版本或历史。
- **稳定标识（DATA-Q-002）**：权威对象、不可变版本、命令、通知事实、文件版本、持久任务与删除清单统一 `uuid` 类型 UUIDv7，由 PostgreSQL 内置函数生成；纯关联行可用父 UUID＋稳定局部序号的复合标识。
- **版本并发（架构总览 §7.3）**：每次影响竞争判断的成功写入单调推进对象版本；命令声明期望版本，不匹配返回状态冲突；重复请求依赖独立幂等键收敛到第一次结果。
- **JSONB 运行时校验（DATA-FRM-003）**：动态答案进入权威修订前按绑定的不可变表单版本校验；缺失 key 表示未含答案，`null` 仅当字段类型明确允许"已确认为空"时使用。
- **授权边界（ADR-006 §2.6）**：JSONB 与 RLS 都不自动实现动态字段权限；读取、导出与修改结果在对象授权后按字段规则生成，实体映射不得代替该判定。

实体基类约定（BaseEntity）：
- `id`: uuidv7（主键，时间有序，由 PostgreSQL 内置 `uuidv7()` 生成）
- `scope`: 作用域标识（社团 ID 或平台标识，用于 RLS）
- `status`: 业务状态（枚举，由领域状态机定义）
- `object_version`: 乐观锁版本（整数，每次更新+1，CAS 竞争依据）
- `created_at`: 创建时间（timestamptz，UTC）
- `updated_at`: 更新时间（timestamptz，UTC，由触发器或应用维护）

表名约定：
- snake_case 命名
- 模块前缀避免跨模块冲突（如 `org_clubs`、`rec_activities`、`aud_corrections`）
- 关联表使用 `{模块}_{主}_{从}` 格式（如 `rec_activity_slots`）

ORM 装饰器约定：
- 实体类继承 `BaseEntity`
- 使用 TypeORM 装饰器（`@Entity()`、`@Column()`、`@OneToMany()` 等）
- JSONB 列使用 `@Column({ type: 'jsonb' })`，值对象用 `@Transformer` 序列化
- 枚举列使用 `@Column({ type: 'enum' })`，枚举值与 common/StateMachineConstants 一致

## 典型调用链

- **命令写入**：`Controller/DTO 适配` → 应用命令组装授权上下文 → 领域校验（状态/版本/前置条件）→ 实体装配＋JSONB 运行时校验 → 同一本地事务写入当前行＋不可变版本＋追加式历史 → 版本不匹配拒绝提交 → 返回结果。
- **后台任务**：`领取任务并取得租约` → 重读目标对象当前状态/版本 → 领域校验 → 以冻结作用域上下文写入 → 幂等更新任务状态（OPS-JOB-003/004）。
