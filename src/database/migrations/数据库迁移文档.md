# migrations · 数据库迁移开发指导

> 更新日期：2026-08-12
> 目录位置：src/database/migrations/
> 权威依据：ADR-007、ADR-014；[部署运维与恢复手册](../../../docs/operations/部署运维与恢复手册-v1.0.md) §14（OPS-UPG-001~006）；数据模型与约束 v1.0 §6

## 核心职责

本目录是生产数据库结构的唯一受控变更入口：扩展安装、表结构、索引、RLS Policy、权限授予与派生载体全部经版本化迁移执行（OPS-DB-005）。关键不变量：

- 迁移具有版本、顺序、已完成步骤识别、幂等重入边界和失败处置（OPS-UPG-002）。
- 迁移身份与普通运行身份隔离（OPS-DB-004/005）；结构变更不得由 ORM 自动同步、框架启动副作用或未登记脚本在运行期触发（OPS-UPG-002）。
- 迁移中断或结果不确定时不盲目重跑，不把进程退出码单独当作状态权威；先核对迁移版本、已完成步骤、数据库/扩展与应用兼容，再选择继续、修复、恢复或保持关闭（OPS-UPG-004）。
- 索引、扩展与派生载体必须具有版本与回滚/不可回滚边界（OPS-DB-005）；搜索规范化载体按表证据门控（ADR-007 §8）。

## 关键组件

| 组件 | 类型 | 职责 |
|---|---|---|
| 版本化迁移脚本 | 目录 | 按版本号与依赖顺序组织的结构变更脚本，显式记录对象归属模块与跨模块依赖（ADR-014 §2.8） |
| 迁移版本与步骤登记表 | 运行表 | 记录已应用版本、已完成步骤与失败痕迹；进程退出码不单独作为状态权威 |
| `MigrationExecutor` | 工具 | 按顺序执行、识别已完成步骤、幂等重入、失败中止与处置分支 |
| `MigrationIdentityProvider` | 配置基础设施 | 受控迁移身份凭据，与普通业务/后台连接完全隔离（OPS-DB-004） |
| `PreflightProbe` | 部署工具 | 数据库/扩展/应用兼容核对：PostgreSQL 18.x、必要扩展、统一 Schema（OPS-DEP-001/002） |
| 发布说明与回滚文档 | 文档 | 来源版本、迁移顺序、必要扩展、依赖兼容、已知问题、回滚步骤与不可回滚警告（OPS-UPG-001/005） |

## 使用与准入规则

- 允许：扩展安装、建表/改表、索引、RLS Policy 与权限授予、规范化派生载体；全部必须版本化并在单一 Schema 内统一编排。
- 禁止：生产临时建索引；依赖默认 `search_path`；迁移身份承担普通应用流量或成为产品超级管理员后门；以开发环境验证代替生产证据。
- 不可安全回滚的迁移必须在变更前警告并提供恢复路径，不得承诺所有升级都可原地回滚（OPS-UPG-005）。
- 升级作业必须明确各阶段 HTTP 写入、任务领取、现有租约与外部副作用的处理；会状态分叉或旧版本写入不兼容的阶段关闭相应写入（OPS-UPG-003）。

迁移文件命名约定：
- 格式：{yyyyMMddHHmmss}_{kebab-case-description}.ts
- 示例：20260812100000_create-org-clubs-table.ts
- 每个迁移文件导出 up() 和 down() 函数
- 迁移版本登记表：表名 _migration_log，字段（version, applied_at, checksum）
- 迁移工具首版方向：自定义迁移 runner 基于 `_migration_log` 单一登记表编排（生产环境禁用 ORM 自动同步，`synchronize: false`）；无论 ORM 选型结果如何（候选 TypeORM，待 `DEP-Q-001` 评审确认），其原生 migrations 表一律不启用，避免双账本

## 核心逻辑摘要

- **版本发布前置（OPS-UPG-001）**：每个正式版本声明支持的来源版本、配置变化、数据库迁移顺序、必要扩展、依赖兼容、已知问题与回滚边界；不得跨越未声明来源版本直接升级。
- **迁移执行（OPS-UPG-002）**：以版本、顺序与已完成步骤为状态事实；迁移身份与普通运行隔离；重入时先识别已完成步骤再决定继续或修复。
- **不确定处置（OPS-UPG-004）**：中断或结果不确定时先核对迁移版本、已完成步骤、数据库/扩展和应用兼容，再按发布说明选择继续、修复、恢复或保持关闭；维护期间按作业单明确任务停止领取、等待完成或保持积压（OPS-JOB-005）。
- **规范化载体（ADR-007 §8）**：小表可查询时计算；大表仅在证据下选择表达式索引、生成列、可重建派生列或集中投影；不为全部可搜索对象强制统一持久化结构。
- **高权限隔离（OPS-DB-004）**：迁移、维护、恢复特权连接与普通流量隔离，不得由产品超级管理员取得，也不得因故障临时切换给普通请求。

## 典型调用链

- **正常升级**：`发布说明核对来源版本` → `PreflightProbe` 预检（PostgreSQL 18.x、必要扩展、统一 Schema）→ `MigrationExecutor` 以受控迁移身份按顺序执行并登记版本/步骤 → 失败即中止并保留痕迹 → 验证 RLS、权限授予与扩展 → 记录迁移证据 → 恢复普通写入与任务领取。
- **中断恢复**：`迁移进程中断` → 停止盲目重跑 → 核对迁移版本登记与已完成步骤 → 核对数据库/扩展/应用兼容 → 按发布说明选择继续、修复、恢复或保持关闭（OPS-UPG-004）。
