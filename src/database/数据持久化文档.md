# database · 数据持久化总目录开发指导

> 更新日期：2026-08-12
> 目录位置：src/database/
> 权威依据：ADR-005、ADR-006、ADR-007、ADR-014；[数据模型与约束 v1.0](../../docs/specification/数据模型与约束-v1.0.md) §6；[部署运维与恢复手册](../../docs/operations/部署运维与恢复手册-v1.0.md) §8.2、§9

## 核心职责

本目录为 PostgreSQL 持久化的文档入口：连接与上下文管理的实现代码位于 `src/adapters/db/`，受控结构变更位于 `migrations/`，实体映射位于 `entities/`。本目录不含连接池与 RLS 上下文的实现代码，仅索引其文档并固定以下关键不变量：

- 单 PostgreSQL 数据库承载首版权威业务数据、平台运行数据与可重建派生数据；统一应用业务 Schema，不按社团、领域模块或联合活动拆库/拆 Schema（ADR-014、OPS-DB-001）。
- 首版只支持 PostgreSQL 18.x（OPS-DEP-002），更新前核验发布说明、迁移、扩展、RLS、备份恢复与关键查询；其他大版本不得自动进入兼容范围。
- 必要扩展：内置 `uuidv7()`、UTF-8、确定性 `pg_unicode_fast` 权威顺序、`pg_trgm`（近似层 `word_similarity` 阈值 0.6）、`btree_gist`（时间不重叠约束）；不使用 `pgcrypto` 保存托管秘密（OPS-CFG-002）。
- 隔离采用应用层逐请求授权＋数据库作用域约束＋普通社团业务表选择性 RLS 的三层混合策略；联合协作域独立建模，不得放宽普通作用域过滤（ADR-005）。
- 扩展安装、迁移与结构变更只由受控迁移身份执行；不依赖默认 `search_path`、ORM 自动同步或生产临时建索引（OPS-DB-005）。

## 关键组件

| 组件 | 类型 | 职责 |
|---|---|---|
| `migrations/` | 目录 | 版本化、有序、可识别已完成步骤的受控结构变更载体（见迁移文档） |
| `entities/` | 目录 | 关系骨架与 JSONB 动态答案的持久化映射（见实体模型文档） |
| `DbConnectionManager` | DB 适配（实现位于 `src/adapters/db/`） | 连接池、按入口类型区分读写能力；RLS 上下文建立与清理由 `ConnectionContextBuilder`/`ContextGuard` 承担（见 db 适配文档） |
| `RlsContextHelper` | DB 适配（接口位于 `src/shared/`，实现位于 `src/adapters/db/`） | 单目标/集合只读上下文重建、验证、清理与失败关闭（运维手册 §9.1、OPS-DB-003） |
| `MigrationIdentityProvider` | 配置基础设施 | 受控迁移身份凭据的加载与隔离，不进入普通业务连接 |
| `PreflightProbe` | 部署工具 | PostgreSQL 版本、必要扩展、统一 Schema、排序能力证据基线（OPS-DEP-001/002） |
| `SearchNormalizationCarrier` | 派生载体 | `pg_trgm` 近似层与版本化规范化函数载体，按表证据门控（ADR-007 §8） |

## 使用与准入规则

- 允许：连接池与事务管理、RLS 上下文生命周期、受控迁移编排、实体映射、扩展与版本前置检查、可重建派生载体。
- 禁止：为每个社团/模块建立独立数据库或 Schema；运行期依赖 ORM 自动同步或框架启动副作用改变结构；依赖默认 `search_path`；引入 `pgcrypto` 持久化秘密；产品超级管理员取得数据库高权限身份（OPS-DB-004）。
- 每个受保护数据库操作在事务边界内重建并验证最小单目标或登记式集合只读上下文；集合只读上下文不可写入；成功/回滚/异常/超时/取消后清理，归还连接池前证明无跨请求残留；上下文缺失、污染或类型混用时失败关闭（运维手册 §9.1、OPS-DB-003）。
- 数据模型逐类标注数据域（普通社团/联合协作/平台/派生与技术运行）、作用域来源、结构约束与 RLS 适用性及例外（ADR-005 §4）；不启用 RLS 的例外必须记录原因与等效数据库约束，不以开发便利为理由。

## 核心逻辑摘要

- **启动前置（OPS-DEP-002）**：缺少必要扩展在预检或迁移阶段失败，不得运行后静默取消名称近似或时间不重叠约束；证据只保存必要摘要与安全定位。
- **身份分层（DATA-RLS-003）**：HTTP 普通应用、后台任务、派生/重建、迁移、备份/恢复身份分别最小权限；普通应用身份无 `BYPASSRLS` 类绕过，迁移身份不承担普通流量。
- **RLS 与作用域（ADR-005）**：作用域上下文只由服务端在认证与对象/工作空间解析后建立；客户端提交的社团标识、旧链接或缓存值不得直接成为数据库会话上下文。
- **搜索派生（ADR-007 §8）**：近似层阈值显式固定 0.6，不依赖数据库会话隐式默认值；规范化唯一权威为 PostgreSQL 中显式版本化的规范化函数，HTTP/后台只提交原始文本。

## 典型调用链

- **受保护请求**：`HTTP 入口认证` → `RlsContextHelper` 按可信身份与目标对象建立单目标上下文 → 事务内执行命令/查询（当前行＋不可变版本＋历史同成同败）→ 清理上下文 → 归还连接池。
- **部署/升级**：`PreflightProbe` 建立证据基线（版本/扩展/Schema/排序）→ 受控迁移身份执行结构变更 → 验证 RLS 与权限授予 → 启动 HTTP/后台入口并上报启动状态。
