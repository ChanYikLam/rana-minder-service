# shared · 跨模块通用能力（事务、审计、幂等与 RLS 上下文）

> 更新日期：2026-08-12
> 目录位置：src/shared/
> 权威依据：系统架构总览 §5.1/§7.2/§11.2、ADR-003、ADR-004、部署运维手册 §9（OPS-DB-002~004）、SRS-故障恢复（AUD-003、GOV-006~009）

## 核心职责

平台策略层的横向落地能力，供全部领域模块与支撑模块共用：关键审计写入、幂等依据、本地原子事务辅助与 RLS 连接上下文辅助。机制只此一份，任何模块不得自建第二套。

- **审计写入器**：关键成功、失败、权限与特权访问审计与业务结果在同一提交边界保存；审计保存失败则原命令回滚，业务不得成功（AUD-003、GOV-006~009、SRS-FAIL-008）。
- **幂等依据**：由稳定业务意图生成幂等键并校验语义摘要；与唯一追踪编号严格分离，二者不得混同（ADR-004 §2.5、总览 §11.2）。
- **事务辅助**：本地原子提交编排——业务结果、不可变历史、关键审计、通知事实与收件人快照、任务意图按所在事务边界同成同败（八类边界，总览 §7.2、ADR-003 §2；任务意图同事务持久化，ADR-004 §2.2）。
- **RLS 上下文辅助**：每个受保护数据库操作在事务边界内重建最小单目标或集合只读上下文、验证并清理；连接归还池前证明无跨请求残留；集合只读上下文不可写（OPS-DB-002/003）。

关键不变量：本目录不得携带或依赖任何具体领域业务状态；只提供机制与规则，业务解释与状态机归属仍由领域模块负责；领域模块不得以"共用能力"为由把业务表访问下沉到本目录。

## 关键组件

| 组件 | 类型 | 职责 |
|---|---|---|
| `AuditWriter` | 审计写入器 | 在同一提交边界保存关键审计（操作者、当时角色/作用域、对象、必要脱敏差异、结果与失败原因）；保存失败使业务回滚。调用方，不持有数据库连接 |
| `IdempotencyHelper` | 幂等依据 | 幂等键生成/校验、语义摘要比对（相同键不同摘要＝IFC-ERR-009）、重复提交返回原结果 |
| `TransactionContext` | 事务接口 | 定义事务边界抽象（业务＋历史＋审计＋通知事实＋任务意图的原子提交，按事务类别收口与回滚）；由 `adapters/db/` 实现 |
| `RlsContextHelper` | RLS 上下文接口 | 定义单目标/集合只读上下文的事务内建立、验证、清理与归还前残留证明抽象；由 `adapters/db/` 的 `ConnectionContextBuilder`＋`ContextGuard` 实现 |
| `TrackingIdGenerator` | 追踪辅助 | 唯一追踪编号生成与派生关系关联（请求→命令→外部调用/任务），与幂等键严格区分 |
| `EntityValidator` | 实体校验组合 | 按不可变表单版本执行结构/类型/范围/必填/条件/对象引用/附件检查（DATA-FRM-003）；校验原语来自 `common/RuntimeValidators` |

## 使用与准入规则

- **使用**：应用命令用例与后台执行编排通过统一装配使用；领域模块不得绕开 shared 自行写审计、自行实现幂等或在事务外提交外部执行意图。
- **可以放进来**：与具体领域无关的横向机制——审计契约与写入、幂等规则、事务边界辅助、RLS 上下文生命周期、追踪编号规则。
- **禁止放进来**：具体业务表读写、领域状态机与枚举、通知事实的业务语义、Casdoor/存储/邮件等外部适配实现（归 src/adapters）、任何领域的业务状态存储或缓存。
- **实现位置**：事务与 RLS 上下文的**实现**位于 `adapters/db/`（`DbConnectionManager`、`TransactionScope`、`ConnectionContextBuilder`、`ContextGuard`）；本目录只持有抽象接口（`TransactionContext`、`RlsContextHelper`）与调用方机制（`AuditWriter` 等），不持有数据库连接。
- **校验职责**：校验原语来自 `common/RuntimeValidators`，本目录组合为实体级校验逻辑（`EntityValidator`）。
- 审计内容按 GOV-001、AUD-003：不得写入密码、发信密钥、令牌、验证码、附件正文、完整个人资料与被正式删除的业务正文；分类不确定时按更严格级别处理（GOV-009）。

## 核心逻辑摘要

- **审计原子性**：关键审计与业务结果同一提交边界，失败即回滚；运行日志不得替代业务审计；跨状态机联动的审计归属以 SRS 转换明细的原子副作用为准（ADR-003 §3）。
- **幂等语义**：客户端重试、后台重试、迟到响应、重复回调与恢复重放汇聚到同一业务意图，至多一份有效业务结果；重复成功返回第一次结果，不产生第二份历史、通知或外部写入（总览 §7.3）。
- **事务边界**：八类边界是语义模板而非互斥技术组件，重叠时满足全部约束；业务事实与执行意图要求同成同败时必须在同一本地事务持久化，不得先提交业务再靠内存回调/进程内队列补建任务（ADR-004 §2.2）。
- **RLS 生命周期**：从可信服务端身份与业务对象重建最小上下文，事务边界内建立并验证；成功、回滚、异常、超时与取消后清理；缺失、污染、格式错误或上下文类型混用失败关闭；迁移/特权连接与普通流量隔离（OPS-DB-002~004）。
- **追踪与去重分离**：追踪编号只用于关联与排障，绝不参与去重；幂等键只用于去重，不用于关联（总览 §11.2）。

## 典型调用链

HTTP 命令 → 用例组装授权上下文并声明期望状态/版本 → `TransactionContext`（由 `adapters/db/` 实现）开启本地事务并按 `RlsContextHelper` 抽象建立 RLS 单目标上下文 → 领域校验与业务写入（业务结果＋不可变历史）→ `AuditWriter` 在同一事务写入关键审计（通知事实与任务意图按边界纳入）→ 原子提交 → 清理 RLS 上下文并归还连接 → 后台执行单元取得租约后以同样机制复核状态、版本、权限与幂等，经可信回读后收口。
