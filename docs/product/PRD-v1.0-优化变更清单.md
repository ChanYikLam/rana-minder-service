## 1. 清单目的

本清单用于管理 PRD v1.0 内部评审后发现的表达缺口、追踪缺口和潜在新增需求。它不是新的需求事实来源，也不直接改变 PRD 或 SRS。

处理顺序固定为：

1. 记录变更候选及其问题来源；
2. 判断其属于文档修复、既有事实补写、新增行为、替代既有行为或明确非目标；
3. 新增或改变行为时，先更新《需求事实总账》并取得唯一需求编号；
4. 再更新 PRD 的用户故事、验收条件、非目标和成功指标；
5. 最后同步 SRS 的角色能力、授权、状态机、失败、通知、审计和质量约束；
6. 更新“事实—PRD—SRS—接口—数据—测试”追踪矩阵。

## 2. 状态、类型与版本建议

### 2.1 状态

| 状态 | 含义 |
|---|---|
| 待一致性修复 | 已有权威事实，不需要重新决定产品行为，只需补齐或纠正文档与追踪 |
| 待产品确认 | 会改变权限、状态、范围或用户可见行为，未确认前不得写成正式需求 |
| 待范围确认 | 需求价值可能成立，但需决定进入当前 v1.0、延后 v1.1 或明确拒绝 |
| 维持非目标 | 已被明确拒绝、延期或排除，不因本轮优化自动重开 |
| 已完成 | 总账、PRD、SRS 和追踪关系均已更新并通过复核 |

### 2.2 变更类型

| 类型 | 处理规则 |
|---|---|
| D：文档修复 | 不改变产品行为；可直接修订 PRD/SRS 表达和追踪 |
| E：既有事实补写 | 总账已有事实；补 PRD 用户承诺及 SRS 显式追踪 |
| N：新增需求 | 用户确认后先新增事实编号，再进入 PRD 和 SRS |
| C：规则变更 | 记录旧规则、替代规则、影响对象和迁移边界后再更新下游文档 |
| NG：非目标复核 | 默认维持当前非目标；只有用户明确要求时重新发现需求 |

### 2.3 版本建议

- 当前 PRD 和 SRS 尚未正式签署，普通内部修订继续使用 v1.0，并增加修订记录。
- 若某项已对外发布、已被开发使用，或改变已签署行为，则保留 v1.0 基线并建立 v1.1 draft。
- “建议纳入 v1.0”只表示分析建议，不代表用户已经确认。
