## 版本与变更记录规则

- PRD 与 SRS 在文档顶部维护“版本内修订记录”，并共用《PRD 优化变更清单》中的 `PRD-OPT-xxx` 变更编号。
- 修订记录至少包含变更编号、日期、修改摘要、影响事实与章节、是否改变产品行为和复核结果；未知的具体复核人姓名不臆造，正式签署前使用“需求方已确认”等角色化状态。
- 当前 PRD 和 SRS 已于 2026-08-01 通过单一责任人三视角完成内部签署，已确认的内部修订继续归入 v1.0。签署后新增产品行为应建立 v1.1 draft；不改变行为的错字、链接、追踪和治理元数据修复可以保留原版本，但仍应记录。
- 版本内修订记录用于回答“改了什么”；需求事实总账继续回答“当前权威规则是什么”，逐项决策记录回答“为什么这样决定”，分轮评审记录回答“哪些范围已经评审”。四者不得互相替代。

## 工作方式

每个模块按照“提问 → 用户确认 → 写入事实总账 → 复核影响 → 下一轮提问”推进。未经用户确认的行为不得伪装为已确认需求；确需先提出方案时，标记为“建议待确认”。

状态统一为：

- `内部已确认`：项目内部已经形成明确业务规则。
- `治理待确认`：涉及校方身份、隐私、共享、保留或特权访问，需要校方责任人确认。
- `建议待确认`：产品分析提出的候选规则，尚未得到用户确认。
- `延期`：确认不属于当前开工范围。
- `拒绝`：明确不建设。
