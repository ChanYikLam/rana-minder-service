# ADR-003：八类事务边界基线

> 状态：已接受  
> 修订状态：第 2 节第 5 类事务边界已按 `PRD-OPT-055` 由 [ADR-011](ADR-011-内置最小观测边界.md) 收窄，不再包含系统外运维告警事实或投递任务；8 类边界总数及其他七类不变（详见第 8 节）  
> 决策日期：2026-07-30  
> 决策范围：系统架构设计第一轮  
> 上游基线：[系统架构总览 v1.0](系统架构总览-v1.0.md)、[SRS v1.0](../specification/SRS-v1.0.md)及两份规范性明细  
> 产品行为变更：否  
> 代码编写授权：已按需求方 [`GOV-CODE-WAIVER-001`](../governance/代码开工前置跳过与风险接受记录-v1.0.md) 豁免开放；本 ADR 不表示验证或发布通过

## 1. 背景

RanaMinder 同时存在本地强一致业务、直接影响学生权益的通知、Casdoor 外部写入、文件检查、邮件、批量执行、正式删除和可重建派生数据。数据库事务无法与 Casdoor、邮件、对象存储或其他外部依赖形成真实的跨系统原子事务；另一方面，若把所有操作都改为最终一致，又会削弱邀请竞争、状态版本、面试容量、通知事实和关键审计等必须在本地立即成立的规则。

因此需要在数据模型、接口契约、安全设计和测试规格之前，固定“本地必须同成同败的内容”和“提交后可恢复执行的内容”。

主要上游来源：`SRS-INV-008`、`SRS-INV-014` 至 `SRS-INV-016`、`SRS-INV-024`，`SRS-FAIL-003` 至 `SRS-FAIL-013`，以及状态机转换明细中的原子副作用、幂等、并发、拒绝与恢复规则。

## 2. 已接受决策

RanaMinder 后续数据模型、接口契约、安全设计和测试规格必须共同遵守以下 8 类事务边界：

| 边界类型 | 同一本地原子提交必须包含 | 提交后可恢复执行 | 失败收口 |
|---|---|---|---|
| 1. 纯本地领域命令 | 当前状态与版本、领域结果、不可变历史、关键审计；直接影响权益时还包含通知事实和收件人快照 | 非必要渠道投递和派生视图刷新 | 原子提交失败则业务不变；重复请求返回原结果 |
| 2. 权益事件与通知 | 业务结果、通知事实、收件人快照、去重依据和关键审计 | 站内信投影、邮件及其他允许渠道 | 通知事实保存失败使原业务回滚；渠道失败不得重复业务 |
| 3. Casdoor 资料或 Group 写入 | 不可变业务意图、处理中状态、原关系或原值快照、幂等标识、执行任务和审计 | 外部写入、可信回读、重试、对账和必要补偿 | 未确认前新权限不生效；失败按领域规则保持原状态或进入高优先级异常 |
| 4. 文件上传、检查与绑定 | 文件元数据、上传/检查版本、引用意图和执行任务 | 字节写入、恶意内容检查、安全预览和清理 | 未检查文件不可读；旧任务不得恢复已替换、删除、隔离或失权文件 |
| 5. 邮件与系统外告警 | 对应通知或告警事实、渠道任务和安全摘要 | 外部投递、退信处理和重试 | 邮件失败不回滚已保存通知事实的普通权益业务；邮箱验证不能绕过；告警失败继续可见 |
| 6. 受控批量执行 | 批次预览快照、固定目标和批次状态；每个单项使用独立本地事务 | 逐项执行、汇总和仅失败项重试 | 部分成功不整体回滚；成功项不得重复 |
| 7. 正式删除与恢复 | 删除范围、执行清单、最小删除审计、步骤状态和幂等依据 | 数据库、附件、缓存、索引、未过期导出及备份恢复后的删除重放 | 部分失败不得宣称完成，也不得补偿恢复已经删除的个人数据 |
| 8. 派生索引、缓存与重算 | 源对象版本或变更事实、重建任务 | 搜索、统计、个人中心、工作台和缓存刷新 | 陈旧派生数据不得授权；范围收紧、归档、失权和删除必须使旧结果失效 |

这 8 类是事务语义模板，不是互斥的技术组件。同一业务命令可能同时适用通用领域命令边界和更严格的权益通知、外部写入或文件规则；重叠时必须满足全部适用约束，不得选择较弱边界规避上游要求。

## 3. 全局执行原则

1. 授权、业务前置条件、状态与版本竞争以及本地业务提交必须同步判定。
2. 外部副作用开始前，业务意图、任务、幂等依据和必要状态必须已经可靠持久化且可查询。
3. 外部响应成功不自动等于业务成功；上游要求回读的写入只能以可信回读结果收口。
4. 外部结果不确定时先回读，再决定成功、重试、补偿或失败，不能盲目重复写入。
5. 客户端重试、后台重试、迟到响应、重复回调和恢复重放必须共享同一业务意图，至多形成一份有效业务结果。
6. 失败不得扩大权限、覆盖不可变历史、丢失通知事实、重复已成功权益或让未经检查的文件可用。
7. 关键审计属于对应本地提交边界；运行日志和指标不能替代业务审计。
8. 跨状态机联动是否必须同一本地事务，继续以 SRS 转换明细的“必须原子完成的业务副作用”为准。

## 4. 候选方案与取舍

| 候选方案 | 优点 | 主要问题 | 结论 |
|---|---|---|---|
| 本地原子提交＋外部可恢复执行，按 8 类边界约束 | 本地一致性明确；外部故障可恢复；与状态机、通知、审计和故障规则一致 | 数据、接口和测试必须显式表达处理中、任务、幂等、失败与恢复状态 | 采用 |
| 把外部调用纳入同步请求并视为同一事务 | 表面流程较直接 | 无法形成真实跨系统原子性；长事务、超时和不确定结果会产生假成功或重复副作用 | 不采用 |
| 全部业务改为异步最终一致 | 入口响应快，形式上解耦 | 削弱必须立即成立的本地不变量，并显著增加中间状态、补偿和授权风险 | 不采用 |

## 5. 对后续文档的约束

- 数据模型必须表达状态版本、幂等依据、不可变历史、通知事实、外部意图、任务、尝试、租约、步骤状态和必要快照，但具体表结构留待数据规格。
- 接口契约必须区分已完成、处理中、失败、结果不确定和可重试，并定义重复请求和版本冲突语义，但具体 HTTP、RPC 或消息形式留待接口设计。
- 安全设计必须证明后台任务、回调、短链、批量、恢复重放和派生数据不会绕过当前授权、状态或字段范围。
- 测试规格必须覆盖正常提交、原子回滚、重复请求、并发竞争、外部超时、回读、迟到响应、重复回调、部分成功、补偿、恢复和派生失效。
- 运维设计必须能够观察任务积压、尝试、最终收口和告警失败，但不能用运行指标修改业务事实。

## 6. 非目标与未决定事项

本 ADR 不决定：

- 使用数据库持久任务、事务发件箱、消息队列或其他可靠投递机制；
- PostgreSQL Schema、表、字段、索引、隔离级别、锁和行级安全；
- 任务轮询周期、租约时长、重试次数、退避算法、超时或死信实现；
- API 风格、状态码、消息主题、序列化格式或供应商产品；
- 哪些部署拓扑、缓存、搜索、对象存储或可观测性产品被采用。

其中后台任务与可靠投递机制已由 [ADR-004](ADR-004-后台任务与可靠投递机制.md) 收口，数据隔离与选择性 RLS 已由 [ADR-005](ADR-005-数据隔离与选择性RLS.md) 收口；其余事项仍须进入后续 ADR、数据、接口、安全、测试和运维设计，不得作为本决策的隐藏默认值。

## 7. 结论与替代条件

ADR-003 完成系统架构设计第一轮的事务边界确认。若后续设计发现某条已确认 SRS 原子副作用无法映射到这 8 类边界，必须先回到架构评审补充或替代 ADR，不能由实现自行削弱原子性。任何替代决策都必须证明不会破坏状态机唯一责任、授权、通知、审计、幂等、故障恢复和正式删除边界。

## 8. 后续收口说明

2026-07-30，[ADR-011](ADR-011-内置最小观测边界.md) 按 `PRD-OPT-055` 取消系统外运维告警。因此第 5 类事务边界当前只保留邮件渠道任务、外部邮件投递、退信和重试，不再建立运维告警事实或外部告警投递任务；8 类边界总数及其他七类边界保持不变。运维设计仍须在应用可运行时通过内置状态和脱敏日志呈现任务积压、尝试与最终收口，但不承担系统外告警失败重试。
