# ADR-014：单数据库与统一应用业务 Schema

> 状态：已接受  
> 决策日期：2026-07-30  
> 决策范围：数据模型第一轮暴露的 PostgreSQL 物理布局与隔离承载方式  
> 上游基线：[系统架构总览-v1.0](系统架构总览-v1.0.md)、[ADR-001](ADR-001-首版应用形态与后台任务运行单元.md)、[ADR-003](ADR-003-八类事务边界基线.md)、[ADR-005](ADR-005-数据隔离与选择性RLS.md)、[ADR-006](ADR-006-PostgreSQL主数据库与动态表单混合存储方向.md)、[ADR-012](ADR-012-分级部署与恢复优先的生产拓扑.md)、[数据模型与约束-v1.0](../specification/数据模型与约束-v1.0.md)

> 代码编写授权：已按需求方 [`GOV-CODE-WAIVER-001`](../governance/代码开工前置跳过与风险接受记录-v1.0.md) 豁免开放；本 ADR 只约束实现方向，不表示验证或发布通过。

## 1. 背景与问题

ADR-005 已排除“每个社团独立数据库”的首版方案，并确认应用逐请求授权、数据库作用域约束与选择性 RLS 的纵深防御路线；ADR-003、ADR-006 与 ADR-012 又分别要求持久任务、动态表单和备份恢复落在 PostgreSQL 权威数据边界内。数据模型第一轮据此提出 `DATA-Q-001`：首版应采用统一应用业务 Schema、按模块拆分 Schema，还是进一步拆分数据库。

该问题会影响连接上下文、外键与事务边界、迁移编排、RLS 策略覆盖、备份恢复和模块访问规则，已达到架构决策级别。2026-07-30 的第一轮数据设计评审确认采用方案 A。

## 2. 已接受决策

RanaMinder 首版采用以下数据库物理布局：

1. 使用单个 PostgreSQL 数据库承载 RanaMinder 首版权威业务数据、平台运行数据和可重建派生数据；外部 Casdoor、S3 兼容对象存储及通知渠道仍是数据库外部依赖。
2. RanaMinder 自有业务表与平台运行表置于统一应用业务 Schema；Schema 的具体名称属于后续实现命名，不在本 ADR 中选择。
3. 首版不为每个社团、每个领域模块或每类联合活动建立独立数据库或独立 Schema。
4. 统一 Schema 不改变模块数据所有权。领域命名、权威对象归属、模块访问规则和受控服务边界继续约束写入；其他模块不得因共享 Schema 而直接改写非本模块权威表。
5. 普通社团数据依靠稳定社团作用域字段、作用域一致的主外键和唯一约束、逐请求连接上下文及候选表上的选择性 RLS 隔离；联合活动依靠显式联合域关系表达，不伪装为单社团数据；平台数据、运行数据和派生数据按数据模型中的类别分别约束。
6. 统一 Schema 不是授权边界。应用逐请求授权、数据库角色分离、作用域约束、失败关闭和选择性 RLS 仍须同时成立；普通应用身份不得拥有 RLS 绕过能力。
7. 已确认的八类事务边界继续在单数据库本地事务内保持原子性。Casdoor、对象存储和外部通知渠道不被错误纳入本地数据库原子提交，而由写入意图、幂等、回读、重试和对账闭环处理。
8. 数据库迁移须按单一 Schema 统一编排，并显式记录对象所属模块、跨模块依赖和迁移顺序；本 ADR 不选择 ORM 或迁移工具。
9. 普通应用、后台任务、迁移、备份恢复和受控平台运维身份应分别定义最小权限。迁移或恢复身份的必要高权限不得下放给日常业务连接。
10. 本 ADR 不决定逻辑表名、字段物理类型、主键生成方式、具体索引、RLS Policy 文本、连接池实现、PostgreSQL 版本、ORM 或迁移框架。

## 3. 候选方案与取舍

| 方案 | 主要收益 | 主要代价与结论 |
|---|---|---|
| A：单数据库＋统一应用业务 Schema | 八类事务边界可以直接使用本地事务；跨模块外键、统一备份恢复、选择性 RLS 和首版运维最简单；与模块化单体及当前规模证据一致 | 需要用模块所有权、命名、访问规则和测试防止共享 Schema 演变为任意跨模块写入；已接受 |
| B：单数据库＋按模块拆分 Schema | 物理命名空间更强，部分权限可按 Schema 粗分 | 跨 Schema 外键、迁移顺序、搜索统计和共享运行表编排更复杂，且不能替代逐行作用域隔离；首版收益不足以覆盖复杂度，不采用 |
| C：按模块拆分数据库 | 故障域与独立扩缩容边界更强 | 破坏已确认的本地事务边界，引入分布式一致性、跨库查询、备份协调和更高运维成本；与首版模块化单体边界不符，不采用 |
| 每个社团独立数据库或 Schema | 物理租户隔离直观 | 租户生命周期、迁移、连接、联合活动、跨社团统计和恢复成本显著增加；每社团独立数据库已由 ADR-005 排除，本 ADR 同时排除首版每社团独立 Schema |

## 4. 数据与安全约束

1. 每张权威表必须在数据模型中归属且仅归属一个写入责任模块；跨模块读取与命令协作不得模糊所有权。
2. 普通社团作用域表必须携带可验证的稳定社团作用域，并优先通过作用域一致的复合外键、唯一性和 RLS 候选策略阻止跨域引用。
3. 联合活动不得仅靠一个“当前社团 ID”表达；必须保存联合域、参与社团关系及相应对象归属。
4. 平台特权操作必须使用显式平台身份与审计上下文，不能通过缺失社团上下文隐式获得全局访问。
5. 连接池复用时必须在事务边界内建立、校验并清理连接上下文；上下文缺失、非法或残留时失败关闭。
6. 数据库对象命名和迁移清单应能识别责任模块，但命名规则本身不构成授权或完整性保证。
7. 备份与恢复以单数据库一致性恢复为基础；对象存储、Casdoor 和外部通知仍按各自恢复、回读和重放边界处理。

## 5. 对下游文档的强制输入

| 下游设计 | 必须继承的输入 |
|---|---|
| 数据模型 | 统一应用业务 Schema、唯一写入责任模块、四类数据隔离、作用域一致约束、联合域关系和选择性 RLS 候选范围 |
| 接口设计 | 不暴露 Schema 布局为产品语义；所有命令仍经过模块边界与逐请求授权；跨模块写入不得退化为直接表写入 |
| 安全设计 | 连接上下文生命周期、数据库角色矩阵、RLS 失败关闭、绕过身份边界和平台特权审计 |
| 测试设计 | 跨社团引用、联合域访问、缺失或污染上下文、普通身份越权、模块越权写入和恢复后隔离回归 |
| 迁移设计 | 单 Schema 迁移编排、模块归属、依赖顺序、回滚或前滚策略及权限授予；不得从工具默认行为反推规则 |
| 运维与恢复 | 单数据库备份恢复、对象存储一致性核对、外部副作用重放、派生数据重建和高权限身份隔离 |

## 6. 不受本决策影响的边界

本决策不改变当前 236 个需求事实、40 个用户故事、27 条全局不变量、29 个状态机、306 条详细转换、13 条故障规则、54 条 NFR 或八类事务边界；不改变 Casdoor、对象存储、通知、搜索与缓存的既有责任；不设计具体 API、SQL DDL、业务代码，也不选择 ORM、数据库迁移工具或依赖版本。

## 7. 重新评估条件

出现以下证据时，应新建替代 ADR，而不是静默偏离本决策：

1. 法规、学校制度或客户合同要求社团级或数据类别级物理隔离；
2. 实测容量、锁竞争、维护窗口、恢复时间或故障域证据表明单数据库无法满足已确认 NFR；
3. 某模块形成独立发布、独立扩缩容、独立数据生命周期或独立团队自治的稳定边界；
4. PostgreSQL 单库内的 RLS、索引、分区或资源治理无法在可接受复杂度内提供所需隔离与性能；
5. 备份恢复演练证明统一恢复边界与业务恢复优先级冲突；
6. 联合活动或平台级统计出现必须跨物理租户边界处理的新产品事实。

在这些条件出现前，首版不得以“未来可能拆分”为由提前引入多 Schema、多数据库或每社团物理分片。

## 8. 结论

`DATA-Q-001` 已关闭：RanaMinder 首版采用单个 PostgreSQL 数据库和统一应用业务 Schema，以模块所有权与访问规则、作用域字段及一致性约束、联合域关系和选择性 RLS 实现隔离。该结论冻结数据库物理布局方向，但不冻结具体表结构、类型、索引、Policy、数据库版本或工具选型；需求方后续已豁免开工前置阶段并授权在开发／测试环境直接实现，生产迁移与真实数据门仍关闭。
