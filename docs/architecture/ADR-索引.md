## 1. 使用规则

1. ADR 只记录产品事实无法唯一决定、但会影响实现、部署、成本、性能或运维的技术决策。
2. ADR 不得新增或改变需求事实、PRD 或 SRS 行为；发生冲突时按“需求事实 → PRD → SRS → 架构/ADR”的顺序处理。
3. 每项 ADR 必须记录候选方案、选择理由、影响、不影响的上游边界、代价和重新评估条件。
4. 已接受 ADR 不原地改写历史结论；需要替代时创建新的 ADR，并将旧 ADR 标记为已被替代。
5. ADR 被接受不等于代码开工批准；数据、接口、安全、测试、运维、追踪和签署等开工门条件仍须独立完成。

## 3. 当前开放项

系统架构设计第一轮已经完成应用形态、逻辑模块、状态机责任和事务边界确认；后台任务与可靠投递机制由 ADR-004 收口，数据隔离实现由 ADR-005 收口，ADR-006 在重新比较 MariaDB 后确认 PostgreSQL 主数据库及动态表单混合存储方向，ADR-007 收口搜索与可重建缓存边界，ADR-008 收口对象存储与文件检查/预览边界，ADR-009 收口 Casdoor 适配方式，ADR-010 确认单文件外置配置与秘密部署方式，ADR-011 按 `PRD-OPT-055` 收口内置最小观测边界，ADR-012 收口分级部署与恢复优先的生产拓扑，ADR-013 收口 Vue 与 NestJS 首版应用技术栈，ADR-014 关闭数据设计问题 `DATA-Q-001` 并确认单数据库与统一应用业务 Schema。当前第一轮开放架构项为 0；`DATA-Q-001` 至 `DATA-Q-014` 均已作为数据设计关闭，其中 `DATA-Q-011` 确认正式数据不自动删除、临时/技术数据受控清理与策略发布边界，但不产生新开放架构项；`DATA-Q-013` 是 ADR-009 已允许退化路径的版本化落地，`DATA-Q-014` 在 ADR-010、ADR-012 已确认的外置配置与恢复边界内细化应用秘密数据契约。未来只有达到架构决策级别或出现重新评估证据时才新增或替代 ADR，不得用框架默认值改变产品行为。
