# ADR-007：首版搜索与可重建缓存边界

> 状态：已接受  
> 决策日期：2026-07-30  
> 决策范围：系统架构后续技术决策  
> 上游基线：[系统架构总览 v1.0](系统架构总览-v1.0.md)、[ADR-004](ADR-004-后台任务与可靠投递机制.md)、[ADR-005](ADR-005-数据隔离与选择性RLS.md)、[ADR-006](ADR-006-PostgreSQL主数据库与动态表单混合存储方向.md)及 [SRS v1.0](../specification/SRS-v1.0.md)  
> 产品行为变更：否  
> 代码编写授权：已按需求方 [`GOV-CODE-WAIVER-001`](../governance/代码开工前置跳过与风险接受记录-v1.0.md) 豁免开放；本 ADR 不表示验证或发布通过

## 1. 背景与约束

`REC-047` 要求公开发现入口分别提供“找社团”和“找活动”两个名称搜索模式，并在活动模式提供活动类型、报名状态和截止时间筛选；`NFR-001` 要求复杂统计与搜索在代表性规模下满足响应目标。与此同时，`CFG-007` 要求可见范围收紧后页面缓存和搜索索引失效，`CFG-008` 要求权限模板发布后权限缓存立即失效并在下一次受保护请求重新鉴权，`STAT-003` 要求统计始终能够从正式业务记录重算。

因此，搜索和缓存只能是权威业务事实的派生加速层。它们不得成为授权、当前状态或不可恢复业务数据的唯一来源，也不能通过引入基础设施默默扩大上游已经确认的搜索对象、匹配方式、个性化推荐或排序等产品承诺。

## 2. 已接受决策

1. 首版优先使用 **PostgreSQL 查询与索引**满足当前已确认的关键词搜索、结构化筛选和统计查询；首版不强制部署 Elasticsearch、OpenSearch 或其他独立搜索引擎。
2. 首版允许使用应用进程内或等效轻量的**可重建缓存**，但不强制部署 Redis 或其他独立共享缓存。缓存全部丢失、过期或被主动清空时，系统必须能够从 PostgreSQL 权威事实或其他明确权威来源重新读取或计算出相同的正确业务结果；缓存故障最多影响性能，不能改变业务结果。
3. 缓存未命中必须回到权威来源。禁止把当前成员/部门/职位关系、授权结果、业务状态、表单草稿或正式提交、幂等记录、后台任务与租约、通知事实、审计、正式删除清单、文件检查状态或 Casdoor 同步结果只保存在缓存中。
4. 已发布且不可变的表单版本、低频变化的公开配置和可重建统计等可以成为缓存候选；是否缓存、缓存键、过期时间、容量和淘汰策略由后续数据、接口和性能规格按访问模式决定，本 ADR 不规定默认值。
5. 受保护请求始终执行当前服务端授权。权限判定结果不能因缓存命中而跳过当前用户、对象、操作、作用域和业务状态检查；RLS、字段权限、联合活动授权和附件访问规则继续独立生效。
6. 可见范围收紧、权限模板发布、业务状态变化、事实纠错和正式删除必须触发对应缓存或派生索引失效。无法证明安全失效的敏感或个性化结果首版不得缓存；具体失效事务、消息、版本键、TTL 和失败恢复方式进入数据、接口、安全与测试规格。
7. 搜索结果和统计结果必须能够追溯到 PostgreSQL 权威记录；缓存、搜索索引或统计读模型与权威记录不一致时，以权威记录为准，并按既有故障恢复规则重建、失效或告警。
8. 多应用实例可以各自持有可重建进程内缓存，不要求首版提供跨实例共享缓存。若实际压力、命中率、数据库负载或一致性验证证明共享缓存或独立搜索具有必要性，应创建补充或替代 ADR 后再引入。

## 3. 候选方案与取舍

| 候选方案 | 优点 | 主要问题 | 结论 |
|---|---|---|---|
| PostgreSQL＋可选可重建应用缓存 | 部署依赖少；没有独立搜索索引同步；适合开源单机和当前参考规模；缓存丢失不影响正确性 | 多实例缓存不共享；复杂中文检索、命中率和数据库负载需要实际验证 | 首版采用 |
| PostgreSQL＋Redis，共享缓存但不引入独立搜索 | 多实例可共享热点结果并集中失效 | 增加网络依赖、安全、监控、备份误用和高可用成本；仍须解决授权与失效正确性 | 首版不强制；有证据后再评估 |
| PostgreSQL＋Redis＋独立搜索引擎 | 大规模全文检索、相关性和复杂搜索扩展能力较强 | 部署和运维最重；存在索引延迟、越权字段复制、权限收紧和删除传播风险 | 首版不采用 |
| 完全不允许任何缓存 | 状态路径最直接，不存在缓存失效问题 | 不可变表单定义和低频配置会产生不必要重复读取，也失去低成本性能优化空间 | 不作为强制限制 |

## 4. 对后续文档的约束

- 数据模型与查询规格必须标明权威记录、可重建派生数据、候选缓存对象及禁止缓存的权威状态，并用代表性数据验证 PostgreSQL 搜索、筛选和统计性能。
- 接口契约必须说明哪些查询可以缓存、缓存未命中和缓存故障如何回源，以及状态、权限、可见范围、纠错和删除变化如何触发失效。
- 安全设计必须阻止缓存键遗漏社团/协作域/访问者范围，阻止旧权限或已收紧字段继续命中，并证明缓存和搜索索引不能绕过 RLS、字段权限或附件重新鉴权。
- 测试规格必须覆盖冷缓存、缓存清空、过期、并发失效、多实例短暂不一致、权限撤销、可见范围收紧、纠错、删除、重建以及权威库不可用时不得返回假新鲜结果。
- 运维设计必须能够观测查询延迟、命中率、失效失败、重建积压和数据库负载；未来引入独立基础设施时不得把其可用性默认为已有承诺。

## 5. 不受本决策影响的边界

本 ADR 接受时不改变当时已经确认的公开目录关键词和三类筛选行为，也不自行新增个性化推荐、拼音搜索、错别字纠正、模糊匹配、智能排序或其他搜索承诺；后续由上游产品事实确认的搜索行为按第 8 节收口说明承接。本 ADR 始终不改变任何统计口径、角色权限、字段可见性、状态机、删除或审计要求。

本 ADR 不决定：

- PostgreSQL 的具体索引、全文检索扩展、分词器、SQL 或查询计划；
- 缓存框架、缓存库、序列化格式、缓存键、TTL、容量和淘汰算法；
- 未来 Redis、Elasticsearch、OpenSearch 或其他产品的选择；
- 前后端语言、ORM、API 风格、仓库结构和生产高可用拓扑；
- 对象存储、文件检查/预览、Casdoor 适配、秘密、观测和系统外告警实现。

## 6. 重新评估条件

出现以下任一情况时，可以创建补充或替代 ADR：

- 代表性数据和参考硬件验证证明 PostgreSQL 查询与受控索引不能满足 `NFR-001`；
- 多实例部署中重复计算或数据库读取形成经测量的容量瓶颈；
- 已确认产品范围新增当前数据库方案难以承载的高级全文检索行为；
- 可见范围、字段权限和正式删除能够在独立索引中得到可证明、可监控、可恢复的安全传播；
- 引入共享缓存或独立搜索的收益能够覆盖新增的部署、故障、安全和运维成本。

重新评估不得以缓存命中率或搜索相关性为理由削弱当前授权、状态权威、失效和删除边界。

## 7. 结论

ADR-007 收口“搜索与缓存”开放项。首版以 PostgreSQL 查询和索引承载当前搜索与统计需求，允许使用丢失后可从权威来源重建的应用级缓存，但不强制 Redis 或独立搜索引擎。该决策为数据、接口、安全、性能测试和运维设计提供边界，不构成具体实现选型或代码开工批准。

## 8. 后续收口说明

2026-07-30，[ADR-011](ADR-011-内置最小观测边界.md) 收窄首版观测范围。查询延迟、缓存命中率和数据库负载仍可作为专项性能测试证据，但不是首版内置状态页、指标导出或系统外告警的强制产品能力；运行期仅须按上游要求通过脱敏日志和必要的内置状态识别失效失败、重建积压及最近异常。搜索与缓存权威边界不变。

2026-07-30，`REC-047` 经产品搜索专项复核扩展为“找社团”和“找活动”两个独立名称搜索模式：前者按社团展示名称搜索，后者按活动名称搜索并承接既有三类活动筛选，同一时刻不组合两个名称条件。随后上游确认并再次简化名称搜索通则：人员姓名支持任意连续汉字子串及学号/账号精确检索，但不提供人员错别字候选；社团展示名称、活动名称、部门名称、职位名称和 Casdoor Group 名称支持中文任意连续子串及受控错别字近似候选；首版所有对象均不提供拼音或首字母搜索。非人员搜索结果固定按“稳定标识或名称精确命中→中文连续子串命中→错别字近似候选”分层，近似候选不得超过任何直接命中；去除首尾空白后不足 3 个汉字、字母或数字有效字符时不启用近似层。该上游产品行为仍由 PostgreSQL 查询、索引和可重建派生模型承载，不改变本 ADR 的权威、授权、失效、删除或独立搜索引擎边界。筛选专项随后确认报名截止时间同时提供今日截止、3 日内、7 日内三个快捷范围和自定义起止日期，并由服务端按发起查询时的平台时区自然日分别转换为 `[D, D+1 日)`、`[D, D+3 日)`、`[D, D+7 日)` 的权威截止时间区间；截止日期命中不等于正在报名。“正在报名”由查询时的公开资格、报名通道开放状态、活动暂停/终态覆盖和当前有效截止共同派生，不新增活动状态、缓存权威或个人资格结论。这些选择只细化既有 PostgreSQL 结构化筛选输入，不引入独立搜索设施。`DATA-Q-009` 已据此批准 PostgreSQL 官方随附的 `pg_trgm` 作为首版第一个必要扩展，并确认第三层使用 `word_similarity()` 按“用户输入片段→权威名称连续范围”方向计算，首版近似阈值显式固定为 `0.6`；不得仅依赖数据库会话中的隐式默认值。第三层候选固定按 `word_similarity()` 降序、规范化名称稳定顺序和对象 UUID 排序，不引入热度、点击量、个性化或领域业务信号。第一、第二层不新增搜索相关性分数，沿用对应领域列表已经明确的内部排序；没有明确领域排序时，使用规范化名称的 `pg_unicode_fast` 稳定顺序和对象 UUID 兜底，稳定 ID 精确与名称精确不再细分优先级。搜索文本统一采用“NFC→Unicode 大小写折叠→再次 NFC→去除首尾 Unicode 空白→连续内部 Unicode 空白压缩为一个 U+0020 空格”的规范化顺序；不折叠标点、简繁体或全角/半角，权威显示名称和业务唯一性不受该派生规则影响。PostgreSQL 中的显式版本化规范化函数是唯一执行权威；HTTP 应用、后台任务、导入、修复和重建路径只提交原始文本，应用侧预览不得成为可信写入值。规范化物理载体和索引均按表证据门控：小表可以查询时计算，具体表也可以在证据下使用表达式索引、存储生成列、普通可重建派生列或集中投影；不为全部可搜索对象强制统一持久化结构。具体表级载体/索引仍须后续证据关闭。未来重新引入拼音搜索必须先回到产品和数据评审。
