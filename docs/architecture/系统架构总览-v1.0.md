## 1. 文档定位与规则分类

本文把已确认的产品行为转化为后续数据、接口、安全、测试和部署设计共同遵守的架构边界。它不新增产品行为，也不改变事实、PRD 或 SRS。

本文使用三类表述：

| 分类 | 含义 | 处理方式 |
|---|---|---|
| 上游强制约束 | 已由需求事实、PRD 或 SRS 确认的行为与质量边界 | 架构不得改变；冲突时以上游文档为准 |
| 第一轮架构结论 | 为满足上游约束而形成的逻辑分解、依赖方向和一致性边界 | 本轮进入架构评审；评审后成为下游设计约束 |
| 已接受架构决策 | 产品事实无法唯一决定、已经完成候选比较和明确确认的技术选择 | 进入 ADR 并成为后续设计约束；不因此改变产品行为或打开代码开工门 |
| 开放架构项 | 不改变产品行为、但会影响实现、部署、成本或运维的技术选择 | 必须进入 ADR；ADR 作出前不得伪装成既定技术栈 |

权威顺序保持为：

1. 需求事实总账；
2. 已确认 PRD；
3. 已确认 SRS 及规范性明细；
4. 本架构总览和后续 ADR；
5. 数据、接口、安全、测试与部署设计；
6. 实现。

最初第一轮架构评审没有新增产品行为；其后需求方通过 `PRD-OPT-055` 收窄观测范围，本文仅同步该上游变化并由 ADR-011 记录实现边界。

## 2. 第一轮产出与非目标

### 2.1 本轮形成的架构基线

1. 明确 RanaMinder 与浏览器、Casdoor、数据库、对象存储、文件检查/预览和邮件之间的边界，并明确系统外运维告警不属于首版产品能力。
2. 将业务能力拆为 12 个领域模块和 3 个平台支撑模块。
3. 为 SRS 的 29 个状态机指定唯一写入责任模块，避免多个模块争夺同一业务状态。
4. 区分本地原子提交与外部可恢复执行，并以 ADR-003 确认 8 类事务边界。
5. 冻结普通社团隔离域、联合协作域、平台特权域和文件访问域的信任边界。
6. 给出容器化单机、拆分部署和容量扩展必须保持不变的逻辑结构。
7. 列出后续 ADR、数据、接口、安全、测试和运维文档的输入与阻断项。

### 2.2 本轮非目标

- 本文主体不自行决定前端、后端语言与框架；当前选择已由 [ADR-013](ADR-013-Vue与NestJS首版应用技术栈.md) 收口；
- 不定义具体仓库布局；首版应用形态和后台运行单元边界按 [ADR-001](ADR-001-首版应用形态与后台任务运行单元.md) 执行；
- 不决定消息队列、任务调度、缓存、搜索、对象存储和文件检查产品；观测范围已由 ADR-011 收口，但不选择具体日志框架或状态采集实现；
- 不定义 URL、RPC、消息主题、请求/响应结构或错误码；
- 不定义表、列、索引、分区、行级安全或迁移脚本；
- 不把接口级重试次数、退避算法、锁类型和超时时间写成产品事实；
- 不编写 PoC、生产骨架、迁移或任何业务代码。

| 权益通知不可丢 | 权益业务与通知事实及收件人快照同一可靠边界 | 通知事实属于本地业务事务；邮件等渠道属于提交后执行 | NTF-001 至 NTF-003；SRS-INV-008；SRS-FAIL-008、009 |

| 文件先检查后访问 | 未检查文件不可预览、下载或正式绑定 | 文件元数据、检查状态、引用和字节存储分离；访问每次重新鉴权 | GOV-008；SRS-INV-013；SRS-FAIL-006 |

## 4. 系统上下文

### 4.1 系统边界

RanaMinder 边界内包括响应式 Web 交互、应用命令与查询、领域状态机、服务端授权、业务历史、通知事实、业务审计、后台任务意图、文件元数据、派生读模型和内置最小运维状态。RanaMinder 不拥有学校账号密码、Casdoor Group 主数据、邮件最终投递或文件恶意内容检查能力；首版也不提供系统外运维告警渠道。

| 参与者或外部系统 | 与 RanaMinder 的关系 | 权威边界 | 失败时的最低行为 |
|---|---|---|---|
| 未登录访客 | 浏览明确公开的社团和招新内容 | 无身份和业务写权限 | 只允许公开页面 |
| 已登录学生/申请人/成员 | 处理本人资料、申请、面试、邀请和成员事项 | 本人关系不授予他人或管理权限 | 按身份、资料门和对象状态拒绝或降级 |
| 社团负责人、人事管理员、部门负责人、普通面试官 | 在当前社团、部门、活动或轮次范围内管理和评审 | 当前权限由 Casdoor Group、本地模板和任务共同计算 | 失权后旧入口、缓存和链接同时失效 |
| 超级管理员 | 平台接入、安全、配置、治理、异常和正式删除 | 当前平台 Group；高风险命令还需重新认证和实时检查 | Casdoor 无法可信确认时高风险操作关闭 |
| Casdoor | 统一认证、账号状态、学校级 Organization 和 Group 当前关系 | 身份与当前 Group 的外部权威 | 使用最小降级、回读、重试和对账；不得本地后门放权 |
| PostgreSQL | 本地业务状态、版本、历史、通知事实、审计、文件元数据和任务意图的权威持久层 | RanaMinder 本地业务事实权威 | 不可用时停止业务写入，不返回假成功 |
| 对象存储 | 附件原件、安全预览副本、导出文件及其字节内容 | 文件字节；授权仍由 RanaMinder 元数据和对象关系决定 | 不放行附件或未完成产物 |
| 文件检查/安全预览能力 | 检查恶意内容并生成受控预览 | 只提供检查结果和衍生物，不授予访问权 | 文件保持检查中、等待、隔离或失败 |
| 邮件服务 | 邮箱验证和符合资格的附加通知渠道 | 投递结果，不是业务或通知事实权威 | 普通权益业务不回滚；邮箱验证不得绕过 |

### 4.2 信任边界

| 边界 | 不可信输入 | 必须在边界内完成的校验 |
|---|---|---|
| 浏览器 → 应用 | 工作空间社团、角色、对象 ID、版本、文件引用、跳转地址和幂等键 | 认证、请求完整性、对象归属、当前权限、字段范围、状态、版本和安全限制 |
| 应用 → Casdoor | 令牌、Claims、Group 结果、Webhook/回调和写入响应 | 签发方、受众、有效期、回调关联、事件签名/时间/重放、实际版本能力及回读 |
| 应用 → 文件基础设施 | 文件名、扩展名、声明类型、检查结果、短期地址 | 实际类型、大小、恶意内容、对象引用、当前权限、链接期限和结果版本 |
| 普通隔离域 → 联合协作域 | 社团角色、活动参与、材料、评价、结论和导出范围 | 锁定参与名单、当前启用状态、活动阶段、作者归属、记录关系和字段权限 |
| 业务事务 → 外部副作用 | Casdoor 写入、邮件、文件处理、导出和统计任务 | 本地意图先持久化；外部结果可回读、重试、补偿或明确失败 |
| 运行日志/指标 → 运维界面 | 请求、错误、任务和依赖状态 | 脱敏；不得包含业务正文、内部评语、附件、完整联系方式、令牌或密钥 |

## 5. 逻辑架构与模块责任

### 5.1 分层

| 层次 | 责任 | 禁止事项 |
|---|---|---|
| 交互与入口层 | 响应式 Web、公开入口、个人空间、管理工作空间、请求适配 | 不负责最终授权，不保存可覆盖领域对象的页面状态 |
| 应用用例层 | 组织命令/查询、建立授权上下文、调用领域规则、划定事务、编排外部任务 | 不绕过状态机，不直接把外部成功当成本地业务成功 |
| 领域层 | 业务对象、29 个状态机、不变量、命令前置条件、领域事件和拒绝原因 | 不依赖浏览器、邮件、对象存储或具体队列产品 |
| 平台策略层 | 服务端授权、幂等、审计、通知事实、安全限制、版本与任务租约策略 | 不代替具体领域对象判断，不自动作出人员权益决定 |
| 适配与执行层 | Casdoor、数据库、对象存储、文件检查、邮件和搜索/缓存适配 | 不拥有产品状态，不从派生数据授予权限 |
| 持久化与派生层 | PostgreSQL 权威记录、对象字节、缓存、搜索索引、统计读模型和备份 | 缓存、索引、统计和备份不能成为在线授权或当前状态权威 |

### 5.4 依赖方向

1. 交互入口只能调用应用用例，不能直接写数据库、对象存储或 Casdoor。
2. 应用用例以目标对象为锚点建立授权上下文；授权组件提供判定能力，但目标领域模块保留业务前置条件和状态转换的最终解释权。
3. 一个状态机只由其责任模块写入；跨模块命令通过应用编排调用，禁止共享表更新制造隐式耦合。
4. 通知事实和关键业务审计作为本地提交能力被领域命令调用；通知渠道和运行日志在提交后执行，不能反向决定业务成功。
5. Casdoor、文件、邮件、搜索和缓存全部通过可替换适配边界接入，领域规则不得依赖供应商专有对象；首版不设置系统外运维告警适配边界。
6. 派生入口、统计、搜索索引和缓存只能读取权威对象并可被重建；不得形成独立可写状态或授权来源。
7. 后台任务执行器可以推进已获授权且已持久化的业务意图，但每次取得租约和提交结果时仍须执行对应状态、版本、权限或领域前置检查。

## 6. 数据权威与所有权

| 信息类别 | 当前权威 | RanaMinder 保存内容 | 禁止的替代权威 |
|---|---|---|---|
| 账号、禁用/删除状态 | Casdoor | 稳定身份绑定、最近可信状态、同步和审计证据 | 本地会话、旧令牌或缓存 |
| 当前社团、部门、职位关系 | Casdoor Group | Group 稳定映射、业务意图、处理中状态、回读与不可变历史 | 本地成员表或任期历史单独授予当前权限 |
| 权限模板和任务授权 | RanaMinder 已发布版本与当前任务 | 模板版本、映射、生效范围、任务及撤销事实 | 前端角色选择、旧缓存、历史职位 |
| 普通与联合业务状态 | 各自责任领域模块 | 强类型对象、版本、状态、历史和并发证据 | 通知、个人中心、管理工作台或搜索索引 |
| 动态答案 | RanaMinder 表单提交版本 | 答案修订、表单版本、资料快照和字段权限依据 | 当前个人资料覆盖旧提交 |
| 文件字节 | 对象存储中的受控对象 | 文件元数据、检查版本、引用、授权对象和删除状态 | 永久公开 URL 或客户端文件名 |
| 通知 | RanaMinder 通知事实 | 事件、收件人快照、渠道状态和已读/隐藏状态 | 邮件投递结果 |
| 业务审计 | RanaMinder 独立审计记录 | 操作者、角色、作用域、差异、结果、请求和追踪关系 | 运行日志或第三方平台日志 |
| 搜索、统计、个人中心和工作台 | 可重建派生视图 | 投影版本、刷新时间和源对象引用 | 派生状态覆盖领域状态或授予访问 |
| 备份 | 正式权威数据的恢复副本 | 恢复点、清单、加密和演练证据 | 未重放删除清单的旧副本直接上线 |

所有本地业务对象必须能够表达稳定对象标识、所属作用域、当前状态、状态版本、创建/更新时间及必要的历史关联。具体字段、唯一性、外键、索引和隔离机制进入数据模型文档。

## 7. 同步、异步与事务边界

### 7.1 总体原则

用户请求中的授权、业务前置条件、版本竞争和本地业务提交是同步判定；Casdoor 写入、邮件、文件检查/预览、导出、复杂统计、搜索投影和部分删除步骤属于提交后可恢复执行。是否使用消息队列、数据库任务表或其他机制由 ADR 决定，但不得改变下列保证：

- 外部依赖结果未知时不得宣称最终成功；
- 每份外部业务意图必须先可靠持久化并可查询；
- 同一业务意图和同一外部操作必须可幂等重试；
- 必须回读的外部写入只能以可信回读收口；
- 重试、迟到响应、重复回调和恢复重放不得生成第二份业务结果；
- 失败不得扩大权限、覆盖历史或丢失通知事实。

### 7.2 八类事务边界（已确认）

| 边界类型 | 同一本地原子提交必须包含 | 提交后执行 | 失败收口 |
|---|---|---|---|
| 1. 纯本地领域命令 | 当前状态/版本、领域结果、不可变历史、关键审计；有权益影响时包含通知事实和收件人快照 | 非必要投递与派生视图刷新 | 原子提交失败则业务不变；重复请求返回原结果 |
| 2. 权益事件与通知 | 业务结果、通知事实、收件人快照、去重依据和关键审计 | 站内信投影、邮件和其他允许渠道 | 通知事实保存失败使原业务回滚；渠道失败不重复业务 |
| 3. Casdoor 资料或 Group 写入 | 不可变业务意图、处理中状态、原关系/原值快照、幂等标识、任务和审计 | 外部写入、可信回读、重试、对账和必要补偿 | 未确认前新权限不生效；失败按领域规则保持原状态或进入高优先级异常 |
| 4. 文件上传、检查与绑定 | 文件元数据、上传/检查版本、引用意图和任务 | 字节写入、恶意内容检查、安全预览和清理 | 未检查不可读；旧任务不得恢复已替换、删除、隔离或失权文件 |
| 5. 邮件渠道投递 | 对应通知事实、邮件渠道任务和安全摘要 | 外部邮件投递、退信处理和重试 | 邮件不回滚普通权益业务；邮箱验证不能绕过；平台运维异常不创建外部邮件任务 |
| 6. 受控批量执行 | 批次预览快照、固定目标和批次状态；每个单项使用独立本地事务 | 逐项执行、汇总和仅失败项重试 | 部分成功不整体回滚；成功项不得重复 |
| 7. 正式删除与恢复 | 删除范围、执行清单、最小删除审计、步骤状态和幂等依据 | 数据库、附件、缓存、索引、未过期导出及备份恢复后的删除重放 | 部分失败不得宣称完成，也不得补偿恢复已删个人数据 |
| 8. 派生索引、缓存与重算 | 源对象版本或变更事实、重建任务 | 搜索、统计、个人中心、工作台和缓存刷新 | 陈旧派生数据不得授权；范围收紧、归档、失权和删除必须使旧结果失效 |

### 7.3 并发与幂等保证

1. 每个命令声明期望状态或对象版本；提交时不匹配则拒绝并返回状态冲突。
2. 每个可重试业务意图具有稳定幂等标识；重复成功返回第一次结果，不产生第二份历史、通知或外部写入。
3. 面试冲突、容量、唯一申请、邀请竞争、最后负责人、版本发布和关系互斥必须由同一提交边界中的数据库约束或等效并发控制保证；具体锁策略进入数据与 ADR。
4. 改期必须原子释放旧占用并获得新占用；失败时旧安排保持有效。
5. 预约命令和截止任务使用可竞争的版本与执行租约；取消、重新确认和执行只允许一个成功。
6. 外部回调、轮询、人工重试和后台重试共享同一业务意图与收口规则，不能各自产生一份结果。

## 8. 关键跨组件流程

| 流程 | 同步入口检查 | 本地提交边界 | 外部/异步阶段 | 完成判据 |
|---|---|---|---|---|
| 受保护查询或命令 | 认证、安全限制、资料门、目标对象、当前 Group、模板/任务、作用域、状态和字段范围 | 查询不写业务；命令按第 7 节提交 | 必要时刷新派生数据 | 返回内容和能力均不超过本次授权 |
| 邀请接受并成为成员 | 邀请状态/期限、本人、账号、资料门、社团/部门、成员关系和版本 | 接受事实、成员生效处理中、历史、通知和 Casdoor 意图 | 写 Group、回读、重试或补偿 | 回读确认全部目标关系后才开放权限 |
| 部门/职位/负责人变更 | 操作者当前权限、关系前置条件、负责人连续性、对象版本和高风险确认 | 关系命令进入处理中，保存原关系、历史、通知/审计和外部意图 | Casdoor 写入与回读 | 新关系可信确认；失败保持原有效权限或进入已定义异常 |
| 权益状态变更 | 领域状态、作用域、操作者和版本 | 业务结果、历史、通知事实、收件人快照和关键审计 | 站内信及可选邮件投递 | 本地事务成功即形成业务事实；渠道结果独立可追踪 |
| 附件正式提交 | 文件引用、检查状态、当前字段/对象权限、表单版本和业务状态 | 正式提交版本与已检查文件引用原子绑定 | 预览衍生、后续清理 | 所有必需附件可用且绑定成功 |
| 联合材料访问 | 当前身份、锁定参与社团、社团启用、当前角色/任务、活动阶段、作者归属和字段范围 | 敏感访问审计 | 短期文件地址或派生响应 | 任一条件失效后旧入口和短链不能继续访问 |
| 受控批量操作 | 当前工作空间、允许的单一类型、固定目标预览和版本 | 批次确认；随后每项独立提交 | 逐项外部任务和通知投递 | 汇总准确；失败项可重试且成功项不重复 |
| 正式删除与灾难恢复 | 超级管理员、重新认证、范围预览、原因、状态和删除资格 | 删除清单/步骤或恢复门状态持久化 | 跨存储删除、备份恢复、删除重放、附件检查和 Casdoor 对账 | 所有在线副本核验完成；恢复门通过后才开放普通写入 |

## 9. 故障隔离与恢复责任

| 故障域 | 必须隔离的影响 | 恢复责任 | 上游规则 |
|---|---|---|---|
| Casdoor 登录/状态不可确认 | 不得扩展旧权限；15 分钟内仅最小白名单，之后仅公开页面 | 身份与组织模块回读账号/Group，授权模块重新计算，会话按规则恢复 | SRS-FAIL-001、SRS-FAIL-002 |
| Casdoor 资料同步 | 不影响其他本地业务事实；第三值不自动选边 | 身份与资料模块回读、回退或等待本人选择 | SRS-FAIL-003 |
| Casdoor Group 写入 | 新权限不得提前生效；原关系按领域规则保持 | 邀请/成员或组织模块拥有业务意图，Casdoor 适配器执行回读和重试 | SRS-FAIL-004 |
| PostgreSQL | 全部业务写入停止；缓存和客户端不得替代权威库 | 运维恢复数据库并验证一致性后开放 | SRS-FAIL-005 |
| 对象存储/检查/预览 | 仅附件相关能力降级；未经检查不放行 | 文件模块按文件版本恢复任务 | SRS-FAIL-006 |
| 邮件 | 不回滚已保存通知事实的普通权益业务；邮箱验证保持关闭 | 通知模块重试、停止并通过站内信或内置状态显示失败；身份模块继续执行验证门 | SRS-FAIL-007 |
| 通知事实持久化 | 直接影响权益的原业务不得提交 | 原领域命令整体重试 | SRS-FAIL-008 |
| 站内信关闭 | 业务和通知事实继续；显示与投递暂停 | 通知模块恢复后按原事件时间补投 | SRS-FAIL-009 |
| 后台任务 | 不改变原业务，不伪造完成 | 任务责任模块按版本和当前权限重试 | SRS-FAIL-010 |
| 正式删除/备份恢复 | 删除不能假完成；恢复不能复现已删内容或直接开放写入 | 数据生命周期与运维模块共同执行清单、检查、对账和开放门 | SRS-FAIL-011、SRS-FAIL-012 |
| 不可变配置发布 | 全部对象继续使用旧版本，不能混合生效 | 配置与发布模块重新预览、发布新版本或按新版本回滚 | SRS-FAIL-013 |

故障处理的业务所有者始终是拥有该业务意图或状态机的模块；基础设施适配器只报告结果并执行可恢复动作，不能自行决定录取、任免、成员、权限或归档结果。

## 10. 部署视图与扩容路径

### 10.1 必须支持的逻辑运行单元

| 逻辑运行单元 | 责任 | 单机部署 | 拆分部署 |
|---|---|---|---|
| Web 与应用入口 | 页面、查询、命令接入、授权和同步响应 | 可与应用运行单元共同部署 | 可多实例部署，但不得依赖实例本地会话授予权限 |
| 应用领域运行单元 | 应用用例、领域规则和本地事务 | 可与入口共同部署 | 首版作为模块化单体横向扩展，不按领域拆成微服务 |
| 后台任务运行单元 | 外部写入、回读、通知、文件、导出、到期、删除和重算 | 可同机独立进程/容器 | 可按任务类型和积压独立扩展 |
| PostgreSQL | 本地权威业务数据 | 可在参考单机方案部署 | 生产可独立节点；备份、恢复和容量按 NFR 验证 |
| 对象存储 | 附件、预览和导出字节 | 可使用兼容单机实现 | 可使用独立可扩容存储 |
| 文件检查/预览 | 恶意内容检查和安全衍生 | 可与后台节点同机隔离运行 | 可独立扩展并限制资源 |
| 外部适配 | Casdoor 和邮件 | 通过配置连接 | 与应用拓扑无关，保持相同契约 |

官方容器化单机与拆分部署必须使用同一套程序和相同业务规则；单社团部署也只能通过配置限制范围，不得形成源码分支。正式环境使用 HTTPS，不要求 Kubernetes。

### 10.2 扩容顺序

1. 先以代表性数据验证数据库查询、授权投影、面试冲突和写入事务，不用缓存掩盖错误模型。
2. 将无状态入口和应用运行单元横向扩展；会话、幂等、租约和授权不能依赖单实例内存。
3. 按积压和资源类型独立扩展后台任务、文件检查和导出执行能力。
4. 将附件、预览、导出与数据库存储分离，保持引用、权限和删除清单一致。
5. 搜索、缓存和统计读模型可按负载引入或拆分，但始终可重建且不得成为授权权威。
6. 首版不强制 PostgreSQL 自动高可用、读扩展、分区或归档产品；未来引入须基于容量、故障或恢复证据创建补充 ADR，且不能降低事务、RPO/RTO和删除重放要求。

### 10.3 分级部署与恢复优先（ADR-012）

首版提供完整单机 Docker 档位，并以同一发布物支持应用、后台任务、PostgreSQL、对象存储和文件检查按需拆分。拆分只表示职责、资源或故障域分离，不自动宣称高可用。正式部署必须把可恢复备份放到与唯一在线副本不同的故障域，并通过事务日志、恢复演练、删除重放和 Casdoor 对账证明恢复能力。

首版不强制负载均衡、双应用节点、PostgreSQL 主备自动切换、分布式对象存储、共享缓存、服务发现或 Kubernetes。`NFR-004` 中的双应用完整设计容量继续作为参考拓扑，不是所有生产部署的强制采购要求。99.5%、RPO 15 分钟和 RTO 4 小时保持不变；具体拓扑的可用性、容量与恢复结论必须绑定测试证据。

## 11. 安全与可观测性架构边界

### 11.1 安全设计必须继续细化的控制面

- OIDC 请求关联、签发方、受众、有效期、重新认证时间和会话撤销；
- 当前 Casdoor Group 的可信读取、缓存上限、失权传播和实时高风险检查；
- 普通社团隔离、联合协作域、字段级权限和对象级短链；
- 服务账号最小权限、秘密加密、轮换和浏览器零暴露；
- 文件隔离、检查、预览转换、水印和下载审计；
- 自动安全限制的事件可信度、聚合窗口、阈值版本和防拒绝服务；
- 真实学生数据启用、暂停、恢复及恢复后的只读/写入边界；
- 导出、批量、搜索、统计和特权查看的滥用控制。

这些控制已进入独立的[`安全设计与实现级威胁模型`](../specification/安全设计与实现级威胁模型-v1.0.md)，其第一轮已完成内部确认。本总览只固定信任边界和依赖方向；安全设计提供实现中立的控制与负向证据入口，但不提前声称具体控制已经实现或测试通过。

### 11.2 内置最小观测边界

每次入口请求、后台任务和外部调用必须具有唯一追踪编号及可关联的派生关系；业务幂等键与追踪编号不得混同。普通脱敏运行日志默认保留 90 天，其中 30 天在线、60 天压缩归档；网络运行和安全事件日志至少保留 6 个月，业务审计独立长期保留。超级管理员内置只读状态页仅显示应用版本与启动状态、数据库连通性、任务积压与最近异常，以及 Casdoor 同步、邮件、文件检查、通知和备份的最近结果与更新时间；过期状态显示未知。应用仍可运行时，严重异常在该页面和脱敏日志中提示。

首版不监测主机 CPU、内存、磁盘等机器资源，不提供供外部监控消费的机器健康接口，不建设独立监测进程、系统外运维告警、应用宕机自动发现、指标/追踪导出或完整观测平台。内置观测不得成为业务或权限权威，具体实现按 ADR-011 执行。

追踪：NFR-006；SRS-NFR-024 至 029。
