# ADR-008：S3 兼容对象存储与文件可恢复提交

> 状态：已接受  
> 决策日期：2026-07-30  
> 决策范围：系统架构后续技术决策

## 1. 背景与约束

`FORM-007` 至 `FORM-009` 要求附件先检查后访问、每次访问重新鉴权、只生成短时访问地址、替换形成新文件版本且旧修订继续引用原附件；`AUD-007` 至 `AUD-009` 要求临时文件安全清理、正式删除跨数据库、附件存储、缓存、索引和导出传播，并在恢复后重新应用删除清单。`NFR-002` 至 `NFR-004`、`NFR-007` 又要求附件独立纳入容量、备份、恢复、故障降级以及单机/拆分部署。

PostgreSQL 适合保存强一致的文件业务事实和引用关系，但大量照片、视频、普通文件、预览及导出字节会扩大数据库 I/O、备份和恢复负担。应用服务器本地磁盘则难以同时支持容器重建、多应用节点、独立扩容和可验证恢复。因此需要确定文件字节、元数据、检查状态和业务引用的权威边界，并为数据库与对象存储之间不存在分布式原子事务的事实建立恢复路径。

## 2. 已接受决策

1. 首版使用**兼容 S3 接口的对象存储**保存附件原件、安全预览、水印或转码等派生物、临时导出及其他文件字节。PostgreSQL 不以普通业务表二进制字段或大对象作为这些文件的首版权威存储。
2. PostgreSQL 保存文件元数据、不可变文件版本、所属数据域、创建者、业务引用、检查/处理状态、内容校验依据、对象定位信息、生命周期状态、删除意图和必要审计关联。对象存储对文件字节负责，但不能决定业务归属、可见性或访问权限。
3. 应用服务器本地磁盘不得作为正式文件的唯一权威副本。官方容器化单机部署可以附带本地运行的 S3 兼容对象存储服务；拆分部署和部署者自选实现继续使用同一应用能力边界，不要求固定云厂商。
4. 新上传文件在检查完成前必须处于不可正式访问的隔离边界。文件字节成功进入对象存储不等于业务提交成功、检查通过或附件已经正式绑定；未检查、检查中、检查失败或隔离文件不能生成普通预览/下载入口，也不能满足要求附件的正式提交条件。
5. 文件检查、安全预览、元数据清理、水印和其他派生处理由可独立运行的后台任务执行。任务必须遵守 ADR-004 的持久意图、租约、至少一次、幂等、当前条件复核和恢复语义；重复执行不得覆盖原件、产生多份有效业务版本或重复放行。
6. 每次附件访问必须先由应用依据当前用户、对象、操作、作用域、业务状态和字段权限重新鉴权，再通过受控响应或短时有效地址访问私有对象。对象存储键、历史地址、缓存命中或持有旧短链均不能成为授权依据；具体短链机制和时长进入接口与安全规格。
7. 数据库事务与对象存储操作不伪装成跨系统原子事务。上传、正式绑定、版本替换、派生生成、孤儿清理和正式删除必须通过可查询技术状态、持久任务/意图、幂等对象定位、补偿和对账形成可恢复提交；部分失败不得返回假成功。
8. 已提交附件替换必须创建新的应用级文件版本和对象引用，不覆盖旧修订所引用的原件。是否启用对象存储供应商自身的版本功能不影响该要求，也不能替代应用级版本和历史引用。
9. 草稿孤儿、扫描失败文件、无有效引用上传和临时导出按已确认期限异步清理，执行前重新检查当前引用；正式删除通过独立删除清单传播到所有在线对象和派生物，恢复后必须重新应用删除清单并核对数据库—对象存储一致性。
10. 对象存储及附件字节必须与 PostgreSQL 一同进入备份、容量、监控、故障演练和恢复验收。只恢复数据库或只恢复对象存储都不能宣称业务已经完整恢复。

## 3. 候选方案与取舍

| 候选方案 | 优点 | 主要问题 | 结论 |
|---|---|---|---|
| S3 兼容对象存储＋PostgreSQL 元数据＋隔离检查与可恢复提交 | 文件容量可独立扩展；支持单机与拆分部署；便于私有对象、短时访问、派生物和生命周期治理；可替换实现 | 增加独立依赖；数据库与对象操作需要持久状态、补偿、对账和联合恢复 | 首版采用 |
| 应用服务器本地文件系统 | 初始搭建和调试直接 | 容器重建、多节点共享、容量迁移、权限隔离、备份和恢复边界较差，容易形成不可见单点 | 不作为正式权威存储；可用于受控临时处理 |
| PostgreSQL 保存全部文件字节 | 元数据和字节可进入同一数据库事务与备份流程 | 数据库体积、WAL、I/O、备份恢复和扩容压力显著增加，不适合照片、视频和大型导出 | 首版不采用 |
| 固定单一云厂商对象存储接口 | 可充分使用特定供应商能力 | 破坏开源可部署性和可替换边界，形成供应商锁定 | 不采用 |

## 4. 对后续文档的约束

- 数据模型必须区分文件逻辑记录、不可变版本、对象字节、派生物、业务引用、处理状态和删除状态，并证明旧提交修订持续指向正确版本。
- 接口契约必须定义上传初始化、字节接收、检查状态查询、正式绑定、预览/下载授权、替换、取消和删除的前置条件、幂等、并发、失败及恢复语义，但不得让客户端自行宣布检查通过或正式绑定。
- 安全设计必须覆盖对象键不可猜测、存储默认私有、隔离区与可访问区、真实类型识别、恶意内容检查、预览沙箱、元数据移除、短链泄漏、跨社团引用和每次访问重新鉴权。
- 测试规格必须覆盖伪造扩展名、未检查访问、检查服务不可用、重复回调/任务、对象已写数据库未写、数据库已写对象缺失、版本替换竞争、清理与并发引用、正式删除部分失败及恢复后二次删除。
- 部署运维必须记录 S3 兼容范围、支持的实际实现和版本、容量阈值、加密与凭据、网络边界、备份、恢复、对象盘满、检查积压、孤儿对账和删除重放，并在单机与拆分拓扑验证相同行为。

## 5. 不受本决策影响的边界

本 ADR 不改变允许的文件类别、真实类型白名单、单文件大小、数量上限、安全检查、本人附件回看、字段权限、水印、审计、版本、归档、清理期限或正式删除行为，不新增产品需求或 `PRD-OPT` 编号。

本 ADR 不决定：

- MinIO、Ceph、Amazon S3、其他云服务或具体 S3 兼容产品；
- Bucket、对象键、分段上传、加密算法、短链协议、过期时间和网络拓扑；
- 病毒检查、内容识别、图片处理、视频转码、文档预览和水印产品；
- 各文件类型是否支持在线预览以及具体转换格式；
- 具体表、字段、状态枚举、任务参数、重试次数、清理期限和备份产品；
- 前后端语言、ORM、API 风格、Casdoor 适配、秘密/观测/告警产品和生产高可用拓扑。

## 6. 重新评估条件

出现以下任一情况时，可以创建补充或替代 ADR：

- 实际部署环境无法提供满足安全、兼容、备份和恢复要求的 S3 兼容实现；
- 目标对象大小、数量或访问模式经验证无法由当前兼容边界经济承载；
- 某类文件需要不同的合规隔离、地域、不可变保留或专用流媒体能力；
- 对象存储与 PostgreSQL 的恢复、删除或一致性演练无法满足已确认 RPO/RTO 和数据治理规则；
- 替代方案能够证明在开源单机、拆分部署、安全检查、权限、版本、删除和恢复方面具有更低总风险。

替代决策不得以减少基础设施为由把未检查文件放行、让对象存储直接授权、覆盖历史原件、跳过删除传播或把本地临时盘变成未备份的唯一副本。

## 7. 结论

ADR-008 收口“对象存储与文件检查/预览”开放项。首版以 S3 兼容对象存储承载文件字节，以 PostgreSQL 承载文件元数据、业务引用和处理状态，并通过隔离检查、持久任务、幂等、补偿和对账完成跨存储可恢复提交。该决策为数据、接口、安全、测试和运维设计提供边界，不构成供应商选型、具体 API 或代码开工批准。
