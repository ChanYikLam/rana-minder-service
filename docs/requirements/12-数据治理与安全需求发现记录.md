# RanaMinder 数据治理与安全需求发现记录

> 状态：产品行为已内部冻结  
> 日期：2026-07-28

## 已确认的前置约束

1. 普通社团数据严格隔离，联合活动形成经申请人同意的跨社团协作域。
2. 超级管理员拥有平台全局能力，所有特权查看和高风险操作必须审计。
3. 当前产品长期保留正式业务历史、不提供匿名化，并允许超级管理员按正式流程删除数据。
4. 动态表单允许社团配置个人资料、图片和附件字段。
5. Casdoor 管理统一身份和当前 Group 关系，本系统管理业务历史及动态表单内容。

## 本模块待冻结范围

- 数据分类、数据目录和系统秘密边界；
- 动态表单的数据最小化、禁止字段和个人信息告知；
- 真实数据启用、暂停和恢复权限；
- 普通社团隔离域和联合活动协作域的治理开关；
- 超级管理员特权、威胁模型和安全处置要求。

## 2026-07-28：内部数据分类

1. 公开数据包括社团展示名称、Logo、简介和公开招新说明等。
2. 内部业务数据包括部门及职位结构、非公开统计和业务配置等。
3. 个人业务数据包括学号、姓名、学院、年级、联系方式、报名表、附件、面试评价、任职经历和纠错材料等。
4. 系统秘密包括密码、Casdoor 令牌、服务账号、邮件密钥、验证码和加密密钥。
5. 每个字段和文件类型登记来源、用途、权威系统、访问角色、共享范围、保留方式和纠错方式。
6. 分类不确定的数据默认按照更严格级别处理。
7. 系统秘密不得在业务页面、通知、审计和导出中显示明文。

## 2026-07-28：超级管理员代表校方启停真实数据

1. 部署中的超级管理员被视为校方授权代表。
2. 系统不建设校外审批、审批材料上传、逐次授权证明或真实数据治理检查单。
3. 超级管理员可以直接启用、暂停或恢复真实学生数据处理，无需其他角色批准。
4. 启停操作需要明确确认并记录操作人、时间、状态变化和审计，但不构成审批流程。
5. 暂停后现有真实数据进入只读保护，不自动删除，也不允许继续新增。
6. 恢复后继续按照当前有效角色、业务状态和治理规则处理。

## 2026-07-28：动态表单中的个人字段与统一说明

1. 社团负责人和人事管理员可以直接增加联系方式、证件图片和其他个人资料字段。
2. 表单设计者不需要逐字段填写用途，也不需要超级管理员审批。
3. 申请人提交前只展示一次统一的数据使用与共享说明，不对每个字段单独解释。
4. 普通招新和联合活动的统一说明分别反映各自已经确认的查看及共享范围。
5. 密码、验证码、Casdoor 令牌、邮件密钥等系统秘密始终禁止收集，任何管理员都不能解除。
6. 超级管理员发现明显违规或危险表单时可以立即停用并记录审计。
7. 停用表单不会自动删除既有提交，已有内容继续按访问、纠错和正式删除规则处理。

## 2026-07-28：联合活动治理开关

1. 联合面试默认可用，不需要超级管理员逐个审批活动。
2. 超级管理员可以全局禁止创建新的联合活动；已经成立的活动继续运行，除非按既有规则强制结束。
3. 超级管理员可以紧急关闭新的跨社团批量导出和未完成导出文件下载，该安全限制立即生效并优先于活动配置快照。
4. 关闭跨社团导出不会自动关闭参与社团的在线查看权限。
5. 已下载到系统外的文件不能召回。
6. 重新开启后不自动补生成关闭期间未执行的导出。
7. 开关变化需要明确确认、通知受影响管理员并审计，但不需要审批。

## 2026-07-28：联合活动共享说明和同意证据

1. 统一说明列出首次公布时已经锁定的参与社团、共享数据类别、跨社团评价和结论查看、未报名社团邀请、长期归档及跨社团导出。
2. 说明列出首次公布时已经锁定的全部参与社团，并明确活动进行中不会新增参与方或扩大共享对象。
3. 申请人拒绝说明则不能参加联合活动；原社团如有普通路径，仍可参加普通面试。
4. 系统保存申请人账号、联合活动、说明版本、确认时间、锁定参与社团和报名表版本。
5. 首次公布后参与社团不得主动退出；紧急停用只暂停该社团访问，不改变锁定名单或申请人的共享确认。
6. 未来增加原说明未包含的全新共享类别时，只能应用到后续新活动，不能静默扩大既有同意范围。

## 2026-07-28：异常访问检测与安全限制

1. 检测连续跨社团越权、批量遍历学生、绕过导出的大量附件下载、异常频率查询和疑似会话盗用。
2. 检测结合正常招新工作量，不能仅因管理员查看大量本社团申请人就判定异常。
3. 达到高风险条件时，可限制查询、附件下载和导出并终止可疑会话。
4. 安全检测不能自动修改录取结论、成员关系或职位。
5. 系统通知用户本人、相关社团负责人和超级管理员，并保留完整安全审计。
6. 只有超级管理员可以解除安全限制；无需他人审批，但必须填写处理说明。
7. 误判期间保留业务记录，不产生静默丢失或状态变化。

## 2026-07-28：管理员账号增强保护

1. 所有管理员仅通过 Casdoor 登录，本系统不设置独立管理员密码或后门账号。
2. 正式环境中的超级管理员必须在 Casdoor 开启多因素认证。
3. 删除正式数据、修改 Casdoor 映射、变更权限模板、全平台导出和关闭真实数据等高风险操作，要求最近 10 分钟内重新完成身份认证。
4. 每次高风险操作实时检查用户当前 Casdoor Group，不能仅依赖登录时权限。
5. 管理员被移出职位或超级管理员 Group 后，终止其现有管理会话。
6. 正式环境至少配置两名超级管理员。
7. Casdoor 不可用时不允许使用本地备用账号绕过认证，高风险操作继续关闭。

## 2026-07-28：文件检查、预览和下载安全

1. 文件上传后先进入检查中，完成前任何角色都不能预览或下载。
2. 同时检查扩展名、实际文件类型、大小和恶意内容。
3. 危险或不合规文件进入隔离，通知上传者重新上传并记录安全审计。
4. 检查服务不可用时保持等待或失败，不开放未经检查的文件。
5. 图片和文档预览使用安全转换副本，原文件保持不变并受权限保护。
6. 每次预览和下载重新鉴权，只生成短期有效链接，不提供永久公开地址。
7. 申请材料预览继续添加查看者和时间水印；下载和敏感预览均留审计。

## 2026-07-28：Casdoor OIDC、事件与服务账号安全

1. 登录校验请求关联、回调地址、令牌签发方、适用系统和有效期。
2. Casdoor 事件通知校验签名、时间和重复事件；重复到达不得重复修改成员或权限。
3. 当前版本不能安全提供事件通知时，使用最小权限服务账号定期对账。
4. 管理凭据仅在服务端加密保存，不下发浏览器、不进入日志。
5. 服务账号只授予读取用户和管理规定 Group 所需的最小权限，并支持轮换。
6. 修改 Casdoor 的请求具有唯一编号，超时后先查询实际结果再决定是否重试。
7. 接口错误不能返回令牌、密钥、内部文件路径或完整个人数据。

## 2026-07-28：统一数据使用与共享说明

1. 普通招新和联合活动分别提供简短摘要及可展开、查阅和保存的完整说明，不逐字段弹窗。
2. 申请人在每个活动、每个说明版本首次正式提交前确认一次；同一版本后续修改提交不重复弹窗。
3. 摘要至少说明处理主体及联系方式、数据类别、招新和成员管理用途、查看角色、保存与导出规则、超级管理员特权，以及个人查询、更正和删除渠道。
4. 联合活动额外列出首次公布时已经锁定的参与社团，并说明完整报名材料、附件、内部评价和结论共享、未报名社团邀请、长期保留及跨社团导出。
5. 系统保存申请人账号、确认时间、活动、说明版本、锁定参与社团和表单版本。
6. 单纯文字优化不重新确认；新增用途、数据类别或共享范围只能对后续新提交生效并重新确认，不能追溯扩大既有同意。
7. 联合活动进行中不新增或主动退出社团；紧急停用社团立即失去访问权，但不改变固定参与方确认。

## 当前待确认

无行为层面的待确认项。MFA、强制重认证、OIDC Claims、Webhook、管理 API 和服务账号权限仍须在首批正式代码中使用实际 Casdoor 环境验证。

## 本模块内部冻结结论

数据分级、动态表单采集边界、真实数据启停、联合活动治理开关、共享同意证据、异常访问、管理员增强认证、文件安全和 Casdoor 接口安全的产品行为已经内部冻结。超级管理员在部署中代表校方，不建设外部审批流程。证件图片无逐字段说明、未来社团默认共享、长期归档、跨社团完整评价导出和超级管理员全局能力作为已知高风险事实保留；实际 Casdoor 安全能力、检测阈值、扫描服务和密钥托管进入首批正式代码验证、SRS、架构及运维规格。
