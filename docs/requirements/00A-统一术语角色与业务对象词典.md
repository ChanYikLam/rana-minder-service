# RanaMinder 统一术语、角色与业务对象词典

> 版本：v1.0
> 最后更新：2026-08-01
> 状态：随需求事实总账内部冻结  
> 适用范围：PRD、SRS、架构、接口、数据模型、测试、界面文案和开源文档

## 一、使用规则

1. `RanaMinder` 是本项目唯一正式产品名称。本文档集中的“本系统”“本产品”均指 `RanaMinder`；面向外部首次介绍时可写作“RanaMinder（高校学生社团人员管理系统）”，后续统一使用 `RanaMinder`。
2. 本词典统一解释已经确认的业务语言，不独立新增需求。
3. 发生冲突时，以《00-需求事实总账》中的编号需求为准，并同步修订本词典。
4. 文档和界面不得仅写“管理员”而不说明具体角色；接口和测试必须写明操作人的当前角色及作用域。
5. “角色”默认指本系统业务角色；涉及 Casdoor 的 Role 对象时必须完整写作“Casdoor Role”。当前阶段不使用 Casdoor Role。
6. “社团负责人”与口语中的“会长”含义相同；权威文档统一使用“社团负责人”。
7. “人事管理员”与口语中的“人事”含义相同；权威文档统一使用“人事管理员”。
8. “部门负责人”与口语中的“部长”含义相同；权威文档统一使用“部门负责人”。
9. “入社”“入会”“加入协会”统一表达为“成为社团成员”。

## 二、身份与外部系统

| 术语 | 统一定义 | 不得混同 |
|---|---|---|
| 学校统一身份认证 | 学生进入本系统前必须经过的学校身份认证能力，当前由 Casdoor 对接并向本系统提供身份。 | 本系统不提供学生独立密码注册。 |
| Casdoor Organization | 承载本校统一学生身份的学校级 Casdoor 组织。本项目首期采用一个学校级 Organization。 | 不是单个社团。 |
| Casdoor Group | Casdoor 中用于表示社团、部门、职位及其当前成员关系的对象。只有被超级管理员明确接入并配置用途的 Group 才具有本系统业务含义。 | 未接入 Group 不能因名称或层级自动成为社团、部门或职位。 |
| Casdoor Role | Casdoor 的 Role 对象。当前方案明确延期，不用于表示职位或产生本系统权限。 | 不得把业务角色或职位 Group 写成 Casdoor Role。 |
| Casdoor 账号 | 以学号为账号标识的外部身份账号；其禁用或删除会立即影响本系统登录和权限。 | 不等于某个社团的成员身份。 |
| Casdoor 故障 15 分钟窗口 | Casdoor 暂不可确认时，仅对故障前已可信登录且未超过 15 分钟的会话开放最小白名单的短暂降级窗口。 | 不等于继续沿用全部旧权限；只允许公开页面、本人基础资料只读和既有本人表单草稿非附件字段编辑，超时后除公开页面外全部受保护请求关闭。 |
| 未登录访客 | 尚未通过 Casdoor 统一认证的访问者，只能查看平台与社团明确公开的信息，不构成本系统正式用户。 | 不能报名、处理邀请、访问个人资料或取得任何成员与管理权限。 |
| 普通平台用户 | 已通过 Casdoor 统一认证、拥有有效学校级账号，但当前可以不属于任何已接入社团的用户；可维护平台公共资料、完成邮箱验证、浏览公开内容并参加允许的招新或处理发给本人的邀请。 | 不等于普通成员；是否属于某社团必须按该社团当前 Group 关系判断。 |
| 公开发现入口 | 未登录访客和已登录用户发现公开社团及已公开普通招新、联合活动的统一入口；分为“找社团”和“找活动”两个独立模式，前者按社团展示名称搜索，后者按活动名称搜索并支持活动类型、报名状态和截止时间筛选；报名状态中的“正在报名”按查询时的报名通道开放状态、活动暂停/终态覆盖和当前有效截止共同派生；截止时间同时提供今日截止、3 日内、7 日内三个快捷范围和自定义起止日期；快捷范围按发起查询时的平台时区自然日计算，分别覆盖当天、当天及随后两天、当天及随后六天；已完成活动进入独立历史区域。 | 同一时刻只使用一种名称搜索，不提供社团名称与活动名称组合查询；“正在报名”不是新增活动状态，也不代表访问者具备个人报名资格；两类截止筛选入口使用同一时间区间语义；截止日期命中不等于正在报名；入口可见不等于符合报名资格，不得展示内部业务信息，也不提供个性化推荐、自动匹配或个性化排名。 |
| 名称搜索通则 | 人员名称支持任意连续汉字子串（含单字），学号或账号只做精确检索，且不提供人员错别字候选；社团展示名称、活动名称、部门名称、职位名称和 Casdoor Group 名称支持中文任意连续子串，并可提供受控错别字近似候选。非人员结果固定按“稳定标识或名称精确命中→中文连续子串命中→错别字近似候选”分层，近似候选不得超过直接命中；去除首尾空白后，汉字、字母和数字合计不足 3 个有效字符时不产生近似候选，达到 3 个有效字符后才允许进入第三层。Casdoor Group 原始名称可直接检索，稳定 Group 标识精确匹配。首版所有对象均不提供拼音或首字母搜索。 | 中文子串和近似匹配只产生候选，不构成对象身份、唯一性、授权或业务资格；短输入仍可精确或连续子串命中。受保护选择器先按当前范围与权限过滤，最终以稳定对象标识重新校验。每层内部的排序与分页稳定键进入数据设计。动态答案正文、评价、附件内容、通知正文和审计差异不因此进入全文搜索；未来新增拼音搜索必须重新进行产品与数据评审。 |
| 身份上下文 | 一次请求中经过验证的用户、账号状态、当前社团、联合活动作用域及当前有效业务角色集合。 | 不能只凭页面传入的 club_id 或角色名称授权。 |
| 全局个人空间 | 以当前用户本人为中心，按“待我处理、进行中、历史记录”聚合其跨社团申请、面试、邀请、审批、任务及成员状态的个人入口；每项标明所属社团、业务对象、期限和当前状态，并可按社团及业务类型筛选。 | 不等于某个社团工作空间，也不会因此产生跨社团管理权限；其状态来自权威业务对象，不是通知快照的副本。 |
| 待我处理 | 全局个人空间中当前需要用户本人采取行动的聚合分区，包括资料补充、面试、邀请、成员生效异常、本人申请以及凭当前角色可处理的审批或任务。 | 不是通知未读列表；通知已读不代表事项完成，业务完成后也不得继续因旧通知显示为待处理。 |
| 当前社团管理工作空间 | 用户进入社团管理功能前明确选定、并在受保护页面持续显示的当前社团界面上下文。 | 只是导航和请求上下文，不是授权来源；切换不会改变任何 Casdoor Group 或业务关系。 |
| 当前有效角色集合 | 用户在目标社团内由当前职位 Group、已发布权限模板及有效临时任务共同形成的角色和权限来源集合。 | 不要求手动选择一个角色；权限并集不得突破结构范围、显式拒绝、安全限制或对象状态。 |
| 角色型待办 | 责任主体是某个当前业务角色而非固定个人的未完成事项，例如待审批、异常处理或社团级联合确认；当前任一合格角色可按规则处理。 | 原处理人离任不使待办作废、重建或永久无人处理；也不允许超级管理员默认代作普通业务决定。 |
| 个人草稿 | 尚未正式提交、作者身份不可转移的评语、表单或其他个人工作内容；作者失去相应权限后不得继续提交。 | 不能作为工作交接内容转给继任者冒名完成；继任者必须创建自己的记录。 |
| 预约管理命令 | 由有权管理员创建、计划在未来执行的任命、免职、调岗或已批准辞职生效命令；执行前保存不可变内容和计划时间。调度器取得执行租约前，原发起人或任何当前对同一完整命令有权的管理员均可填写原因取消。 | 取消不产生反向 Group 关系；内容变化必须取消后新建，执行开始后不得使用通用取消。 |
| 预约管理命令待重新确认 | 由管理员发起的未来任命、免职或调岗等命令，在执行前发现原发起人已经失去所需权限时进入的暂停状态。 | 不等于原命令已执行或被自动取消；必须由当前有权管理员按原内容重新确认或取消，修改内容则新建命令。 |
| 预约管理命令业务前置条件失效暂停 | 预约命令到达执行时间时，操作者仍有权限，但账号、成员或组合任命资格、部门、职位、目标关系、负责人连续性或对象状态已不再满足原命令而进入的暂停状态。 | 不等于外部写入失败、自动取消或等待条件恢复后自动执行；只能由当前有权管理员取消，或在条件恢复后按原内容重新确认新的执行时间。 |
| 管理工作台 | 在当前社团管理工作空间内，按用户当前权限聚合待审批、面试、结果、邀请、异常和逾期事项的管理入口。 | 不是跨社团管理总控台，也不保存可覆盖原业务对象的独立状态。 |
| 受控批量操作 | 对预览后固定的一组对象，编排执行同一业务类型的多个独立命令；每项分别鉴权、校验、审计和通知。 | 不是一次大事务，也不是任意字段修改、业务数据导入或绕过单项规则的快捷入口。 |
| 部分成功 | 一次受控批量操作中部分独立命令成功、其他命令失败的完成结果；成功项保留，失败项列明原因并可单独重试。 | 不等于整批失败或回滚；重试失败项不得重复已经成功的业务。 |
| 平台公共资料 | 学生在平台范围填写一次并复用的资料，例如学院、年级、邮箱和手机号等固定字段及平台配置的补充字段。 | 不包含社团、部门、职位等当前 Group 关系，也不等同于某次报名表。 |
| 同步 | 本系统与 Casdoor 之间读取或写入固定字段、账号状态及 Group 当前关系，并通过回读、重试和对账达到确认状态。 | 本地历史事件不是可独立覆盖 Casdoor 当前值的同步源。 |
| 资料同步第三值 | 普通可编辑字段同步失败后的可信读回值，既不同于本地目标值，也不同于修改前有效值，表明同步期间发生了外部并发变化。 | 不是普通写入失败、同步成功或可直接回退的旧值。 |
| 同步冲突待本人选择 | 普通可编辑字段出现第三值后停止自动写入的状态；本地继续显示目标值并标记冲突，由用户本人比较本地目标值与 Casdoor 当前值后明确选择。 | 超级管理员或系统不能代替用户选边；姓名、学号等只读权威字段不进入此状态。 |
| 对账 | 将本系统预期关系与 Casdoor 实际值比较，识别外部修改、失败、缺失或结构异常，并进入确认的恢复流程。 | 不得把差异静默改写成正常历史。 |

## 三、组织、职位与权限

| 术语 | 统一定义 | 不得混同 |
|---|---|---|
| 平台 | 一套系统实例及其学校级配置、安全开关、公共模板和超级管理员作用域。 | 不等于某个社团。 |
| 已接入社团 | 由超级管理员从既有 Casdoor Group 中人工选择并完成配置、校验和启用的自治社团空间。 | 系统不创建 Casdoor Group，也没有“新建社团”业务。 |
| 社团空间 | 已接入社团在本系统中的配置、业务数据和权限隔离边界。 | 停用或解除接入不等于删除历史空间。 |
| 部门 | 超级管理员从社团 Group 的后代 Group 中人工配置的组织单元。 | 未配置的下级 Group 不是本系统部门。 |
| 职位 | 由既有 Casdoor Group 表示的当前任职关系，可直属社团或位于某个部门范围。 | 职位不是权限本身，也不是 Casdoor Role。 |
| 职位 Group | 被配置为职位用途的 Casdoor Group；用户当前是否属于该 Group 决定其当前是否担任该职位。 | 本地任期历史不能单独制造当前职位。 |
| 权限模板 | 本系统维护的、与职位 Group 受控映射的一组业务能力。普通职位可以不映射任何管理能力。 | 权限模板不是可由社团任意创建的 Casdoor Role。 |
| 当前关系 | Casdoor 当前记录的社团、部门和职位 Group 成员关系，是本系统当前身份与访问权的权威来源。 | 不等于本地保存的历史经历。 |
| 历史事件 | 本系统保存的入社、入部、任命、调岗、辞职、免职、退出和换届等不可变事实及纠错链。 | 不能脱离 Casdoor 单独改变当前关系。 |
| 停用社团 | 保留 Casdoor 当前关系和全部本地历史，但社团空间进入只读的可恢复状态。 | 不等于归档、解除接入或删除。 |
| 同步异常只读 | 已接入 Group 被删除、移动或失去访问权限后形成的映射异常状态；普通写入关闭，受影响期限冻结，仅超级管理员可修复映射。 | 修复、重绑或重新接入成功不等于恢复启用，必须先进入已停用。 |
| 待重新接入 | 有历史的社团空间异常解除当前 Group 映射后的受限状态，仅超级管理员可查看历史和重新接入。 | 重新接入通过校验后仍先进入已停用，不自动开放普通角色权限。 |
| 解除接入 | 取消某 Casdoor Group 与社团空间的当前映射；有历史数据时仍保留空间及历史，并限制普通社团角色访问。 | 不删除 Casdoor Group，也不删除历史数据。 |
| 归档社团 | 当前产品不存在的功能。 | 不得用该词指停用、解除接入或活动归档。 |

## 四、业务角色

业务角色不是互斥用户类型。一个普通平台用户可同时属于多个社团，并在不同社团叠加普通成员、管理角色或临时任务角色；每次操作仍按目标对象所属社团、部门、活动、轮次和当前状态鉴权。

| 角色 | 定义与典型作用域 |
|---|---|
| 超级管理员 | 代表校方的平台级角色，可由有效的学校工作人员 Casdoor 账号担任，不要求属于任何社团；管理社团接入、Casdoor 映射、平台配置、安全开关、全局纠错和正式删除等特权操作，其访问与操作必须审计。 |
| 社团负责人 | 社团级管理角色，可管理本社团全部部门范围内的招新、成员、职位、配置和历史；默认具备本社团活动全部申请人范围的面试职能，无需额外赋职。系统在启用状态下必须保证每个社团至少一名有效负责人。 |
| 人事管理员 | 社团级人力资源管理角色，在已确认规则内管理本社团招新、成员、任免、换届、纠错和展示配置；默认具备本社团活动全部申请人范围的面试职能，无需额外赋职；可以为空缺。 |
| 部门负责人 | 部门范围管理角色，人员、职位、录取标签和成员历史仍只管理本部门；但作为各级负责人之一，默认可查看和评论本社团当前面试活动的全部面试者，无需额外赋职。只能对申请表中正式报名本部门的人设置本部门“内部选定录取”标签，不能给未报名者打标签，也无权创建或管理面试轮次、对外发布招新结果、操作录取邀请或改变成员关系。 |
| 普通面试官 | 活动内的额外临时赋职，可授予本社团任一当前成员，包括已担任管理角色者。赋职作用域明确为整个面试活动或单个面试轮次：活动级覆盖该活动全部轮次和面试者，轮次级只覆盖指定轮次和面试者；可查看作用域内全部面试者材料并填写本人评语，但不能设置部门“内部选定录取”标签，也不获得轮次管理、结论发布或邀请权限。负责人、人事管理员和部门负责人使用默认面试职能时不需要取得此临时角色；活动结束、指定轮次关闭或任务撤销后对应赋职失效。 |
| 普通成员 | 当前属于社团 Group、但不一定属于部门或担任管理职位的用户。 |
| 申请人 | 已进入普通招新或联合活动申请流程的学生；在接受邀请并完成 Casdoor 关系确认前不具有成员权限。 |
| 候选人 | 招新流程中的过程性称呼，不是独立的当前成员类型或长期身份。 |
| 历史成员 | 已退出或被移除、当前不再属于社团 Group，但本系统保留其既有经历的用户。 |
| 平台管理员 | 权威文档不使用的模糊称呼；如确指超级管理员，必须改写为“超级管理员”。 |
| 社团管理员 | 仅在概述中允许使用的集合称呼，可能包含社团负责人和人事管理员；权限判断、接口和验收中必须拆成具体角色。 |

## 五、普通招新

| 术语 | 统一定义 | 不得混同 |
|---|---|---|
| 普通招新活动 | 单个社团独立开展、与联合活动状态和数据完全分离的招新业务对象。 | 不得把已开始的普通面试转换为联合面试。 |
| 招新批次 | “普通招新活动”的同义业务称呼，用于表示一次有独立配置、报名和结束状态的招新。权威流程图优先使用“普通招新活动”。 | 不等于学年；同一学年可有多个批次。 |
| 报名通道 | 普通招新活动中控制新报名和申请人修改的独立业务对象，包含未开放、开放、暂停和已关闭，并独立保存窗口、截止和状态版本；自动到期或人工关闭后，只要活动仍为进行中且未整体暂停，负责人或人事管理员可携合法未来截止创建新窗口并重开。 | 不等于整个活动的暂停或结束；重开不改变活动主状态、既有已提交申请或下游历史，也不自动恢复已退出或其他业务终态申请。 |
| 申请 | 一个学生在一个普通招新活动中的唯一申请对象，承载报名版本、顺序志愿、调剂选择及其选拔路径；报名截止后已经主动退出时，负责人或人事可为原申请创建申请人专属恢复窗口，本人重新提交成功后仍在同一对象内形成新修订。 | 多个志愿或恢复操作都不会创建第二份同活动申请；恢复窗口不等于全局报名通道重开，也不复活旧路径、面试安排或邀请。 |
| 身份异常 | 普通招新申请人被 Casdoor 可信确认为禁用或删除后进入的受限状态；不自动淘汰，账号恢复可继续原流程。本社团负责人或人事管理员核实当前状态后可独立发布资格失效等明确申请级结论，超级管理员仅异常处置。 | 不等于普通资格条件变化；不能仅凭异常持续时间自动判定，不授予部门负责人或面试官发布结论的权限。 |
| 顺序志愿 | 申请人对本次开放部门按第一、第二等顺序表达的偏好。 | 志愿顺序不会自动阻止后续志愿部门并行考察。 |
| 允许调剂 | 申请人授权本社团未填报部门查看其完整报名资料并纳入部门考察的选择；截止后锁定。 | 不存在额外“调剂考察邀请”。 |
| 部门选拔路径 | 某个部门针对一份申请形成的可审计考察关系，承载面试、评价、候补、结论和邀请。 | 仅因“允许调剂”可见不等于已经建立路径。 |
| 面试轮次 | 普通招新中由社团负责人或人事管理员配置的有序、全社团共用面试阶段；可配置任意多轮，每名申请人在每轮最多形成一份有效面试记录。 | 不存在部门独立轮次，也不等于跨社团联合面试。 |
| 社团统一面试轮次 | 整个社团共同安排和使用的普通招新面试轮次；不同部门可依据同一有效记录形成各自判断。 | 部门无权创建专属面试；一名申请人不会因多个部门而重复参加同一轮。 |
| 面试任务 | 把面试官、申请人、轮次和排期绑定起来的临时授权对象。 | 面试官的社团职位本身不自动授予所有申请资料访问。 |
| 面试时间冲突 | 同一申请人已有有效面试安排，或同一面试官已有明确分配任务，且两个时间区间实际重叠的状态；结束时间等于另一安排开始时间不算重叠。 | 不包含已取消、已作废或已释放安排，也不因管理角色拥有默认全量评审权限而自动产生。 |
| 明确分配面试任务 | 负责人或人事把某个活动、轮次或时段的面试工作明确指派给当前成员形成的日程占用。 | 不等于负责人、人事或部门负责人无需指派即可拥有的材料查看和评语权限。 |
| 我的面试日程 | 全局个人中心中聚合本人作为申请人或明确分配面试官的有效普通与联合面试安排的视图。 | 当前 v1.0 不包括外部日历订阅、ICS 导出或第三方日历同步。 |
| 面试记录 | 一次实际排期、出勤和面试事实的记录；每名申请人在每轮最多有一份有效记录。异常记录可由有权管理员填写原因后作废，原记录永久保留，随后才可重新安排。 | 换时或未实际参加前的重排不是重复面试；不得通过免试伪造已完成记录。 |
| 面试评价 | 面试官基于动态评价表填写的评分、评语和建议，保留作者和修改历史。 | 不等于正式晋级、淘汰或录取结论。 |
| 内部结论 | 有权角色形成但尚未向申请人发布的晋级、暂缓、候补、录取、不录取或路径结束判断。普通招新中，社团负责人和人事管理员管理完整内部结论；部门负责人的决定型权限仅为对正式报名本部门者设置或取消“内部选定录取”标签。 | 未发布结论或标签不应显示为申请人的正式结果，也不产生录取邀请或申请人通知。 |
| 公开结果 | 在普通招新中经社团负责人或人事管理员正式发布、申请人可见并触发通知的结果。 | 不包含内部评分、评语或讨论；部门负责人无发布权。 |
| 候补 | 部门级的临时状态，必须在活动结束前转为录取邀请或最终不录取。 | 不是整份申请唯一状态，也不是自动排序。 |
| 录取邀请 | 已报名社团向申请人发出的有有效期的加入具体部门或社团的正式要约；普通招新中仅社团负责人或人事管理员可创建和操作。 | 发出邀请不等于已经成为成员；部门负责人作出内部录取决定不等于已经发出邀请。 |
| 撤回邀请 | 发出方在申请人尚未接受时，使待处理邀请提前进入“已撤回”终态的操作。 | 已接受邀请不能撤回或改回待处理；普通招新接受后的关系变化必须走成员生命周期。 |

## 六、多社团联合面试

| 术语 | 统一定义 | 不得混同 |
|---|---|---|
| 联合活动 | 两个或以上平等社团经全体确认成立、共同安排一次面试并共享确认范围内资料的独立业务对象。 | 不存在牵头社团，也不与普通招新互相转换。 |
| 拟参与社团 | 尚处于发起或新增确认阶段、未获得联合资料访问权的社团。 | 不等于正式参与社团。 |
| 参与社团 | 已完成全体确认并被首次公布时的锁定名单包含、因而获得联合协作域权限的社团。 | 首次公布后不得主动退出；紧急停用只暂停权限，不删除参与身份。 |
| 联合协作域 | 由联合活动、当前参与关系、角色、记录作者和业务阶段共同形成的跨社团授权边界。 | 不能只用 club_id 表达。 |
| 成立 | 所有拟参与社团在确认期限内分别确认后，联合活动正式获得参与关系和共享边界。 | 发起不等于成立。 |
| 拟参与社团调整 | 联合活动首次公布前增加或移除拟参与社团，并使全部拟参与社团重新确认的操作。 | 首次公布后参与社团名单永久锁定，不再提供新增社团操作。 |
| 首次公布 | 联合活动第一次进入公开预告状态，学生可查看活动、锁定参与社团、报名时间和共享说明，但尚不一定能够提交报名。 | 该事件永久锁定参与社团名单，禁止后续新增或主动退出。 |
| 首次开放报名 | 联合活动第一次允许申请人正式提交报名的事件，也是联合招新正式开始事件。 | 可以与首次公布同时发生，但事件语义和时间记录分开。 |
| 联合报名通道 | 每个联合活动唯一的报名入口业务对象，独立保存“未开放、开放、暂停、已关闭”状态、窗口版本、截止与变更历史；活动成立后，任一当前参与社团负责人或人事管理员均可独立执行通道人工命令。暂停使旧截止版本失效，恢复必须设置合法新截止并创建新窗口；延期仅在开放状态替换为更晚的新截止版本；开放或暂停均可在活动非终态时填写原因后人工关闭；自动到期或人工关闭后，只要活动仍非终态，即使已进入邀请阶段也可携合法未来截止创建新窗口并重开。 | 独立于联合活动主状态，也不复用普通报名通道对象或版本；暂停期间不自动继承剩余时长，旧截止任务不得关闭通道；延期不得恢复暂停或已关闭入口；关闭和重开均不改变活动主状态或锁定名单；重开不复活旧截止，不改写已提交申请及下游历史，也不自动恢复已取消或已归档申请。 |
| 撤回参与意向 | 首次公布前，某拟参与社团退出拟参与名单的操作；名单变化使既有确认失效，剩余拟参与社团必须重新确认。 | 首次公布后不再允许社团主动退出；紧急停用是另一种异常状态。 |
| 联合共享同意 | 申请人参加联合活动前对完整跨社团材料、评价和结论共享的明确确认；拒绝者不能参加联合活动。 | 与“服从联合调剂”是两个不同选择。 |
| 服从联合调剂 | 申请人是否允许未报名的参与社团向其发出加入邀请的选择，范围覆盖所有参与社团及其本次开放部门。 | 不影响参与社团按联合共享规则查看材料。 |
| 联合申请 | 每名申请人在一个联合活动中形成的独立强类型申请对象，独立保存表单版本、共享同意、状态、版本和归档历史。 | 不并入联合活动主状态，也不复用普通招新申请状态。 |
| 联合面试 | 联合活动中申请人只参加一次、供所有参与社团共同考察的面试。 | 各社团不拥有不同联合轮次；后续考察必须另建普通面试。 |
| 联合单次面试记录 | 每名联合申请人在一个联合活动中至多形成的一份独立强类型面试对象，独立保存共享排期、出勤、评价关联、状态、版本和归档结果；客观无效时由任一参与社团负责人或人事管理员单独作废，原尝试作为历史保留，并在同一业务对象内重新建立有效排期。 | 不为各参与社团分别复制，也不复用普通招新面试记录状态；作废补面不形成社团专属轮次或第二个联合面试业务对象。 |
| 面试作废待复核 | 联合面试作废后叠加在所有未因邀请接受而锁定的参与社团结论及未接受联合邀请上的正交标志；保留原对象、内容和版本，暂时禁止接受并冻结邀请剩余有效时长，直至补面完成并由各社团分别复核自己的结论。 | 不表示结论被删除、改判或邀请被拒绝；待复核邀请仍可由申请人拒绝或发出社团撤回；保留结论时继续冻结前剩余时长，修改重发时使用新完整有效期；不适用于已接受权益。 |
| 邀请已过期 | 邀请在有效期届满前未被接受、拒绝或撤回，由系统截止任务形成的终态；业务上与拒绝一样禁止继续接受并允许按规则重新发出。 | 不等于申请人主动“已拒绝”；通知、审计和统计必须标明系统到期来源。 |
| 参与社团结论 | 每个“联合活动＋申请人＋参与社团”独立形成的通过、调剂和录取结论对象；邀请接受后对应结论锁定。 | 不并入联合活动或联合申请主状态；一个社团不能修改另一社团结论。 |
| 加入邀请 | 未报名社团在申请人服从联合调剂时发出的社团加入要约。 | 已报名社团发出的是录取邀请；两者接受后均进入成员生效流程。 |
| 联合邀请接受后关系变更 | 联合邀请一旦接受即保留为已接受历史；其后仅能通过部门关系移除、成员移除或成员退出改变当前关系。 | 不存在联合活动内的“已接受后改为不录取”；某社团的成员流程不得影响其他参与社团。 |
| 第一份邀请 | 联合活动中任一参与社团向任一申请人成功发出的第一份录取邀请或加入邀请。 | 不需要全体社团批准；参与名单早已在首次公布时锁定，本事件进一步禁止取消整个活动。 |
| 邀请阶段 | 第一份邀请发出后至活动结束的阶段；整个联合活动不能再取消。 | 不等于所有社团都已发出邀请；新增和主动退出自首次公布后即始终禁止。 |
| 正常结束 | 所有邀请进入终态后，由全部参与社团在确认期限内一致确认结束。 | 任一社团单独确认不能结束。 |
| 强制结束 | 超级管理员用于处理未按期确认或仍有未处理邀请的特权操作；未处理邀请立即失效，已接受成员保留。 | 不等于撤销已接受录取。 |

## 七、成员生命周期

| 术语 | 统一定义 | 不得混同 |
|---|---|---|
| 常规入社邀请 | 社团负责人或人事管理员在招新、联合活动和职位任命之外，向尚非本社团当前成员的有效平台用户发出的入社要约；可附带至多一个初始部门，必须由对象本人按完整内容整体接受或拒绝。 | 不是普通招新录取邀请、联合活动加入邀请，也不是非成员职位任命中的直接组合操作。 |
| 初始部门 | 常规入社邀请中由发送人可选指定的至多一个部门；如指定，它与社团成员关系作为同一接受包生效。 | 不是多个部门选项；对象不能在接受时改选，也不能只接受社团关系。 |
| 成员业务生效时间 | 申请人接受有效邀请的时间；Casdoor 写入确认前权限仍处于生效处理中。 | 不等于 Casdoor 回读成功时间。 |
| 成员身份生效处理中 | 邀请已接受，但相应 Casdoor Group 尚未回读确认的过渡状态；不得提前开放成员权限。普通招新活动取消时，该接受事实和同步意图保留，任务脱离活动并按成员/关系流程继续执行。 | 不是邀请待处理；活动取消不能把它改成邀请失效或自动补偿为非成员。 |
| 成员经历段 | 一段从实际加入到实际退出的本地历史；退出后重新加入创建新经历段。 | 不覆盖此前经历。 |
| 任期 | 一次独立职位任命的计划与实际开始、结束记录。 | 计划结束不会自动卸任。 |
| 调岗 | 在保持社团成员身份的前提下改变部门或职位关系的正式业务操作。 | 不等于重新参加本社团招新。 |
| 兼任 | 同一用户同时属于多个部门或多个职位 Group 的合法当前状态。 | 后续任命不会自动覆盖既有职位。 |
| 辞职 | 干部主动申请结束一个或多个职位，经该职位上级批准后生效；通常保留成员和部门关系。 | 不等于退出社团。 |
| 免职 | 有权管理者主动结束某人的职位；是否保留部门和成员关系按明确操作范围处理。 | 不得借改历史任期静默免职。 |
| 成员退出 | 成员主动申请离开社团，经负责人或人事管理员批准后移除该社团下部门、职位和访问权。 | 不等于干部辞职。 |
| 成员移除 | 有权管理员发起的非自愿离社流程，必须说明原因、通知并保留历史。 | 不等于正式数据删除。 |
| 换届批次 | 对同一社团的一组续任、新任、卸任和空缺安排进行预览、确认并执行的业务对象。 | 系统切换学年不会自动执行换届。 |
| 历史成员状态 | 本地对已结束成员经历的展示结果。 | 当前产品不自动写入 Casdoor 校友标签。 |

## 八、动态表单与文件

| 术语 | 统一定义 | 不得混同 |
|---|---|---|
| 固定业务骨架 | 用户、学号、业务对象、作用域、状态、审批、任期、邀请、权限、时间等必须由系统强类型建模的字段集合。 | 不能放进任意自定义 JSON 代替。 |
| 动态字段 | 管理员在有权表单范围内配置的文本、数字、选择、日期、图片、文件等补充字段。 | 不能改变核心状态或授权含义。 |
| 表单定义 | 一类业务表单的字段、校验、显示条件和权限设计。 | 不等于某个用户的提交。 |
| 表单版本 | 发布后不可覆盖的表单定义快照；修改必须形成新版本。已停用版本不得直接重新启用，复用时只能以其为来源创建新草稿并按完整发布流程形成新版本编号。 | 回滚或复用都要发布新版本；不能删除中间历史、改变原停用状态或静默改绑既有提交和活动快照。 |
| 草稿 | 尚未正式提交、可继续编辑且不进入正式筛选的用户内容。 | 不是正式业务记录。 |
| 表单提交 | 用户在特定表单版本下正式提交的一组答案及当时自动带入资料快照。 | 当前个人资料后续变化不会改写旧提交。 |
| 提交修订 | 业务允许编辑时，对正式提交进行的新版提交；旧修订继续可还原。 | 不覆盖原答案和原附件。 |
| 原提交者回看下限 | 原提交者本人实际填写并正式提交的动态答案和附件，在其仍有权访问所属业务记录且数据未被正式删除时必须继续对本人可见。 | 内部评分、评语和管理字段应存入独立评价或管理记录，不能混入申请人填写字段后在提交后对本人隐藏。 |
| 自动带入字段 | 从平台批准的基本资料目录读取、在表单内只读展示并随提交保存快照的字段。 | 表单不能通过这些字段直接回写个人资料。 |
| 附件 | 与草稿或正式提交版本绑定、经过类型与恶意内容检查并按当前权限访问的文件对象。 | 不提供永久公开链接。 |
| 文件引用 | 附件与草稿、提交修订、纠错或其他业务记录之间的有效关联。 | 有有效引用的文件不得被孤儿清理删除。 |

## 九、通知、审计与数据处理

| 术语 | 统一定义 | 不得混同 |
|---|---|---|
| 权益事件 | 直接影响学生报名机会、面试安排、结论、邀请、成员、部门、职位、审批或资料有效性的变化。 | 不能静默发生，必须生成通知事实。 |
| 通知事实 | 与业务状态在同一可靠边界保存的事件、收件人快照和必要摘要，是通知存在的权威记录。 | 不等于某封邮件已经成功发送。 |
| 站内信 | 通知事实在系统内的默认权威展示渠道；紧急关闭时仍保留事实并在恢复后补投。 | 邮件不能替代通知事实。 |
| 邮件任务 | 根据通知事实、模板、用户偏好、验证邮箱和社团发信配置产生的可选附加投递。 | 邮件失败不回滚已成功业务。 |
| 纯内部管理通知 | 仅服务于管理员待审批、角色交接、内部协作、批量结果、普通配置变更或普通后台任务结果，不直接告知学生权益变化的通知副本。 | v1.0 默认只发站内信；不等同于学生权益通知、联合共同邮件或安全通知；平台运维异常不构成邮件例外。 |
| 事实纠错 | 普通编辑关闭后，对客观错误追加原值、新值、原因、证据、处理人和时间的特殊流程。 | 不用于表达对主观评价不满，也不能直接改当前 Casdoor 权限。 |
| 纠错申请撤回 | 纠错申请的原提交人在批准或驳回成功提交前，将“待处理”或“逾期待处理”申请终结为“已撤回”的本人命令。 | 处理人查看、领取、开始调查或申请逾期均不取消撤回权；处理角色不得代撤，已批准或已驳回后不得撤回。 |
| 审计 | 对关键成功和失败操作记录操作者、当时角色、作用域、时间、对象、差异、结果和请求编号的不可由应用管理员改删的证据。 | 不得记录密码、令牌、验证码、邮件密钥或附件正文。 |
| 活动归档 | 普通招新或联合活动完成或取消后自动进入长期只读，并按当前有效角色重新鉴权的状态。 | 不需要人工归档操作，也不等于归档社团。 |
| 长期保留 | 正式业务记录没有普通自动到期删除规则，持续保存直到超级管理员执行正式删除。 | 不意味着所有角色永久拥有访问权。 |
| 正式删除 | 超级管理员预览范围、填写原因并二次确认后，从本系统正式业务数据及在线副本移除内容，同时保留不含被删正文的最小删除审计。 | 不删除 Casdoor 账号或 Group，也无法召回系统外副本。 |
| 匿名化 | 移除身份但保留匿名业务记录的能力；当前明确不提供。 | 不得用纠错或删除接口变相实现。 |
| 业务数据导入 | 面向业务管理员批量创建或修改成员、历史、招新或表单记录的能力；当前明确不提供。 | 数据库迁移、灾难恢复和虚构示例初始化属于运维，不是业务导入。 |
| 导出 | 根据操作者当前记录级和字段级权限生成带来源、审计和有效期的数据副本。 | 导出不是访问授权的扩大，也不是永久下载权。 |

## 十、配置、时间与开工门

| 术语 | 统一定义 | 不得混同 |
|---|---|---|
| 平台默认值 | 超级管理员设置的全平台策略基线及允许范围。 | 默认值修改不追溯改变已发布活动。 |
| 社团默认值 | 负责人或人事管理员在平台允许范围内设置的本社团新业务默认配置。 | 不是某个已发布活动的当前配置。 |
| 活动配置快照 | 普通招新或联合活动发布、成立时固定的期限、模板、表单和策略版本。 | 平台或社团默认值变化不能静默覆盖快照。 |
| 学年 | 系统根据平台时区和年度分界日自动生成、命名并切换的时间维度。 | 学年切换不自动换届、卸任或结束活动。 |
| 社团届次 | 社团自己维护并关联某个系统学年的届次名称。 | 不由系统按学年自动创建。 |
| 最近 10 分钟重新认证 | 高风险命令提交前，由 Casdoor 提供可验证的最近认证时间，证明当前管理员在最近 10 分钟内重新完成了受信任认证。 | 不等于普通会话仍有效、页面二次确认或实时权限检查；重新认证不能替代当前 Group、对象、作用域、业务状态和命令版本校验。 |
| 确定性严重安全事件 | 由受信任服务端证据可信确认、无需依赖访问量推测即可认定的严重认证、会话或授权安全事件。 | 不等于单次普通失败、客户端自报信息或尚未聚合的行为异常；只有可信度满足已发布安全规则时才能立即自动限制。 |
| 行为异常安全信号 | 批量遍历、异常频率、大量附件访问等必须结合时间窗、身份、会话、目标范围、当前任务和正常业务规模综合判断的风险迹象。 | 单一信号不是已确认攻击，也不能仅因正常招新工作量较大自动限制。 |
| 真实学生数据处理状态 | 平台级治理状态，区分尚未允许、正在允许和暂停处理真实学生数据；首次启用、暂停和恢复均只能由当前有效超级管理员在最近 10 分钟重新认证、实时确认当前 Group 并明确确认后执行。 | 不是导入数据、启用某个学生账号、创建成员关系或授予额外权限。 |
| 真实数据技术启用门 | 使用真实学生数据前，必须完成实际 Casdoor、授权隔离、通知、文件安全、备份恢复等能力验证的门槛。 | 不再建设额外校外治理审批流。 |
| 文档开工门 | PRD、SRS、架构、接口、数据、安全、测试追踪和开发团队签署全部完成后，允许开始第一批正式验证代码的状态。 | 不代表技术风险已经通过代码验证。 |
| Mandatory First-Code Validation | 正式编码后的首个受限里程碑，只验证 Casdoor、普通/联合授权内核、动态表单/文件及事务一致性。 | 验证失败时不得继续堆叠业务功能。 |

## 十一、禁止使用的模糊表达

后续文档、接口和验收场景中，以下表达必须被替换：

- “管理员可以操作” → 写明超级管理员、社团负责人、人事管理员或部门负责人。
- “角色同步” → 写明 Casdoor Group 当前关系同步，或本地权限模板计算。
- “录取成功” → 区分邀请已发出、邀请已接受、成员生效处理中和 Casdoor 已确认。
- “活动结束” → 区分普通招新完成/取消/强制完成，或联合活动正常结束/强制结束。
- “删除数据” → 区分草稿清理、附件替换、正式删除和当前不提供的匿名化。
- “归档” → 仅表示业务活动自动只读归档，不得表示社团停用或解除接入。
- “共享给社团” → 写明普通社团域内共享，或联合协作域内向首次公布时锁定的哪些参与社团和角色共享。
- “通知用户” → 写明通知事实、站内信及是否产生可选邮件任务。
- “从 Casdoor 获取成员资料” → 区分固定个人字段与社团、部门、职位 Group 当前关系。
- “批次” → 在首次出现时明确是普通招新活动、换届批次、确认轮次还是其他对象。
