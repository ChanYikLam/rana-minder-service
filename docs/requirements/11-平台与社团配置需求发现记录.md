# RanaMinder 平台与社团配置需求发现记录

> 状态：产品行为已内部冻结  
> 日期：2026-07-28

## 已确认的前置约束

1. 社团必须从既有 Casdoor Group 接入，本系统不提供新建或归档社团功能。
2. 社团接入、启用、停用、解绑和重新绑定仅由超级管理员操作。
3. 动态表单、通知模板、发信账号和业务期限均已存在可配置需求。
4. 配置不能绕过业务状态机、权限边界、审计或权益通知要求。

## 本模块待冻结范围

- 社团接入信息与本地展示资料；
- 学年、届次和默认时间上下文；
- 平台默认值、允许范围、社团覆盖和活动快照；
- 动态表单模板、通知模板和发信配置的责任边界；
- 配置版本、预览、回滚、生效和新社团初始配置。

## 2026-07-27：社团展示资料

1. Casdoor Group ID、绑定关系和原始 Group 名称是接入信息，只能由超级管理员管理。
2. 本系统保存社团展示名称、Logo、简介、联系方式和招新说明等展示资料。
3. 展示名称可以不同于 Casdoor Group 名称，但超级管理员后台始终显示二者对应关系。
4. 社团负责人和人事管理员可以修改本社团展示资料，超级管理员可以代为修改。
5. 修改立即生效且无需审批，但保留修改历史和审计。
6. 展示资料修改不改变 Casdoor Group、成员关系或权限。

## 2026-07-27：平台默认值、社团覆盖与活动快照

1. 超级管理员为邀请有效期、确认期限、资料补充期限和导出文件期限等策略配置平台默认值及允许范围。
2. 社团负责人和人事管理员可以在允许范围内设置本社团默认值。
3. 创建具体招新或联合活动时，可以再次设置该活动的值。
4. 活动发布时形成配置快照；后续平台或社团默认值变化不影响已经发布的活动。
5. 已发布活动只能在业务状态允许时单独修改配置。
6. 修改影响学生选择时间、邀请期限或其他权益时必须通知受影响学生。
7. 所有配置修改均显示作用域和生效时间，并记录旧值、新值和修改人。

## 2026-07-27：系统自动维护学年、社团管理届次

1. 学年不由超级管理员逐年手工创建，而由系统自动维护。
2. 平台初始化一次时区和每年的学年分界日；系统据此自动生成学年名称、起止日期并切换当前学年。
3. 新建招新活动、任期、换届和统计默认使用当前学年；获授权用户可以为补录或提前筹备选择其他已生成学年。
4. 社团负责人或人事管理员维护本社团届次名称，并将届次关联到一个系统学年。
5. 系统切换当前学年不会自动创建社团届次、结束招新、执行换届、卸任干部或改变成员关系。
6. 超级管理员只在校历变化时调整未来学年的分界规则，修改必须审计。
7. 已经被正式业务引用的历史学年不得因规则变化被自动重写。

## 当前待确认

无行为层面的待确认项。实际 Casdoor 字段、Claims、管理 API 和服务账号权限仍须在首批正式代码中验证。

## 2026-07-28：Casdoor 字段映射配置

1. 只有超级管理员可以配置本系统字段与 Casdoor 字段的映射。
2. 学号/账号和姓名是必需映射，真实数据启用后不得随意删除。
3. 学院、年级、邮箱和手机号等只能从固定同步白名单中映射，动态表单字段不能映射到 Casdoor。
4. 修改前测试实际 Casdoor 接口，并预览受影响字段和用户数量。
5. 映射不存在、类型不兼容或可能造成批量数据丢失时禁止发布。
6. 映射只决定外部字段位置，不改变字段只读、可编辑、双向同步或姓名更正规则。
7. 新映射发布后执行一次受控对账，冲突沿用身份模块规则。

## 2026-07-28：配置版本、预览与回滚

1. 表单模板、通知模板、权限模板、字段映射和平台策略使用“草稿—预览/测试—发布”流程。
2. 已发布版本不可覆盖；修改创建新版本。
3. 回滚通过从旧版本创建一个新的发布版本实现，不删除中间版本和历史。
4. 权限模板、字段映射等高风险配置发布前展示影响对象并二次确认。
5. 配置变化影响学生权益或管理员权限时必须通知。
6. 已发布活动保留自身配置快照，不受模板和默认值回滚影响。
7. 社团展示资料立即生效，不要求完整发布流程，但仍保留历史。
8. 邮件密钥不能通过版本回滚恢复旧明文，只能重新填写或轮换。

## 2026-07-28：新社团接入向导

1. 只有超级管理员可以执行新社团接入向导。
2. 向导依次选择社团 Casdoor Group、填写展示资料、选择部门和职位 Group、映射权限模板。
3. 启用前必须存在负责人职位 Group，且其中至少有一名有效负责人。
4. 新社团继承平台默认策略、公共表单模板和默认通知模板，继承后形成独立配置。
5. 邮件密钥可以稍后配置；缺失时社团只能发送站内信，不阻止启用。
6. 启用前检查 Group 重复绑定、层级关系、负责人连续性和权限越界。
7. 任一步骤失败时保持未启用，不向普通用户开放，也不产生部分生效的权限。
8. 可以提供虚构示例模板，但不创建或导入真实成员数据。

## 2026-07-28：社团展示资料可见范围

1. 未登录用户可查看社团展示名称、Logo、简介和公开招新说明。
2. 有效登录学生还可查看社团主动公开的联系方式。
3. 本社团成员可查看成员范围联系方式和内部说明。
4. 每个联系方式字段必须选择“已登录学生可见”或“仅本社团成员可见”。
5. 个人联系方式不得默认向未登录用户公开。
6. 公开展示页不得包含成员名单、部门关系、职位人员或其他业务数据。

## 本模块内部冻结结论

社团展示资料、系统自动学年、社团届次、平台与社团默认值、活动配置快照、Casdoor 字段映射、配置版本和新社团接入向导产品行为已经内部冻结。表单模板、通知模板、邮件密钥和权限模板沿用对应已冻结模块。实际 Casdoor 字段、Claims、管理 API、服务账号权限和配置发布的缓存一致性进入首批正式代码验证、SRS、架构与接口契约。
