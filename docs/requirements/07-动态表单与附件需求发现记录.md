# RanaMinder 动态表单、附件与资料版本需求发现记录

> 状态：产品行为已内部冻结  
> 日期：2026-07-27

## 已确认的前置约束

1. 所有提交到系统的业务表单都必须支持可配置字段，不能把业务问项写死在页面或数据表中。
2. “动态”不包括身份、组织关系、权限、状态、审批、邀请、任期和审计等核心系统字段；这些数据必须保持强类型和明确约束。
3. 平台固定资料同步白名单与 Casdoor 双向同步；普通自定义表单答案仅保存在本系统。
4. 已发布报名表不可直接覆盖，旧提交需要按原版本长期还原。
5. 表单和附件访问始终服从普通社团隔离域、联合活动协作域和当前有效角色，不能依赖永久直链。

## 本模块待冻结范围

- 当前范围内表单类别、固定业务骨架和动态字段边界；
- 设计、发布、停用、复制和版本迁移权限；
- 字段类型、条件规则、校验、对象引用和字段级权限；
- 用户基本信息自动带入、快照、编辑和回写；
- 草稿、提交、修订、补充窗口和旧版本还原；
- 图片与文件的上传、扫描、预览、替换、删除和下载；
- 新增必填字段、用途变化、告知同意和生效范围；
- 导出、纠错、归档、保留与删除。

## 2026-07-27：适用范围、设计权限、字段能力与自动带入

### 固定业务骨架与动态字段

1. 平台资料、普通和联合招新报名、面试评价、成员相关申请等当前范围内的用户提交表单均采用动态字段；课程模块已由用户明确取消，不再包含课程报名与反馈。
2. 每类业务仍有固定骨架，以保存提交人、业务对象、作用域、状态、审批、时间、版本和权限等系统事实。
3. 动态字段不能替代用户、学号、社团、部门、职位、状态、任期、邀请或权限字段，也不能改变工作流含义。

### 表单设计与发布权限

1. 超级管理员管理平台公共资料表和平台模板。
2. 社团负责人和人事管理员管理本社团报名、成员申请及社团级评价表。
3. 部门负责人仅管理本部门业务中的评价、反馈等部门表单。
4. 普通成员和面试官只能填写被分配的表单，不能设计或发布。
5. 草稿可修改；发布后版本不可覆盖，后续变化发布新版本；停用不删除历史定义、提交和附件。

### 首批字段与规则

1. 支持单行文本、长文本、数字、日期、日期时间、单选、多选、下拉、是/否、评分、照片、视频和普通文件。
2. 支持权限受控的人员、社团、部门等系统对象选择。
3. 支持可重复填写的经历列表或子表。
4. 支持必填、默认值、提示语、长度、数值范围和正则格式校验。
5. 支持依据同一表单前序答案进行条件显示和条件必填。
6. 不允许表单设计者注入 JavaScript 等任意代码；条件和校验使用系统提供的安全配置能力，并在服务端再次执行。

### 自动带入用户基本信息

1. 表单支持从当前用户基本资料自动带入信息。
2. 可选来源必须来自平台批准的基本资料字段目录，不能自行读取任意 Casdoor Claim 或未授权业务数据。
3. 不能通过对象选择或自动带入能力读取其他用户无权公开的资料。
4. 自动带入字段在表单中只读，不能作为单次答案修改，也不通过表单回写个人资料；用户必须到个人资料页面修改，姓名仍走更正申请，学号不可修改。
5. 草稿每次打开时读取最新个人资料；每次正式提交或重新提交保存当时的个人资料快照。
6. 后续个人资料变更不改写历史提交；每个提交修订可还原其提交时的快照。

## 2026-07-27：版本迁移、字段权限与条件隐藏

### 表单版本迁移

1. 新申请和新提交默认使用最新已发布版本。
2. 旧草稿再次打开时迁移到最新版本。
3. 已提交表单继续绑定原版本；只有业务规则允许再次编辑时，才迁移到最新版本并形成新的提交修订。
4. 相同稳定字段标识的旧答案自动带入；新增必填字段必须补填。
5. 字段类型发生不兼容变化时必须创建新字段，不能强制转换旧答案。
6. 删除字段不再出现在新版本，但旧表单版本和旧提交继续完整保留。
7. 表单管理员不能直接替用户修改已提交答案；只能开放补充窗口或走事实纠错流程。

### 字段级权限

1. 字段可按提交者、面试官或评价人、部门负责人、社团负责人、人事管理员和超级管理员等角色配置查看权限。
2. 字段权限只能进一步收紧对象级权限，不能让原本无权访问该申请、成员或联合活动的人获得数据。
3. 字段编辑权限还必须服从业务状态、表单提交者和评价作者等既有规则。
4. 人员、社团、部门等系统对象选项按当前业务范围过滤，并在提交时由服务端重新校验。

### 条件隐藏答案

1. 当前条件不满足而隐藏的字段不保存到本次提交，防止用户提交自己已经不可见的旧值。
2. 已经存在于此前正式提交版本中的答案继续留在原修订中，不因新版本条件变化而删除。
3. 条件显示和必填规则必须在服务端与客户端使用同一规则结果校验，不能只依赖页面隐藏。

## 2026-07-27：上传安全、附件访问与文件版本

### 上传类别、限制与安全检查

1. 允许格式、真实文件类型白名单和单文件大小由平台统一配置，社团及表单管理员不能自行放宽。
2. 表单管理员只需选择照片、视频、普通文件等平台提供的上传类别，并可配置该字段最多允许上传几个文件；数量不得突破平台硬上限。
3. 系统按真实文件类型校验，不能只信任文件名扩展名；默认禁止可执行文件、脚本及高风险压缩文件。
4. 图片生成安全预览图，并移除定位信息等不必要元数据。
5. 文件必须通过安全扫描后才能正式提交、预览或下载。
6. 扫描服务暂时不可用时允许保存草稿，但不能正式提交，页面必须显示扫描等待或失败状态。

### 查看、下载与防泄露

1. 附件每次访问都重新检查当前角色、社团、部门、任务、联合活动关系和业务状态。
2. 不提供永久公开链接，只生成短时有效的访问地址。
3. 安全格式可在线预览，其他平台允许的格式只能下载；字段可以进一步限制预览或下载，但不能扩大既有权限。
4. 招新报名和面试材料的预览、下载默认添加查看者和时间水印，原文件保持不变。
5. 下载及敏感附件预览记录审计日志。
6. 提交者在仍有权查看对应历史提交时，可以查看和下载自己的附件。

### 替换、删除与历史版本

1. 草稿中的文件可以自由替换或删除。
2. 已提交表单仅在业务允许编辑时可替换附件；替换产生新文件版本，旧文件继续绑定旧提交修订。
3. 表单锁定后不能普通替换或删除附件，只能进入事实纠错流程。
4. 表单设计者停用或删除文件字段不会删除已有附件。
5. 草稿文件删除后对用户立即不可见，系统稍后执行安全物理清理。
6. 正式提交过的附件不允许普通用户物理删除；当前不提供匿名化，正式删除只能按超级管理员删除流程执行。

## 2026-07-27：模板复用、新增必填字段与数据生命周期

### 表单模板复用

1. 社团负责人和人事管理员可以复制本社团已有表单，复制结果为独立草稿。
2. 超级管理员维护平台公共模板，社团可从公共模板创建自己的独立表单。
3. 社团可申请将自有表单发布到平台模板库，由超级管理员审核后发布。
4. 模板和跨社团副本只包含结构、字段和校验规则，不包含任何提交数据、附件或内部人员信息。
5. 原表单中引用特定人员、部门等社团内部对象的选项在复制时清除，使用方必须重新配置。
6. 副本与原表单独立演进，任何一方的后续修改都不会自动同步到另一方。

### 新增必填字段与用途变化

1. 新版本新增必填字段直接适用于新提交和迁移后的草稿，不让既有正式提交自动失效。
2. 需要既有提交者补充时，管理员必须单独发出补充请求并设置明确期限。
3. 补充期间原提交保持原业务状态；超过期限后的影响由所属业务明确定义，表单引擎不能自行淘汰、拒绝或撤销权益。
4. 平台公共必填资料沿用生效日期和分范围写操作限制规则。
5. 新增敏感字段或改变资料用途时必须重新展示用途说明并取得确认。
6. 用户拒绝新增用途时不删除既有历史，但可能无法继续参与确实依赖该资料的新业务。

### 导出、纠错、归档和治理删除

1. 导出只包含操作者当前可查看的提交和字段，不能利用批量导出扩大权限。
2. 附件须单独选择导出，并继续受下载权限控制；导出记录操作人、时间和范围。
3. CSV、Excel 等表格导出必须防止公式注入。
4. 表单归档后普通编辑关闭，查看范围跟随所属业务的归档角色权限。
5. 事实纠错产生追加纠错记录或新修订，原答案、附件和审计继续保留。
6. 正式提交的保留规则跟随所属业务，不因停用表单、删除字段或删除模板而改变。
7. 当前产品不提供匿名化能力；正式数据删除仅由超级管理员按 AUD-007 至 AUD-009 的范围、预览、二次确认、传播和审计规则执行。

## 本模块内部冻结结论

动态表单的固定业务骨架、字段类型、条件规则、基本资料自动带入、版本迁移、字段权限、附件安全、访问授权、模板复用和数据生命周期产品行为已内部冻结。平台文件白名单、敏感字段目录、保留期限、治理删除、对象存储及扫描服务等实现与治理约束进入配置基线、数据治理、SRS 和架构决策，不再由业务开发临场决定。
