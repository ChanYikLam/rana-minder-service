# RanaMinder 成员生命周期、任期与换届需求发现记录

> 状态：产品行为已内部冻结  
> 日期：2026-07-27

## 已确认的前置约束

1. 当前社团、部门和职位关系以 Casdoor Group 为权威；本系统保存不可变历史事件。
2. 接受普通或联合录取后，成员业务生效时间为接受时间，Casdoor 回读确认前不开放权限。
3. 成员可以同时加入多个社团、多个部门和多个职位。
4. 合法社团成员可以暂时不属于任何部门。
5. 启用中的社团必须至少有一名负责人；最后负责人退出或离任必须同时指定继任者。
6. 每学年统一换届，负责人或人事管理员均可确认正式换届。
7. 干部允许中途辞去或被撤销职位，但职位离任不应自动等同于退出社团。
8. 退出社团时需要处理该社团下的全部部门、职位和访问权限，同时保留历史。

## 本模块待冻结范围

- 成员、部门成员、职位任期的状态与时间；
- 主动退出、被移除、干部辞职和免职；
- 调岗、转部门、兼任和解除兼任；
- 年度换届、批量操作和失败补偿；
- 校友、历史成员和重新加入；
- Casdoor 外部变化、纠错和历史时间线。

## 当前访谈起点

先区分社团成员身份、部门关系和职位任期，并确认主动退出与干部中途辞职的生效方式。

## 2026-07-27：成员状态、退出、辞职与随时任命

### 成员状态

1. 不设置独立的试用成员或预备成员当前身份。
2. 申请人和候选人只属于招新流程，接受录取并完成 Casdoor 生效后才成为正式成员。
3. 干部职位结束或部门调整不自动失去社团成员身份。
4. 离开社团后转为历史成员，当前 Group 关系移除但历史保留。

### 主动退出

1. 成员退出不是单方面立即生效，需要社团管理员批准。
2. 退出申请需要成员本人二次确认。
3. 批准后处理全部部门、职位和访问权限并通知相关人员。
4. 最后一名负责人必须先完成交接或由超级管理员紧急处置。
5. 具体哪些角色属于这里的“社团管理员”、如何驳回或撤回，下一轮确认。

### 干部中途辞职

1. 干部可以选择一个或多个职位辞职，并选择立即或未来生效时间。
2. 辞职原因可以不填写，但必须获得该职位上级批准。
3. 生效后只移除对应职位和权限，保留成员、部门和其他并行职位。
4. 最后一名负责人仍受交接连续性限制。
5. 各类职位的上级审批映射下一轮确认。

### 任意时间任命

1. 社团负责人和人事管理员可以在招新、换届之外的任意时刻发起职位任命。
2. 可选候选人来自学校级 Casdoor Organization，不限于某次招新名单。
3. 此规则尚未说明候选人是否必须已经是本社团成员，也未明确是否要改变此前已经确认的任命层级，因此必须在下一轮消除冲突。

## 2026-07-27：审批映射与非成员组合任命

### 成员主动退出审批

1. 任一社团负责人或人事管理员可以审批成员退出，部门负责人不能审批。
2. 待审批期间成员可以撤回申请。
3. 批准和驳回都必须通知成员，驳回必须填写原因。
4. 任何人不能审批自己的退出；最后一名负责人必须先交接。

### 干部辞职上级

1. 普通部门职位：本部门负责人、人事管理员或社团负责人审批。
2. 部门负责人：人事管理员或社团负责人审批。
3. 人事管理员：社团负责人审批。
4. 社团负责人：另一名现任负责人审批；没有其他负责人时进入正式交接，由人事确认继任者，或由超级管理员紧急处理。
5. 审批人不能审批自己的辞职。

### 任意时间组合任命

1. 任意时间任命不扩大既有任命层级，人事管理员仍不能任命社团负责人。
2. 候选人可以来自整个 Casdoor Organization。
3. 非本社团成员被任命时，系统将加入社团、加入职位所属部门和任命职位作为一次组合操作。
4. 操作者需要明确确认，操作完成后通知被任命人，不要求被任命人再次接受。

## 2026-07-27：主动移除、部门调动与任期

### 社团主动移除成员

1. 社团负责人或人事管理员可以将普通成员移出社团。
2. 部门负责人只能将普通成员移出自己负责的部门，不能直接终止其社团成员身份。
3. 部门负责人可由社团负责人或人事管理员移除；人事管理员只能由社团负责人移除；社团负责人由另一名现任负责人移除，紧急情况可由超级管理员处理。
4. 最后一名社团负责人不能直接被移除，必须先完成负责人交接。
5. 主动移除必须填写原因、二次确认、通知当事人并保留完整历史；任何人不能通过主动移除入口处理自己，自己离开应走退出或辞职流程。

### 部门加入、退出与调动

1. 社团负责人和人事管理员可以直接将成员加入或移出任意部门，无需成员接受，但必须通知成员。
2. 部门负责人只能直接管理本部门普通成员，不能改变其其他部门、职位或社团成员身份。
3. 成员可以申请加入或退出部门，由对应部门负责人、社团负责人或人事管理员审批。
4. 成员可以同时属于多个部门，也允许成为零部门成员。
5. 跨部门调动按一个原子业务操作处理：加入目标部门，并根据操作者的选择决定是否退出原部门；失败时不得只完成其中一半。

### 职位任期与部门关系历史

1. 每次任命建立独立任期，记录计划开始、计划结束、实际开始和实际结束时间。
2. 默认任期为当前学年，有权管理员可以调整，并可以立即生效或预约未来生效。
3. Casdoor 职位 Group 关系仅在任期实际开始或实际结束时变更。
4. 中途辞职或免职保留原计划任期，另记实际结束时间和原因。
5. 连任或下一学年继续任职创建新任期，不延长或覆盖上一条历史任期。
6. 部门成员关系保留加入和退出历史，但不强制设置年度任期。

### 负责人设置下限

1. 部门不要求一定设置部门负责人；没有负责人时，部门事务由社团负责人或人事管理员处理。
2. 启用中的社团必须至少有一名社团负责人，不能出现负责人空缺。

## 2026-07-27：年度换届、非自动卸任与历史成员

### 年度换届批次

1. 社团负责人或人事管理员均可创建、修改和确认换届方案，不强制共同审批，创建人可以自行确认。
2. 换届方案可以包括续任、新任、卸任及部门负责人空缺，并支持立即或预约生效。
3. 生效后的社团必须至少有一名负责人；人事管理员和各部门负责人允许空缺。
4. 执行时先新增并回读确认全部新任关系，再开始移除旧任关系。
5. 新任阶段发生失败时，撤回本批次已经成功的新任操作并保持旧任不变。
6. 新任已全部生效后，若旧任移除部分失败，不撤销新任；换届进入“部分异常”，失败旧任可能暂时继续持有权限，系统持续重试和对账，并通知社团负责人、人事管理员和超级管理员。
7. 换届异常未解决前，不允许再次发起会与该批次冲突的职位变更或换届操作。

### 计划结束时间不自动卸任

1. 任期到达计划结束时间时，不自动卸任，也不自动撤销 Casdoor Group 或系统权限。
2. 实际卸任只由换届生效、辞职审批生效或有权管理员主动免职触发。
3. 计划时间已经结束但没有实际卸任事件时，当前职位和权限继续有效。
4. 计划结束和实际结束分别保留，不能用计划时间覆盖真实职位状态。
5. 前台不展示“计划任期已结束”、逾期或到期状态；只要没有实际卸任，仍正常显示为在任。
6. 计划结束前可以按社团配置的提前天数提醒任职者、社团负责人和人事管理员；重复提醒频率可配置或关闭。

### 历史成员与重新加入

1. 成员退出或被移出社团后成为历史成员，不再拥有该社团访问权限。
2. 首期不单独建立“校友”身份，也不根据年级自动推断毕业；需要时可通过自定义标签表达。
3. 历史成员重新加入时创建新的成员经历，不恢复旧部门、旧职位和旧权限。
4. 新旧经历关联同一学生账号，每段入社和离社经历独立保存并可在时间线中还原。

## 2026-07-27：审批逾期、Casdoor 外部变更与历史纠错

### 退出与辞职申请逾期

1. 退出和辞职申请均不自动批准或自动驳回。
2. 超过可配置处理期限后，审批任务标记为逾期并提醒审批人与申请人，成员和职位当前状态不变。
3. 申请人在审批完成前可以撤回；撤回与审批并发时只能有一个操作成功。
4. 辞职已批准但预约未来生效时，申请人不能单方面撤销，必须由原审批人或其他具备该职位审批权的人同意取消。
5. 取消批准、调整生效时间等变化必须通知当事人并保留完整历史。

### Casdoor 外部直接变更

1. Casdoor 直接添加或移除成员、部门、职位 Group 时，当前状态以 Casdoor 为准，本系统不自动改回。
2. 本系统为每次变化追加“Casdoor 外部变更”历史事件；能够获取可靠上游时间时使用该时间，否则使用检测时间并标记原始生效时间未知。
3. 外部变化造成零社团负责人、孤立部门职位等非法状态时，本地权限立即按最小权限收敛，社团进入高优先级治理异常。
4. 治理异常期间只允许负责人补位、关系修复或超级管理员停用等修复操作，不能继续普通高权限业务变更。

### 历史纠错与禁止重放

1. 历史记录错误通过追加纠错记录修正，原始事件及旧值继续保留。
2. 仅修改历史展示不能改变当前权限或 Casdoor 关系。
3. 需要改变当前关系时，必须发起正式的 Casdoor 关系变更并按正常同步规则确认。
4. 不提供“一键按历史重放全部关系”，防止错误恢复已经离任人员的成员或管理权限。

## 本模块内部冻结结论

成员、部门关系、职位任期、主动退出、主动移除、辞职、免职、年度换届、历史成员、重新加入及 Casdoor 外部关系变化的产品行为已经内部冻结。提醒投递、纠错角色、异常允许操作集、Casdoor 批量写入幂等与补偿等跨模块约束，分别进入通知、纠错、SRS 和接口契约继续细化，不再由开发者临场决定业务行为。
