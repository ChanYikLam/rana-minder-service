# RanaMinder 站内信与权益通知需求发现记录

> 状态：产品行为已内部冻结  
> 日期：2026-07-27

## 已确认的前置约束

1. 所有影响学生权益的变化都必须形成通知事实记录，不能静默发生。
2. 正常情况下站内信是默认权威展示渠道；超级管理员可以在紧急情况下关闭站内信功能。
3. 邮件是可选附加渠道；录取结果等事件可以选择同时发邮件，但并非必须。
4. 通知不能扩大业务访问权限，通知链接打开时必须重新鉴权。
5. 通知投递和重试不能导致录取、任命、撤销等原业务重复执行。

## 本模块待冻结范围

- 通知事件目录、可启用邮件的事件目录和收件人快照；
- 站内信、邮件及未来其他渠道的关系；
- 通知内容、模板、敏感信息和业务跳转；
- 已读、未读、已处理、隐藏和过期状态；
- 业务事务、通知记录、投递队列和一致性；
- 重复事件去重、失败重试、永久失败告警和人工补发；
- 发送、投递、退信、已读等状态的含义和审计。

## 2026-07-27：权威渠道、收件人、站内信与重要邮件

### 通知与业务一致性

1. 权益业务变更与待发送通知记录必须在同一业务事务中保存。
2. 通知记录无法保存时，原业务操作整体失败并回滚。
3. 通知记录成功保存后，后续界面投递或邮件暂时失败不回滚已经生效的业务。
4. 系统持续重试失败投递并允许人工补发，补发只重发通知，不能重复执行原业务操作。
5. 收件人名单在业务事件发生时形成快照，后续人员换届不改变历史收件人。
6. 超级管理员紧急关闭站内信时，通知事实仍必须保存；关闭期间如何展示和恢复补投下一轮确认。

### 权益事件与最少内容

1. 直接影响学生权益的事件必须通知学生本人。
2. 管理员收件人按具体事件选择负责人、人事、部门负责人或超级管理员，不能无差别广播。
3. 事件目录至少覆盖报名补充、面试排期、结论、邀请、成员加入/退出/移除、部门职位、审批、联合活动、强制结束、资料同步失败和权益纠错。
4. 通知只携带理解事件所需的最少信息，不复制完整报名表、内部评价、联系方式或附件。
5. 通知内业务链接每次打开都重新鉴权；收到过通知不等于永久拥有目标数据访问权。

### 站内信能力

1. 支持已读、未读、全部标记已读、类型筛选和跳转业务页面。
2. 权益通知不能被用户物理删除，但可以归入已处理或隐藏列表。
3. 有期限的通知显示当前可处理、已处理、已撤回或已过期状态；过期后保留历史。
4. 同一逻辑事件的重复投递只对应一条站内信。
5. 用户可长期查看与自己直接相关的安全摘要，内部详情继续按当前权限实时鉴权。

### 可选邮件通知

1. 邮件不是强制渠道，而是可以按规则选择启用的附加渠道；允许使用邮件的通知默认开启邮件。
2. 录取结果是允许选择同时发送邮件的明确场景。
3. 未选择邮件时仍必须创建站内信；选择邮件时在站内信之外创建独立邮件投递任务。
4. 邮件不能替代站内信；站内信仍是系统内的权威通知记录。
5. 由谁可以关闭默认邮件、配置粒度、邮件内容和失败处置下一轮继续确认。

### 邮箱验证与社团发信密钥

1. 用户邮箱新增验证要求；手机号仍不需要短信验证码。
2. 首次填写邮箱后立即发送验证邮件；验证前只能浏览、维护个人资料、重发验证邮件和退出登录，不能进行其他业务写操作。
3. 修改已验证邮箱时保留旧邮箱为当前有效值，新邮箱验证成功后才替换并同步；失败或未完成不改变旧邮箱。
4. 验证链接24小时有效，重发需要频率限制；验证邮件使用超级管理员配置的平台级发信账号。
5. 每个社团必须配置自己的邮箱发信密钥，不能借用其他社团密钥；没有有效配置时只能发站内信。
6. 社团负责人或超级管理员任一方均可单独配置该社团账号，不要求共同确认；人事管理员和部门负责人无权查看或修改。
7. 密钥不明文回显，只能重新填写或轮换；新配置必须通过测试邮件后启用，所有配置变化审计并通知负责人。
8. 密钥失效时暂停邮件渠道并通知负责人和超管，不影响站内信和业务。

### 联合活动的发信账号

1. 单一社团独立作出的录取、邀请、撤回等通知使用该社团自己的发信账号。
2. 联合排期、参与社团变化、共同结束等事件使用平台级发信账号；超级管理员的强制结束也使用平台账号。
3. 社团没有密钥时，其独立事件只发站内信，不能借用其他参与社团密钥。
4. 平台账号不可用时共同事件只发站内信，不阻止联合活动操作。

## 2026-07-27：站内信紧急开关、邮件内容与自定义模板

### 站内信紧急关闭

1. 站内信在正常情况下默认开启。
2. 超级管理员可按全平台或指定社团紧急关闭站内信。
3. 关闭必须填写原因、二次确认、设置预计恢复时间并写入特权审计。
4. 关闭期间用户不能进入对应站内信页面或实时看到新消息，但权益事件仍保存通知事实和收件人快照，状态标记为暂停投递。
5. 权益业务可继续，默认邮件渠道仍按配置尝试发送；页面必须显示通知服务暂停状态。
6. 恢复后按原事件时间补投暂停期间通知，不重复产生业务事件。
7. 超过预计恢复时间仍未开启时，系统持续提醒超级管理员。

### 邮件内容和失败处理

1. 邮件可直接说明收件学生本人的录取、未录取、邀请、面试时间、职位变化或审批结果等必要信息。
2. 邮件不得包含内部评分、评语、非公开原因、完整报名表、附件、其他学生数据或后台信息。
3. 邮件链接只跳转正常登录页面，不包含免登录令牌。
4. 邮件失败不回滚业务；临时失败自动重试。
5. 明确退信或连续失败24小时后停止重试，通过站内信提示用户并通知相应管理员。
6. 邮箱变更后允许重发到当前已验证邮箱，旧投递记录继续保留。

### 默认模板与社团 HTML 模板

1. 超级管理员维护平台默认通知模板。
2. 社团负责人、人事管理员、部门负责人等各级管理员，可在自身有权管理的业务范围内基于默认模板修改文字信息。
3. 社团负责人或人事管理员可以上传并直接启用本社团自定义 HTML 邮件模板，无需超级管理员审核。
4. 模板修改只影响后续通知；已经发送的通知保留发送时的模板版本和实际内容。
5. HTML 允许常见排版标签和受限行内样式，禁止脚本、表单、iframe、自动跳转、外部 JavaScript/CSS、可执行内容和危险协议。
6. 允许使用外部图片，不限制为平台托管资源；由此产生的第三方跟踪和隐私风险进入治理清单。
7. 普通链接只允许 HTTPS，业务操作按钮只能链接本系统；固定变量白名单自动转义，不能读取任意报名表、评语或未授权字段。
8. 模板必须支持预览、测试邮件、版本保存和回滚。

### 邮件默认开启、关闭和用户偏好

1. 所有允许使用邮件的学生权益通知默认开启邮件。
2. 社团负责人和人事管理员可按活动或通知类型关闭本社团邮件，也可在正式发布结果或邀请时取消本次可选邮件；部门负责人无权发布普通招新结果或邀请，因此不能触发或单独控制这类邮件。
3. 人工发布时有权操作者可取消本次邮件，自动通知使用活动配置；超级管理员可统一停用某类邮件。
4. 学生可以关闭普通业务邮件，但不能关闭邮箱验证、邮箱变更和安全通知。
5. 未验证邮箱、用户关闭普通邮件或社团没有有效发信密钥时，只保存通知事实并按可用状态投递站内信。
6. 自定义模板未选择、失效或未通过安全校验时，自动回退平台安全默认模板。

## 2026-07-28：邮件署名与回复地址

1. 平台邮件使用平台当前展示名称；社团独立邮件使用该社团当前展示名称。
2. 联合活动共同事件和超级管理员操作使用平台名称，社团独立结论与邀请使用相应社团名称。
3. HTML 模板不能覆盖或伪装发件人身份。
4. 回复地址固定为实际发信账号，不另设可指向任意地址的 Reply-To。
5. 更换发信账号必须重新通过测试邮件，成功后只影响后续邮件，历史投递保留原身份。

## 2026-07-28：普通招新内部改判通知

1. 社团负责人或人事管理员修改部门负责人作出的内部决定时，必须向作出原决定的部门负责人账号生成独立内部站内信。
2. 通知至少关联对应申请和部门，并显示原决定、新决定、修改人和修改时间；改判理由不是必填项。
3. 内部改判尚未形成申请人可见结果，不向申请人发送通知，也不默认投递邮件。
4. 后续正式发布或再次改变申请人权益时，另行生成申请人权益通知，不能把内部改判通知当作已经完成对外告知。
5. 内部通知同样保存通知事实、收件人快照并支持失败补投；业务链接每次打开重新鉴权，原决定人后续失权时不能通过旧链接继续访问申请资料。

## 本模块内部冻结结论

通知事实、站内信、可选邮件、邮箱验证、社团发信密钥、联合活动发信来源、投递失败、紧急关闭及模板管理的产品行为已内部冻结。精确事件模板目录、密钥加密、邮件供应商、事务消息、重试调度、HTML 净化器和积压补投容量进入 SRS、接口、安全与架构规格；外部图片跟踪风险和紧急关闭导致的通知延迟进入治理风险清单，不再由业务开发临场决定。
