# RanaMinder 普通招新需求发现记录

> 状态：产品行为已内部冻结；本文保留历史访谈过程  
> 最后更新：2026-07-28  
> 适用范围：单一社团独立开展的普通招新，不适用于多社团联合面试

## 已知事实

1. 所有申请人必须先通过学校统一身份认证登录，并满足资料完整度写操作门槛。
2. 试点社团每届约 50 名成员、3—4 个部门，每年约 200 人报名。
3. 招新基本流程为“报名 → 多轮面试 → 录取”，没有笔试。
4. 申请人可以填写第一志愿、第二志愿等有顺序的部门志愿。
5. 招新允许部门调剂。
6. 报名表、面试评价等表单字段必须通过动态表单能力配置，不得写死。
7. 普通面试与联合面试是两条完全独立的业务路径，不能互相转换或共享状态。
8. 接受录取后，需要通过已确认的 Casdoor Group 变更规则建立当前社团、部门和职位关系，本系统保存历史事件。

## 本模块需要冻结的范围

- 招新批次及完整状态生命周期；
- 报名资格、申请唯一性和顺序志愿；
- 草稿、提交、修改、撤回和材料补充；
- 多轮面试、面试任务、排期和评价；
- 调剂、候补、结论、录取邀请与成员生效；
- 并发、撤销、到期、重复请求、Casdoor 失败和恢复；
- 权限、通知、审计、归档和导出。

## 当前访谈起点

先确认招新批次的管理权限、同一申请人的申请唯一性，以及批次状态和暂停规则。

## 2026-07-27：招新批次、申请唯一性与状态

### 管理权限

1. 社团负责人和人事管理员可以创建、配置、发布、暂停、结束或取消本社团招新批次。
2. 部门负责人只能管理本部门的志愿、评价任务和内部决定，不能创建或管理面试轮次，也不能发布、结束或取消整个批次。
3. 超级管理员仅用于异常或违规处置，不能取代社团日常运营角色。

### 申请唯一性

1. 同一学生在同一普通招新批次中只能有一份申请。
2. 第一、第二等部门志愿都属于这份申请，不能拆成多份报名表。
3. 学生可以同时申请其他社团。
4. 同一社团存在不同时间的其他招新批次时，学生可以分别申请。
5. 重复点击和并发请求不能生成重复申请。

### 批次与报名通道状态

1. 批次生命周期为：草稿、进行中、已完成、已取消。
2. 报名通道状态为：未开放、开放、暂停、已关闭。
3. 暂停报名仅停止新申请和申请人修改；现有面试、评价和管理员处理可以继续。
4. 暂停整个批次时，所有业务操作和截止时间一起冻结。
5. 恢复批次后，受影响的截止时间按照暂停时长顺延。
6. 已完成或取消的批次长期只读，不单独提供归档操作。

## 下一轮访谈范围

确认报名资格、既有成员是否可报名、顺序志愿数量与修改，以及报名表草稿、提交、撤回和补充材料规则。

## 2026-07-27：报名资格、顺序志愿与申请修订

### 报名资格

1. 默认允许账号有效、已经完成必填资料补充的在校学生报名。
2. 批次可按年级、学院等 Casdoor 固定字段配置资格条件，条件必须在报名前向学生公开。
3. 资格在提交申请时校验，不符合条件时必须展示明确原因。
4. 当前已经属于该社团的成员不能再次参加本社团普通招新，应使用成员调岗流程。
5. 当前成员仍可报名其他社团。
6. 曾经退出或离任的历史成员可以重新报名，且旧成员经历与新申请分别保留。

### 顺序志愿

1. 每个批次可以配置最少和最多志愿数量。
2. 志愿只能选择该批次开放招新的部门，且不能重复。
3. 报名修改截止前，申请人可以增加、删除或调整志愿顺序。
4. 每次正式提交都必须满足当时有效的志愿数量规则。

### 报名表修订

1. 截止前可以保存草稿；草稿不进入正式筛选和面试安排。
2. 正式提交后，在修改截止前仍可编辑并重新提交；每次提交形成可追溯版本。
3. 截止前可以撤回，并在截止前再次提交。
4. 修改截止后，报名答案和志愿顺序锁定。
5. 社团负责人或人事管理员可以为指定申请人开启有期限的补充窗口。
6. 管理员不能替申请人直接修改报名答案，只能要求其补充或通过事实纠错流程处理错误。

## 下一轮访谈范围

确认批次发布后资格、部门和报名表结构的变更边界，以及撤回、取消和资格变化对既有申请的影响。

## 2026-07-27：发布后变更、表单版本与退出招新

### 批次配置变更

1. 开放报名后仍可增加招新部门、放宽资格或延长截止时间。
2. 上述变化只要影响学生权益，就必须通知受影响人员。
3. 删除部门、收紧资格或改变志愿数量规则前，必须先暂停报名。
4. 系统需要列出全部受影响申请人，并为其开启重新选择窗口。
5. 既有申请不能因为规则变化被自动判为不合格或自动删除。

### 报名表版本

1. 已发布的报名表版本不可直接覆盖，后续修改产生新版本。
2. 旧提交连同原表单版本长期可还原。
3. 申请人再次编辑时迁移到最新版本，能够稳定对应的旧答案自动带入。
4. 新增必填字段必须由申请人补填；删除字段不删除旧答案。
5. 新增资料用途或敏感字段时，必须重新向申请人告知。

### 主动退出招新

1. 接受录取前，申请人可以随时退出本次普通招新，报名截止后也不例外。
2. 退出后取消尚未进行的面试和未接受的录取邀请，并通知相关管理员。
3. 申请、已经完成的面试记录和评价继续保留。
4. 报名截止前可以自行重新提交；截止后只能由负责人或人事重新开放。
5. 已经接受录取并成为成员后，不能再使用“退出招新”，必须进入成员退出流程。

## 下一轮访谈范围

确认多轮普通面试的轮次作用域、申请人每轮面试次数，以及预约、换时、请假和缺席规则。

## 2026-07-27：多轮面试、跨部门路径与预约

### 面试轮次

1. 每个普通招新批次可以配置任意多个有顺序的面试轮次。
2. 全部轮次都是社团统一面试轮次，由整个社团共同安排和使用。
3. 部门无权创建独立面试轮次；不同部门依据同一份有效面试记录开展考察。
4. 社团可以继续增加二面、三面等后续轮次，但每一轮仍是全社团共用。

### 申请人的面试路径

1. 同一申请人在每个轮次最多参加一次并形成一份有效面试记录，不因申请或调剂到多个部门而重复。
2. 尚未实际参加时的换时、请假、迟到或缺席重排不占用该轮次数。
3. 某部门结束申请人的本部门路径，不影响其他部门继续依据社团统一面试记录考察；社团统一结论可以结束全部路径。

### 面试预约与出勤变化

1. 管理员预设时间段、地点或线上方式、容量和面试官，申请人自行选择。
2. 有剩余容量且未到截止时间时，申请人可以自行更换时间。
3. 截止仍未选择时，由管理员安排。
4. 请假、迟到或缺席后，可以重新安排。
5. 管理员可以调整申请人已经选择的时间。
6. 所有时间和出勤状态变化都必须通知申请人。
7. 普通面试的数据、排期和状态与联合面试完全独立。

## 下一轮访谈范围

确认谁能创建和管理轮次、谁能担任面试官、面试官可以查看哪些材料和其他人的评价，以及评价修改和锁定时点。

## 2026-07-27：面试权限、资料访问与评价互见

### 轮次与面试官管理

1. 社团负责人和人事管理员可以创建、调整全部普通面试轮次。
2. 部门负责人不能创建、调整、取消或关闭面试轮次，也不能管理轮次时间段。
3. 普通面试官必须是本社团当前成员，由社团负责人或人事管理员通过具体任务临时指派；部门负责人同样需要被指派才能取得面试任务权限。
4. 其他社团成员或校外人员不能直接担任普通面试官。

### 面试官资料访问

1. 面试官只能查看自己被分配的申请人。
2. 对已分配申请人，可以查看完整报名表、图片、附件和联系方式。
3. 所有相关部门共同使用社团统一面试记录，但部门负责人不能查看其他部门独立形成的部门结论。
4. 任务撤销或批次结束后，普通面试官失去查看权。
5. 社团负责人和人事管理员查看本批次全部资料；部门负责人查看与本部门志愿或调剂路径相关的资料、统一面试记录及本部门结论。

### 评价互见与修改

1. 每位面试官独立填写动态评价表。
2. 首次提交自己的评价前，不能查看同轮其他面试官的评分和评语。
3. 首次提交后可以查看同轮评价，并在轮次关闭前修改自己的评价。
4. 每次修改均保留版本与操作者历史。
5. 轮次关闭后不能普通修改，只能发起事实纠错。
6. 申请人只能查看面试安排和对外发布的结果状态，不能查看内部评分、评语或讨论。

## 下一轮访谈范围

确认社团统一轮次的晋级/淘汰决定权、轮次结论状态、对外发布时间及已发布结论的修改规则。

## 2026-07-27：轮次结论、关闭与发布

### 社团统一轮次结论模式

1. 社团统一轮次创建时选择“社团统一筛选”或“共享面试材料、部门分别判断”。
2. 统一筛选模式由负责人或人事管理员作出统一结论；淘汰会结束全部部门路径。
3. 仅共享材料模式下，各志愿部门分别作出结论；一个部门淘汰不影响其他部门。
4. 普通面试官只能提交评价和建议，不能直接决定晋级或淘汰。

### 轮次结论与关闭

1. 普通轮次结论包括：进入下一轮、暂缓决定、结束该部门路径；“需要重新面试”不属于结论。
2. 社团统一筛选还可以结束申请人的全部部门路径。
3. 只有社团负责人和人事管理员可以关闭轮次。
4. 未处理面试或缺少必需评价时不能关闭。
5. 有权管理员可以显式豁免缺失项，但必须记录原因。

### 对外发布

1. 内部结论不会自动显示给申请人，必须由有权角色发布。
2. 负责人和人事可复核、修改并发布所有结论；部门负责人只能形成本部门内部结论，不能向申请人发布。
3. 发布后立即通知申请人。
4. 批次结束前可以修改已经发布的结论，但权益变化必须再次通知并保留修改历史。
5. 修改结论不能修改或覆盖面试官的原始评价。

## 下一轮访谈范围

确认顺序志愿对并行考察和最终录取的约束、调剂同意与调剂池访问，以及申请人能否接受多个部门结果。

## 2026-07-27：并行志愿与调剂资料授权（部分确认）

### 已确认

1. 多个志愿部门可以并行考察申请人。
2. 志愿顺序向有权部门展示，用于表达申请人的倾向，但不阻止后续志愿提前面试或作出结论。
3. 一个部门结束申请人的部门路径，不影响其他部门路径。
4. 申请人勾选“允许调剂”后，本社团全部部门负责人都可以查看其完整报名资料。
5. 勾选允许调剂本身已经构成授权，不再设计“调剂考察邀请”或二次接受机制。
6. 未勾选允许调剂时，未填报部门不能查看该申请材料或建立部门路径。

### 当时尚待补全（已由后续规则解决）

- 申请人是否可以在报名截止前或截止后撤回“允许调剂”。
- 未填报部门开始实际安排面试时，是否需要单独通知申请人，以及申请人能否拒绝某个具体部门的调剂考察。

### 多部门录取已确认

1. 申请人可以同时接受多个部门的最终录取邀请。
2. 接受第一个部门后成为社团成员并建立该部门关系。
3. 后续接受其他部门邀请时增加部门关系，不重复创建社团成员身份。
4. 接受一个部门不会自动拒绝其他部门的有效邀请。

## 2026-07-27：调剂锁定、部门考察与录取邀请

### 调剂选择锁定

1. 申请人可以在报名修改截止前开启或关闭“允许调剂”。
2. 截止后该选择完全锁定，申请人和普通社团管理员均不能更改。
3. 截止后若不愿继续接受调剂，只能退出整个招新，不能只撤回调剂授权。

### 部门不创建独立面试

1. 未填报部门不为调剂申请人另行创建部门面试。
2. 部门直接依据完整报名资料和已有社团统一面试记录形成判断。
3. 如需进一步考察，只能由社团负责人或人事管理员新增面向整个社团的后续轮次。
4. 部门没有独立面试权限不妨碍其作出最终录取或不录取结论。

### 录取邀请

1. 只有负责人和人事管理员可以根据复核后的部门录取决定发出任意部门邀请；部门负责人只能作出内部录取决定，不能创建、发送、撤回或重发邀请。
2. 邀请必须有有效期，状态包括待处理、已接受、已拒绝、已过期和已撤回。
3. 接受前可以撤回；拒绝或过期后可以重新发出。
4. 邀请及每次状态变化必须通知申请人并保留历史。

## 下一轮访谈范围

确认调剂部门内部考察的显式建档与通知、接受邀请后的 Casdoor 生效状态，以及接受后关系变化应进入的成员流程。

## 2026-07-27：调剂路径建档与录取生效

### 调剂部门路径

1. 部门负责人在写入本部门评价或结论前，必须先执行“纳入本部门考察”。
2. 该操作建立可审计的部门选拔路径，重复操作不能建立重复路径。
3. 仅内部建档和考察不通知申请人。
4. 内部决定及其修改不通知申请人；由负责人或人事安排额外面试、正式发布部门结论或发出录取邀请时必须通知申请人。

### 接受邀请与 Casdoor 生效

1. 申请人接受邀请后，邀请立即且幂等地变为“已接受”。
2. 成员业务生效时间记录为申请人接受邀请的时间。
3. Casdoor 写入并回读确认前，页面显示“成员身份生效处理中”，不得开放成员权限。
4. Casdoor 确认成功后开放对应社团和部门权限。
5. 15 分钟仍失败时，邀请保持已接受，成员尚未正式生效，同时通知申请人和管理员。
6. 后续重试不要求申请人再次接受。

### 申请人接受后退出

1. 已接受邀请不能由申请人撤销或改回待处理。
2. 申请人希望离开时必须走普通成员退出流程。
3. Casdoor 尚在同步处理中也不例外，系统需要安全处理接受写入与退出请求之间的竞态。
4. 接受和退出历史不得删除。

## 下一轮访谈范围

确认社团对已经接受邀请的处理、多个部门关系下的成员流程影响，以及普通招新批次完成与取消条件。

## 2026-07-27：接受后的成员处理、完成与取消

### 已接受邀请改走成员流程

1. 邀请只有在申请人尚未接受且仍为待处理状态时才能撤回；接受与撤回并发时只允许一个操作成功。
2. 邀请一旦接受便进入不可逆终态，不提供“撤销已接受录取”或把邀请改回待处理的操作。
3. 只需要结束某个已接受部门关系时，使用成员模块的部门关系移除流程，保留其他部门及社团成员身份。
4. 社团需要主动终止成员身份时，使用成员移除流程；申请人本人希望离开时，使用成员退出申请和审批流程。
5. 成员流程按照影响范围处理部门、职位、成员和访问权限，通知学生并保留完整历史；原录取邀请始终保留“已接受”事实。

### 正常完成招新活动

1. 报名通道必须已经关闭。
2. 所有申请人和部门选拔路径必须形成终态，且相应结果已经由负责人或人事管理员正式发布；仅存在部门内部决定不能完成活动。
3. 所有录取邀请必须进入已接受、已拒绝、已过期或已撤回之一。
4. 不得存在尚未完成的成员同步。
5. 负责人或人事管理员确认完成后，活动记录长期只读。
6. 已经建立的成员关系不因活动结束而改变。

### 取消招新活动

1. 取消后所有未完成面试和未接受邀请立即失效，并通知申请人。
2. 已经接受且生效的成员关系不会自动撤销。
3. 存在已接受录取时必须二次确认取消，并提示管理员另行处理成员关系。
4. 取消后的活动及其历史长期只读。

## 下一轮访谈范围

确认候补状态、最终未录取通知、长时间未决活动和超级管理员强制完成规则。

## 2026-07-27：候补、最终结果与强制完成

### 部门候补

1. 候补是部门级状态，不是整份申请唯一状态。
2. 申请人可以同时处于多个部门候补，也可同时持有其他部门录取邀请。
3. 部门负责人可在本部门内部决定维持候补、建议录取或建议不录取；负责人和人事管理员可修改任意部门决定，并负责正式转入邀请或公开不录取结果。
4. 候补必须由负责人或人事管理员正式转为录取邀请或最终不录取，不能带着候补状态正常结束招新活动。

### 最终未录取

1. 只有全部部门路径均结束，并且不存在候补、有效邀请或成员生效处理中状态时，才可显示整份申请最终未录取。
2. 任一部门仍在考察或处理时，单部门淘汰不能让系统显示整体未录取。
3. 最终结果发布后必须通知申请人。

### 超级管理员强制完成

1. 只有超级管理员可以强制完成长期未决活动。
2. 未完成面试取消，未决路径和候补结束，未接受邀请立即过期。
3. 所有受影响申请人收到通知。
4. 已接受录取和成员关系保留。
5. Casdoor 成员同步可转为独立故障任务继续处理，不阻止强制完成。

## 下一轮访谈范围

确认活动结束后的申请人、部门负责人、普通面试官访问范围，以及结束后事实纠错和已发布结果纠错规则。

## 2026-07-27：结束后访问与事实纠错

### 结束后访问

1. 申请人可查看自己的报名表版本、面试安排、公开结果和录取邀请，但不能查看内部评分、评语或讨论。
2. 社团负责人和人事管理员查看全部资料。
3. 部门负责人只查看真正进入过本部门选拔路径的申请人和关联共享面试记录。
4. 活动结束后，部门负责人不能继续浏览仅因“允许调剂”而曾经可见、但从未进入本部门路径的其他申请人。
5. 普通面试官失去全部访问权。
6. 超级管理员因纠错或违规处置查看时必须审计。

### 按现任角色授权

1. 历史管理访问按当前有效角色计算。
2. 离任负责人、人事管理员和部门负责人失去相应管理查看权。
3. 新任人员按照当前职责获得社团全部或本部门范围的历史访问权。

### 结束后事实纠错

1. 活动结束后所有普通编辑锁定，只保留事实纠错。
2. 申请人可以申请纠正本人资料或明显事实错误。
3. 负责人、人事管理员和超级管理员可以处理纠错。
4. 面试官把甲的评价误写给乙时，可以申请修正自己的错误记录。
5. 原值、新值、原因、处理人和时间全部保留。
6. 纠错影响学生权益时必须通知学生；学生不查看内部纠错日志。

## 下一轮访谈范围

最后确认活动进行中修改面试轮次的限制、申请人账号中途禁用，以及部门 Group 异常时的招新降级方式。

## 2026-07-27：轮次变更与身份、部门异常

### 已开始轮次的结构保护

1. 尚未开始的轮次可以修改、删除、重排，也可以新增未来轮次。
2. 已有排期、评价或结论后，轮次不得删除，也不能改变结论模式；全部轮次始终为社团统一轮次。
3. 已开始轮次只允许取消，取消后原记录继续保留。
4. 新增或取消轮次需要记录原因并通知受影响申请人。

### 申请人身份异常

1. Casdoor 禁用或删除账号后，申请进入身份异常，不自动删除或判为未录取。
2. 立即终止登录，暂停该申请人的未进行面试和未处理邀请截止时间。
3. 异常期间不能新增或接受录取。
4. 管理员收到通知，可核实后发布资格失效或其他结论。
5. 账号恢复后继续流程，个人截止时间按暂停时长顺延。
6. 已经成为成员的账号立即失去访问权，但全部历史保留。

### 部门 Group 异常

1. 部门 Group 删除、移动或失去访问权限时，只暂停该部门路径，其他部门继续。
2. 受影响申请人、负责人、人事和超级管理员收到通知。
3. 修复或重新绑定后恢复，截止时间按异常时长顺延。
4. 异常期间不能接受该部门录取或授予部门权限。

## 2026-07-28：免试、暂缓与无效面试作废

### 跳轮或免试

1. 普通招新允许针对单个申请人执行跳轮或免试。
2. 只有社团负责人和人事管理员可以操作普通轮次；部门负责人无面试轮次管理权。
3. 操作必须填写原因并保留审计记录。
4. 如果改变申请人已经可见的面试安排或公开流程，必须通知申请人。
5. 跳轮或免试只使申请人进入下一轮或后续判断节点，不能直接代表录取或淘汰，也不能伪造一份已完成的面试记录。

### 暂缓决定与无效面试作废

1. 暂缓决定必须设置处理期限，且不得晚于整个招新活动的结束时间。
2. 暂缓到期只提醒有权管理员，不自动淘汰或改变申请人路径。
3. 同一申请人在同一轮次最多参加一次并形成一份有效面试记录，不允许以“重新面试”为由重复参加同一轮。
4. 尚未实际参加时的换时、请假、迟到或缺席重排不占用该轮次数。
5. 面试已经开始或完成，但因断网、面试对象错误等原因无效时，社团负责人、人事管理员或超级管理员可以填写原因并将原记录标记为“作废”。
6. 作废记录、评价、操作者、原因和时间永久保留且不计为有效面试；作废后才可重新安排，对申请人可见的变化必须通知。
7. 存在未解决暂缓状态时，不能正常关闭对应轮次或完成招新活动；超级管理员强制完成除外。

### 2026-07-28 轮次模型修订说明

1. 本节及前文现行表述覆盖此前“社团共享轮次＋部门独立轮次”的方案。
2. 普通招新只保留社团统一面试轮次，部门无权创建面试。
3. 可配置任意多轮，但同一申请人在每轮最多形成一份有效面试记录。
4. 作废是无效面试重新安排的唯一例外，不删除原始事实。

### 不建设利益冲突回避模块

1. 不提供面试官利益冲突申报、自动关系识别或强制回避功能。
2. 管理员仍可通过既有能力撤销或重新分配面试官任务。
3. 不在动态表单默认模板或未来 AI 能力中变相加入强制利益关系申报。

## 2026-07-28：资格快照与规则收紧补救

### 报名资格

1. 有效、未禁用且完成必填资料的 Casdoor 学生账号具备默认报名资格，不依赖单独的“在校状态”字段。
2. 学院、年级等公开资格条件在申请提交或重新提交时校验，并保存当时的资格依据快照。
3. 提交后个人资料变化不自动取消或重新判定既有申请；再次编辑并重新提交时按最新资料校验。
4. Casdoor 账号禁用或删除仍立即进入身份异常，不适用资格快照。

### 发布后规则收紧

1. 删除部门、收紧资格或改变志愿数量规则时，必须为受影响申请人设置专门的重新选择截止时间并通知。
2. 逾期未处理者进入“调整逾期、待管理员处理”，不自动淘汰。
3. 负责人或人事管理员可延长窗口、恢复原规则，或填写原因后明确作出资格不符结论并通知申请人。
4. 存在未处理的调整逾期申请时，活动不能正常完成；超级管理员强制完成除外。

## 2026-07-28：部门决定与录取发布权限分离

### 内部决定权

1. 部门负责人可对已报名本部门，或已勾选允许调剂并进入本部门选拔路径的申请人，形成和修改本部门内部决定。
2. 内部决定可覆盖晋级、暂缓、候补、录取、不录取和结束本部门路径；它不会自动显示给申请人，也不会自动生成邀请或通知。
3. 部门负责人修改自己的内部决定时保留全部版本、作者和时间，但不要求填写修改理由。

### 复核、改判与对外发布

1. 社团负责人和人事管理员可以查看、维持或修改任意部门的内部决定。
2. 只有社团负责人和人事管理员可以正式发布部门或整体结果，以及创建、发送、撤回和重新发送普通招新的录取邀请。
3. 部门负责人不能直接公布结果、发送录取通知，或通过其他通知入口绕过发布权限。
4. 内部决定被社团负责人或人事管理员改判时，原决定仍保留并标明原决定人、修改人和版本；不强制填写改判理由。
5. 改判发生后，系统必须向作出原决定的部门负责人发送内部站内信，至少关联对应申请和部门，并显示原决定、新决定、修改人及时间。
6. 内部改判通知不发送给申请人，也不默认发送邮件；正式发布和任何影响申请人权益的后续变化必须另行通知申请人。
7. 邀请被接受后不再允许任何角色通过招新流程撤回或撤销；后续关系变化统一按部门关系移除、成员移除或成员退出处理。
