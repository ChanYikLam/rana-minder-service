# RanaMinder 纠错、审计、归档与历史访问需求发现记录

> 状态：产品行为已内部冻结  
> 日期：2026-07-27

## 已确认的前置约束

1. 普通招新和联合活动结束后业务记录锁定，只允许事实纠错。
2. 所有纠错都必须保留原值、修改值、处理人、时间和理由，不能覆盖审计历史。
3. 学生可以申请纠正本人事实记录；超级管理员可以处理明显错误和违规内容。
4. 普通面试官在活动结束后失去档案查看权。
5. 联合活动和普通招新正式业务长期归档；跨社团长期访问按统一说明、当前角色和超级管理员治理开关执行。

## 本模块待冻结范围

- 普通编辑、业务修订与事实纠错边界；
- 纠错申请、证据、处理、驳回、撤回和权益补偿；
- 审计事件目录、字段、事务一致性和不可篡改性；
- 审计查看、导出、告警和保留；
- 活动归档后的角色访问和当前角色重新鉴权；
- 长期保留、匿名化、删除、备份和导出副本处理。

## 2026-07-27：事实纠错、处理权限与审计基线

### 普通编辑与事实纠错

1. 业务开放期间，有权用户按照业务状态执行普通编辑。
2. 业务锁定或活动结束后，普通编辑关闭，仅允许事实纠错。
3. 客观错误包括对象写错、姓名或经历记载错误、时间地点错误、把甲的评语写到乙名下，以及违规或明显不当内容。
4. 单纯不认同面试官主观评价不属于事实错误，不能通过纠错重写评价。
5. 录取结论确因事实错误可经纠错流程修改并通知学生；已经产生的成员、部门、职位和权限必须调用正式业务流程调整。
6. 纠错追加新记录，原值、原附件和原操作历史继续保留。

### 纠错申请和处理权限

1. 学生可针对本人资料、报名内容和明显事实记录提出纠错申请并上传证据。
2. 社团负责人和人事管理员可以处理本社团纠错，部门负责人不能处理活动结束后的正式纠错。
3. 面试官活动结束前按既有规则修改自己的记录；结束后只能提交纠错申请，不能重新获得完整档案访问权。
4. 原记录作者不能单独批准针对自己错误的纠错，须由另一名负责人、人事管理员或超级管理员处理。
5. 超级管理员可处理明显错误、跨社团争议、违规内容和无人处理事项。
6. 批准、驳回、撤回和处理结果均保留历史；驳回必须填写原因。
7. 纠错影响学生权益时必须通知，并按已确认的邮件默认规则执行。

### 审计内容和不可篡改性

1. 登录、资料同步、权限、社团接入、招新、联合活动、成员、表单、附件、通知、邮件密钥、纠错、导入导出和超级管理员操作均进入审计。
2. 审计包含操作人、当时角色与作用域、时间、来源、关联对象、旧值、新值、结果、失败原因、请求编号和必要网络信息。
3. 密码、邮箱密钥、令牌、验证码和附件正文不得进入审计；敏感字段只记录脱敏差异。
4. 关键状态变更与审计记录在同一事务保存；审计写入失败时关键操作整体失败。
5. 应用内任何管理员都不能修改或删除审计记录。
6. 审计支持按时间、用户、社团、对象和事件类型查询及受控导出。

## 2026-07-27：归档访问与审计查看权限

### 归档后的业务访问

1. 招新或联合活动完成后自动进入只读归档，不要求管理员再次执行归档操作；这与已经取消的“归档社团”无关。
2. 申请人可查看自己的报名版本、附件、公开结果和邀请，不能查看内部评价、纠错日志或审计。
3. 普通面试官在活动结束后失去全部档案访问权。
4. 现任部门负责人只查看真正进入过本部门选拔路径的人员及关联共享记录。
5. 现任社团负责人和人事管理员查看本社团全部相关历史；历史负责人、历史部长和离任成员不因过去职位保留访问权。
6. 联合活动按首次公布时锁定的参与关系、社团启用状态和当前有效角色访问；被紧急停用的参与社团在停用期间不能查看。
7. 超级管理员可以查看全部归档，但每次特权查看都必须审计。

### 审计中心访问

1. 社团负责人和人事管理员可以查询、导出本社团审计。
2. 部门负责人不能进入完整审计中心，只能在自己有权查看的具体业务对象上查看操作历史。
3. 普通成员、申请人和面试官不能查看内部审计。
4. 超级管理员可以查询全平台审计，其查询和导出行为也产生审计。
5. 审计长期保留，不提供应用内删除入口；容量和底层防篡改由架构与运维规格保证。
6. 审计导出继续执行范围控制、敏感字段脱敏和下载审计。

## 2026-07-27：匿名化功能取消

1. 当前产品不提供匿名化能力。
2. 不建设匿名编号、身份字段清除后继续保留统计记录等流程。
3. 不得把普通编辑、事实纠错或删除接口用于变相匿名化。
4. 若未来校方治理明确要求匿名化，必须重新开展需求发现并定义对象、范围、不可逆性、审计和备份传播规则。
5. 完整删除不属于匿名化；其授权和范围在后续规则中单独确认。

## 2026-07-27：超级管理员正式数据删除

1. 超级管理员默认具备校方数据治理授权，不需要为每次删除另行上传审批文件。
2. 超级管理员可以选择删除一条正式记录、某个业务活动范围的数据，或某个用户在本系统中的全部本地业务数据。
3. 删除操作必须填写原因、展示受影响对象清单并进行二次确认。
4. 用户仍有当前成员关系、有效邀请或进行中活动时，必须先结束对应业务关系，不能直接删除造成悬空权限。
5. 删除范围可包括本地个人资料副本、报名表、附件、面试数据、邀请、成员经历、纠错材料和通知记录等被明确选择的正式数据。
6. 删除后只保留最小审计：内部记录标识、执行时间、执行超管和删除类型；不保留姓名、报名内容、评价或附件正文。
7. 删除不自动删除 Casdoor 账号、Claims、Group 或其他校方系统数据，也不能召回已发送邮件及已下载文件。
8. 在线副本、搜索索引、系统内导出和备份按后续已确认的删除传播规则处理。

## 2026-07-27：临时清理与删除传播

### 草稿和临时文件清理

1. 未提交草稿、扫描失败文件、无有效记录引用的上传文件和临时导出可自动清理。
2. 清理期限由超级管理员统一配置。
3. 草稿到期前通知用户；用户继续编辑后重新计算期限。
4. 已提交表单、历史修订及其附件不受临时清理规则影响。
5. 清理执行前再次检查所有引用关系，仍被有效记录引用的文件不得删除。
6. 自动清理结果进入审计。

### 正式删除在副本和备份中的传播

1. 正式删除同步处理在线数据库、附件存储、缓存、搜索索引和系统内尚未过期的导出文件。
2. 联合活动数据删除后，所有参与社团同时失去对应内容，不保留任何参与社团侧可访问副本。
3. 系统保存独立的删除执行清单。
4. 历史备份不立即逐份改写，但恢复后必须重新应用删除清单，防止已删除数据复现。
5. 系统生成的导出文件设置有效期，到期自动删除。
6. 已发送邮件和已下载到系统外的文件无法自动召回；导出时提示下载者承担保管与删除责任。
7. 删除完成或失败均通知相关申请人和超级管理员，并保留处理审计。

## 2026-07-28：纠错时限与联合活动责任边界

1. 纠错申请的处理期限由超级管理员配置；逾期只标记并提醒，不自动批准、驳回或修改业务记录。
2. 纠错证据的查看范围不能超过对应纠错记录和原业务记录权限。
3. 联合活动中，某社团填写的评分、评语和结论，只能由该社团负责人、人事管理员或超级管理员处理；其他社团只能查看纠错结果。
4. 联合排期等无单一社团作者的共同事实，可由任一参与社团负责人或人事管理员处理。
5. 原错误作者不能单独批准自己的归档后纠错；没有另一名合格处理人时交由超级管理员。

## 本模块内部冻结结论

普通编辑与事实纠错、处理权限、审计内容与访问、活动归档、正式数据删除、临时清理及备份恢复后的删除传播产品行为已内部冻结。匿名化明确不建设。超级管理员代表校方，长期保留、全局访问和联合活动长期共享不再等待外部审批，但继续作为高风险事实接受统一说明、当前鉴权和审计约束；审计防篡改存储、删除清单可靠性、跨存储补偿和备份恢复进入 SRS、架构与运维规格。
