## 1. 文档定位、权威顺序与编号规则

### 1.1 文档定位

本文把已经确认的产品行为、SRS 转换规则、架构事务边界和数据约束转换为传输中立的逻辑接口草案。本文不是新的产品需求来源，不得新增角色、权限、状态、通知对象、筛选能力、数据保留行为或外部依赖承诺。

发生冲突时，严格按文档顶部的权威顺序处理。框架 DTO、前端类型、数据库错误、Casdoor SDK 返回值和 PostgreSQL 默认行为均位于本文之后，不能反向改变本文或上游规则。

### 1.2 四类内容分区

| 分类 | 含义 | 本文处理 |
|---|---|---|
| 产品事实与 SRS 约束 | 已确认的用户可见行为、状态转换、授权、通知、故障和恢复规则 | 只承接，不改写 |
| 已接受架构与数据约束 | 模块化单体、8 类事务、PostgreSQL 权威任务、选择性 RLS、对象存储、Casdoor 权威和数据前后置条件 | 作为强制输入 |
| 下游接口设计推导 | 为表达上述规则而建立的逻辑命令、查询、错误和追踪合同 | 使用 `IFC-*` 编号 |
| 技术选择问题 | 上游没有唯一决定，且会影响传输或实现准备的选择 | 使用 `IFC-Q-*` 编号；保留候选、确认结论与影响，未确认前不得写入实现 |

### 1.3 下游编号

| 编号族 | 用途 |
|---|---|
| `IFC-GEN-*` | 通用请求、结果、追踪和安全语义 |
| `IFC-CMD-*` | 逻辑命令分类 |
| `IFC-QRY-*` | 逻辑查询分类 |
| `IFC-TX-*` | 8 类事务边界的接口落点 |
| `IFC-SM-*` | 29 个状态机到逻辑接口的追踪入口 |
| `IFC-ERR-*` | 传输中立错误与拒绝语义 |
| `IFC-NTF-*` | 通知恢复、补投顺序和调度边界 |
| `IFC-FIL-*` | 文件上传、检查、访问、撤权、删除和恢复 |
| `IFC-DATA-*` | 数据约束转化的接口前后置条件 |
| `IFC-Q-*` | 技术选择问题及评审记录 |

这些编号不是需求事实、`PRD-OPT-*`、SRS 或 ADR 编号，不能用来创造产品行为。

## 2. 传输中立总合同

### 2.1 逻辑请求信封

`IFC-GEN-001`：每次逻辑操作必须能够表达下列信息；某项是否由调用方提交或由服务端生成，由后续传输设计决定，但服务端不得信任客户端自报的身份、权限或作用域。

| 信息 | 逻辑语义 | 可信来源 |
|---|---|---|
| 操作者 | 当前稳定主体、可信登录状态和会话安全状态 | 服务端认证结果 |
| 操作 | 登记过的命令或查询类型及其版本 | 服务端接口目录 |
| 目标 | 稳定对象标识和对象类型 | 调用方只提供候选标识，服务端回源验证 |
| 作用域 | 公开、本人、普通社团、联合协作域、参与社团私有域、平台特权或后台单项目标 | 服务端按目标对象和当前授权冻结 |
| 期望状态与版本 | 命令允许的前置状态、对象版本、窗口/截止/配置等必要版本 | 调用方声明，服务端与权威当前值比较 |
| 业务输入 | 强类型、版本化、已登记字段 | 服务端运行时校验 |
| 幂等信息 | 业务幂等键和规范化输入摘要 | 调用方提供键或沿用既有业务意图；摘要由服务端计算 |
| 增强认证证据 | 最近重新认证时间、可信当前 Group 核验及其适用命令 | 服务端认证与 Casdoor 实时读回 |
| 追踪信息 | 当前请求追踪编号和父追踪关系 | 服务端生成；不得替代幂等键 |

### 2.2 逻辑结果信封

`IFC-GEN-002`：逻辑结果至少区分以下类别，不能用一个模糊“成功”覆盖。

| 结果类别 | 必须表达 | 明确不得表达 |
|---|---|---|
| 已完成 | 业务结果、当前状态/版本、必要引用和安全摘要 | 未提交或未回读确认的外部结果 |
| 已受理/处理中 | 稳定业务意图或任务引用、当前阶段、可查询入口和已知限制 | 最终权益已生效 |
| 已拒绝 | 稳定错误分类、安全可披露原因、当前可安全返回的版本/刷新要求 | 未授权对象详情、内部路径、秘密或其他社团信息 |
| 并发冲突 | 当前事实已变化、需刷新或复核的对象/预览版本 | 自动猜测用户意图或静默覆盖 |
| 外部结果不确定 | 业务仍处理中、将先读回再重试或转异常的事实 | 直接宣称成功或失败保持原状态 |
| 依赖不可用 | 受影响能力、允许的降级范围和安全追踪编号 | 绕过校验、排队成功假象或数据库外替代真相 |

`IFC-GEN-003`：前置校验拒绝或本地原子提交失败时，不得发起外部写入，也不得产生成功状态历史、成功通知事实或成功任务结果。外部调用已经发起后的失败或结果不确定必须保留意图与尝试证据，按对应事务回读、重试、补偿或进入异常，不能把“不得再发起”误写成“外部一定未发生”。上游明确要求记录关键失败审计时，只保存最小脱敏失败证据。

## 3. 身份、作用域、重新认证与授权重算

### 3.1 作用域类型

`IFC-GEN-004`：

| 作用域 | 适用入口 | 强制约束 |
|---|---|---|
| 公开 | 公开找社团、找活动及允许公开的详情 | 按访问者类型投影；公开命中不产生报名资格 |
| 本人 | 个人资料、本人申请、邀请、日程、通知和个人副本 | 目标主体必须等于当前主体；仍按对象状态和字段权限重验 |
| 普通社团单目标 | 普通社团详情、命令、文件和后台任务单项 | 服务端冻结唯一 `club_id`；客户端工作空间只是提示 |
| 联合协作单目标 | 联合活动共享记录 | 服务端冻结唯一联合活动；参与关系和活动状态必须当前有效 |
| 联合参与社团私有 | 某参与社团独立结论、邀请或私有字段 | 冻结完整“联合活动＋参与社团”元组，不自由组合两个集合 |
| 平台特权 | 明确列入事实总账的超级管理员操作 | 不形成数据库绕过身份；必须保存目标范围和特权审计 |
| 集合只读 | 个人中心、管理工作台、登记过的跨社团待办或受控统计 | 仅服务端冻结有限集合；禁止写入，详情逐对象重验 |
| 后台单项 | 一个已领取任务的冻结目标 | 引用源意图、作用域、对象版本、租约和任务标识；不得获得全库通权 |

### 3.2 授权重算顺序

`IFC-GEN-005`：受保护操作按以下逻辑顺序失败关闭：

1. 验证当前认证、账号状态、会话和自动安全限制；
2. 识别登记过的逻辑操作，不接受任意命令、字段或查询表达式；
3. 从目标对象解析真实作用域，不以客户端当前工作空间决定；
4. 取得符合该操作时效要求的可信 Casdoor 账号与 Group 事实及本地稳定映射；高风险和上游明确要求当前核验的路径执行实时读回；
5. 叠加当前角色、任务、作者、字段、业务状态和跨状态覆盖规则；
6. 对增强认证命令检查最近 10 分钟重新认证、实时 Group、原因、影响预览和确认；
7. 建立事务本地单目标或登记过的集合只读数据库上下文；
8. 检查期望状态、对象版本、资格、容量、期限和其他领域前置条件；
9. 才允许读取投影或提交命令。

旧页面、旧通知、旧任务、缓存、搜索命中、导出申请时权限和客户端传入的角色均不能跳过上述顺序。管理角色失权后，下一次受保护查询、详情、文件访问和命令立即按当前事实拒绝。

## 4. 命令、查询、任务与导出分类

### 4.1 逻辑命令

| 编号 | 分类 | 适用范围 | 强制结果语义 |
|---|---|---|---|
| `IFC-CMD-001` | 本地权威命令 | 仅需 PostgreSQL 本地事务完成的状态、配置、审批、确认或历史变化 | 全部原子事实提交后才返回已完成 |
| `IFC-CMD-002` | 外部效果命令 | Casdoor、文件、邮件、导出生成等提交后外部动作 | 先持久化业务意图和任务；未可信收口前返回处理中 |
| `IFC-CMD-003` | 高风险命令 | SRS 高风险目录及后续威胁模型同级命令 | 当前作用域、影响范围、必要重新认证、实时 Group、原因、确认、版本和审计缺一即拒绝 |
| `IFC-CMD-004` | 受控批量命令 | 已确认的四类批量操作及失败项重试 | 冻结目标和预览版本，逐项按单目标命令执行，允许部分成功 |
| `IFC-CMD-005` | 截止、调度与系统命令 | 到期、提醒、重建、对账、恢复和清理等受信任任务 | 只能执行 SRS 明确授权的自动转换；旧版本任务幂等忽略 |
| `IFC-CMD-006` | 正式删除与恢复命令 | 正式删除清单、跨存储步骤、恢复门 | 先撤权；逐步核验；部分失败不得宣称完成或补偿复原已删数据 |

### 4.2 逻辑查询

| 编号 | 分类 | 权威来源与重验 |
|---|---|---|
| `IFC-QRY-001` | 单对象详情与当前可操作项 | 回源权威聚合、当前状态、当前授权和字段权限；不从通知或缓存推断 |
| `IFC-QRY-002` | 列表、搜索与结构化筛选 | 使用版本化服务端目录；先授权/作用域，再筛选、排序、分页和投影 |
| `IFC-QRY-003` | 个人中心与管理工作台 | 从各领域对象派生；集合只读；每项携带真实作用域，详情和执行逐项重验 |
| `IFC-QRY-004` | 统计与派生结果 | 读取已确认口径及源水位；派生失败或滞后不能扩大数据范围或冒充新权威结果 |
| `IFC-QRY-005` | 任务、同步与恢复状态 | 返回权威任务/业务状态、最近尝试和安全摘要；运行日志不能成为唯一结果来源 |
| `IFC-QRY-006` | 文件访问授权 | 每次按当前业务对象、字段、任务、文件版本、检查和删除状态重算 |
| `IFC-QRY-007` | 导出状态与下载授权 | 生成状态来自导出聚合；每次下载重新检查当前权限、安全开关、有效期和删除状态 |

### 4.3 查询目录和分页

`IFC-QRY-008`：每个可筛选入口必须登记稳定入口版本、筛选键、值类型、操作符、空值/空集合、多值组合、权威字段、作用域、排序、稳定次级键、分页、字段投影、缓存和负向测试。未知键、操作符、任意 JSONPath、任意排序表达式、损坏或跨入口复用的游标必须拒绝，不能静默忽略后返回更宽结果。

普通列表采用稳定游标方向；小型固定目录是否使用页码/偏移留给性能与实现准备评审。游标必须绑定查询入口/版本、规范化筛选摘要、授权作用域的安全等价标识、完整排序键和稳定对象标识。普通游标不是批次或导出的冻结快照。

## 5. 幂等、对象版本和并发

### 5.1 幂等

`IFC-GEN-006`：

1. 幂等作用域至少包含逻辑命令类型、真实作用域和业务幂等键；
2. 服务端按版本化规范化规则计算语义摘要；
3. 同键同摘要重复提交返回原业务结果或原处理中引用，不重复业务、通知、审计成功记录、外部写入或文件；
4. 同键异摘要稳定拒绝为幂等冲突；
5. 业务幂等键、请求追踪编号、任务 UUID 和外部请求号分别保存，不互相替代；
6. 异步重试沿用原业务意图和幂等结果，使用新的尝试编号，不要求用户重复接受、确认或提交。

### 5.2 版本与并发

`IFC-GEN-007`：改变状态、期限、容量、关系、当前发布指针或有效引用的命令必须携带期望对象版本及必要的关联版本。版本不匹配时拒绝并要求刷新，不自动重放到新版本。

| 竞争 | 单胜者合同 |
|---|---|
| 邀请接受、拒绝、撤回、到期或强制失效 | 同一邀请版本只允许一个结果提交 |
| 申请撤回、批准或驳回 | 同一申请版本只允许一个结果提交 |
| 预约取消、重新确认或执行租约 | 同一命令/调度版本只允许一个结果提交 |
| 发布、取消、完成或强制结束 | 同一活动及影响集合版本只允许一个结果提交 |
| 最后面试名额、人员时间冲突和改期 | 容量、来源安排、当前人员占用和版本在同一边界；失败保留旧安排 |
| 最后一名负责人交接 | 当前关系和连续性锚点同一边界；不得出现启用社团零负责人窗口 |
| 当前发布指针 | 失败时旧版本完整有效；不得部分对象使用新版本 |
| 文件绑定与清理 | 引用和文件版本竞争；只允许绑定或清理之一成功 |

数据库约束、死锁或序列化失败必须映射为登记过的逻辑冲突。允许重试时，从认证、授权、对象状态和全部前置条件开始重试完整命令，复用同一业务幂等键；不得只重放最后一条数据库语句。具体 SQLSTATE、锁等待、退避和尝试次数不属于本轮传输合同。

## 6. 8 类事务边界的逻辑接口合同

| 编号 | 输入与前置条件 | PostgreSQL 原子事实 | 提交后任务/外部动作 | 通知与审计 | 失败与恢复结果 |
|---|---|---|---|---|---|
| `IFC-TX-001` 本地业务状态转换 | 当前身份/作用域、期望状态/版本、强类型输入、幂等键 | 当前状态/版本、业务结果、追加历史、关键审计及上游要求的通知事实 | 非必要派生刷新 | 必需审计同事务；权益通知按 `IFC-TX-002` | 任一必需事实失败整体拒绝；同键重放返回原结果 |
| `IFC-TX-002` 直接权益与通知 | 权益命令、当前收件人规则和对象版本 | 权益结果、通知事实、收件人快照、逻辑去重键、关键审计 | 站内呈现和可选渠道投递 | 通知事实保存失败则权益命令回滚 | 渠道失败不回滚已提交权益；恢复只补投渠道 |
| `IFC-TX-003` Casdoor 外部写入 | 稳定映射、原值/关系快照、目标、对象版本、幂等键 | 业务意图、处理中状态、原快照、目标、任务和审计 | 外部写、定向回读、重试、补偿和对账 | 受理、最终成功/失败按领域通知；全部尝试可追踪 | 结果不确定保持处理中并先回读；未确认不授新权限；部分成功补偿或异常 |
| `IFC-TX-004` 文件上传/检查/绑定 | 当前业务/字段权限、上传会话、文件/检查/引用版本 | 元数据、不可变文件版本、对象定位意图、检查任务、引用意图和状态 | 字节接收、晋升、检查、预览和删除 | 上传/检查/访问按规则审计 | 跨存储不伪造原子；旧任务按版本失效；未核验不可绑定或访问 |
| `IFC-TX-005` 通知渠道投递 | 已存在通知事实、渠道资格、发件身份/模板版本 | 渠道意图、任务和模板/目标地址快照 | 站内信生成、邮件发送、结果查询和重试 | 渠道尝试独立审计，不复制业务通知事实 | 永久失败保留证据；不得重执行业务或冒充已读 |
| `IFC-TX-006` 受控批量 | 固定社团、操作/业务类型、目标 ID/预览版本、参数、确认和批次幂等键 | 预览、冻结清单、批次状态和单项意图 | 每项独立走对应事务，之后汇总 | 每项审计/权益通知不能由批次摘要替代 | 成功项保留；失败项结构化返回；只可重试原失败项 |

### 6.1 站内信恢复补投

`IFC-NTF-001`：站内信恢复后，每个曾关闭范围内同一收件人的积压通知按原事件时间升序补投；原事件时间相同时，按稳定逻辑事件标识排序。不同社团范围和不同收件人可以公平并行，并使用有界批次、分区恢复水位、任务租约和逻辑事件幂等防止单一积压阻塞其他范围。并行只改变投递调度，不改变通知事实、收件人快照、原事件时间、邮件资格、权益业务结果或已读状态；重试不得重复执行业务。

## 9. 派生查询、搜索、筛选、个人中心与工作台

`IFC-QRY-009`：

1. 派生查询的业务状态来自权威对象当前行；缓存、搜索、通知和工作台状态只作入口；
2. “找社团”和“找活动”是独立查询模式，不能混用名称条件；
3. “正在报名”按查询时公开资格、报名通道开放、无活动暂停/终态覆盖且当前有效截止晚于服务端时刻共同派生；它不是持久状态或个人报名资格；
4. 截止快捷范围和自定义日期使用平台时区、服务端可信时钟及已确认半开区间语义；
5. 个人中心只聚合本人事项和当前仍有权的角色型事项；每项携带真实作用域和稳定目标引用；
6. 管理工作台固定当前社团，不跨社团合并管理数据；打开、筛选、详情和命令均重新授权；
7. 搜索或筛选只缩小已授权候选集合；总数、分面和零结果使用相同授权、RLS、字段和删除谓词；
8. 派生数据滞后或不可用时，只能安全回源、转为可追踪异步任务或明确不可用，不能去掉筛选或作用域；
9. 权限收紧、状态变化、社团停用、联合参与失效、字段权限变化或正式删除必须使相关缓存、索引、旧详情和旧游标失效。

## 13. 第一轮技术选择评审记录

### IFC-Q-001：是否先冻结传输中立逻辑契约

状态：已确认。2026-07-31，需求方选择方案 A。

确认方案 A：现在冻结本文的逻辑命令/查询分类、作用域、错误语义、幂等、对象版本、并发和 8 类事务合同；REST、GraphQL、RPC、URL、HTTP 方法/状态码、序列化和 SDK 留到实现准备阶段另行评审。

| 方案 | 优点 | 缺点/风险 |
|---|---|---|
| A. 先冻结传输中立逻辑契约（建议） | 可立即约束安全、测试、迁移和恢复设计；306 条转换不被 API 风格绑架；未来比较传输方案时有稳定语义基线 | 实现准备阶段仍需再做一轮传输映射和公开错误码设计 |
| B. 等 API 风格选定后一起冻结 | 一次形成传输和语义文档，表面上减少文档轮次 | 安全、测试和迁移继续缺少稳定接口输入；容易让 URL、框架 DTO 或 HTTP 默认行为反向塑造业务语义 |

影响范围：接口评审状态、后续安全/测试/迁移/恢复输入，以及实现准备阶段的工作拆分。

不影响范围：236 个需求事实、40 个用户故事、27 条 SRS 全局不变量、29 个状态机、306 条转换、13 条故障规则、54 条 NFR、12＋3 个模块、8 类事务、ADR-001 至 ADR-014、`DATA-Q-001` 至 `DATA-Q-014`、Casdoor 当前权威和代码开工门。

方案 A 已确认，但不等于选择任何 API 风格、ORM、迁移框架、Casdoor SDK 或依赖版本，更不构成代码开工批准。

### IFC-Q-002：站内信恢复后的积压补投顺序与并行边界

状态：已确认。2026-07-31，需求方选择方案 A。

含义：上游已经要求站内信恢复后按原事件时间补投全部积压通知、逻辑事件去重且不得重复业务，但尚未冻结全平台/多社团同时恢复时是否使用一个全局严格队列，以及如何避免单个大范围积压阻塞其他社团或收件人。

| 方案 | 逻辑合同 | 优点 | 缺点/风险 |
|---|---|---|---|
| A. 范围与收件人内有序、跨范围公平并行（建议） | 每个关闭范围内，同一收件人按原事件时间升序补投，时间相同时按稳定逻辑事件标识排序；不同社团范围和不同收件人可公平并行，使用有界批次、恢复水位和逻辑事件幂等；并行只改变投递调度，不改变通知事实或原事件时间 | 用户时间线稳定，避免单个大积压拖住全平台；容易扩容并证明不漏不重 | 需要维护分区水位、公平调度和跨工作器租约测试，不提供一个简单的全局完成序号 |
| B. 全平台严格按原事件时间串行 | 所有恢复范围共用一个全局队列，严格按原事件时间及稳定标识补投 | 全局顺序最直观，审计单一 | 任一大社团、慢收件人或坏任务可能阻塞其他范围；恢复吞吐和故障隔离较差 |
| C. 只保证最终补投，不保证收件人内顺序 | 任务可任意并行，只依赖幂等确保最终送达 | 吞吐最高，实现较少 | 同一用户可能先看到后续结果再看到前置通知，不足以落实“按原事件时间补投” |

影响范围：`IFC-TX-005`、`IFC-QRY-005`、通知任务租约、恢复水位、批量大小、内置状态和通知失败/恢复测试。

不影响范围：通知事实和收件人快照的原子保存、邮件资格、权益业务结果、已读状态、通知保留、站内信关闭范围、API 风格和代码开工门。

本问题是传输中立的投递调度合同，不选择队列产品、工作器数量、批量数值或具体实现框架，也不新增通知事件或收件人。

确认结论已形成 `IFC-NTF-001`，作为 `IFC-TX-005`、`IFC-QRY-005`、通知任务租约和恢复测试的共同输入。
