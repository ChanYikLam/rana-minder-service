## 3. 通用跨组件信封与不变量

### 3.1 关联标识

`XCC-GEN-001`：一次跨组件处理必须能够关联下列标识，且不得混同：

| 标识 | 用途 | 禁止替代 |
|---|---|---|
| 业务对象及对象版本 | 定位当前权威对象和竞争版本 | 不替代业务幂等键 |
| 业务命令或业务意图标识 | 定位一次用户或系统业务意图 | 不替代请求追踪或任务尝试 |
| 业务幂等键及规范化摘要 | 汇聚客户端重试、后台重试和恢复重放 | 不编码个人信息，不跨主体或作用域复用 |
| 请求追踪及父追踪 | 关联入口请求和派生调用 | 不决定业务是否成功 |
| 任务及尝试标识 | 定位持久任务、租约和单次尝试 | 不成为领域状态或授权依据 |
| 外部请求或对象定位 | 关联 Casdoor、邮件或对象字节 | 不成为本地业务权威或永久访问凭据 |
| 证据及决定记录 | 关联实际测试、运维和验收决定 | 不由普通运行日志单独充当 |

### 3.2 权威、授权与版本

`XCC-GEN-002`：每个入口、异步尝试、文件访问、导出下载、恢复重放和人工重试均从当前可信身份或受控系统身份重新建立最小作用域，并按当前对象、状态、版本、角色、任务、字段权限、安全开关、删除状态和依赖状态重新校验。旧页面、旧通知、旧缓存、旧短链、旧导出申请、旧任务权限或申请时角色不能永久放权。

### 3.3 本地提交与外部执行顺序

`XCC-GEN-003`：适用 ADR-003 的命令必须先在 PostgreSQL 本地权威事务中保存全部必需业务事实、不可变历史、关键审计、通知事实、快照、业务意图、幂等依据和持久任务，再允许提交后动作开始。Casdoor、对象存储、文件检查、邮件和导出生成均不伪装为分布式原子事务。若任一必需本地事实保存失败，业务保持提交前状态，且不得形成成功历史或成功结果。

### 3.4 快照和不可变边界

`XCC-GEN-004`：表单发布版本、正式提交修订、收件人、模板/发件身份、批次目标、导出数据与字段范围、删除范围和配置发布均按上游要求保存不可变版本或申请时快照。快照用于还原历史和限制执行范围，不能替代执行或下载时的当前授权、当前删除状态和当前安全限制。

### 3.5 异步执行与结果收口

`XCC-GEN-005`：提交后动作以 PostgreSQL 持久任务/事务发件箱为权威，按至少一次执行和有版本租约设计。每次尝试必须先重检 `XCC-GEN-002`；重复领取、租约过期、进程崩溃、迟到响应、重复回调和恢复重放必须收敛到至多一份有效业务结果。外部结果不确定时先可信回读或查询，再决定完成、重试、补偿、永久失败或人工处置，不得盲目重放。

### 3.6 结果语义

`XCC-GEN-006`：组件间及面向调用方的结果至少区分“已完成、已受理/处理中、已拒绝、并发冲突、依赖不可用、可重试失败、结果不确定、永久失败或需人工处置”。未完成产物不可下载、不可用于授权、不可作为统计或恢复通过证据。状态过期或来源不可确认时显示“未知”，不得沿用最近成功伪装健康。

### 3.7 审计、运行证据与验收证据

`XCC-GEN-007`：关键业务审计与对应本地命令同事务保存且不可由应用管理员改删；任务尝试和普通运行日志只保存脱敏技术证据，不能替代业务审计。验收决定必须引用实际执行记录、环境、版本、步骤、结果、脱敏原始证据和复核角色。未提供实际证据时状态只能为“未执行”或“结果未知”，不能为“通过”。
