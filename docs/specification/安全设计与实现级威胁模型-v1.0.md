## 1. 文档定位、权威顺序与编号

### 1.1 文档定位

本文把已经确认的产品事实、SRS 规则、架构决策、数据约束、接口契约和 Casdoor 集成契约转化为实现级安全设计输入。本文不是新的产品需求来源，不改变角色、状态机、通知、期限、保留期、自动限制行为或外部系统权威。

发生冲突时，严格按以下顺序处理：

需求事实 > PRD > SRS > 架构/ADR > 数据模型与约束 > 接口契约 > Casdoor 集成契约 > 本安全设计 > 测试与实现。

本文适用于安全测试设计、迁移设计、实现准备、部署准备和恢复演练。需求方已于 2026-07-31 明确确认第一轮收口；后续变更仍须服从本文权威顺序，不得以第一轮完成冒充控制已经实现、测试已经执行或代码开工门已经开启。

### 1.2 规则属性

| 属性 | 含义 | 本文处理方式 |
|---|---|---|
| 产品事实与 SRS 安全规则 | 用户可见行为、角色、状态、失败、通知、期限和保留边界 | 只引用，不改写、不扩张 |
| 已接受架构、数据、接口和 Casdoor 约束 | 模块、事务、存储、作用域、RLS、任务、文件、错误和集成边界 | 作为强制前置条件 |

| 待确认技术选择 | 机制、组件、具体数值、学校实例能力和部署参数 | 放入 SEC-Q-* 或部署前证据门，不冒充已确认规则 |

本轮不选择 REST、GraphQL、RPC、URL、HTTP 状态码、公开错误信封、认证库、会话库、Casdoor SDK、ORM、迁移框架、扫描器、密钥提供器、限流组件、UI 库或具体依赖版本。Vue、NestJS、PostgreSQL、OIDC、Casdoor 或浏览器的默认行为均不能替代本文控制。

本轮未使用外部资料创建安全规则；本地权威文档已经足以形成草案。后续若核对通用机制，只能使用正式 OIDC/OAuth 规范、OWASP、PostgreSQL 官方文档和 Casdoor v3.108.0 对应官方资料，并标注“外部事实、设计推导或建议”；官方资料仍不能替代学校真实实例证据。

| SEC-AST-005 | 联合活动锁定参与关系、共享材料、参与社团私有字段、作者社团和结论 | 联合域内最小共享、私有域隔离、作者归属不变 | 非参与社团、其他参与社团私有投影、总数侧信道 |
| SEC-AST-006 | 表单目录、固定业务骨架、JSONB 动态答案、正式修订和附件引用 | 版本化、强类型、字段授权、历史不可改写 | 未登记字段、系统秘密字段、任意表达式执行 |
| SEC-AST-007 | 文件原件、派生预览、检查结果、短期访问证据、水印和删除状态 | 隔离、完整性、当前授权、撤权优先、可恢复删除 | 公共 Bucket、永久链接、邮件附件、未检查访问 |
| SEC-AST-008 | 业务命令、幂等键、对象版本、任务意图、租约、批次冻结目标和结果 | 单一业务结果、防重放、防旧租约提交、结果引用授权 | 跨主体复用、追踪编号替代幂等键 |
| SEC-AST-009 | 业务审计、安全事件、网络运行日志、普通运行日志、任务尝试和状态页证据 | 分层、最少内容、正确保留、访问受控 | 令牌、密钥、完整外部响应、附件正文、完整联系方式 |
| SEC-AST-010 | 外置配置、服务账号、秘密引用、受控加密材料、根密钥引用和轮换状态 | 浏览器零暴露、最小权限、可轮换、可恢复 | 仓库、镜像、浏览器、日志、公开发布物 |
| SEC-AST-011 | 删除执行清单、备份、恢复点、删除重放和恢复批准 | 已删不复现、旧权限不复活、恢复前写入关闭 | 可直接服务业务的备份副本、绕过当前授权的恢复环境 |
| SEC-AST-012 | 搜索、筛选、统计、个人中心、工作台、缓存和读模型 | 可重建、非权威、权限裁剪、失权后失效 | 权限判定输入、业务真相或跨社团枚举渠道 |

## 3. 信任主体、攻击者能力与假设

### 3.1 信任主体

| 编号 | 主体 | 信任边界 |
|---|---|---|
| SEC-ACT-001 | 未登录访客 | 只能使用已确认的公开能力；全部客户端输入不可信 |
| SEC-ACT-002 | 已登录普通用户 | 身份证据可被验证，但提交的标识、作用域、字段和版本仍不可信 |
| SEC-ACT-003 | 社团负责人、人事管理员、部门负责人、临时任务角色 | 只在当前社团、部门、活动、轮次或任务范围内受信任；角色名不等于对象授权 |
| SEC-ACT-004 | 超级管理员 | 是产品平台角色，不是数据库、对象存储或宿主机高权限身份；特权命令仍须完整校验 |
| SEC-ACT-005 | HTTP 应用运行单元 | 可执行请求级授权；不得依赖前端或框架默认保护 |
| SEC-ACT-006 | 后台任务运行单元 | 只能使用冻结意图、最小作用域、当前租约和对象版本；不自动继承 HTTP 请求身份 |
| SEC-ACT-007 | 数据库普通应用身份 | 受应用授权和选择性 RLS/作用域约束；不得具有 BYPASSRLS 等绕过能力 |
| SEC-ACT-008 | 迁移、维护和恢复身份 | 与普通运行身份物理或逻辑隔离，仅在受控窗口和证据门内使用 |
| SEC-ACT-009 | Casdoor、对象存储、邮件、文件检查服务和数据库 | 外部或独立依赖；响应、迟到结果和可用性均需验证，不天然可信 |

### 3.2 攻击者与故障能力

本文至少假设以下能力存在：枚举业务标识；修改客户端字段、作用域和版本；重放链接、令牌、幂等键、Webhook 或外部响应；利用旧页面、旧通知、旧缓存和旧任务；控制一个普通账号或有限管理账号；诱导浏览器发起非预期请求；提交恶意 HTML、JSON、文件、压缩包或大规模查询；制造并发、超时、连接中断、迟到响应和部分成功；利用连接池残留、特权连接、恢复副本、日志或状态页泄密；利用自动安全限制制造拒绝服务或大范围误伤。

本文不假定学校 Casdoor v3.108.0 具备未验证的 Claims、MFA、auth_time、签名事件、分页、限流、Webhook 或服务账号能力。无法由正式配置和学校实例证据证明的能力不得成为放行条件。

## 4. 信任边界、入口与外部依赖

| 编号 | 边界或入口 | 主要输入 | 默认安全结论 |
|---|---|---|---|
| SEC-BND-001 | 浏览器与 RanaMinder 前端 | 页面状态、导航、表单、文件、缓存 | 全部可被篡改；不能保存权威权限或长期秘密 |
| SEC-BND-002 | 浏览器/客户端与 HTTP 应用 | 身份证据、命令、查询、标识、版本、幂等和文件会话 | 服务端完整校验；缺失或不可信即拒绝 |
| SEC-BND-003 | HTTP 应用与 PostgreSQL | 请求身份、单目标或集合只读作用域、事务、查询和写入 | 事务内建立上下文并清理；缺失、污染或残留失败关闭 |
| SEC-BND-004 | 后台任务与 PostgreSQL | 冻结意图、租约、对象版本、重试和结果 | 每次尝试验证最小作用域、当前租约和当前条件 |
| SEC-BND-005 | RanaMinder 与 Casdoor v3.108.0 | OIDC 身份、账号/Group 读取、关系写入、读回、对账 | 当前账号/Group 以可信读回为准；未确认不授新权限 |
| SEC-BND-006 | RanaMinder 与对象存储/文件检查/预览 | 文件字节、对象键、检查、派生预览和删除 | 字节与元数据分离；未检查、旧版本、失权或删除中不可访问 |
| SEC-BND-007 | RanaMinder 与邮件/通知渠道 | 已保存通知事实、收件人、模板和投递结果 | 渠道不改变业务；结果不确定不得宣称投递成功 |
| SEC-BND-008 | 普通运行与迁移/维护/恢复 | 高权限身份、备份、恢复点、删除重放 | 分离授权、受控时窗、最小操作、完整证据；不得服务普通请求 |
| SEC-BND-009 | 日志、审计、状态页和支持排障 | 追踪编号、错误、安全事件、业务责任证据 | 载体分层、内容允许清单、访问控制和保留期独立 |
| SEC-BND-010 | 派生搜索/统计/缓存与权威对象 | 索引、读模型、聚合、总数和分面 | 仅可重建查询；不得放权，详情与下载必须回源重验 |

外部依赖发生失败、超时、连接中断、结果不确定、迟到响应或恢复时，必须保持真实状态。写后读回、周期对账、补偿和恢复只能收敛既有业务意图，不能创建新权限或新产品行为。

## 6. 身份认证、会话与重新认证边界

### 6.1 普通登录与会话建立

1. 只有被配置且经部署证据验证的学校 Casdoor v3.108.0 实例可作为签发方。运行实例指纹、签发方标识或发现结果与配置不一致时，不建立新会话，高风险操作和 Casdoor 写入保持关闭。
2. 服务端必须验证签发方、受众、主体绑定、签名与密钥来源、令牌时效、账号状态以及防登录流程混淆所需的请求关联证据。算法、库、会话载体和具体参数留到实现准备评审。
3. 本地账号映射必须以稳定的外部主体绑定为基础；可变姓名、邮箱、学号展示值不得单独替代主体绑定。无法证明主体稳定性时不得自动合并本地历史。
4. 会话只保存继续验证当前身份和授权所需的最小证据。浏览器不能持有 Casdoor 服务账号秘密、对象存储长期凭据或可跨主体复用的高风险授权证明。
5. 登录成功不等于具有任何社团权限。每个受保护请求仍执行 SEC-CTL-005。

### 6.2 撤销、禁用、删除与恢复

账号可信确认禁用或删除后立即禁止登录、终止本地会话并撤销当前访问，不适用 15 分钟宽限。Casdoor 暂不可确认时严格沿用 SRS-FAIL-001 的三类最小白名单；超时后仅公开页面可用。账号恢复后要求重新登录并按当前关系授权，不自动恢复已结束业务、已撤销任务、历史角色、旧短链或缓存。

会话撤销必须传播到 HTTP 请求、后台任务的新尝试、文件访问、导出下载和高风险命令。已经合法提交的业务历史不因撤权删除；尚未可信提交的操作不得在恢复时自动当作成功。

### 6.3 最近 10 分钟重新认证

重新认证证据只证明认证新鲜度，不替代当前 Group、领域权限、对象状态、版本、原因、影响预览和确认。证据必须可验证地绑定当前主体、认证时刻、当前执行链及其适用的高风险命令上下文，不能由客户端自报时间或旧页面缓存生成。

若学校实例能提供并经实测证明可信的认证时间或认证强度证据，可据此建立等价证明；若不能，则必须通过学校实例可验证的重新认证流程形成等价可信证据。无法证明最近 10 分钟、实例指纹不一致、当前 Group 不可确认、证据过期/复用/跨主体、权限变化或对象版本冲突时，高风险命令失败关闭。

正式环境超级管理员多因素认证要求来自既有 SRS；学校 v3.108.0 的实际能力和配置必须在部署前验证，不能因官方源码存在相关能力就认定学校实例已经启用。

## 7. 逐请求授权与多租户/联合域

### 7.1 授权计算

每个受保护请求至少按以下顺序重新计算：

1. 当前身份、会话有效性、账号是否禁用/删除及故障降级状态；
2. 当前 Casdoor Group 新鲜度是否满足普通或权限敏感请求要求；
3. 本地角色模板版本、任务是否有效、作者归属和服务端允许的操作；
4. 当前业务对象、状态机状态、期望状态、对象版本和领域前置条件；
5. 普通社团域、联合协作域、参与社团私有域、平台特权域或登记式集合只读域；
6. 记录级、字段级、附件、联系方式、内部评价、导出和特权查看权限；
7. 安全限制、文件检查/删除状态、并发和资源保护；
8. 成功后需要同事务保存的业务历史、关键审计和通知事实。

客户端提交的角色、社团、部门、任务、作者、权限列表、对象可见性、字段列表或“已确认”标志都只是待验证输入。

### 7.2 普通社团隔离

普通社团读写以单一目标社团为结构边界。服务端对象查询、关系查询、计数、分面、导出、统计和附件访问必须使用同一作用域；先按全局标识取对象再在应用层“补查权限”的路径不得造成无权对象存在性或内容泄漏。对象标识可猜测、连续或被客户端替换时，授权结果仍不改变。

### 7.3 联合协作域

联合协作域只能由首次公布时锁定的参与社团关系建立。共享材料在联合域内按业务规则投影；参与社团私有字段、作者所属社团、独立结论、任务范围和联系方式继续按独立条件求交。社团停用不删除参与身份和作者历史，但立即撤销该社团当前联合访问。

列表投影不能替代详情授权；详情、文件、导出和命令执行时必须重验参与关系、字段、作者、任务和对象状态。不得通过联合对象反向枚举其他社团私有对象、总数、分面或错误差异。

### 7.4 派生入口与失权传播

搜索、筛选、统计、个人中心、工作台、通知和缓存都不是授权权威。派生结果可以因刷新延迟短暂不完整，但不能因旧数据继续放权。点击旧页面、旧通知、旧链接、旧搜索结果或旧导出时，必须回到当前权威对象重新授权；无权时按存在性隐藏规则拒绝。

## 8. PostgreSQL、选择性 RLS 与后台任务

### 8.1 应用授权与数据库约束分工

应用层负责角色、任务、作者、状态机、字段和命令语义；数据库结构性约束和普通社团业务表选择性 RLS 负责缩小可触及记录集合。RLS 不是完整业务授权，应用授权也不能成为绕过数据库隔离的理由。

单个 PostgreSQL 数据库和统一应用业务 Schema 不等于模块间可任意读写。12 个领域模块和 3 个平台模块继续遵守数据所有权与模块访问规则；跨模块读取、命令和事务只能通过已确认契约进入，派生查询不能成为绕过所有权的共享数据层。

### 8.2 连接上下文

单目标读写上下文只允许一个明确目标作用域；登记式集合只读上下文只能包含服务端根据当前授权冻结的集合，不能由客户端任意上传社团清单。上下文必须在数据库事务内由服务端建立、验证和绑定，并在提交、回滚、异常和连接归还前清理。

缺失、非法、过期、与命令不一致或检测到残留上下文时，请求失败关闭且连接不得继续服务普通请求，直到清理和验证成功。验证必须覆盖连接池复用、并发请求、异常回滚、嵌套调用、后台任务和超时取消，证明不会跨请求、跨用户或跨社团残留。

### 8.3 绕过身份与维护路径

普通应用和后台任务身份不得拥有绕过 RLS 或等价的无条件全表访问能力。迁移、维护、恢复身份必须与普通运行隔离，限定用途、环境、时窗和批准，记录实际目标与结果；恢复副本不得直接接入普通流量。产品超级管理员身份不能映射为数据库高权限身份。

### 8.4 任务、租约和结果提交

任务创建时冻结业务意图、目标、作用域、参数摘要、对象版本和业务幂等键；每次领取取得有版本的租约。工作者提交结果时同时验证任务仍为当前尝试、租约未被取代、对象版本和关键授权条件仍有效。租约过期后旧工作者的迟到提交必须失败，不能覆盖新租约结果。

后台任务只获得完成该意图所需的最小读写范围。任务不能把单目标扩大为集合、把冻结集合扩大为新查询结果、把申请时权限变成永久权限，或复用其他主体的成功结果。

## 9. 高风险命令安全合同

本文承接 SRS 第三轮 8.2 的 18 类高风险命令目录，不增加或删除命令类型。其中上游明确要求最近 10 分钟重新认证的命令继续使用该门；上游明确“现有事实未列入 10 分钟清单”的恢复类命令不得由本文擅自升级产品行为，但仍执行当前身份、Group、权限、状态、原因、版本和审计规则。

所有高风险命令按以下前置和后置条件执行：

| 阶段 | 必须满足 |
|---|---|
| 预览前 | 当前身份、实例指纹、账号、当前 Group、平台角色和目标作用域可信 |
| 确认前 | 目标主体、实际影响范围、对象版本、权限版本和不可逆/不可召回边界已展示 |
| 提交前 | 原因、明确确认、适用时最近 10 分钟重新认证、当前 Group 实时核验和期望版本仍有效 |
| 本地提交 | 命令结果、必要历史、不可变特权审计和上游要求的通知事实同成同败 |
| 外部执行 | 先保存意图；响应未知先回读；未确认不授新权限或宣称成功 |
| 失败 | Casdoor 不可确认、指纹不一致、权限变化、证据过期/复用、预览或对象版本变化时零成功副作用并要求重新开始 |

审计至少关联操作者、当时角色/作用域、目标、旧值/新值必要差异、原因、预览/对象版本、认证和 Group 证据引用、请求追踪、业务幂等键及结果，但不保存令牌、密钥、附件正文或完整个人资料。

## 10. 错误、拒绝与信息披露

错误继续使用 IFC-ERR-001 至 IFC-ERR-016 的传输中立分类；本文不选择 HTTP 状态码或公开错误信封。

1. 对无权对象和本就不存在对象使用不会泄露存在性的外部结果；内部安全证据可记录脱敏拒绝类别和安全追踪编号。
2. 认证失败、重新认证不足、无权、作用域不匹配、对象不可见、版本冲突、幂等冲突、依赖未知和提交失败必须在内部分类上可区分，但外部细节只暴露用户可采取下一步所需的最小信息。
3. 错误不得包含数据库/对象存储键、内部路径、堆栈、策略表达式、Group 全量、其他社团标识、完整外部响应、令牌、秘密或阈值。
4. 安全追踪编号不能编码用户、社团、权限或秘密；支持人员仍须按当前权限读取对应证据。
5. 对跨社团枚举、总数、分面和不同拒绝路径的响应体、缓存和可观察时序进行差异测试；机制实现可有合理差异，但不能稳定泄露无权对象事实。

## 11. 文件安全

### 11.1 上传、隔离和检查

文件字节存 S3 兼容对象存储，PostgreSQL 保存元数据、不可变应用文件版本、引用、检查、状态和删除清单。沿用 DATA-Q-012：每个隔离部署环境使用待检查隔离区、权威原件区和临时派生区三个私有 Bucket；开发、测试/验收和生产不共享 Bucket、凭据或备份。同一环境不按社团拆 Bucket，租户隔离仍由当前业务授权、数据库引用和字段权限实现。

对象键由服务端生成不少于 128 位有效熵的高熵随机定位符，只写一次且不编码用户、学号、社团、业务对象、原始文件名、权限或内容摘要；客户端不能提交或复用对象键。应用级不可变文件版本是唯一业务版本，三个在线 Bucket 不启用对象存储原生 Versioning 或 Object Lock；具体 Bucket 名称、对象存储产品和 create-only 等价实现证据留到部署验证。

上传前验证当前业务对象和字段允许文件、上传会话与主体绑定、数量和声明大小在现有配置范围。完成上传后以实际字节重新识别类型和大小，不信任扩展名、文件名或客户端 MIME。文件名仅作显示数据并按不影响存储键、响应或日志结构的方式处理。

临时上传、原件、派生预览和待删除对象始终位于私有边界。检查覆盖恶意内容、不合规类型、内容嗅探差异、压缩包嵌套/解压资源、解析器异常和转换资源消耗；具体扫描器、转换器、限制数值和对象存储产品留待后续评审。任何检查步骤未完成、超时、结果不可信或版本不匹配时保持不可访问。

### 11.2 预览、下载和短期访问

原件与派生预览使用独立版本和引用；预览失败不能改变原件状态，派生内容也不能替代原件完整性证据。每次预览或下载重验当前业务对象、字段权限、文件版本、检查状态、删除状态、社团/联合关系、任务和安全限制。必要水印只作为追责和最小披露辅助，不能替代授权或改变原件。

短期访问证据必须绑定文件版本、允许操作和有效期，并避免在公开、可转发或可被不适当载体持久保存的位置暴露。旧短链、任务结束、字段失权、社团停用、文件隔离或正式删除开始后拒绝访问。

### 11.3 清理、正式删除与恢复

清理和正式删除先撤销业务访问，再推进数据库、对象、预览、缓存、索引和未过期导出步骤。清理失败保持不可访问且继续重试，不回退为可用。恢复后以数据库权威引用、文件版本、检查状态、删除清单和当前授权重新核验；备份或旧对象版本不能直接放行。

## 12. 动态表单与 JSONB

1. 身份、业务对象、作用域、状态、审批、关系、邀请、任期、权限和时间保存在固定强类型骨架；JSONB 只承载版本化目录允许的动态答案。
2. 每次保存和提交按目标表单版本验证稳定字段标识、类型、允许值、大小、深度、对象引用、条件和字段权限。未知字段、同名覆盖、类型混淆、越界结构和无权字段拒绝，不以“保留后用”为由原样落库。
3. 客户端不能提供任意 JSONPath、查询表达式、模板表达式或脚本参与数据库或业务执行。允许的查询和计算必须来自服务端登记目录并绑定字段类型和作用域。
4. 条件隐藏由服务端重算；客户端回传隐藏旧值不能进入新修订。系统秘密、密码、验证码、令牌、服务账号和密钥不能成为字段、答案、模板变量或导出内容。
5. 对象选择在展示和提交时均按当前作用域过滤和重验，防止伪造标识、跨社团残留或复制旧引用。
6. 安全控制不得擅自改变正式提交修订、附件、活动快照和原提交者本人可见下限；事实纠错和正式删除继续按上游规则执行。

## 13. 幂等、批量、并发与通知恢复

幂等键必须绑定当前主体、操作类型、作用域、目标、参数摘要和业务意图。服务端比较同键请求的规范化参数；同键异参、跨用户/社团复用、结果对象已失权或摘要冲突时拒绝。追踪编号、任务编号和外部请求编号可关联业务幂等键，但不能互相替代。

受控批量先冻结单一社团、单一操作/业务类型、目标 ID、参数、对象版本、预览版本和影响范围。执行时每项重新鉴权、检查当前状态/版本并独立提交；成功项不回滚，失败项结构化保留，重试只能包含原失败项且继续使用原业务幂等语义。任何重新查询筛选结果、加入新对象或扩大字段的行为都必须形成新预览和新确认。

PostgreSQL 权威任务按至少一次执行设计；重复尝试必须收敛到单一业务结果。外部副作用在响应不确定时先回读，不能盲重放。站内信恢复严格承接 IFC-NTF-001：通知事实和收件人保持，恢复按原事件时间幂等补投，绝不重放原业务。

|---|---|---|

Webhook 默认关闭。若未来启用，只能触发受控刷新或对账，不能直接禁用账号、增删 Group、改变成员/职位、发布结论或恢复权限。缺失、重复、迟到、乱序、伪造和重放均通过可信读回收敛；学校实例没有可证明的事件签名、唯一标识或顺序能力时，不得自行假定存在。

## 15. 秘密与配置

1. 部署目录使用一份外置配置文件并以只读方式挂载；环境差异通过配置表达，不在源码、镜像或公开文档硬编码学校信息和秘密。
2. 配置中的秘密仅保存外部引用或服务端受控密文；根密钥只以外置版本化引用提供，不能与密文一起进入数据库备份、仓库或镜像。
3. Casdoor、数据库、对象存储、邮件和文件检查服务账号分别最小授权，不共享全能凭据；读取、写入、轮换和撤销责任分离到实际需要的运行单元。
4. 轮换必须支持新旧版本的受控过渡、失败回滚和恢复验证，但不得把旧明文重新写入普通配置或日志。根密钥丢失或不可验证时，受影响能力失败关闭并进入恢复流程。
5. 浏览器、页面源、前端构建物、URL/可导航参数、通知、错误、普通日志、审计和状态页均不得暴露服务秘密、令牌、私钥或完整外部响应。
6. 日志采用字段允许清单和错误脱敏；疑似秘密在落盘前拒绝或移除，不能先写原文再依赖后续清理。

数据库托管秘密的加密算法沿用 DATA-Q-014 已确认的 AES-256-GCM、数据库外版本化密钥环和强类型秘密引用；这是既有数据约束的承接，不在本文重新选型。具体密钥提供器、秘密管理产品和加密库仍待实现准备评审；恢复旧备份后必须按既有边界重新录入或轮换应用秘密。

## 17. 滥用与自动安全限制

| 场景 | 风险信号 | 允许的最小控制 | 禁止行为 |
|---|---|---|---|
| 登录 | 可信严重认证/会话事件，或时间窗内异常失败 | 终止可疑会话、限制风险上下文；低可信信号只记录 | 不因客户端自报立即大范围限权 |
| 搜索/筛选/统计 | 跨社团离散对象、异常频率、总数/分面探测、昂贵组合 | 对相关查询施加版本化资源预算、限流或暂停 | 不泄露阈值，不改变业务结果 |
| 导出/批量 | 超范围目标、重复预览、并发生成、同键异参 | 冻结范围、单项授权、队列/并发保护、当前权限重验 | 不自动扩展目标或回滚成功项 |
| 文件 | 大量不同附件、短链探测、压缩/转换资源异常 | 限制相关预览/下载/上传，失效风险短链，保持文件隔离 | 不删除正式文件或放行未检查内容 |
| 特权查看 | 无业务任务的大范围详情或联系方式读取 | 当前权限、原因/范围证据、审计和最小范围限制 | 不把超级管理员变为数据库全权身份 |

事件判定保存规则版本、聚合窗口、必要脱敏信号、可信度、命中原因、限制范围和结果。具体阈值、窗口和限流数值留待基于容量与攻击样本的配置基线，不创建验证码、封禁期限或新用户行为。

自动响应只限制相关查询、下载、导出或可疑会话，不改变申请、录取、邀请、成员、部门、职位或评价。解除由上游已确认主体执行并保留说明。控制必须有误伤恢复、范围收敛和防攻击者利用限制制造拒绝服务的证据。

## 19. 删除、备份与恢复

正式删除先撤销访问并冻结删除范围、对象版本和跨存储清单。数据库、附件、预览、缓存、索引和未过期导出逐步删除；任一步失败都保持“未完成”，已完成步骤不通过补偿恢复个人数据，未完成步骤幂等重试。最小删除审计不保留被删正文。

备份静态和传输保护、默认 30 天及 30 至 60 天配置范围沿用 SRS；备份不能成为普通查询、导出或文件下载入口。恢复在隔离边界完成，先验证恢复点和一致性，再重放删除清单、核对附件引用/字节/预览、执行 Casdoor 全量对账并处理同步异常。恢复门通过前不得开放普通写入，高风险和权限敏感操作继续失败关闭。

恢复后的旧会话、旧 Group 快照、旧任务租约、旧短链、旧缓存和旧导出不自动复活。所有业务访问仍按恢复后的当前账号、Group、本地授权、对象状态、字段和删除状态重验。

## 28. SEC-Q-001 实现中立安全合同的冻结时点（已关闭：采用方案 A）

### 28.1 问题含义

在认证库、会话实现、API 风格和安全组件尚未选型时，是否先冻结本文的实现中立控制目标、威胁—控制—验证证据、失败关闭规则和安全前后置条件，而把具体 CSRF/CORS/CSP/Cookie 方案、限流数值、密钥提供器、漏洞扫描工具及依赖版本留到实现准备或部署阶段评审。

### 28.2 推荐方案 A

现在冻结实现中立安全合同，使安全测试、迁移和部署恢复设计获得稳定输入；具体机制和数值在传输形态、学校实例能力和验证证据明确后再选择。

优点：

- 不会让未确认的 API、会话、部署和依赖选择反向改变产品、接口或架构边界；
- 可以立即展开负向测试、迁移不变量、恢复门和学校实例证据；
- 机制可以按实际威胁和环境证据比较，并保留替换空间。

缺点：

- 进入编码前仍需一次实现准备评审；
- 当前不能给出可直接复制的中间件配置、数值或依赖清单。

### 28.3 备选方案 B

现在同时选择具体安全机制和工具。

优点：实现路径更直接，部署清单可更早形成。

缺点：API、会话、域名/部署拓扑和学校实例能力尚未冻结，容易把工具默认行为误写为产品规则，并产生较高返工和错误兼容风险。

### 28.4 影响范围

选择 A 将冻结本文 SEC-THR、SEC-CTL、SEC-VER、失败关闭规则、前后置条件和追踪入口；具体机制、参数、组件和版本继续待评审。选择 B 则需要在本轮扩大范围，先完成会话/API/部署/组件选型及相应 ADR 或实现决策，再重新核对本文。

### 28.5 不影响范围

无论选择 A 或 B，均不改变 236 个需求事实、PRD/SRS、29 个状态机、306 条转换、18 类高风险命令、8 类事务边界、13 条故障规则、54 条 NFR、ADR-001 至 ADR-014、DATA/IFC/CAS 已确认结论、Casdoor v3.108.0 基线和既有期限/保留规则。本段形成时代码开工门关闭；需求方后续仅通过 `GOV-CODE-WAIVER-001` 改变代码编写授权，不改变上述安全合同。

关闭记录：2026-07-31，需求方确认采用方案 A。本文冻结实现中立的安全控制目标、威胁—控制—验证证据、失败关闭规则和安全前后置条件；具体 CSRF、CORS、CSP、Cookie 方案、限流数值、密钥提供器、漏洞扫描工具及依赖版本留到实现准备或部署阶段评审。该单项关闭本身不等于安全设计第一轮收口；需求方随后已另行明确确认第一轮收口。
