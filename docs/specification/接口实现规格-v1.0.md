## 2. 传输层基线（与前端实际调用对齐）

`API-GEN-001`：以下基线直接取自接口清单，后端实现必须兼容，前端不得因后端实现而改动调用形态：

| 项 | 基线 | 来源 |
|---|---|---|
| API 前缀 | `/api`（当前无版本前缀；版本策略见 `API-Q-002`） | 清单全部端点 |
| 请求信封 | `{ action?, targetId?, expectedVersion?, idempotencyKey?, input }` | 清单 §1.1 |
| 成功响应 | `{ "code": 0, "data": {...} }`（data 可为 null） | 清单 §1.2 |
| 失败响应 | `{ "code": "IFC-ERR-xxx", "message": "脱敏文案", "supportId": "MOCK-XXXX", "fieldErrors"?: {...} }` | 清单 §1.2 |
| 任务式响应（202） | `{ "code": "IFC-ERR-013"\|"IFC-ERR-014", "data": { "taskId": "...", "status": "processing" } }` | 清单 §1.2 |
| 列表分页 | `{ items: [...], nextCursor: string \| null }` | 清单 §1.4 |
| 认证 | `Authorization: Bearer`；会话经 `GET /api/auth/session`；重认证 proof 经 `POST /api/auth/reauth` 随 `input.reauthProof` 提交 | 清单 §1.6、§4 |
| 错误码 | 17 类 `IFC-ERR-001~017`（含清单新增的 `IFC-ERR-017` 请求体解析失败） | 清单 §1.3 |
| 文件上传例外 | `POST /api/files/upload` 直接发送 `FormData`，无信封包装 | 清单 §1.1、§9 |
| 乐观锁 | 请求信封顶层 `expectedVersion` 字段（非 HTTP 头）；不匹配 → `409 IFC-ERR-008` | 清单 §1.1 |
| 幂等 | 请求信封顶层 `idempotencyKey` 字段；同键幂等返回 → `IFC-ERR-009` 语义 | 清单 §1.1 |

`API-GEN-002`：接口契约 `IFC-GEN-001` 逻辑信息与传输落地的映射：

| `IFC-GEN-001` 信息 | 传输落地 | 说明 |
|---|---|---|
| 操作者 | `Authorization: Bearer <token>`；会话由 `GET /api/auth/session` 建立 | 服务端认证结果；账号禁用时拒绝建立会话（`403 IFC-ERR-011`） |
| 操作 | HTTP 方法＋路径；业务动作经请求信封 `action` 表达 | 未登记的路径/动作拒绝 |
| 目标 | 路径参数（`:clubId`、`:activityId`、`:memberId` 等）或信封 `targetId` | 调用方只提供候选标识，服务端回源验证（`IFC-DATA-001`） |
| 作用域 | 普通社团：路径 `:clubId`（客户端提示，服务端冻结）；联合域：`:jointId`；平台：`/api/admin/*` | 服务端按目标对象与当前授权冻结；越界 → `403 IFC-ERR-004`（`RME` 映射见 §7） |
| 期望状态与版本 | 信封顶层 `expectedVersion`；关联版本（预览、窗口、配置）随 `input.previewVersion` 等字段声明 | 不匹配 → `409 IFC-ERR-008` |
| 业务输入 | 信封 `input` 内强类型字段 | 未知/非法字段 → `422 IFC-ERR-005` |
| 幂等信息 | 信封顶层 `idempotencyKey`（表单提交等使用；其余端点由客户端自动生成） | 语义见 §8 |
| 增强认证证据 | `POST /api/auth/reauth` 签发一次性 `proof`（TTL 10 分钟、消费即失效），随 `input.reauthProof` 提交 | 失效 → `401 IFC-ERR-002` |
| 追踪信息 | 响应/日志中的安全追踪编号（`supportId`） | 不得替代幂等键 |

## 3. 请求信封规范

`API-GEN-003`：所有 `POST / PUT / DELETE` 请求体统一信封（文件上传除外）：

```json
{
  "action": "string?",
  "targetId": "string?",
  "expectedVersion": "number?",
  "idempotencyKey": "string?",
  "input": { "...": "业务字段" }
}
```

1. 业务字段一律位于 `input` 内；后端实现必须按 `input` 解析，**不兼容**平铺写法（mock 部分端点的平铺兼容是过渡行为，后端不做）；
2. `expectedVersion` 不匹配 → `409 IFC-ERR-008`，响应体携带当前数据（如 `currentData`）供刷新；
3. `idempotencyKey` 相同请求幂等返回原结果（`IFC-ERR-009` 语义）；
4. 信封字段未知（非上述 5 键）→ `422 IFC-ERR-005`；
5. `GET / DELETE` 不使用信封，参数走 query 与路径；
6. 文件上传例外：`POST /api/files/upload` 发送 `FormData`（文件字节 + 元数据字段），无信封。

## 4. 响应信封规范

`API-GEN-004`：接口契约 `IFC-GEN-002` 的 6 类逻辑结果在传输层的落地：

| `IFC-GEN-002` 结果类别 | 传输形态 | HTTP 状态码 | 说明 |
|---|---|---|---|
| 已完成 | `{ "code": 0, "data": {...} }` | `200/201`（`204` 用于无内容删除类） | 返回业务结果、当前状态/版本 |
| 已受理/处理中 | `{ "code": "IFC-ERR-014", "data": { "taskId", "status": "processing" } }` | `202` | 只返回意图/任务与查询入口 |
| 已拒绝 | `{ "code": "IFC-ERR-xxx", "message", "supportId", "fieldErrors"? }` | 按 §7 映射 | 安全可披露原因 |
| 并发冲突 | `409` ＋ `IFC-ERR-008/009/010` | `409` | 返回当前版本或冲突区间供刷新 |
| 外部结果不确定 | `{ "code": "IFC-ERR-013", "data": { "taskId", "status": "processing" } }` | `202` | 先回读再重试/补偿（§11） |
| 依赖不可用 | `503` ＋ `IFC-ERR-012` | `503` | 按故障规则降级，不得伪成功 |

`API-GEN-005`：错误响应只允许包含稳定错误码、脱敏文案、`supportId`（安全追踪编号）与字段级错误（`fieldErrors`）；不得包含报名正文、内部评语、附件内容、完整联系方式、令牌、密钥、数据库结构、内部路径或其他社团对象（承接接口契约 §8 与安全设计脱敏规则）。

## 5. 认证、会话与增强认证（`API-AUTH-*`）

`API-AUTH-001`：会话建立与 Casdoor 集成（对齐清单 §1.6、§4）：

1. `GET /api/auth/casdoor/login-url`：返回 Casdoor 登录跳转地址（OIDC 授权码流程）；
2. Casdoor 回调后，前端请求 `GET /api/auth/session` 建立会话：返回 `{ user, profileGate, degraded, degradedSince, permissions, workspace }`；
3. `DELETE /api/auth/logout`（`POST` 同语义）：退出登录；
4. 账号 `disabled: true` 时拒绝建立会话 → `403 IFC-ERR-011`「账号已被禁用」；
5. Casdoor 不可用时按 `IDN-009`/`SRS-FAIL-001` 输出 15 分钟白名单降级窗口（`degraded/degradedSince`），登录路径失败关闭。

`API-AUTH-002`：资料与同步（`IFC-SM-002/003` 查询落点）：

- `GET /api/auth/profile`：本人资料（含 `version`、`syncStatus`）；
- `PUT /api/auth/profile`：保存白名单字段（信封 `expectedVersion` 乐观锁；保存即置位 `profileComplete`，`syncStatus.phone='pending'`）；
- `POST /api/auth/profile/send-email-code`、`POST /api/auth/profile/verify-email`：邮箱验证；
- `POST /api/auth/profile/sync-conflict`：资料同步冲突选择（`input: { field, chosenValue }`）。

`API-AUTH-003`：增强认证（高风险操作，`IFC-CMD-003`）：

1. `POST /api/auth/reauth`：签发一次性 `proof`（TTL 10 分钟，消费即失效）；
2. 高风险命令（权限模板发布、保留策略发布/执行、正式删除）随 `input.reauthProof` 提交；
3. `reauthProof` 缺失/失效 → `401 IFC-ERR-002`，命令不执行。

`API-AUTH-004`：后台任务与受信任调度不经过 HTTP 认证端点：后台执行单元使用服务账号身份（最小权限、独立于普通用户、可审计），任务载荷内携带冻结的作用域、源意图、对象版本与租约引用（`IFC-GEN-004` 后台单项作用域）；服务账号凭据只存在于服务端配置与秘密引用中（`ADR-010`、`DATA-Q-014`）。

## 7. 错误码与 HTTP 状态码映射（17 类全表）

`API-ERR-001`：错误码直接采用 `IFC-ERR-xxx` 字符串作为响应 `code`（对齐清单 §1.3），HTTP 状态码映射如下；错误码只增不改，本地化文案由前端按 `code` 渲染：

| 码 | HTTP | 含义 | 典型使用点（清单） |
|---|---|---|---|
| `IFC-ERR-001` | `401` | 未认证或认证失效 | 会话失效 |
| `IFC-ERR-002` | `401` | 高风险操作需重新认证 | 权限模板发布、保留策略发布/执行、正式删除（`reauthProof` 失效） |
| `IFC-ERR-003` | `403` | 无权限 | 各域 `forbidden()` |
| `IFC-ERR-004` | `403` | 作用域越界 | 工作空间不可访问 |
| `IFC-ERR-005` | `422` | 输入不合法 | 缺发布原因、删除原因、字段错误 |
| `IFC-ERR-006` | `422` | 前置条件不满足 / 业务拒绝 | 状态机守卫失败与业务校验（招新/联合/成员域主要错误；**不用 409**） |
| `IFC-ERR-007` | `409` | 状态冲突 | 纠错处置（非 submitted/overdue）；个别端点以 422 携带 fieldErrors 返回 |
| `IFC-ERR-008` | `409` | 版本 / 影响预览冲突 | 表单 `expectedVersion`、模板/保留策略/删除 `previewVersion` |
| `IFC-ERR-009` | `409` | 幂等键冲突 | 表单提交同键异参 |
| `IFC-ERR-010` | `409` | 资源竞争 | 预留（容量、单胜者竞争） |
| `IFC-ERR-011` | `403` | 安全限制 | 账号禁用（会话拒绝建立） |
| `IFC-ERR-012` | `503` | 依赖服务不可用 | 文件不存在或已过期（部分文件端点 404 复用此码） |
| `IFC-ERR-013` | `202` | 外部结果不确定 | 任务式响应 |
| `IFC-ERR-014` | `202` | 结果处理中 | 任务式响应 |
| `IFC-ERR-015` | `404` | 不存在或不可见 | 对象不存在；部门负责人越界伪装 404 |
| `IFC-ERR-016` | `500` | 安全提交失败 | 兜底 |
| `IFC-ERR-017` | `400` | 请求体解析失败 | 请求体非法（清单新增，接口契约未列） |

`API-ERR-002`：数据库约束、死锁或序列化失败必须映射为登记过的逻辑冲突（`IFC-GEN-007`）：唯一性/单胜者 → `409 IFC-ERR-010`；可安全重试的序列化失败 → `503 IFC-ERR-012`。允许重试时从认证、授权、对象状态和全部前置条件开始重试完整命令，复用同一幂等键；具体 SQLSTATE、锁等待与退避参数不属于本规格。

## 8. 幂等、对象版本与并发

`API-GEN-006`（幂等）：

1. `idempotencyKey` 位于请求信封顶层；表单提交类端点必用，其余命令端点由客户端自动生成；
2. 服务端按版本化规范化规则计算语义摘要（`IFC-GEN-006`）；键的幂等作用域包含逻辑命令类型、真实作用域与业务幂等键；
3. 同键同摘要重复提交：返回原业务结果或原处理中引用，不重复业务、通知、审计成功记录、外部写入或文件；
4. 同键异摘要：`409 IFC-ERR-009`，原结果保持；
5. 幂等记录保留期与清理进入 `API-Q-003` 评审（建议 24 小时 + 受控清理，承接 `DATA-Q-011` 临时数据规则）；
6. 业务幂等键、请求追踪编号、任务 UUID 与外部请求号分别保存，不互相替代。

`API-GEN-007`（版本与并发）：

1. 乐观锁经信封顶层 `expectedVersion` 字段承载（资料保存、表单草稿保存等）；`previewVersion` 承载影响预览版本（权限模板、保留策略、正式删除）；
2. 版本不匹配 → `409 IFC-ERR-008`，响应携带当前版本/数据要求刷新；不自动重放到新版本；
3. 单胜者竞争（邀请接受、申请撤回、名额、时间占用、负责人交接、发布指针、文件绑定与清理，见 `IFC-GEN-007` 表）由服务端同一事务边界裁决，只允许一个成功；
4. 跨对象边界（面试/邀请/结论多对象联动）的并发以清单端点标注的状态机版本规则为准（如邀请 `version` 比较并交换）。

## 13. 与上游契约的差异登记（后端实现必须处理）

接口清单以 mock 层为准，与上游逻辑契约或需求文档存在下列差异；清单已声明"冲突以后者为准并回改"，后端实现按下表结论处理，本表随实现推进更新：

### 13.1 状态机编号简写

- 清单附录 A 使用 `SM-xxx` 简写（如 `SM-REC-001`），权威编号为 `SRS-SM-xxx`；
- 后端文档、数据模型与审计必须使用权威编号 `SRS-SM-xxx`；清单保留简写仅为对照实现。

### 13.2 错误码映射差异（清单 §1.3 vs 接口契约 §8）

| 项 | 接口契约语义 | 清单映射 | 后端实现结论 |
|---|---|---|---|
| `IFC-ERR-002` 重新认证不足 | 未指定 HTTP 状态码 | `401` | 采用 `401`（与未认证一致、便于前端跳重认证）；登记 `API-Q-006` |
| `IFC-ERR-011` 安全限制 | 未指定 | `403`（账号禁用） | 采用 `403`；批量滥用限流用 `429` 的结论进入 `API-Q-006` |
| `IFC-ERR-017` 请求体解析失败 | 未列（接口契约 16 类） | `400` | 采用 `400`，补充进错误码目录 |
| 状态机守卫失败 | `IFC-ERR-007` 状态冲突 `409` | 招新/联合/成员域一律 `422 IFC-ERR-006`；纠错域 `409 IFC-ERR-007` | 维持清单事实：业务前置/状态机拒绝用 `422 IFC-ERR-006`，"当前状态不在允许集合"仅在纠错等已登记端点用 `409`；全库统一映射规则进入 `API-Q-006` |

### 13.3 mock 未校验的权限（后端必须补鉴权）

- `GET /api/admin/joint`：清单注明"mock 未校验（契约应为平台管理员）"——后端按 `platform:joint:manage`（或等价已确认权限）鉴权；

### 13.4 mock 占位与演示行为（后端不实现）

- `nextCursor` 恒为 `null`：后端实现真实游标（§9）；
