## 3. `TST-*` 编号与稳定追踪合同

`TST-*` 是下游测试设计编号，不是需求事实、用户故事、SRS、`PRD-OPT-*`、ADR、`DATA-*`、`IFC-*`、`CAS-*` 或 `SEC-*` 编号。任何 `TST-*` 都必须保留上游引用；发现产品行为歧义时返回需求层确认，达到架构决策级别时建立新 ADR，不能由测试自行决定。

| 编号族 | 规则 |
|---|---|
| `TST-SM-<nnn>-R<rrr>` | `<nnn>` 对应 `IFC-SM-<nnn>`；`<rrr>` 是该状态机在 SRS 明细中的表行序号 |
| `TST-SM-<nnn>-R<rrr>-<facet>` | 某一转换的测试分面；稳定键同时保存 SRS 状态机、当前状态、命令/触发事件和表行序号 |
| `TST-TX-001` 至 `008` | 8 类事务边界 |
| `TST-FAIL-001` 至 `013` | 13 条 `SRS-FAIL-*` |
| `TST-NFR-001` 至 `054` | 54 条 `SRS-NFR-*` |
| `TST-IFC-*`、`TST-CAS-*`、`TST-DATA-*` | 对应既有接口、Casdoor 和数据设计编号的一对一测试入口 |
| `TST-SEC-THR-*`、`TST-SEC-CTL-*`、`TST-SEC-VER-*` | 对应既有安全威胁、控制目标和验证入口 |

逐转换固定分面如下：

| 分面 | 含义 | 对每条转换的要求 |
|---|---|---|
| `NOM` | 按该转换行全部前置条件执行规范路径 | 必需 |
| `AUT` | 无权主体、错误作用域或不可确认权限 | 必需 |
| `STA` | 当前对象状态不符合该行 | 必需 |
| `VER` | 对象版本、相关版本或冻结快照不匹配 | 必需 |
| `CON` | 与冲突命令并发，验证单胜者和真实冲突结果 | 必需 |
| `REV` | 提交前或外部动作/任务执行中失权；系统触发行则验证可信来源在提交前失效 | 必需 |
| `FLT` | 适用依赖或保存点故障 | 适用时必需 |
| `TMO` | 适用调用、任务或等待点超时 | 适用时必需 |
| `UNK` | 外部结果不确定、迟到或无法可信确认 | 适用时必需 |
| `RTY` | 按原业务意图和幂等语义完整重试 | 适用时必需 |
| `CMP` | 既有规则要求补偿或异常收口 | 适用时必需 |
| `RCV` | 故障或降级后的恢复、读回、对账或重放 | 适用时必需 |

`NOM/AUT/STA/VER/CON/REV` 为 306 条转换的固定设计分面，共形成 `306 × 6 = 1,836` 个逐行基础入口。条件分面必须在逐行用例设计时依据该转换的副作用、外部依赖和上游故障规则判定；未执行时仍标记“未执行”，只有保留不适用依据后才能标记“不适用”。

## 5. 业务场景家族

| 场景 | 稳定入口 | 最低验证目标 |
|---|---|---|
| 正常 | 对应转换的 `NOM` | 只在全部前置条件满足时形成上游规定结果 |
| 拒绝 | 转换行拒绝条件、`AUT/STA/VER` | 无假成功、无禁止副作用，错误披露最小化 |
| 撤回 | SRS 中邀请、申请、纠错等撤回转换 | 仅允许状态和主体可撤回，既有历史保留 |
| 取消 | 活动、预约、窗口等取消转换 | 禁止边界、通知、审计和并发结果与上游一致 |
| 过期 | 邀请、链接、窗口、任务、下载等截止触发 | 服务端时间、版本和终态竞争单胜者 |
| 失权 | `REV` 及失权后读取矩阵 | 旧页面、旧通知、旧链接、缓存、文件和导出不继续放权 |
| 并发 | `CON` | 单胜者、冲突可见、无重复权益或重复关系 |
| 版本冲突 | `VER` | 旧对象/相关版本不覆盖新状态 |
| 故障 | `FLT`、`TST-FAIL-*` | 失败关闭、真实状态、禁止假成功 |
| 超时 | `TMO` | 超时不等于失败或成功；按上游进入未知、读回或重试 |
| 结果不确定 | `UNK` | 保持处理中/异常，先可信读回，不提前授权 |
| 重试 | `RTY` | 重新鉴权和校验完整命令，复用业务意图，不只重放最后一步 |
| 补偿 | `CMP` | 不扩大作用域，不恢复已撤权或已删除事实 |
| 恢复 | `RCV` | 读回、对账、重放、幂等和恢复门全部满足 |
| 强制处置 | 上游明确列出的强制完成、强制停用、紧急关闭和正式删除命令 | 重新认证、原因、影响预览、二次确认、实时权限和审计完整 |
| 归档 | 上游活动终态与只读归档触发 | 关闭普通编辑但保留合法纠错、历史和按当前权限读取 |
| 越权 | `AUT`、`TST-SEC-THR-001`、`TST-SEC-THR-002`、`TST-SEC-THR-003` | IDOR、跨社团、联合私有字段和字段级越权均失败 |

## 9. 54 条 NFR 的逐编号验收入口

每个 `TST-NFR-*` 一对一继承对应 `SRS-NFR-*` 行的已确认环境/输入、执行与测量方法、阈值、通过标准、证据、失败/例外边界和事实来源。本节只把这些规则深化为实现中立的执行合同，不新增性能、容量、可用性、保留期限、浏览器或 AI 承诺，不把参考硬件写成承载保证，也不选择测试工具、浏览器自动化工具、云产品、观测平台、CI 产品或依赖版本。

### 9.1 通用执行、五态结果、证据与决定合同

下列合同由 54 条 `TST-NFR-*` 每一行显式继承：

1. **前置环境与依赖**：执行记录必须列出构建/发布标识、配置版本、合成数据集、数据规模、拓扑、浏览器或运行环境，以及每个适用依赖的“可用/降级/不可用/未知”状态。缺少必要前置时只能记“阻塞”，不得降低规模或删去失败样本后判通过。
2. **可重复执行**：保存规范化步骤、负载或场景模型版本、开始/结束时间、观察窗口、并发/时钟/故障编排和随机种子（如适用）。长时间稳定运行使用单次执行计划中预先登记的观察窗口；该窗口是执行参数，不构成新的产品可用性或持续时长承诺。
3. **失败**：任一已确认阈值或通过标准不满足、证据不完整、出现禁止副作用、越权、泄密、假成功、静默丢失或用失败样本换取统计达标时，结论为“失败”。
4. **超时**：上游已有时限时按该时限判定；上游没有数值时限时，超时结果记录为“阻塞”或“失败”并保留实际时长，不得由测试自行创造通过阈值。
5. **降级**：只有上游明确允许的降级范围才可继续验收；降级不得扩大权限、伪造成功、改变业务结论或隐藏失败样本。
6. **结果未知**：外部调用、迁移、恢复、扫描或测量无法可信确认时不得判通过；必须保留未知原因、最后可信状态和后续读回/复验入口。
7. **恢复**：失败证据不得被成功重跑覆盖。恢复后重新核对前置状态，并建立独立执行记录；备份任务成功不能代替恢复通过，恢复子项成功不能代替普通写入恢复门通过。
8. **证据**：只保存脱敏配置/环境指纹、输入规模、原始结果定位、聚合报告、日志/审计/状态摘要、截图或扫描报告、失败和恢复关联；不得保存真实学生数据、秘密或完整敏感外部响应。
9. **决定**：执行者不得自行把结果改写为验收结论。复核角色检查环境、步骤、原始证据和例外依据；验收决定字段只允许“待填写/通过/失败/阻塞/不适用”，当前全部为“待填写”。

## 14. 完成定义、验收追踪与执行门

一个测试入口只有在以下条件全部满足后才能标记“通过”：

1. 上游规则和版本明确，未出现无来源行为；
2. 合成数据、角色、作用域、状态、版本、时钟和依赖条件可复现；
3. 正向结果、拒绝结果和禁止副作用均得到实际验证；
4. 适用的并发、失权、故障、超时、未知、重试、补偿和恢复已执行；
5. 请求/任务/外部调用父子追踪与业务幂等键分别可核对；
6. 证据已脱敏且不保存禁止内容；
7. 失败重跑不能覆盖原始失败证据；
8. 有权评审人给出验收结论。
9. 对 `TST-NFR-*`，还必须填写 §9.1 的依赖状态、五态判据、复核角色和验收决定，并证明相应重点场景及安全/运维交叉入口没有未说明的缺口。
