## 1. 目的与边界

本矩阵逐条回答“每项需求事实如何进入 PRD、SRS、架构/ADR、接口/Casdoor、数据约束、安全控制、测试入口以及验收状态与证据”。它用于发现遗漏、反向核验无来源表述，并在不复制第二份状态机转换正文的前提下形成可复核的下游追踪链。

本矩阵不是新的需求来源，不改变事实状态。发生冲突时，仍按“需求事实总账 → PRD → SRS → 架构/ADR → 数据、接口、安全、测试与运维”的权威顺序处理。表中的“主要落点”只列最直接的前四个位置；出现“等”表示同一事实还有其他辅助落点。

全链路追踪采用“逐事实直接映射＋家族/状态机级继承＋实际执行状态”三层表达。家族包只集中复用共同的下游合同；每个事实行仍须显式引用所属家族包，能够稳定定位到状态机、故障或 NFR 的事实还须追加直接编号。设计入口存在不等于测试或验收通过；没有实际执行记录时统一标记“未执行；证据：无”。

### 2.9 映射粒度、继承和验收状态合同

1. **逐事实直接映射**：事实已经指向稳定的 `SRS-SM-*`、`SRS-FAIL-*` 或 `SRS-NFR-*` 时，逐事实行继续给出对应的 `IFC-SM-*`、`SEC-TRC-SM-*`、`TST-SM-*`、`TST-FAIL-*` 或 `TST-NFR-*` 入口。状态机直接链只引用既有编号，不复制 306 条转换正文。
2. **家族/状态机级继承**：事实没有专属下游编号时，逐事实行引用本节的事实家族包。家族包中的编号是该家族可适用的共同合同集合；具体事实只继承与其 SRS 落点、对象、状态和操作相符的部分，不表示集合内每个编号都直接适用于每条事实。
3. **不适用**：拒绝、延期或历史裁决本身没有独立实现落点时，必须写明“不适用”的类别和上游依据。拒绝边界仍须接受范围、接口暴露、发布物或负向防回归检查；“不适用”不等于可以留空。
4. **尚待实际执行**：`TST-*`、`SEC-VER-*` 和 `OPS-VER-*` 只是设计或验证入口。没有单次执行记录、脱敏证据和复核决定时，统一写“未执行；证据：无”，不得写成通过。
5. **转换稳定定位**：`SRS-SM-* → IFC-SM-* → SEC-TRC-SM-* → TST-SM-*` 按同一序号一对一对应；每个状态机内部继续使用 `IFC-SM-000` 的“状态机＋当前状态＋命令/触发事件＋表行序号”和测试规格的 `R<rrr>` 六分面定位。覆盖 29/29 个状态机、306/306 条转换，但当前执行结果仍为 0/306。
