# RanaMinder Git 协作与代码冲突治理规范 v1.0

> 规范编号：`GOV-GIT-001`  
> 建立日期：2026-08-23  
> 适用范围：`ranaminder-service` 及后续进入编码阶段的各仓库  
> 当前状态：**建议待确认（建议稿）** —— 用户提出三项降冲突实践，本规范将其落地为团队可执行约定；正式签署前不视为已确认需求  
> 上游基线：[代码开工前置跳过与风险接受记录](../governance/代码开工前置跳过与风险接受记录-v1.0.md)、ADR-001 至 ADR-014

## 1. 目标与原则

代码冲突不是"发生了再解决"，而是"从源头减少发生、发生时低成本解决、合入前自动兜底"三道防线。

1. **减少冲突发生**：通过分支策略、任务切分、小步提交，避免多人长期改同一块代码。
2. **低成本解决**：通过 `rerere` 复用历史解决方案、`rebase` 把冲突提前到本地，避免把擦屁股留给评审人。
3. **合入前自动兜底**：通过 CI 模拟合并（merge-group）在合入前把冲突和编译/测试失败拦截在流水线里。

## 2. 三道防线

### 防线一：减少冲突发生（源头治理）

| 编号 | 规则 | 说明 |
|---|---|---|
| `GOV-GIT-001-A` | 主分支保护 | `main` 禁止直接推送，所有改动必须经 PR 合入；PR 至少 1 人评审通过且 CI 全绿 |
| `GOV-GIT-001-B` | 短生命周期分支 | 功能分支从 `main` 拉出，尽早合回；分支存活不超过 1~2 个迭代，避免长分支漂移 |
| `GOV-GIT-001-C` | 按模块切分任务 | 依 ADR-002 的 12 个领域模块边界分配任务，减少多人并发触碰同一模块/文件 |
| `GOV-GIT-001-D` | 小步提交 | 每个提交只做一件事，粒度到"能独立回滚/评审"；避免超大 PR |
| `GOV-GIT-001-E` | 避免重构与业务混提 | 格式化、重命名、脚手架升级等大规模无行为变更单独成 PR，不与业务逻辑混在一起 |

### 防线二：低成本解决冲突（个人习惯）

**规则 A —— 开启 rerere（复用冲突解决方案）**

```bash
# 全局开启后，Git 会记住你解决过的冲突模式
git config --global rerere.enabled true
```

作用：当 AI 或同事再次产生同样的冲突时，Git 自动应用上次的解决方案，你只需确认。对反复改同一批配置文件（如 `.cnb.yml`、接口契约、锁文件）尤其有效。

**规则 B —— 用 Rebase 代替 Merge（拉取时）**

不要用裸 `git pull`（默认会生成丑陋的合并提交），改用：

```bash
# 把本地改动"挪"到主干最新提交"头顶"，冲突提前在本地解决
git pull --rebase
```

或将仓库级默认行为固定下来：

```bash
# 对本仓库生效
git config pull.rebase true
git config branch.main.rebase true
```

原则：**冲突解决必须发生在发起 PR 之前、本地/自己分支上**，而不是等 PR 后让评审人替你处理合并冲突。

> 注意：对已推送的共享分支不要随意 `rebase`（会改写历史）；`rebase` 只用在尚未共享或自己独占的功能分支上。合入 `main` 推荐用 squash/merge 保留干净历史，具体在防线三约定。

### 防线三：合入前自动兜底（CI 门禁）

在 `.cnb.yml` 流水线中加入"模拟合并"步骤：把当前 PR 分支合并到 `main`（或目标分支）后再跑编译/类型检查/测试。若合并本身冲突或合并后构建/测试失败，CI 直接标红，禁止合入。

关键点：**CI 必须在"已合并到目标分支后的代码"上跑测试**，而不是只在 PR 分支上跑，否则测的是"过时的代码"。GitHub 的 `merge-group` 机制即为此设计；在 CNB 流水线中用"检出→合并→构建测试"实现等价效果。

```
# .cnb.yml 中模拟合并的等价示意
# 1. 检出目标分支 main
# 2. 将 PR 分支合并进来（git merge --no-ff）
# 3. 在合并结果上执行：安装 → 类型检查 → 构建 → 测试
# 4. 任一步失败 → CI 标红 → 阻止合入
```

## 3. 推荐落地清单

- [ ] 仓库级启用 `git config pull.rebase true`、`branch.main.rebase true`、`rerere.enabled true`。
- [ ] 建立 `.cnb.yml` 流水线，加入"模拟合并 + 构建/测试"门禁（当前仓库尚无流水线）。
- [ ] 配置 `main` 分支保护：PR 必须、CI 必须全绿、禁止直接推送。
- [ ] 将本规范要点写入贡献指南（`docs/` 侧的贡献说明），让每位协作者首日即知。
