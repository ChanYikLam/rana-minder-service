- 已在正式文档中新增独立的 `docs/frontend/` 域，避免把下游 UI/交互设计混入上游 PRD、SRS 或 ADR 的权威职责。

## 5. 实际合并顺序

1. 需求方发出“合并到正式 docs”的单独指令。
2. 冻结合并前提交、`git status`、16 个来源文件和 4 个既有待同步正式文件的 SHA-256。
3. 保留既有 `docs` 未提交/未跟踪变更，通过快照区分批次，不重置、不覆盖用户已有修改。
4. 创建 `docs/frontend/` 与 `docs/frontend/assets/wireframes/`，按 16 项映射逐文件提升。
5. 复制后、正文改写前逐项对比来源与目标 SHA-256，结果为 16/16 相同；合并执行当时 `temp` 保持 16/16 只读，后续按第 7 节记录完成来源核验与删除。
6. 重写相对链接、临时状态标签和目标文件名；不改变页面 ID、视图 ID、证据 ID、需求 ID 或状态机 ID。
7. 最小同步 `docs/README.md`、开工 TODO 与正式全链路追踪入口；不把候选依赖写成已安装或已锁定事实。
8. 执行 Markdown、本地链接、SVG XML/ID/锚点、43/43 页面、215/215 状态与 30/30 旅程步骤校验。
9. 记录合并结果；代码开工仍需满足接口、数据、安全、测试、依赖锁定和实现准备门。
