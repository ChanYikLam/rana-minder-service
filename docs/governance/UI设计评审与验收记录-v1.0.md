## 1. 使用说明

项目采用单一责任人三视角内部确认，不虚构产品、前端、UI 三名独立签署人。项目责任人分别从“产品与需求”“架构与安全”“测试与运维”三个视角逐项检查。

状态使用：`□`＝未执行，另可填写“通过 / 不通过 / 待讨论 / 不适用”。“通过”必须在状态单元格或问题记录中定位证据；“不通过/待讨论”必须关联 `UI-RVW-*`。严重与高优先级问题全部关闭只是 UI 评审通过的必要条件，不会自动打开代码开工门。

问题严重级别：严重（阻塞使用或违反业务规则）、高（影响核心流程或一致性）、中（体验问题）、低（细节优化）。
