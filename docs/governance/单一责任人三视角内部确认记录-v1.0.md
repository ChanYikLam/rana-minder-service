## 3. 三视角确认合同

### 3.1 产品与需求视角

确认目标：需求事实、PRD 和 SRS 之间不存在用下游推断覆盖上游事实的情况；当前产品范围、用户故事、非目标、权限和状态行为可作为后续实现的产品约束。

复核要点：

1. 236 个事实编号唯一，PRD 用户故事为 40 个，SRS 全局不变量为 27 条；
2. 29 个状态机、306 条转换、13 条故障规则和 54 条 NFR 均有稳定入口；
3. 拒绝、延期和历史冲突裁决保持边界，不因签署恢复为产品范围；
4. 签署不新增产品行为，不把参考配置、设计建议或实现默认值写成需求事实。

### 3.2 架构与安全视角

确认目标：架构、ADR、数据、接口、Casdoor 与安全设计在当前粒度上没有已知的相互矛盾，且实现不得突破上游权限、作用域、事务、故障和恢复边界。

复核要点：

1. ADR-001 至 ADR-014 均已接受，第一轮开放架构项为 0；
2. DATA-Q-001 至 DATA-Q-014、IFC-Q-001 至 IFC-Q-002、CAS-Q-001 至 CAS-Q-002、SEC-Q-001 均已关闭；
3. Casdoor、PostgreSQL 和对象存储的权威边界、普通社团隔离域与联合协作域、八类事务边界及恢复后写入门保持一致；
4. 具体 API 风格、物理 DDL、迁移、ORM、工具、平台和依赖版本仍不由本次签署决定。

### 3.3 测试与运维视角

确认目标：当前测试、非功能验收和运维文档已提供可执行、可复核的设计入口，并真实保留尚未执行的状态。

复核要点：

1. 29/29 个状态机和 306/306 条转换具有稳定测试定位，13/13 条故障及 54/54 条 NFR 有测试入口；
2. 54/54 条 NFR 具有逐项可执行验收合同，九类重点场景均有覆盖；
3. 24/24 个 OPS-VER 入口、全部恢复演练、全部安全与业务测试仍为“未执行”；
4. 规格收口、备份任务成功或签署完成均不得冒充实际测试、恢复或部署通过。
