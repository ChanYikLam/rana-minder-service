## 1. 文档定位与设计原则

### 1.1 文档定位

本文把已确认的产品行为、用户旅程和非功能约束转化为前端 UI/UX 设计规范。不新增产品行为，不改变需求事实、PRD 或 SRS。发生冲突时以上游文档为准；框架组件、DTO、前端状态管理和具体 API 均位于本文之后，不能反向改变本文或上游规则。

### 1.2 设计原则

| 原则 | 含义 | 上游来源 |
|---|---|---|
| 权限驱动界面 | 页面能力随服务端逐请求授权结果动态呈现；前端工作空间、角色标签、旧链接和缓存不是授权来源；失权后相关入口即时隐藏或禁用 | ORG-038；GOV-007；SRS 8.1 |
| 状态机驱动流转 | 29 个状态机决定页面操作可用性；不可操作须明确提示业务原因，而非简单禁用 | SRS 第二轮；架构 5.3 |
| 双空间模型 | 全局个人空间（无需选社团）与当前社团管理工作空间（持续醒目显示当前社团）分离；切换只改变工作空间，不改变任何关系 | IDN-022；ORG-038 |
| 权益可见 | 影响学生权益的变化必须通知；通知不等于业务状态，页面以权威业务对象当前状态为准 | NTF-001 至 NTF-003 |
| 响应式一致 | 电脑与手机业务能力一致；布局可不同，关键操作、结果和授权不得只在电脑端存在 | NFR-009；SRS-NFR-040 |
| 可访问性基线 | 达到 WCAG 2.2 对应 AA 数值（对比度、键盘、非纯颜色提示），不扩大为完整 AA 认证 | NFR-009；PRD-OPT-054；SRS-NFR-044/045 |
| 品牌可配置 | 学校名称、Logo、域名、默认模板可通过配置替换，不改源码、权限或业务规则 | NFR-008；SRS-NFR-032/039 |
| AI 不参与界面决策 | 界面不提供 AI 自动录取、排序、评价或任免入口；AI 辅助仅为草稿，须人工确认采用 | NFR-010；SRS-NFR-046 至 048 |

### 1.3 已确认约束与待确认视觉提案

| 类型 | 规则 | 自检方式/状态 |
|---|---|---|
| 已确认安全约束 | 不得仅凭前端传入的社团标识、角色名、旧缓存或页面状态放行操作 | 每页标注服务端重新授权点 |
| 已确认可访问性约束 | 状态、错误和权限结果不得仅用颜色表达；核心流程必须可由键盘完成 | 页面状态检查、键盘走查和对比度实测 |
| 候选视觉方向 | 墨青＋琥珀、避开蓝紫色相；尚未获得设计评审确认 | 建议待确认；确认前不得称为产品禁令 |
| 已确认图标实现 | 使用 Lucide Vue 的统一线性 SVG 图标；界面文案不以 emoji 代替功能图标 | 需求方确认于 2026-08-01；具体图标与可访问名称仍逐项验收 |

## 2. 设计系统

### 2.1 字体系统

以下字体组合是视觉候选，不是已确认产品事实。正式采用前必须核验许可证、中文字符覆盖、Web 字体体积、加载失败回退和不同平台渲染；系统字体回退不得被禁止：

| 用途 | 字族 | 字重 | 说明 |
|---|---|---|---|
| 标题与强调 | HarmonyOS Sans SC 候选＋系统中文无衬线回退 | 600 / 700 | 许可证与 Web 子集待核验；避免依赖 900 字重造成额外下载 |
| 正文 | HarmonyOS Sans SC 候选＋系统中文无衬线回退 | 400 / 500 | 字体加载失败时保持可读和布局稳定 |
| 数据与技术 | JetBrains Mono 候选＋系统等宽回退 | 400 / 500 | 仅用于确需等宽的状态码、统计数字和时间戳，不强制用于普通学号文本 |
| 表格数字对齐 | 优先使用 `font-variant-numeric: tabular-nums` | 400 | 不为数字对齐强制下载额外字体 |

#### 2.2.3 对比度自检

关键文字与背景组合须达到 WCAG 2.2 AA 普通文字 4.5:1、大号文字 3:1：

| 组合 | 浅色对比度 | 深色对比度 | 结论 |
|---|---|---|---|
| text-primary on bg-base | 16.41:1 | 17.68:1 | 通过 |
| text-secondary on bg-base | 7.16:1 | 7.65:1 | 通过 |
| text-on-primary on primary | 9.07:1 | 9.39:1 | 通过 |
| text-on-accent on accent | 8.14:1 | 10.48:1 | 通过 |
| text-primary on bg-elevated | 17.49:1 | 16.31:1 | 通过 |
| text-secondary on bg-elevated | 7.63:1 | 7.06:1 | 通过 |
| border on bg-elevated（必要控件边界） | 3.45:1 | 3.45:1 | 通过非文本 3:1 |
| border-strong on bg-elevated | 4.80:1 | 4.09:1 | 通过非文本 3:1 |
| success on success-subtle | 约 6.49:1 | 约 5.23:1 | 通过 |
| danger on danger-subtle | 约 6.80:1 | 约 5.28:1 | 通过 |
| warning on warning-subtle | 约 6.37:1 | 约 5.43:1 | 通过 |
| info on info-subtle | 约 6.49:1 | 约 5.15:1 | 通过 |

以上数值按候选色值的 WCAG 相对亮度公式计算；设计交付和实现仍须用实际字体、字号、背景、透明度和交互状态复测。普通文字至少 4.5:1，大号文字至少 3:1，必要非文本界面组件与状态图形至少 3:1。

#### 2.2.4 双主题兼容性规则

1. 组件禁止硬编码色值，一律通过令牌消费。
2. 深色主题下 primary 为亮色，其背景上文字必须使用 --text-on-primary（深色），不得沿用浅色主题的浅色文字。
3. subtle 类令牌在深色主题下使用深色变体（如 primary-subtle 由浅墨青改为深墨青），保证背景与文字对比度。
4. 阴影在深色主题下使用更深的黑色叠加，不使用浅色主题的灰色阴影。
5. 图标和状态指示须同时具有文字或图形辅助，不依赖单一颜色区分（非纯颜色提示）。

### 2.7 动效

克制有力，服务于状态反馈：

| 类型 | 时长 | 缓动 | 用途 |
|---|---|---|---|
| 微交互 | 150ms | ease-out | 悬停、按钮按压 |
| 状态切换 | 200 至 300ms | ease-out | 面板展开、抽屉 |
| 页面转场 | 200ms | fade | 路由切换 |

## 3. 信息架构与导航模型

### 3.1 四层结构

| 层 | 入口 | 是否需登录 | 是否需选社团 | 核心内容 |
|---|---|---|---|---|
| L1 公开发现 | 顶部导航"找社团、找活动" | 否 | 否 | 公开社团、普通招新、联合活动、历史活动 |
| L2 登录用户与本人参与 | 顶部导航“我的”或公开活动中的本人操作入口 | 是 | 否 | 个人空间，以及本人报名、共享同意、面试和邀请处理；不要求先选择社团工作空间 |
| L3 社团管理工作空间 | 选择当前社团后进入 | 是 | 是 | 工作台、招新、联合活动、成员、表单、统计、配置 |
| L4 平台管理 | 超级管理员入口 | 是 | 否 | 社团接入、Casdoor 映射、权限模板、安全开关、运维状态 |

### 3.2 导航模型

#### 顶部全局导航栏

所有页面固定显示：

- 左：品牌区（可配置 Logo、学校名、RanaMinder）
- 中：主导航（找社团、找活动、我的、当前社团工作空间、平台管理（仅超级管理员））
- 右：通知图标（带未读角标）、用户菜单（姓名、学号、角色摘要、退出登录）；若双主题候选方案通过评审，再增加浅色/深色主题切换。

#### 当前社团指示器

进入 L3 后持续醒目显示：

- 顶部导航下方或侧边栏顶部固定显示当前社团名称。
- 点击可切换到对当前页面有权的社团；切换只改变工作空间，不改变任何关系。
- 高风险操作提交前再次显示目标社团和影响范围（ORG-038）。

#### 侧边栏（L3 社团管理）

模块顺序：工作台、普通招新、联合活动、成员管理、部门与职位、动态表单、统计导出、社团配置。

xs 与 sm 断点下转为抽屉式，由顶部菜单按钮触发。

### 3.3 双空间切换规则

| 场景 | 行为 |
|---|---|
| 无社团用户登录 | 仅可见 L1 与 L2；L3 入口隐藏，提示"你当前不属于任何社团" |
| 进入社团管理 | 必须选定一个当前有权社团；无权进入时拒绝并提示 |
| 切换社团 | 只能切换到对当前页面有权的社团；切换不改变关系 |
| 同社团多角色 | 自动合并允许能力，不要求手动选角色；页面显示当前生效角色及权限来源 |
| 高风险提交 | 最终提交前展示目标社团和实际影响范围，由操作者明确确认 |

## 4. 角色能力矩阵

9 类角色可叠加，每次操作由服务端按当前主体、目标对象所属社团、部门、活动、轮次、状态和具体操作重新鉴权。本表只作导航与典型能力总览，不是客户端授权矩阵；逐页设计视图见第 6 章。

| 角色 | L1 公开 | L2 个人与本人参与 | L3 社团管理 | L4 平台管理 | 关键能力与限制 |
|---|---|---|---|---|---|
| 未登录访客 | 只读公开内容 | 不可 | 不可 | 不可 | 选择报名时引导登录 |
| 普通平台用户 | 可 | 可（本人） | 不可 | 不可 | 补资料、验证邮箱、报名、处理邀请 |
| 申请人 | 可 | 可 | 不可 | 不可 | 报名、选志愿、选面试、查结果、处理邀请 |
| 普通成员 | 可 | 可 | 可（本人关系） | 不可 | 查看本人关系、申请加入退出调动部门 |
| 普通面试官 | 可 | 可 | 可（任务范围） | 不可 | 查看作用域内面试者材料、填写本人评语；无选定、发布、邀请权 |
| 部门负责人 | 可 | 可 | 可（本部门加全社团面试评审） | 不可 | 管理本部门人员职位；给本部门报名者设内部选定标签；全社团面试评审 |
| 人事管理员 | 可 | 可 | 可（全社团） | 不可 | 招新、成员、任免、换届、表单、纠错、统计导出；默认全社团面试职能 |
| 社团负责人 | 可 | 可 | 可（全社团） | 不可 | 全部社团业务、负责人连续性、配置；默认全社团面试职能 |
| 超级管理员 | 可 | 可 | 不可（可处置异常） | 可 | 社团接入、映射、模板、安全开关、真实数据门、正式删除、运维状态 |

补充：

- 管理角色失效时，由该角色产生的默认面试职能立即撤销；若同一人另有仍有效的临时面试任务，只保留该任务范围（ORG-037）。
- 临时面试官赋职作用域为整个面试活动或单个面试轮次，不得以模糊无限期角色扩大到其他活动。
- 超级管理员不要求属于任何社团，但其访问与操作必须审计。

### 5.7 通用交互模式

| 模式 | 规则 |
|---|---|
| 权限驱动渲染 | 页面加载与操作后按服务端返回的当前能力渲染；失权入口即时隐藏或禁用并提示原因 |
| 状态机驱动可用性 | 操作按钮可用性随业务状态；不可用时提示业务原因（如"报名通道已关闭"） |
| 目标冻结 | 高风险确认后冻结目标标识和参数；期间变化则拒绝并要求刷新 |
| 版本冲突处理 | 提交时版本不匹配返回冲突；展示最新值，用户刷新后重新提交 |
| 外部处理中 | Casdoor 或外部写入处理中时显示 ProcessingTag，不假成功；完成或失败后更新 |
| 降级渲染 | Casdoor 故障 15 分钟内仅渲染白名单能力；其他入口禁用并提示 |
| 键盘可达 | 所有操作可通过键盘完成；焦点可辨识；模态陷阱可退出 |
| 同步冲突本人选择 | 第三值冲突时并列展示本地目标值与 Casdoor 当前值，由用户本人选择，系统不选边 |

### 6.1 P0 核心流程页面

#### 6.1.1 Casdoor 登录页

**角色场景**：未登录访客与所有需认证用户。
**布局**：居中单卡片，最大宽度 420px。上方品牌区（可配置 Logo + 学校名 + RanaMinder），中间"使用学校统一身份认证登录"主按钮，下方访客入口链接（浏览公开社团与活动）。背景使用 bg-base 加微妙几何线条装饰（墨青色系，非渐变）。
**关键组件**：品牌区 BrandArea、主按钮 Button(primary, size=lg, icon=log-in)、访客链接 TextLink、降级提示 DegradedBanner（Casdoor 故障时显示）；主题切换仅在双主题方案获批后加入。
**状态与权限变体**：
- 正常：主按钮可点击，跳转 Casdoor 认证。
- Casdoor 故障：主按钮禁用，DegradedBanner 显示"学校统一身份认证暂不可用，新登录已暂停"。
- 已登录：自动跳转个人空间或来源页。
**交互规则**：点击主按钮跳转 Casdoor；回调后服务端校验账号状态与资料完整性，决定跳转目标。不得在本系统提供独立账号密码输入。

#### 6.1.2 资料补充页

**角色场景**：首次登录或后续新增必填字段生效后资料缺失的用户（US-ID-02）。
**布局**：顶部步骤指示（补充资料 -> 验证邮箱 -> 完成），中间 DynamicForm 渲染平台公共补充资料表单，右侧或下方同步状态指示器。
**关键组件**：步骤指示 Stepper、DynamicForm、SyncIndicator、保存按钮 Button(primary)、"稍后补充"提示 TextLink（仅浏览，不可业务写）。
**状态与权限变体**：
- 缺失必填字段：表单标记必填项；用户可浏览全部页面，但除补充资料与退出外不可执行业务写操作，顶部常驻提示条。
- 资料完整但邮箱未验证：进入邮箱验证步骤。
- 资料完整且邮箱已验证：解除写限制，跳转来源页。
**交互规则**：保存后本地立即生效并进入 Casdoor 同步；SyncIndicator 显示同步中、已同步或失败。固定字段（学号、姓名）只读展示，不可编辑。

#### 6.1.3 邮箱验证页

**角色场景**：首次填写邮箱或修改已验证邮箱的用户（US-ID-02、IDN-011）。
**布局**：居中卡片。显示当前待验证邮箱（脱敏，如 ch***@gdmu.edu）、"发送验证邮件"按钮、24 小时倒计时与重发频率限制提示。修改邮箱场景下并列显示旧有效邮箱（标记"当前有效"）与新邮箱（标记"待验证"）。
**关键组件**：邮箱显示 EmailDisplay、发送按钮 Button(primary, icon=mail)、倒计时 Countdown、重发按钮 Button(ghost)、状态徽章 StatusBadge(待验证/已验证)。
**状态与权限变体**：
- 待验证：可浏览与修改资料，不可执行其他业务写操作。
- 验证成功：原子替换旧邮箱，进入 Casdoor 同步。
- 验证失败或过期：链接失效，可重发。
- 重发频率受限：按钮禁用并提示剩余等待时间。
**交互规则**：验证链接一次性、24 小时有效；新邮箱验证成功前旧邮箱继续有效。手机号只校验格式，不发送短信验证码。

#### 6.1.4 个人空间 - 待我处理

**角色场景**：所有已登录用户，无需选择社团（US-ID-04、IDN-022）。
**布局**：顶部 Tab（待我处理 / 进行中 / 历史记录），下方筛选栏（按社团、按业务类型），主体为待办卡片列表。每张卡片显示所属社团、业务对象、关键期限、当前状态与操作入口。
**关键组件**：TabBar、FilterBar、TodoCard（社团标签 + 业务类型图标 + 标题 + 期限 + 状态徽章 + 操作按钮）、空状态 EmptyState。
**待办类型**：待补资料、即将开始面试、待处理邀请、成员生效异常、本人发起后待处理申请、凭当前角色可处理的审批或任务。
**状态与权限变体**：
- 无社团用户：仍可进入，显示本人相关事项（申请、邀请等）。
- 管理型待办：只显示当前仍有权处理的对象；点击详情时按目标对象重新鉴权。
- 失权待办：即时从列表消失或标记"已无权处理"。
**交互规则**：页面加载与操作后读取各权威业务对象当前状态；通知只用于提醒，未读不等于待处理，已读不等于已完成。筛选不串数据。聚合入口不产生跨社团管理权限。

#### 6.1.5 个人空间 - 进行中

**角色场景**：所有已登录用户。
**布局**：与待我处理一致的 Tab + 筛选 + 列表结构。展示本人正在进行的申请、面试、邀请、审批参与、任务与成员状态。
**关键组件**：TabBar、FilterBar、ProgressCard（进度阶段 + 当前状态 + 下一步 + 期限）、Timeline（展开查看阶段历史）。
**状态与权限变体**：
- 申请人：显示报名审核、面试安排、结果等待、邀请处理等阶段。
- 面试官：显示明确分配的面试任务及状态。
- 管理角色：显示本人参与的审批、批量任务等。
**交互规则**：每项明确显示所属社团、业务活动或对象、关键期限和当前状态。状态来自权威业务对象，不维护独立副本。

#### 6.1.6 个人空间 - 历史记录

**角色场景**：所有已登录用户。
**布局**：Tab + 筛选 + 时间线列表。展示已完成的申请、面试、邀请、审批参与、任务与成员经历。
**关键组件**：TabBar、FilterBar、HistoryTimeline（时间节点 + 事件 + 状态 + 关联对象链接）。
**状态与权限变体**：
- 历史记录长期保留，但访问按当前有效角色重新鉴权。
- 失权后历史可见性按业务规则收窄（如普通面试官活动结束后失权）。
**交互规则**：历史只读，不可修改；事实纠错走独立流程。点击关联对象跳转后按当前状态鉴权。

#### 6.1.7 我的面试日程

**角色场景**：作为申请人或明确分配面试官的用户（US-REC-07）。
**布局**：日历视图与列表视图切换按钮。日历视图按日期显示面试安排块；列表视图按时间排序显示详细信息。冲突安排高亮提示。
**关键组件**：视图切换 ViewToggle(calendar/list)、ScheduleBlock（时间 + 社团 + 活动 + 轮次 + 地点/线上 + 状态）、冲突标记 ConflictBadge(danger)、筛选 FilterBar(按社团)。
**状态与权限变体**：
- 申请人视角：显示本人作为申请人的全部有效普通与联合面试安排。
- 面试官视角：显示明确分配给本人的面试任务；默认全量评审权限不产生时间占用。
- 跨社团冲突：只显示"该时段不可用"和冲突区间，不显示另一社团或活动详情。
**交互规则**：v1.0 不提供外部日历订阅、ICS 导出或第三方同步。点击安排可查看详情（按当前权限）。改期走对应业务流程，不可在日程页直接修改。

#### 6.1.8 通知中心

**角色场景**：所有已登录用户（NTF-001 至 NTF-003）。
**布局**：左侧通知列表（未读优先、按时间排序），右侧通知详情。顶部筛选（全部 / 未读 / 按业务类型）与批量已读操作。
**关键组件**：NotificationList、NotificationItem（图标 + 摘要 + 时间 + 未读点）、NotificationDetail（事件摘要 + 跳转入口）、批量已读 Button、空状态 EmptyState。
**状态与权限变体**：
- 站内信紧急关闭时：列表显示"站内信投递暂停，恢复后补投"，通知事实仍生成。
- 通知摘要长期保留，但办理状态从权威业务对象读取。
**交互规则**：通知只用于提醒，不等于业务状态。点击跳转后按当前对象状态重新鉴权；旧通知不能绕过状态（如已过期邀请不可接受）。正文仅含最小信息，不含评语、附件、令牌或完整报名表。

#### 6.1.9 找社团

**角色场景**：未登录访客与已登录用户（US-REC-08、CFG-007）。
**布局**：顶部搜索框（按社团展示名称搜索）+ 社团卡片网格。每张卡片展示社团名称、Logo、简介与公开状态。无筛选条件组合（与找活动互斥，同一时刻只用一种名称搜索）。
**关键组件**：NameSearch（中文连续子串 + 受控错别字近似，分层结果）、ClubCard（Logo + 名称 + 简介 + "查看详情"按钮）、空状态 EmptyState、分页 Pagination。
**状态与权限变体**：
- 未登录：可浏览公开字段；点击报名相关操作引导登录。
- 已登录：公开字段一致，报名资格以实时校验为准。
**交互规则**：不足 3 个有效字符只执行精确与子串搜索，不产生近似候选；近似候选不超过直接命中。首版无拼音或首字母搜索。结果只展示 CFG-007 允许公开的社团字段，不显示成员名单或内部数据。

#### 6.1.10 找活动

**角色场景**：未登录访客与已登录用户（US-REC-08）。
**布局**：顶部搜索框（按活动名称搜索）+ 筛选区（活动类型：普通招新/联合活动；报名状态：正在报名/全部；报名截止时间：今日截止/3日内/7日内/自定义）+ 活动卡片列表。已完成活动进入独立"历史活动"区域。
**关键组件**：NameSearch、FilterPanel（类型 + 状态 + 截止快捷范围 + 自定义日期）、ActivityCard（活动名 + 类型徽章 + 社团 + 截止时间 + 报名状态徽章）、历史活动分区 HistorySection、分页 Pagination。

- 截止快捷范围按平台时区自然日计算（今天、今天及随后两天、今天及随后六天）。
- 历史活动只读，不提供报名入口。
**交互规则**：公开入口可见不等于符合报名资格。提交报名时重新校验账号、资料、活动状态、期限与资格。不提供个性化推荐、自动匹配或排名。

**角色场景**：访客查看公开详情；登录申请人进入独立普通招新申请（US-REC-02、US-REC-08）。
**路由**：`/activity/recruitment/:activityId`（公开详情）、`/activity/recruitment/:activityId/apply`（本人报名）。
**布局**：上部活动信息区（标题、社团、状态、报名通道状态、截止时间、数据使用说明），中部报名表单 DynamicForm（含顺序志愿排序器 PreferenceSorter、调剂选择、附件上传），下部操作栏（保存草稿、正式提交、撤回）。
**关键组件**：ActivityHeader、报名通道状态徽章 StatusBadge、DynamicForm、PreferenceSorter（拖拽排序部门志愿）、AttachmentUpload、调剂选择 Checkbox、操作栏 ActionBar（保存草稿 ghost / 提交 primary / 撤回 danger-ghost）。
**状态与权限变体**：
- 报名通道开放：可填写与提交。
- 通道关闭/暂停：表单只读，提示"报名通道已关闭"。
- 已提交：显示当前状态，可修改（截止前）或撤回。
- 已退出：显示退出状态；若有专属恢复窗口则显示重新提交入口。
- 身份异常：显示异常状态，暂停个人期限。
- 当前社团成员：禁止报名本社团招新，提示"你已是本社团成员"。
**交互规则**：同一活动只有一份申请，重复提交不产生第二份。志愿不重复，满足最少最多数量。保存草稿不进入正式筛选。正式提交时校验资格并保存快照。附件未检查通过不可正式提交。

#### 6.1.12 P-REC-08 / P-JNT-02 联合活动详情与报名

**角色场景**：访客查看首次公布后的联合活动；登录申请人在不选择社团工作空间的情况下创建独立联合申请（US-REC-08、US-JNT-02）。
**路由**：`/activity/joint/:jointId`（公开详情）、`/activity/joint/:jointId/apply`（本人报名）。
**布局**：上部明确显示“联合活动”、锁定参与社团、联合报名通道、当前截止和数据使用摘要；中部可展开完整共享说明；下部是独立联合申请表、附件、服从联合调剂选择、主动同意控件与保存/提交操作栏。
**关键组件**：ActivityTypeIndicator、ParticipantClubList、SharedScopeExplanation、JointApplicationForm、AttachmentUpload、ConsentControl、DraftSaveControl、SubmissionStatePanel。
**状态与权限变体**：
- 未首次公布：不进入公开结果，旧链接不展示活动内部信息。
- 通道未开放/暂停/已关闭：公开详情按规则可见，不能新建或正式提交；既有草稿和历史按服务端当前能力呈现。
- 草稿：材料仍属本人草稿，不形成共享同意，不开放联合协作域。
- 已提交：展示独立联合申请状态和已确认说明版本；参与社团访问仍受紧急停用与当前权限控制。
- 已取消归档/已归档：只读，不允许通过旧页面重新提交。
**交互规则**：同意控件不得预选，也不得沿用其他活动同意。正式提交原子保存申请、资料快照、当前共享说明版本、锁定社团、表单版本、调剂选择和确认时间；缺少或不匹配时保持草稿且不共享草稿材料。拒绝共享只退出本联合申请流程，不影响独立普通路径。

#### 6.1.13 招新管理 - 活动列表

**关键组件**：ClubIndicator、DataTable（活动列、状态徽章、报名通道徽章、申请数、截止时间、操作列）、创建按钮 Button(primary, icon=plus)、状态筛选 FilterPanel。
**状态与权限变体**：
- 部门负责人：可查看活动列表但不可创建、取消或完成活动。
- 超级管理员：仅异常处置时介入。
**交互规则**：点击活动进入活动配置或申请人列表。活动状态与报名通道状态独立显示。工作台状态从权威业务对象读取。

#### 6.1.14 招新管理 - 申请人列表

**角色场景**：社团负责人、人事管理员、部门负责人（全量评审）、临时面试官（任务范围）（US-REC-04、US-REC-05）。
**布局**：顶部筛选（部门、志愿、状态、面试状态、调剂）+ 名称搜索，主体申请人表格或卡片视图。每行显示申请人摘要、志愿、部门路径状态、面试记录、内部标签与操作。
**关键组件**：FilterPanel、NameSearch、ApplicantCard/ApplicantTable、内部选定标签 StatusBadge(accent)、操作菜单（查看详情、安排面试、评价、设标签、发邀请）。
**状态与权限变体**：
- 社团负责人/人事：全量查看与操作，可复核改判部门标签。
- 部门负责人：全量查看与评语，但只能给本部门报名者设"内部选定录取"标签，不可管理轮次、发布或发邀请。
- 临时面试官：仅查看任务范围内面试者材料与填写本人评语。
- 改判通知：负责人/人事改判部门标签时，原设置人收到内部站内信（不提前通知申请人）。
**交互规则**：仅内部评语、建档或标签变化不通知申请人。安排面试、发布结果或发邀请时通知。批量操作经 BatchActionBar 预览后逐项执行。

#### 6.1.15 面试评价

**角色场景**：各级负责人、临时面试官（US-REC-04）。
**布局**：左侧申请人列表（任务范围内），右侧评价面板。评价面板上部显示申请人材料（按字段权限投影），下部 DynamicForm 渲染评价表（评分、评语、建议）。同轮他人评价首评前不可见。
**关键组件**：ApplicantList（任务范围）、评价表单 EvaluationForm、材料预览 MaterialPreview（按字段权限）、提交按钮 Button(primary)、保存草稿 Button(ghost)、轮次状态指示。
**状态与权限变体**：
- 首评前：不可查看同轮他评。
- 轮次关闭前：可修改本人评价，所有版本保留。
- 轮次关闭后：只读，仅允许事实纠错。
- 临时面试官：可写本人评语，不可设标签或作结论。
- 部门负责人：可写评语 + 给本部门报名者设标签，不可发布结论。
**交互规则**：评价保留作者与修改历史。评价不等同于晋级、淘汰或录取结论。内部评分与评语对申请人不可见。

#### 6.1.16 邀请处理

**角色场景**：申请人处理录取邀请（US-REC-06）。
**布局**：个人空间或活动详情内的邀请列表。每张邀请卡片显示社团、部门、有效期倒计时、状态与操作按钮（接受/拒绝）。
**关键组件**：InvitationCard（社团 + 部门 + 有效期 Countdown + 状态徽章）、接受按钮 Button(primary)、拒绝按钮 Button(ghost)、撤回提示（仅发出方待处理时可撤回）。
**状态与权限变体**：
- 待处理：可接受、拒绝；资料不完整或邮箱未验证时可查看但不可接受。
- 已接受：显示成员生效处理中 ProcessingTag，Casdoor 回读确认后显示已生效。
- 已拒绝/已过期：终态，可重新发出。
- 已撤回：终态。
**交互规则**：接受第一个部门邀请建立社团与部门关系，后续接受增加部门关系。已接受邀请不可撤回或恢复为待处理。接受与撤回并发只允许一个成功。Casdoor 回读确认前不授予成员权限。

### 6.2 P1 管理端页面

#### 6.2.1 社团管理工作台

**角色场景**：社团负责人、人事管理员进入社团管理工作空间的默认页（US-ORG-05）。
**布局**：侧边栏"工作台"选中。顶部当前社团指示器。内容区聚合卡片网格，按当前角色展示：待审批、待安排面试、待评审、待发布结果、待处理邀请、同步或通知异常、即将逾期。每个卡片显示数量与快捷入口。
**关键组件**：ClubIndicator、WorkshopCard（数量 + 类别图标 + 快捷入口）、异常标记 Badge(danger)、批量操作入口 BatchActionBar。
**状态与权限变体**：
- 待办状态从权威业务对象与当前权限读取，不维护独立副本。
- 不同角色看到的工作台内容按权限聚合；无权限类别不显示。
- 无人可处理异常高亮并通知负责人、人事、超管。
**交互规则**：点击类别进入对应模块。v1.0 批量操作仅四类：批量分配面试官、批量安排面试、批量发布同类型结果、批量发送同一业务类型邀请；一次批次只属于一个社团一种操作。

#### 6.2.2 招新活动配置

**角色场景**：社团负责人、人事管理员创建和配置招新活动（US-REC-01）。
**布局**：分步配置向导（基本信息 -> 开放部门与资格 -> 志愿与调剂 -> 报名表单 -> 面试轮次 -> 期限 -> 发布预览）。左侧步骤导航，右侧当前步骤表单。
**关键组件**：配置向导 Wizard、步骤导航 StepNav、开放部门选择 ObjectPicker、志愿数量限制、调剂开关、表单版本选择、面试轮次配置区、期限 DateTimePicker、发布预览面板。
**状态与权限变体**：
- 草稿：可编辑，未发布。
- 已发布：形成配置快照，平台与社团默认值变化不静默覆盖。
- 发布后扩大机会可直接生效并通知；收紧规则须暂停报名并建补救窗口。
- 部门负责人不可发布、取消或完成活动。
**交互规则**：发布前预览影响范围。表单版本发布后不可覆盖。活动配置快照独立保留。

#### 6.2.3 报名通道管理

**角色场景**：社团负责人、人事管理员管理招新报名通道（US-REC-01、REC-003）。
**布局**：活动详情内的报名通道卡片。显示通道当前状态（未开放/开放/暂停/已关闭）、当前有效截止、窗口版本历史、操作按钮（开放/暂停/关闭/携新截止重开）。
**关键组件**：报名通道状态徽章 StatusBadge、截止 DateTimePicker、窗口版本时间线 Timeline、操作按钮组（开放 primary / 暂停 warning / 关闭 danger-ghost / 重开 primary）。
**状态与权限变体**：
- 通道与活动主状态独立。
- 已关闭后，活动进行中且未整体暂停时，负责人/人事可携合法未来截止创建新窗口重开。
- 重开不改变活动主状态、既有申请或下游历史，不自动恢复已退出申请。
**交互规则**：自动到期或人工关闭后，重开须携符合配置范围且严格晚于当前时刻的新截止。旧截止保持失效。

#### 6.2.4 面试轮次配置

**角色场景**：社团负责人、人事管理员配置社团统一面试轮次（US-REC-03）。
**布局**：轮次列表 + 每轮配置卡片。卡片含轮次名称、时间段预设、容量、面试官分配、轮次状态（未开始/开放/已关闭）。申请人自选时段或管理员安排。
**关键组件**：轮次卡片 RoundCard、时间段配置 TimeSlotEditor、容量设置、面试官分配 ObjectPicker、轮次状态徽章、冲突检测提示。
**状态与权限变体**：
- 全部普通面试轮次由负责人或人事创建，部门无权创建专属面试。
- 每名申请人每轮最多一份有效面试记录。
- 并发选择不超卖最后名额。
- 明确分配的面试任务重叠时拒绝；默认全量评审权限不产生时间占用。
**交互规则**：冲突检查、容量占用与并发版本在同一提交边界完成。作废与重新安排是两个业务步骤。

#### 6.2.5 内部结论与结果发布

**角色场景**：社团负责人、人事管理员复核、改判并统一发布结论（US-REC-04、REC-018）。
**布局**：左侧部门路径与内部结论列表，右侧结论编辑与发布面板。显示部门"内部选定录取"标签（部门负责人设置）、负责人/人事改判入口、最终结论（录取/不录取/候补）与统一发布按钮。
**关键组件**：部门路径列表、内部选定标签、改判面板（原值 + 新值 + 修改人 + 时间）、结论选择、发布预览、统一发布按钮（HighRiskConfirm）。
**状态与权限变体**：
- 部门负责人只能给本部门报名者设内部选定标签。
- 负责人/人事可改判任一部门标签或调剂路径决定，原值与每次修改保留作者和版本。
- 改判时原设置人收到内部站内信（含原值、新值、修改人、时间），不提前通知申请人。
- 发布前预览影响范围；发布后申请人收到通知。
**交互规则**：结论发布是高风险操作，走 HighRiskConfirm。修改权益结论再次通知且不改写原评价。活动结束后仅允许事实纠错。

#### 6.2.6 联合活动 - 发起与确认

**角色场景**：参与意向社团负责人、人事管理员发起联合活动并确认（US-JNT-01）。
**布局**：发起表单（活动名、说明、拟参与社团、共享范围、期限）+ 拟参与社团确认状态列表。每行显示社团、确认状态（待确认/已确认）、确认人。
**关键组件**：发起表单、拟参与社团选择 ObjectPicker、确认状态列表 ConfirmList、确认按钮（代表本社团确认）、共享范围说明编辑器。
**状态与权限变体**：
- 任一拟参与社团负责人/人事/超管可发起。
- 每个社团由任一现任负责人或人事单独确认即生效；少一个确认即不成立。
- 首次公布前可调整拟参与社团，名单变化后全部重新确认。
- 部门负责人和普通面试官不能执行活动级命令。
**交互规则**：全部确认后活动成立并开放联合协作域。成立前不开放资料。共享同意证据保存活动、说明版本、锁定社团、表单版本和确认时间。

#### 6.2.7 联合活动 - 管理（报名通道与共享排期）

**角色场景**：参与社团负责人、人事管理员管理联合报名通道与共享排期（US-JNT-01、US-JNT-03）。
**布局**：联合活动详情内的报名通道卡片（四态：未开放/开放/暂停/已关闭）+ 共享排期管理区（时间段、申请人安排、容量）。任一参与社团负责人或人事可独立操作通道。
**关键组件**：联合报名通道状态徽章、截止与窗口版本、通道操作（开放/暂停/延期/关闭/重开）、共享排期编辑器、申请人安排、冲突检测。
**状态与权限变体**：
- 任一当前参与社团负责人/人事可独立暂停、恢复、延期、关闭或重开，无需其他社团确认；操作立即向其他社团管理者可见并审计。
- 暂停废止旧截止版本；恢复须设合法新截止并原子创建新窗口。
- 延期仅开放状态允许，替换为更晚截止。
- 第一份邀请发出后不能取消整个活动。
**交互规则**：联合报名通道是独立业务对象，不复用普通报名通道。通道命令执行时重新鉴权。重开不改变锁定名单、已提交申请或下游历史。

#### 6.2.8 联合面试评价

**角色场景**：参与社团负责人、人事管理员、部门负责人、临时联合面试官（US-JNT-03）。
**布局**：左侧联合面试者列表（共享范围内），右侧评价面板。与普通面试评价相似，但显示跨社团评价互见（各社团评分、评语、结论实时可见）。标注当前操作者所属社团。
**关键组件**：联合面试者列表、评价面板、跨社团评价区（各社团评分与评语按社团分组显示）、作废按钮（负责人/人事）、待复核标记。
**状态与权限变体**：
- 参与社团负责人、人事、部门负责人默认查看并评论全部联合面试者。
- 各社团评分、评语、结论和修改历史实时互相可见。
- 联合面试作废由任一参与社团负责人或人事单独执行（客观无效），作废后未锁定结论进入"面试作废待复核"。
- 活动结束前可修改本人评价；邀请接受后录取结论锁定。
**交互规则**：每人只参加一次联合面试。作废保留原排期、出勤、评价、操作者、原因及时间，记录待重新安排。作废通知申请人和全部参与社团管理者。

#### 6.2.9 成员列表

**角色场景**：社团负责人、人事管理员、部门负责人查看成员（US-MEM-01）。
**布局**：顶部筛选（部门、职位、状态、任期）+ 名称搜索，主体成员表格或卡片。每行显示姓名、学号、部门、职位、任期、加入时间、状态与操作。
**关键组件**：FilterPanel、NameSearch（人员名连续子串含单字；学号/账号精确）、MemberTable/MemberCard、任期标签、状态徽章、操作菜单（查看详情、调整部门、任免、移除）。
**状态与权限变体**：
- 部门负责人只看本部门成员。
- 负责人/人事看全社团成员。
- 多部门、多职位并存显示，不强制主部门。
- Casdoor 当前关系与本地历史不一致时标记异常。
**交互规则**：每次职位任命生成独立任期，计划结束不自动卸任。成员可同时属于多个部门或零部门。

#### 6.2.10 部门与职位管理

**角色场景**：社团负责人、人事管理员、超级管理员（接入）管理部门与职位（ORG-011 至 ORG-019）。
**布局**：左侧部门树（社团 -> 部门层级），右侧选中部门详情（成员、职位、部门负责人）。职位列表显示职位名、范围（社团级/部门级）、成员数、操作。
**关键组件**：部门树 DeptTree、部门详情面板、职位列表 PositionList、职位权限模板标签、创建/配置按钮（超管接入 Group）。
**状态与权限变体**：
- 部门与职位从 Casdoor Group 接入，不创建 Group。
- 部门级职位不能访问其他部门；社团级职位按模板全社团范围。
- 部门允许没有部门负责人，回退给负责人或人事。
- 只有超级管理员可接入、配置 Group 映射。
**交互规则**：任命前须先属于对应部门（可"加入部门+任命职位"复合操作，禁止静默加入）。同一 Group 只能映射一种用途。

#### 6.2.11 任命、调岗与免职

**角色场景**：社团负责人、人事管理员、部门负责人（本部门普通职位）（US-MEM-04）。
**布局**：操作表单（选择人员 -> 选择职位 -> 生效方式：立即/预约 -> 影响预览 -> 确认）。预约命令列表显示计划执行时间、状态（待执行/待重新确认/前置条件失效暂停）。
**关键组件**：人员选择 ObjectPicker、职位选择、生效方式（立即/预约 DateTimePicker）、影响预览面板、确认按钮、预约命令列表、状态徽章。
**状态与权限变体**：
- 部门负责人只能管理本部门普通职位。
- 预约命令执行前重新检查原发起人权限；失权时暂停为"待重新确认"。
- 业务前置条件失效时暂停为"业务前置条件失效暂停待处置"，不自动执行或取消。
- 最后一名社团负责人不能无交接离任。
**交互规则**：任命候选按姓名连续子串或学号/账号精确查找。Casdoor 写入回读确认前保持原关系，最长重试 15 分钟。复合操作（加入部门+任命）作为一次原子操作。

#### 6.2.12 换届批次

**角色场景**：社团负责人、人事管理员创建年度换届批次（US-MEM-06）。
**布局**：换届方案编辑器：现任职位列表 + 预览调整（续任/新任/卸任/空缺）。预览面板显示变更影响（新增、移除、保留）。确认按钮（任一现任负责人或人事单独确认）。
**关键组件**：换届方案编辑器 TransitionEditor、职位调整行（现任 -> 新任）、影响预览面板、确认按钮（HighRiskConfirm）、状态徽章（预览/待执行/已生效/部分异常）。
**状态与权限变体**：
- 支持续任、新任、卸任和允许空缺的部门负责人。
- 生效后至少保留一名社团负责人。
- 先确认新任再移除旧任；新任失败时撤回新增保持旧任。
- 旧任移除部分失败时保留新负责人并进入部分异常、持续重试和告警。
**交互规则**：系统学年切换不自动换届。换届生效后角色变化同步执行待办续接、作者保留、预约命令复核规则（US-ORG-04）。

#### 6.2.13 常规入社邀请

**角色场景**：社团负责人、人事管理员向非本社团成员发常规入社邀请（US-MEM-03）。
**布局**：邀请表单（选择人员 -> 可选初始部门 -> 有效期 -> 预览 -> 发送）+ 待处理邀请列表（对象、部门、有效期、状态、操作）。
**关键组件**：人员选择 ObjectPicker（学校级 Organization 中非本社团当前成员）、初始部门选择（至多一个）、有效期 DateTimePicker、邀请列表、撤回按钮。
**状态与权限变体**：
- 只有负责人或人事可发送；部门负责人、普通面试官、普通成员无权。
- 候选范围含无社团用户、其他社团成员、本社团历史成员。
- 被邀请人必须整体接受"加入社团+加入该部门（如有）"，不能只接受一部分。
- 待处理且未接受的邀请可撤回；同一社团同一对象同一时刻最多一份待处理邀请。
**交互规则**：人员按姓名连续子串（含单字）或学号/账号精确查找，无错别字/拼音候选。邀请内容不可原地修改，变更须撤回后新建。接受后 Casdoor 回读确认前不授予权限。

#### 6.2.14 成员申请处理

**角色场景**：部门负责人、社团负责人、人事管理员审批成员申请（加入/退出/调动部门、辞职）（US-MEM-02、US-MEM-04）。
**布局**：待审批申请列表（类型、申请人、目标部门/职位、申请时间、状态）+ 审批面板（申请详情、批准/驳回按钮、驳回原因输入）。
**关键组件**：待审批列表 PendingList、审批面板 ApprovePanel、批准按钮（primary）、驳回按钮（danger-ghost + 原因输入）、状态徽章、撤回标记（申请人已撤回）。
**状态与权限变体**：
- 申请人本人必须从审批候选中排除；排除后无可用负责人时回退给负责人或人事。
- 部门无当前负责人时自动回退给社团负责人或人事。
- 待审批申请可由申请人撤回，撤回后不可再审批。
- 驳回必须填写原因；批准、驳回、撤回均通知。
**交互规则**：审批通过后进入关系变更执行阶段，不能再按待审批撤回。跨部门调动为"加入目标部门+按选择退出原部门"一次原子操作。Casdoor 回读确认前保持原关系。

### 6.3 P2 配置与平台页面

#### 6.3.1 P-FORM-01 动态表单设计器

**角色场景**：社团负责人、人事管理员配置业务表单（US-FORM-01）。
**布局**：桌面端使用字段库、表单画布和属性面板三栏；字段可拖拽排列，也必须提供上移/下移和键盘操作。手机端改为字段列表、分步属性编辑和触控顺序按钮，业务能力不删减。
**关键组件**：字段库 FieldLibrary、表单画布 FormCanvas、字段属性面板 FieldProps、条件显示配置、字段权限配置、预览按钮、保存草稿、发布按钮。
**状态与权限变体**：
- 固定业务骨架字段（学号、姓名、状态、审批等）只读引用，不可删除或冒充。
- 人员、社团、部门等对象字段先按当前作用域过滤。
- 自动带入的用户资料在表单中只读，提交时保存快照。
- 系统秘密字段（密码、令牌、密钥）不可作为字段。
**交互规则**：可复制本社团既有表单或基于平台模板创建草稿；只复制结构不复制提交、附件或原社团对象引用。字段类型不兼容变化须创建新字段。

#### 6.3.2 P-FORM-02 表单版本、填写与修订

**角色场景**：表单发布者管理版本；申请人在所属报名或申请页面填写、迁移、修订并回看本人提交（US-FORM-02）。
**布局**：管理视图使用版本列表（版本号、状态、发布时间、使用该版本的活动/提交数、操作）和版本差异；填写视图嵌入所属业务页面，使用分步表单、迁移提示和修订时间线，不建立脱离业务对象的通用提交页。
**关键组件**：版本列表 VersionList、版本差异对比 VersionDiff、动态表单渲染器 DynamicFormRenderer、迁移提示 VersionMigrationBanner、答案回看 AnswerHistoryViewer、修订时间线 RevisionTimeline、发布/停用/复用按钮。
**状态与权限变体**：
- 已发布版本不可覆盖，停用不删除历史。
- 已停用版本永久不得直接重新启用；复用只能以其为来源创建新草稿，重新预览、测试并发布新版本。
- 旧提交按原版本完整还原。
**交互规则**：发布、停用、复制或复用不得改绑既有提交、附件和活动快照；不提供把旧版本回滚为当前版本的操作。每次重新提交形成独立修订，业务锁定后仅允许事实纠错。

#### 6.3.3 统计概览

**角色场景**：社团负责人、人事管理员、部门负责人查看统计（US-STAT-01）。
**布局**：顶部统计卡片（社团总人数、部门数、招新中、待处理），下方图表区（成员结构、招新漏斗、任期分布）。可下钻明细。
**关键组件**：统计卡片 StatCard、统计图表 StatChart（柱状/饼图/漏斗）、下钻面板、时间筛选、部门筛选。
**状态与权限变体**：
- 社团总人数按学号去重；部门统计允许同一成员分别计入。
- 部门负责人只看本部门。
- 普通与联合活动分别统计。
- 小样本保护：人数过少时不展示可识别信息。
**交互规则**：统计不能直接编辑；源记录纠错或删除后自动重算。不提供成员排行榜、自动评分或人员优劣排名。

#### 6.3.4 异步导出管理

**角色场景**：有权管理者异步导出数据（US-EXP-01）。
**布局**：导出任务列表（任务名、范围、创建时间、状态、有效期、操作）。新建导出表单（选择范围、字段、附件选项、有效期）。
**关键组件**：导出任务列表 ExportList、新建导出表单（范围选择 + 字段勾选 + 附件选项 + 有效期）、状态徽章（生成中/已完成/已过期/失败）、下载按钮、删除按钮。
**状态与权限变体**：
- 字段、附件和记录不超过当前查看权限；联系方式和附件需显式选择。
- 联合导出的其他社团评分、评语和结论明确标注来源。
- 导出默认 24 小时有效，下载时再次鉴权。
- 失权后无法继续下载。
**交互规则**：表格内容防公式注入，秘密永不导出。生成失败可重试。当前产品不存在业务数据导入入口。

#### 6.3.5 社团接入向导

**角色场景**：超级管理员接入已有 Casdoor Group 为社团（US-ORG-01）。
**布局**：分步向导（选择 Group -> 配置基本信息 -> 配置部门与职位 -> 校验 -> 完成）。每步显示 Casdoor Group 选择器与映射预览。
**关键组件**：接入向导 Wizard、Casdoor Group 选择器 ObjectPicker（层级校验）、映射预览面板、校验结果、完成按钮。
**状态与权限变体**：
- 只有超级管理员可接入、启用、停用、解除或重新绑定社团。
- Group 必须满足层级、用途唯一和重复绑定校验。
- 接入时已有成员成为当前关系，未知历史日期不伪造。
- Group 删除、移动或失权后进入同步异常并保留历史。
**交互规则**：本系统不创建、改名、移动或删除 Casdoor Group。非社团 Group 不会因层级或名称自动接入。

#### 6.3.6 Casdoor 映射配置

**角色场景**：超级管理员配置 Casdoor 字段映射（US-CFG-01、CFG-004）。
**布局**：字段映射表（本系统字段 <-> Casdoor 字段、同步方向、是否白名单）。发布新版本前预览受影响字段与用户。
**关键组件**：映射配置表 MappingTable、字段选择、同步方向（双向/只读）、白名单标记、发布预览、发布按钮（HighRiskConfirm）。
**状态与权限变体**：
- 只有固定字段白名单可与 Casdoor 双向同步。
- 动态表单自定义资料只保存本系统，不写入 Casdoor。
- 发布映射是高风险操作，须 10 分钟重新认证。
- 实际 Casdoor 接口测试通过后才能发布。
**交互规则**：类型不兼容、可能批量丢失或测试失败时拒绝。发布为不可变版本并受控对账。

#### 6.3.7 权限模板管理

**角色场景**：超级管理员配置权限模板（US-CFG-01、CFG-008）。
**布局**：权限模板列表（模板名、关联职位 Group、版本、状态）+ 模板编辑器（权限项目录勾选）。发布前预览权限差异和受影响对象。
**关键组件**：模板列表 TemplateList、权限项编辑器 PermissionEditor（从系统固定权限项目录勾选）、关联职位 Group、版本管理、发布预览、发布按钮（HighRiskConfirm）。
**状态与权限变体**：
- 权限模板采用"内置默认 + 超级管理员可配置"模式。
- 每个职位 Group 关联一个模板；部门级模板不能突破部门范围，也不能授予平台超管权限。
- 发布新版本原子切换全部关联对象并立即清除权限缓存。
- 社团管理员不能修改模板或映射。
**交互规则**：发布前展示权限差异和受影响对象，要求 10 分钟重新认证和二次确认。发布失败保留旧版本，回滚通过发布新版本完成。

#### 6.3.8 安全开关

**角色场景**：超级管理员控制平台安全开关（GOV-004）。
**布局**：安全开关列表（开关名、当前状态、影响说明、操作）。包括：全局关闭新的联合活动创建、紧急关闭新的跨社团导出及未完成导出下载、紧急关闭站内信等。
**关键组件**：安全开关列表 SwitchList、开关切换（含确认）、影响说明、操作按钮（关闭用 HighRiskConfirm，恢复用普通确认）、状态徽章。
**状态与权限变体**：
- 关闭类操作（联合创建、跨社团导出、站内信）是高风险，须 10 分钟重新认证。
- 恢复类操作（恢复站内信、重新开启）现有事实未列入 10 分钟清单，用普通确认。
- 关闭只阻止新操作，既有业务继续运行。
**交互规则**：关闭需填写原因、预览影响、二次确认。恢复只恢复后续新能力，不自动补建关闭期间未创建的对象。

#### 6.3.9 真实数据启用门

**角色场景**：超级管理员首次启用、暂停或恢复真实学生数据处理（GOV-002、GOV-007）。
**布局**：真实数据处理状态卡片（当前状态：未启用/已启用/已暂停）+ 操作按钮（首次启用/暂停/恢复）。每次操作须 10 分钟重新认证、实时确认 Group、明确确认。
**关键组件**：状态卡片 StatusCard、启用按钮（HighRiskConfirm）、暂停按钮、恢复按钮、治理条件清单、操作历史。
**状态与权限变体**：
- 首次启用要求正式环境治理条件、至少两名有效超管、当前 Group 可确认。
- 首次启用只开放按当前治理和权限规则处理真实数据，不导入数据、不创建账号/关系或授予额外权限。
- 暂停后禁止新增，不删除既有数据。
**交互规则**：认证、Group、状态、版本或权限失败时保持原状态且无副作用。不得由社团角色、隐藏开关或部署脚本冒充业务启用。

#### 6.3.10 正式删除

**角色场景**：超级管理员正式删除本地业务数据（US-AUD-03）。
**布局**：删除范围选择（单条/活动/用户）+ 预览面板（表单、评价、附件、关系、通知、导出影响）+ 原因输入 + 二次确认。删除执行进度（跨数据库、附件、缓存、索引、导出）。
**关键组件**：范围选择、影响预览面板 ImpactPreview、原因输入、HighRiskConfirm、删除执行进度列表、最小删除审计记录。
**状态与权限变体**：
- 删除前填写原因、预览范围并二次确认；活跃关系、有效邀请或进行中活动阻止删除。
- 在线数据库、附件、缓存、索引和系统内导出同步处理。
- 恢复备份后重新应用删除清单，已删除内容不复现。
- 只保留不含被删正文的最小删除审计。
**交互规则**：删除是高风险操作，须 10 分钟重新认证。部分失败不得宣称完成，不补偿恢复已删数据。删除不操作 Casdoor，也不能召回系统外副本。

#### 6.3.11 内置运维状态

**角色场景**：超级管理员查看系统运维状态（SRS-NFR-027/028）。
**布局**：只读状态面板，分区显示：应用版本与启动状态、数据库连通性、任务积压与最近异常、Casdoor 同步最近结果、邮件最近结果、文件检查最近结果、通知最近结果、备份最近结果。每项显示规范化当前状态和最近更新时间。
**关键组件**：状态面板 StatusPanel（多分区）、状态指示（正常/异常/未知）、最近更新时间、过期状态标记"未知"。
**状态与权限变体**：
- 页面只读，不展示学生业务正文。
- 过期状态必须显示"未知"，不伪装为健康。
- 不要求机器健康监测、外部监控接口或系统外告警。
**交互规则**：应用仍可运行时严重异常在此明确提示。应用完全不可用时不承诺自动发现。内置观测不改变业务结论或权限。

#### 6.3.12 同步冲突选择

**角色场景**：用户本人处理普通可编辑资料的第三值同步冲突（US-ID-03、IDN-006/007）。
**布局**：冲突对比面板，并列显示"本地目标值"与"Casdoor 当前值"，底部两个选择按钮："保留本地目标值"/"接受 Casdoor 当前值"。顶部说明冲突原因与字段。
**关键组件**：冲突对比面板 ConflictCompare（左右两列值对比）、选择按钮（保留本地 primary / 接受 Casdoor ghost）、冲突标记 Badge、字段说明。
**状态与权限变体**：
- 本地继续显示目标值并标记冲突。
- 仅普通可编辑字段进入本人选择；姓名、学号等只读权威字段以 Casdoor 为准，不进入此状态。
- 系统和超级管理员不得替用户选边。
**交互规则**：选择保留本地值时基于最新冲突快照创建新同步版本再写 Casdoor；选择接受 Casdoor 值时原子更新本地并收口。提交选择前重新校验冲突版本和 Casdoor 当前值，旧选择不得覆盖更新值。

## 7. 关键交互流程

### 7.1 高风险操作确认流

适用：结果发布、发送邀请、移除成员、任命免职、强制结束、紧急停用、正式删除、发布映射/模板、全平台导出、真实数据启停、安全开关关闭类操作。

| 步骤 | 界面 | 说明 |
|---|---|---|
| 1 选择对象 | 操作入口 | 用户选择目标对象 |
| 2 影响预览 | ImpactPreview | 显示目标清单、所属社团、部门、预计通知和影响范围；预览后新增对象不进入本批次 |
| 3 重新认证 | Casdoor 重认证 | 10 分钟内通过 Casdoor 重新认证，证明认证新鲜度 |
| 4 目标冻结 | 确认面板 | 冻结目标标识、命令参数、预览版本和期望对象版本 |
| 5 二次确认 | Dialog | 展示目标社团和实际影响范围，操作者明确确认 |
| 6 执行 | 服务端 | 逐项校验权限、版本、前置条件后执行；期间变化则拒绝并要求刷新 |

### 7.2 批量操作流程

适用：批量分配面试官、批量安排面试、批量发布同类型结果、批量发送同一业务类型邀请。

| 步骤 | 界面 | 说明 |
|---|---|---|
| 1 选类型 | BatchActionBar | 选择一种操作类型（不混批） |
| 2 预览固定清单 | ImpactPreview | 显示固定对象清单、目标社团、操作内容、预计通知和影响范围 |
| 3 逐项执行 | 服务端 | 每项独立幂等命令，重新校验权限、版本、状态、容量、资格 |
| 4 部分成功 | PartialSuccess | 成功项保留，失败项逐条显示原因，可单独重试且不重复成功项 |

### 7.3 报名提交流程

| 类型 | 流程 |
|---|---|
| 普通招新 | 选择普通活动 -> 查看公开详情与数据使用说明 -> 登录后进入普通报名 -> 填写志愿、调剂和附件 -> 手动保存草稿（可选）-> 正式提交并校验资格、保存快照 -> 面试、结果与邀请 |
| 联合活动 | 选择联合活动 -> 查看锁定参与社团与共享摘要 -> 登录后进入独立联合报名 -> 填写申请和附件 -> 主动确认当前共享说明 -> 原子提交申请与同意证据 -> 一次联合面试、各社团结论与邀请 |

### 7.4 邀请处理流程

收到邀请通知 -> 查看邀请详情（社团、部门、有效期）-> 校验资料完整性 -> 接受（Casdoor 写入回读，成员生效处理中）或拒绝 -> 回读确认后关系生效。

### 7.5 年度换届流程

创建换届批次 -> 预览续任/新任/卸任/空缺 -> 确认（任一现任负责人或人事）-> 先确认新任 -> 再移除旧任 -> 失败补偿 -> 角色变化同步执行待办续接与预约命令复核。

### 7.6 同步冲突本人选择流程

普通资料 24 小时同步失败 -> 读回 Casdoor 第三值 -> 进入"同步冲突待本人选择" -> 并列展示本地目标值与 Casdoor 当前值 -> 用户本人选择 -> 保留本地（新同步版本再写）或接受 Casdoor（原子更新收口）。

### 8.3 键盘操作

- Tab 顺序遵循视觉流；Shift+Tab 反向。
- 模态框焦点陷阱内，Esc 关闭并返回触发元素。
- 所有拖拽操作都提供键盘和触控替代：志愿与表单字段可用上移/下移按钮调整，操作后播报新位置。
- 跳转链接（Skip to main content）供屏幕阅读器。

### 8.4 非纯颜色提示

所有状态用"图标 + 文字 + 颜色"三重表达：成功（check-circle + 已生效 + 绿）、危险（alert-triangle + 失败 + 红）、警告（clock + 待处理 + 琥珀）、信息（info + 提示 + 青）。

|---|---|---|---|

## 9. 品牌配置与主题化

### 9.1 品牌可配置项

| 配置项 | 令牌映射 | 替换边界 |
|---|---|---|
| 学校名称 | 文案令牌（品牌区、页脚） | 不改权限或业务规则 |

| 域名 | 配置项（非设计令牌） | 部署配置 |
| 默认模板 | 通知/邮件模板 | 模板变量不越权 |
| 品牌主色 | --primary 系列（可选，默认墨青） | 替换后仍须满足对比度门槛 |

### 9.2 主题切换

本节是待确认的交互候选，不是当前产品事实。若双主题方案通过评审：

- 主题偏好可以保存在本地展示偏好中，首次按系统偏好；不得保存身份、权限或业务状态。
- 切换即时生效，令牌驱动，无刷新。
- 深色主题下 primary 背景上文字用 --text-on-primary（深色）。
