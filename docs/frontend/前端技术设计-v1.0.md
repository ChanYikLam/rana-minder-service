### 2.4 技术责任分层

下表说明 RanaMinder 前端从视图层到接口适配层的职责边界；它是分层说明，不是已经交付的架构图：

| 层级 | 组件 | 说明 |
|------|------|------|
| 视图层 | 页面组件、布局系统、shadcn-vue 项目组件、Tailwind 语义令牌和 Lucide 图标适配 | 用户直接交互界面；业务页面不直接依赖 Reka UI 原语 |
| 状态层 | 客户端展示状态、路由适配和组合式职责 | 只保存展示快照，不持有授权或业务权威 |
| 业务层 | 身份模块、组织模块、招新模块、联合模块 | 按 SRS 状态机划分的业务模块 |
| 接口适配层 | 传输客户端、逻辑接口适配、服务端应用入口 | 映射传输中立合同；不信任客户端自报身份、作用域或结果 |

**当前结论**：Vue 3＋TypeScript由 ADR-013 确认；shadcn-vue＋Tailwind CSS＋Lucide Vue、VeeValidate `4.15.1`＋`@vee-validate/zod` `4.15.1`＋Zod `3.25.76`，以及仅管理客户端展示状态的 Pinia `4.0.2` 由需求方于 2026-08-01 确认。版本策略也已确认：Vite、路由及其他精确版本继续作为候选快照，首次安装或纳入锁文件前重新核验并精确锁定；全部依赖在验证和锁文件完成前均不得写成已安装事实。

**终审补充**：Lucide Vue 方案本身不变；原包 `lucide-vue-next@1.0.0` 已被 npm 标记弃用，需求方确认迁移至同一官方仓库的 `@lucide/vue`，查询快照为 `1.28.0`，实际锁定前仍须复核。当前尚无工程清单、锁文件、源码或运行测试，FE-GATE-002/003 未执行；需求方已通过 `GOV-CODE-WAIVER-001` 豁免其作为代码编写前置条件并授权直接编码，但没有将其改写为通过。

### 3.2 页面清单

页面清单、页面 ID 和绝对路径只在《前端需求与交互规格》第 3.2 节与第 4.1 节维护。本技术设计不再复制第二套路由，以免 `/me` 与旧 `/personal`、`/admin` 与旧 `/platform` 等命名并存。

当前正式前端路由评审基线共 43 个唯一页面 ID、68 条具体路径，技术设计仅按权限上下文消费该清单：

| 权限上下文 | 路由根 | 技术责任 |
|---|---|---|
| 公开区 | `/login`、`/explore/*`、`/activity/*` | 不依赖登录态；只显示允许公开的字段和服务端派生状态 |
| 登录用户与本人参与区 | `/me/*`、`/activity/recruitment/:activityId/apply`、`/activity/joint/:jointId/apply`、`/files/:fileId` | 登录后可访问，不要求先选择或属于目标社团工作空间；按本人对象和服务端能力逐项授权 |
| 社团工作空间 | `/org/:clubId/*` | 每次请求由服务端重新校验当前主体、目标社团、业务对象和操作 |
| 超级管理员区 | `/admin/*` | 不得与社团工作空间权限混用；高风险操作执行实时鉴权、影响预览和必要重新认证 |

表单填写、文件选择、确认对话框等可复用交互不因组件复用而自动成为独立页面；只有主草案登记的页面 ID 和路由才计入交付范围。`P-FORM-03` 是明确登记的例外：上传控件仍内嵌，独立 `/files/:fileId` 只呈现经实时鉴权的水印预览与下载。

## 4. 页面路由及导航结构

### 4.1 路由层级

本文件不再维护第二套具体路由树。页面 ID、绝对路径、作用域和父子关系统一引用《前端需求与交互规格》第 3 节和第 4.1 节；路由变更必须先修改主草案，再同步本文的技术影响说明。

技术实现必须保持四类路由责任：

| 路由责任 | 入口示例 | 核心边界 |
|---|---|---|
| 公开区 | `/login`、`/explore/*`、两类 `/activity/*` 详情 | 无需登录；只返回允许公开的字段和状态；普通与联合活动使用明确路由变体和各自领域适配器 |
| 登录用户与本人参与区 | `/me/*`、两类报名入口、`/files/:fileId` | 需要登录但不要求选择社团；对象仍按本人范围和当前业务关系重新授权 |
| 社团工作空间 | `/org/:clubId/*` | URL 中的社团标识只作候选；服务端按目标对象和当前关系重新计算作用域；普通成员只进入本人关系相关入口 |
| 平台管理区 | `/admin/*` | 只对当前有权超级管理员展示；每个特权操作仍重新认证、实时核验并审计 |

### 4.2 导航结构

#### 全局导航（Header）

| 导航项 | 显示条件 | 跳转路由 |
|--------|----------|----------|
| 找社团/找活动 | 所有人；字段投影随登录状态变化 | `/explore/*` |
| 个人中心 | 登录用户 | `/me` |
| 通知 | 登录用户 | `/me/notifications` |
| 社团切换器 | 至少存在一个当前可选社团关系或管理能力 | 选择后进入 `/org/:clubId/dashboard` 或对应本人关系页 |
| 平台管理 | 当前有权超级管理员 | 进入服务端返回的首个有权 `/admin/*` 页面；不虚构独立管理首页 |
| 用户头像/菜单 | 登录用户 | 下拉菜单 |

#### 社团工作空间侧边栏

侧边栏只呈现当前用户在当前社团工作空间可见的模块，模块候选顺序为：工作台、普通招新、联合活动、成员与组织、动态表单、统计与导出、通知配置、纠错与审计、社团配置。入口显隐只改善体验，不能替代服务端逐请求授权；切换社团后必须清空前一社团的管理页展示缓存并重新加载。

### 4.3 路由守卫

路由守卫采用与具体路由库无关的顺序：识别公开入口及普通/联合活动变体；确认本地是否存在可尝试恢复的登录会话；向服务端加载当前页面上下文和可操作项；按资料门、依赖状态与当前作用域呈现业务页或 `P-GEN-01` 至 `P-GEN-04`。前端不得把本地 `isAuthenticated`、角色名或路由元数据当作授权结论。

授权拒绝原因不得未经脱敏写入 URL 查询参数、浏览器历史或可分享链接。无权限页只展示用户下一步所需的最小信息和服务端返回的安全支持编号；内部策略、对象存在性和其他社团信息不得暴露。

本节尚未交付可渲染路由图。后续图表必须由主草案生成或逐项校验，不能手工维护另一套页面数量。

1. **隐藏无权限入口**：根据服务端返回的 `permissions` 动态隐藏按钮/菜单

## 7. 页面状态和权限矩阵

### 7.1 状态机前端映射

前端必须覆盖 29/29 个状态机的页面呈现与可操作项，但不得自行发明“后端英文枚举”或把多个正式状态压缩成会改变业务含义的 `FINAL`、`FAILED` 等泛化状态。传输代码目录尚未确认前，本文沿用 SRS 的规范性中文状态名称；未来代码值必须逐项映射且不可改变状态语义。

完整页面追踪以《前端需求与交互规格》第 7 节为主草案。本文件只冻结下列容易误实现的技术护栏：

| 状态域 | 前端必须保持的语义 | 禁止行为 |
|---|---|---|
| 账号访问（SRS-SM-IDN-001） | 账号禁用或删除后立即拒绝本人登录并终止已有会话；Casdoor 暂不可确认时，仅由服务端判定故障前可信会话及不超过 15 分钟的最小白名单 | 不得显示“禁用/删除后登录查看”；不得由客户端计时器延长降级窗口 |
| 资料写入门（SRS-SM-IDN-002） | 区分待补充、待邮箱验证、可写和分范围受限；页面展示服务端返回的受限范围和补救入口 | 不得把一个范围缺失扩大为全局拒绝，也不得用前端资料快照放行业务写入 |
| 普通活动与报名通道（SRS-SM-REC-001/002） | 活动主状态、整体暂停覆盖、报名通道状态和当前有效截止分别呈现 | 不得把通道“开放”直接等同目录筛选“正在报名”；后者必须由服务端按公开资格、开放、无暂停/终态覆盖和未到截止共同派生 |
| 申请、路径和面试（SRS-SM-REC-003/004/005） | 分别展示申请修订、部门路径/结论、面试安排/出勤/作废状态；按钮来自当前对象可操作项 | 不得用单一申请终态覆盖各路径、邀请和成员生效中的未决状态 |
| 邀请与成员生效（SRS-SM-INV-001、SRS-SM-MEM-001、SRS-SM-MEM-004、SRS-SM-ORG-002） | 接受邀请后展示“已接受，成员生效处理中”；Casdoor 写入并回读确认后才显示成员关系生效和对应权限 | 不得把邀请接受直接文案化为“已成为正式成员”，不得在回读前开放权限 |
| 通知事实与渠道（SRS-SM-NTF-001） | 分开呈现通知事实、站内信/邮件投递、本人已读/隐藏状态和权威业务对象当前状态 | 不得用已读推导已处理，不得用渠道失败回滚或改写已成功业务结果 |

本节尚未交付 29 个状态机的可渲染流程图；不得再写“参见上方流程图”或以局部七张表宣称已经完成 29/29 覆盖。

### 7.2 按钮级权限控制

按钮、字段和页面区块根据服务端随对象查询返回的“当前可操作项、字段权限和安全原因代码”呈现。前端可以组合这些结果用于显示、隐藏或禁用，但不得在浏览器中复制一套基于角色名和状态枚举的授权引擎。

| 阶段 | 前端责任 | 服务端权威责任 |
|---|---|---|
| 页面加载 | 提交目标候选标识和期望页面；展示返回的当前状态、字段投影、可操作项和最小拒绝原因 | 回源对象，按当前主体、操作、作用域、业务状态和依赖状态重新授权 |
| 操作准备 | 展示目标社团、实际影响范围、对象版本和是否需要重新认证 | 冻结可执行操作目录、影响预览和必要版本；高风险命令实时核验当前 Group |
| 最终提交 | 提交已登记操作、目标候选、期望版本、幂等键和业务输入 | 重新执行认证、授权、状态、字段、版本、原因、重新认证和并发校验；前端旧许可不可信 |
| 拒绝/冲突 | 保持原页面数据，不伪造成功；展示可采取的下一步和安全支持编号 | 返回结构化结果类别和最小安全原因，不泄露对象存在性、内部权限策略或他社团信息 |

### 11.3 角色导航语义（非授权矩阵）

| 成员 | 个人区及本人当前成员关系相关入口 | 本人对象、当前关系和服务端可操作项 |
| 申请人 | 公开发现、本人申请、面试和邀请入口 | 本人对象、资料门、活动/通道状态和当前可操作项 |
