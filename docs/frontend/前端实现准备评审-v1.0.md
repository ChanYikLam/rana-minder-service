shadcn-vue 官方 Vite 流程采用 Tailwind CSS 与 `@tailwindcss/vite`，并通过 CLI 将组件源码加入项目；当前 CLI 的 `reka` 基座对应 Reka UI。Reka UI 是 Radix Vue 在 v2 演进中的新名称，并以无样式、可访问基础组件为定位。“基于 Radix Vue”在历史语境成立，正式依赖名应写为 `reka-ui`。[shadcn-vue Vite 安装](https://www.shadcn-vue.com/docs/installation/vite)、[shadcn-vue npm](https://www.npmjs.com/package/shadcn-vue)、[Reka UI 更名说明](https://www.reka-ui.com/docs/overview/introduction)

Pinia 官方将其定位为 Vue 的默认状态管理方案，并提供类型推断、Devtools、测试与模块化能力；这些能力只用于客户端展示状态，不改变 RanaMinder 的服务端授权与业务权威边界。[Pinia 官方说明](https://pinia.vuejs.org/introduction.html)

## 2. 评审原则

1. 第三方库只降低实现成本，不成为需求、授权、业务状态或错误语义的权威来源。
2. `components/ui/*` 是由 shadcn-vue 生成并由项目维护的基础适配层；业务页面不得直接散布 `reka-ui` 原语，通过项目 UI 组件与 `RmField`、`RmDataTable` 等业务适配承接设计令牌和可访问性。
3. 表单的客户端校验只做即时反馈；服务端仍按表单版本、字段权限、业务状态和当前主体重新校验。
4. Pinia 不保存“我有权限”或“命令已成功”等权威结论，只缓存服务端返回的展示快照和当前查询引用。
5. 图标不单独表达状态、权限或危险级别；装饰图标对辅助技术隐藏，纯图标按钮必须有可访问名称。
6. 版本表是 2026-08-01 查询快照；真正创建清单前必须重新查询、核验 peer dependencies、许可证、安全公告和浏览器目标。

## 3. UI 组件与 CSS 方案评审

### 3.1 已确认组合

| 组成 | 责任 | 主要成本/风险 | 结论 |
|---|---|---|---|
| shadcn-vue | 通过精确版本 CLI 生成项目拥有的 Vue 组件源码和 `components.json` | 不像封闭组件包自动升级；重新生成/更新需审查源码差异 | **需求方已确认** |
| Reka UI | 为 Dialog、Select、Dropdown、Tabs 等复杂交互提供无样式原语、键盘和焦点基础 | 基础可访问能力不等于应用级验收；组合和标签仍由项目负责 | shadcn-vue 当前 `reka` 基座 |
| Tailwind CSS | 提供原子化样式、响应式变体和主题变量；使用官方 Vite 插件 | 任意类名散落会削弱令牌治理；v4 面向现代浏览器，需按 NFR 实测 | **需求方已确认** |
| Lucide Vue | 提供统一线性 SVG 图标 | 不能仅凭图标表达状态；必须按图标导入并补可访问名称 | **需求方已确认** |

### 3.2 使用约束

- 首批生成并验证：Button、Field/Input/Select/Checkbox/Radio、Table/Pagination、Dialog/Drawer、Dropdown、DatePicker、Alert、Toast/Sonner、Tabs；上传和业务 DataTable 继续使用项目组合组件。
- CLI 必须使用精确版本，例如 `pnpm dlx shadcn-vue@2.8.1`；生成源码、`components.json` 和后续更新差异全部进入评审，不运行浮动 `@latest`。
- 业务代码只使用项目 `components/ui` 与业务适配组件，不直接导入 `reka-ui`；确需原语扩展时先补组件合同与可访问性测试。
- Tailwind 主题映射到 CSS 语义变量；业务页面不得用具体色阶表达成功、失败、权限或风险语义，也不得用任意值绕过间距/字号令牌。
- 使用 Tailwind v4 官方 `@tailwindcss/vite` 集成；默认不叠加 Sass/Less，不依赖大规模 `@apply` 重建另一套组件系统。[Tailwind Vite 安装](https://tailwindcss.com/docs/installation/using-vite)、[Tailwind 兼容性](https://tailwindcss.com/docs/compatibility)
- Dialog/Drawer 必须验证初始焦点、焦点圈定、Esc、关闭后焦点恢复、标题关联和嵌套禁用策略。
- Table 在窄屏按页面合同转换为卡片、优先列或横向滚动；组件默认溢出不算完成响应式适配。
- shadcn 视觉 preset、基础色和字体尚未由本次选择冻结；它们应接收外部高保真输入，不能从 CLI 默认值反推产品视觉。

## 4. 表单库与动态表单评审

### 4.1 已确认组合

需求方已确认 VeeValidate `4.15.1`＋`@vee-validate/zod@4.15.1`＋Zod `3.25.76`。该组合使用当前稳定通道并满足适配器 `zod ^3.24.0` 约束；VeeValidate v5 文档虽已发布，但 npm 通道仍是 beta，待正式稳定后再单独评估升级，不在首批实现中混用。[VeeValidate npm](https://www.npmjs.com/package/vee-validate)、[v5 迁移说明](https://vee-validate.logaretm.com/v5/guide/migration/)、[Zod 版本](https://www.npmjs.com/package/zod?activeTab=versions)

### 4.2 职责边界

| 层级 | 责任 | 禁止事项 |
|---|---|---|
| 表单定义适配 | 将服务端返回的表单版本、字段类型、条件和字段权限转为已登记的前端字段模型 | 执行任意服务端脚本、JSONPath 或未登记表达式 |
| VeeValidate | 字段值、touched/dirty、字段数组、提交状态和错误聚合 | 充当业务状态机或长期缓存 |
| Zod | 对已登记客户端模型做运行时结构与基础字段校验 | 代替服务端业务、授权、容量、版本和并发校验 |
| shadcn-vue Field/UI 组件 | 呈现控件、标签、帮助、`aria-invalid` 和错误 | 把组件状态或客户端 schema 当作唯一校验源 |
| 服务端 | 权威表单版本、字段权限、条件、业务规则和最终提交校验 | 信任客户端隐藏字段或“已通过”标志 |

### 4.3 必测场景

- 动态字段增删、嵌套字段数组、条件显示、字段权限变化和版本迁移。
- 隐藏/卸载字段的值保留策略必须与服务端表单版本合同一致，不使用库默认值临场决定。
- 服务端字段错误按稳定字段路径回填，并在表单顶部提供错误摘要、首错聚焦和 `aria-describedby`。
- 版本冲突保留本地草稿，获取权威版本后显式比较；不得自动覆盖或把失败显示为成功。
- 文件字段只保存受控上传会话/文件引用，不把对象地址、令牌或未检查文件当作表单值权威。
- `TBD-FE-009` 已按 `PRD-OPT-057` 关闭：v1 仅实现手动保存，不得因表单库能力暗中加入自动保存；未来引入时按新版本产品行为重新评审。

## 5. 状态管理评审

### 5.1 推荐边界

需求方已确认采用 Pinia `4.0.2`，但只存跨组件或跨路由的客户端展示状态：

| Store 候选 | 可保存 | 不可保存为权威 |
|---|---|---|
| `sessionViewStore` | 当前会话展示摘要、过期时间和重新加载状态 | Casdoor 令牌、密码、永久权限结论 |
| `workspaceContextStore` | 服务端返回的当前社团/联合/平台作用域投影和可操作项快照 | 客户端自选作用域、由角色名推导的授权 |
| `operationStatusStore` | 处理中命令的稳定引用、查询状态和最后更新时间 | “已成功”猜测、重复提交开关替代服务端幂等 |
| `notificationViewStore` | 未读计数和当前页展示快照 | 通知事实、权益结果或渠道投递事实 |
| `uiPreferenceStore` | 非敏感布局偏好、分页显示偏好 | 业务筛选权威、敏感字段或跨账号数据 |

页面查询数据优先由页面组合函数管理；是否引入独立服务端状态/查询缓存库不在本轮范围，避免把 Pinia 同时变成请求缓存、业务状态机和授权系统。默认不安装状态持久化插件；如需持久化，仅允许明确列入白名单的非敏感 UI 偏好。

## 7. 16 类逻辑错误到 UI 的映射

权威语义来自[接口契约第 8 节](../specification/接口契约-v1.0.md)。这里不规定 HTTP 状态码、GraphQL 扩展、RPC 状态或公开字段名；传输适配器只把未来公开错误载荷归一到以下逻辑分类。

| 逻辑错误 | 五状态 | 默认载体 | 用户恢复动作 | 自动重试边界 |
|---|---|---|---|---|
| `IFC-ERR-001` 未认证/会话失效 | A | 登录失效页或全局会话提示 | 重新登录并回到安全的原目标 | 禁止自动重放写命令 |
| `IFC-ERR-002` 重新认证不足 | A | 重新认证 Dialog/专页 | 完成重新认证后重新预览并确认 | 原高风险命令不得自动提交 |
| `IFC-ERR-003` 当前无权 | A | 页内无权状态；操作级则就地提示 | 返回可访问入口或刷新当前能力 | 不重试 |
| `IFC-ERR-004` 作用域不匹配 | A | 安全结果页 | 返回当前工作空间 | 不重试；不披露越界对象 |
| `IFC-ERR-005` 输入无效 | F | 字段错误＋表单错误摘要 | 修正并重新提交 | 不自动重试 |
| `IFC-ERR-006` 业务前置条件失败 | F | 页内业务提示/禁用原因 | 按最小原因完成前置或刷新 | 只有权威条件变化后再提交 |
| `IFC-ERR-007` 状态冲突 | F | 状态变化提示 | 刷新权威对象并重新选择动作 | 禁止盲目重试 |
| `IFC-ERR-008` 版本/预览冲突 | F | 冲突面板 | 保留本地输入、加载新版本并显式比较 | 禁止自动覆盖 |
| `IFC-ERR-009` 幂等冲突 | F | 持久错误条 | 停止当前请求并重新发起明确的新用户动作 | 不自动换键或重试 |
| `IFC-ERR-010` 业务竞争冲突 | F | 页内冲突提示 | 刷新容量/时段/唯一对象后重选 | 仅在用户重新选择后提交 |
| `IFC-ERR-011` 安全限制 | A | 最小安全提示 | 结束受限操作；必要时凭支持编号联系管理员 | 不重试，不披露阈值 |
| `IFC-ERR-012` 依赖不可用 | F | 局部降级或故障页 | 稍后重试、返回安全入口 | 读取可有界退避；写命令不自动重放 |
| `IFC-ERR-013` 外部结果不确定 | L | 持久处理中状态 | 查看状态/等待回读 | 禁止重新提交原命令 |
| `IFC-ERR-014` 结果处理中 | L | 进度/任务状态 | 查询最终结果或离开后稍后查看 | 只轮询查询入口，禁止重执行业务 |
| `IFC-ERR-015` 结果不可见 | A | 统一不可访问结果页 | 返回安全入口 | 不重试，不区分不存在与无权 |
| `IFC-ERR-016` 内部提交失败 | F | 持久错误条＋安全支持编号 | 保留安全输入并按合同重新尝试 | 仅在命令合同允许时使用同一幂等语义重试 |

附加规则：Toast 只用于非关键、可消失的补充反馈；A/F/L 主状态和可恢复动作不得只放在 Toast。支持编号可复制，但不得显示堆栈、内部路径、数据库信息、令牌、正文或其他社团对象。
