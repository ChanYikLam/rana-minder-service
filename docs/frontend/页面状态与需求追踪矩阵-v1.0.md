## 1. 能力与文档职责

### 1.1 能力

本矩阵把已确认的页面与路由评审基线转化为可验收的前端状态合同：每个页面必须明确正常、加载、空数据、失败和无权限五类表现，或登记有理由的不适用；每个页面同时回挂用户故事、状态机、设计视图和待采集证据包。完成本矩阵后，设计、原型、实现和测试无需重新猜测页面在非正常场景下应如何收口。

### 1.2 权威与冲突处理

1. 需求事实、PRD、SRS 与状态机转换明细继续是业务规则权威来源。
2. 前端需求规格负责页面 ID 和路由；UI/UX 设计规范负责设计视图 ID 和计划画板 ID；本文不复制第二套路由。
3. 页面状态描述只能解释展示与恢复动作，不得创造状态机跳转、权限、接口或产品承诺。
4. 上游规则变化时，先更新权威来源，再同步本矩阵；不得只修改本矩阵掩盖冲突。

## 2. 五种页面状态合同

| 代码 | 状态 | 进入条件 | 必须呈现 | 不得发生 |
|---|---|---|---|---|
| N | 正常 | 页面主查询或必要上下文成功返回 | 权威当前状态、允许的操作、下一步和必要的作用域提示 | 用前端快照替代服务端授权或业务状态 |
| L | 加载 | 首次加载、刷新、筛选、影响预览或提交等待中 | 骨架、局部进度或处理中提示；保持焦点和重复提交保护 | 把等待中展示为成功，或无限阻塞且无说明 |
| E | 空数据 | 查询成功且有权，但有效结果为零 | 空的原因、当前筛选和安全的下一步；创建型页面可登记不适用 | 把空数据误报为失败，或泄露无权对象的存在 |
| F | 失败 | 查询失败、依赖不可用、版本冲突、业务拒绝或外部结果不确定 | 安全原因、可恢复动作和服务端返回的支持编号；不确定结果显示处理中 | 伪造成功、暴露内部路径/令牌，或无条件重试业务命令 |
| A | 无权限 | 未登录、资料门阻断、对象失权或服务端拒绝授权 | 登录/资料门/无权限等正确收口，安全返回入口；对象存在性按上游规则隐藏 | 仅靠按钮隐藏充当授权，或泄露其他社团与对象信息 |

### 2.1 适用性规则

- 五个槽位必须逐页填写；不适用必须给出页面语义原因，空白不算覆盖。
- 局部失败和局部无权限可以在原页面等价呈现，不要求全部跳转到通用结果页。
- P-GEN-01 至 P-GEN-04 本身是结果或拦截页，其不适用槽位仍需保留理由。
- 业务状态变体不替代五种页面状态。例如“草稿/已提交”属于正常状态内的领域变体，“加载中”不属于业务状态机。
- 手机 Web 与桌面端使用同一状态合同；布局可以不同，业务能力、原因和恢复动作不得删减。

## 3. 证据合同

每个页面使用一个 EV-<模块>-<序号> 证据包，并预留五个证据槽：

- -N：正常状态主低保真帧，含关键权限/业务变体；手机 Web 以响应式行为注释为必需证据，独立视觉帧可由外部设计补充。
- -L：首次加载或关键局部加载帧，含重复提交保护。
- -E：空数据帧，或经评审的不适用说明。
- -F：至少一个可恢复失败和一个不可误报成功的失败/不确定场景。
- -A：未登录、资料门、对象失权或服务端拒绝中适用于该页的场景。

每个证据槽必须登记设计文件稳定链接、画板/帧 ID、版本、采集日期和三视角评审结论。43 个页面均已建立主低保真帧与 N/L/E/F/A 证据槽，J-01 至 J-05 可通过[核心交互旅程索引](assets/wireframes/核心交互旅程索引-v1.0.svg)点击进入对应画板；三视角结论见[前端低保真三视角评审记录](../governance/前端低保真三视角评审记录-v1.0.md)。桌面高保真画面与独立移动适配稿由需求方外部绘制，不是本矩阵的必需证据。低保真评审通过不等于实现或自动化测试通过。
