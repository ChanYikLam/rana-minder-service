## 1. 文档定位与权威关系

### 1.1 本文档的职责

本文档回答两个问题：

1. **前端有哪些页面、每个页面长什么样、用户怎么操作**——从 PRD 用户故事和 SRS 状态机推导。
2. **前端实现需要遵守哪些边界、还需确认哪些技术选择**——从架构总览、ADR 和接口契约推导。

在正式 `docs/frontend` 文档组内，第 3 节页面清单和第 4.1 节路由结构是页面 ID、路由名称与作用域的前端下游设计主规格。其他前端下游文档只引用本文件，不得另行维护一套冲突的页面或路由清单。该定位只约束前端文档内部一致性，不改变需求事实、PRD、SRS、架构与 ADR 的上游权威顺序，也不表示代码开工获批。

### 1.2 权威顺序

冲突时以上游文档为准：

1. 需求事实总账
2. 已确认 PRD
3. 已确认 SRS 及规范性明细（状态机转换明细、故障恢复与质量约束）
4. 系统架构总览与已接受 ADR
5. 数据模型、接口契约、Casdoor 集成契约
6. **本文档（前端需求规格）**
7. 前端实现

### 1.3 关键约束继承

以下上游约束在前端必须遵守，本文档不重复论证：

| 约束 | 来源 | 对前端的直接影响 |
|---|---|---|
| 服务端逐请求授权 | SRS-INV-002；架构 5.4 | 前端不持有授权权威；页面传入的社团、角色、旧权限不可信 |
| 默认拒绝 | SRS-INV-003 | 无明确授权的按钮、入口、数据一律不展示 |
| 社团严格隔离 | SRS-INV-004 | 管理页必须醒目显示当前社团；切换社团重新加载 |
| Casdoor 当前关系权威 | SRS-INV-001 | 前端不缓存当前关系作为授权依据 |
| Casdoor 故障 15 分钟降级 | SRS-FAIL-001、002 | 故障窗口内前端只允许最小白名单操作 |
| 通知只用于提醒 | US-ID-04 | 未读通知 ≠ 待处理，已读 ≠ 已完成 |
| 权益变化不能静默 | PRD 5.4 | 权益相关操作必须有明确反馈 |

## 2. 技术栈与设计约束

### 2.1 技术栈

| 项目 | 选择 | 来源 |
|---|---|---|
| 前端框架 | Vue 3 | ADR-013 |
| 类型系统 | TypeScript | ADR-013 |
| UI 组件方案 | shadcn-vue（当前 `reka` 基座） | 需求方确认于 2026-08-01 |
| CSS 方案 | Tailwind CSS | 需求方确认于 2026-08-01 |
| 图标库 | Lucide Vue（实现包 `@lucide/vue`，查询快照 `1.28.0`） | 需求方确认替换于 2026-08-01；锁定前复核 |
| 表单与客户端校验 | VeeValidate `4.15.1`＋`@vee-validate/zod` `4.15.1`＋Zod `3.25.76` | 需求方确认于 2026-08-01 |
| 客户端状态管理 | Pinia `4.0.2` | 需求方确认于 2026-08-01；仅管理客户端展示状态 |
| 响应式设计 | 移动端 + 桌面端适配 | README；PRD 12.4 |
| 登录方式 | Casdoor 统一认证 | SRS-INV-001；Casdoor 集成契约 |

ADR-013 本身只确认 Vue 3＋TypeScript；需求方后续已在实现准备评审中确认 shadcn-vue、Tailwind CSS、Lucide Vue、上述表单组合和 Pinia `4.0.2`，并确认“当前版本只作候选快照、首次安装或纳入锁文件前重查并精确锁定”的版本策略。构建器、路由库、HTTP 客户端、包管理器、测试框架及其余精确版本仍须按该策略完成安装前核验，当前不得视为已安装事实。

### 2.2 前端不可逾越的边界

1. **前端不是授权来源**。路由守卫和按钮显隐只是体验优化，不替代服务端鉴权。任何操作提交时由服务端重新校验。
2. **前端不缓存业务权威状态**。当前社团、角色、权限、对象状态每次从服务端读取；页面状态不可覆盖领域对象。
3. **前端不直接调用 Casdoor**。所有身份与关系操作走后端应用层，由后端与 Casdoor 交互。
4. **前端不伪造业务结果**。外部依赖（Casdoor、邮件、文件）不确定时只展示"处理中"，不展示成功。
5. **前端不绕过资料门**。资料未补齐或邮箱未验证时，业务写操作入口隐藏或禁用。

```

**主表使用规则：**

1. 页面 ID 表示稳定的业务交互职责；同一 ID 可以有本人、社团管理或超级管理员入口，但不同入口必须在原型画板中明确标注为同一职责的权限变体。
2. `P-REC-08` 使用普通招新和联合活动两个公开详情变体；两类对象继续调用各自领域查询和报名流程，不合并状态机或接口聚合。
3. `P-FORM-03` 的上传控件嵌入所属表单，`/files/:fileId` 只承载经实时鉴权的预览与下载，不提供脱离业务对象的公开文件地址。
4. 静态子路由必须优先于动态参数语义，例如成员操作入口不得被 `:memberId` 当作成员标识吞并；具体路由库的排序机制在实现准备时验证。
5. 未登记的新路径、别名或页面 ID 不得由下游文档或原型自行增加；变更先回写本主表，再同步 UI/UX、技术设计和评审记录。

**路由守卫规则：**

1. 全局导航检查登录状态（Casdoor 会话）；未登录访问受保护页面时跳 `/login`。具体路由库及钩子 API 待技术选型确认。
2. 全局导航检查服务端返回的资料门状态；资料未补齐或邮箱未验证时，业务写入口引导至 `P-GEN-04`（`/me/profile/required`），由该页说明原因并进入 `/me/profile`，只读页面和个人中心仍按上游规则开放。
3. 本人参与路由只要求登录和对应资料门，不要求用户先属于或选择目标社团；目标活动、邀请和记录仍由服务端按当前主体逐项授权。
4. 社团工作空间路由检查当前有权社团是否已选择；前端检查仅用于导航体验，每次请求仍由服务端校验当前用户、`clubId`、业务对象与操作权限。普通成员进入本人关系页不因此获得管理能力。
5. 超级管理员路由与社团工作空间路由分开；是否显示入口来自服务端能力结果，高风险命令仍须实时 Group、重新认证、影响预览和二次确认。
6. 服务端拒绝授权时进入 `P-GEN-02` 或在原页面展示等价拒绝状态，不泄露目标是否存在；Casdoor 降级窗口届满或受保护依赖整体不可用时进入 `P-GEN-03`。登录后恢复导航只能使用已登记的站内目标，不接受外部绝对地址或未登记路径。

### 4.2 客户端状态边界

客户端状态按下列三个概念模块分离。需求方已在实现准备评审中确认采用 Pinia `4.0.2`；本节只定义状态边界，不把 Pinia 提升为授权、业务状态机或服务端查询结果的权威来源。

| 状态类别 | 概念模块 | 内容 | 生命周期 |
|---|---|---|---|
| 会话状态 | session | 登录状态、当前用户标识、资料门状态、Casdoor 故障降级标志 | 登录会话 |
| 工作空间状态 | workspace | 当前社团候选标识、当前服务端返回的角色与权限展示快照、工作空间切换状态 | 选中社团期间 |
| 通知状态 | notifications | 未读计数、最近通知摘要 | 登录会话 |

**关键规则：**

- 客户端只存“当前展示快照”，不存业务权威数据。对象状态、审批结果、申请详情等一律从服务端读取；旧快照不得在提交时替代重新授权与当前状态校验。
- 切换社团工作空间时清空管理类页面缓存，强制重新加载。
- 通知未读数只用于角标提醒；待办列表从服务端读取，不由通知推导（US-ID-04：未读通知 ≠ 待处理）。

### 4.3 组件分层

下列目录仅表达候选职责分层，不是已批准的代码目录或脚手架；实现准备评审可调整名称和物理位置，但不得把服务端授权、业务权威状态或跨作用域数据下沉为浏览器权威。

```
src/
├── components/          基础 UI 组件（与业务无关）
│   ├── form/            表单控件（文本、日期、单选、多选、文件等）
│   ├── feedback/        反馈组件（加载、空状态、错误、确认弹窗）
│   └── layout/          布局组件（导航栏、侧边栏、页头、面包屑）
├── business/            业务组件（跨页面复用）

│   ├── StateTag/        状态机状态标签（通用状态展示）
│   ├── FileUploader/    文件上传与检查状态

│   └── ConfirmScope/    高风险操作前的影响范围确认

**PermissionGuard 组件说明：**

用于控制按钮、入口、操作区域的显隐。接收一个"能力标识"（如 `canPublishResult`、`canSendInvitation`），根据当前服务端返回的权限能力决定是否渲染子组件。**这只是体验优化**，服务端仍独立鉴权。

**ConfirmScope 组件说明：**

用于高风险操作（公布结果、发送邀请、移除成员、任命免职、导出等）。提交前展示目标社团、实际影响范围、预计通知对象；用户确认后提交。若服务端返回作用域已变化，操作被拒绝并要求刷新（US-ORG-02）。

### 4.4 接口对接层

接口契约定义的是传输中立的逻辑命令/查询。前端需要一层接口适配器将逻辑合同映射到后续确认的传输协议。接口契约当前不预先决定 REST/GraphQL/RPC、URL、HTTP 状态码或客户端库。

#### 4.4.1 请求封装

每个逻辑操作必须能够表达下列语义（IFC-GEN-001）。具体哪些字段由调用方提交、哪些由服务端生成，仍由后续传输设计决定：

| 信息 | 说明 | 信任与来源边界 |
|---|---|---|
| commandId / queryId | 已登记的逻辑命令/查询类型及版本 | 前端只能选择服务端接口目录中已登记的候选操作；不得自行创造命令语义 |
| scope | 请求希望操作的作用域 | 前端工作空间或目标对象只提供候选；服务端按对象和当前授权重新计算并冻结真实作用域 |
| targetId | 稳定目标对象标识 | 前端可由路由或页面上下文提交候选标识；服务端必须回源验证对象、归属和可见性 |
| expectedVersion | 期望对象及必要窗口/配置版本 | 前端使用页面加载所得版本声明；服务端与权威当前值比较 |
| idempotencyKey | 业务幂等键 | 调用方提供或沿用既有业务意图；同一提交意图固定复用，服务端计算规范化输入摘要并校验绑定范围 |
| payload | 版本化业务输入 | 前端按已登记字段提交；服务端执行运行时结构、范围和业务前置条件校验 |
| requestTraceId / parentTraceId | 当前请求追踪编号及父子关系 | 由服务端生成；前端只展示响应返回的安全支持编号，不得自报追踪编号或用其替代幂等键 |

#### 4.4.2 结果类别处理

接口返回 6 种结果类别（IFC-GEN-002），前端对应处理：

| 结果类别 | 前端处理 |
|---|---|
| completed | 操作完成，刷新数据，展示成功反馈 |
| accepted | 已受理（异步处理中），展示"处理中"状态，轮询或等待通知 |
| rejected | 展示拒绝原因，不修改数据；根据原因提示用户（如权限不足、状态不满足） |
| concurrency conflict | 展示"数据已被他人修改"，提示刷新后重试 |
| external uncertain | 外部依赖不确定，展示"处理中，请稍后查看"，不展示成功或失败 |
| dependency unavailable | 依赖不可用（如 Casdoor 故障），展示降级提示或最小白名单模式 |

#### 4.4.3 幂等与重试

- 表单提交类操作：生成幂等键，重复提交返回原结果，不产生第二份数据。
- 网络超时：前端可重试同一幂等请求，服务端去重。
- 并发冲突（版本不匹配）：不自动重试，提示用户刷新。

### 4.5 权限与可见性控制

前端权限控制分三层，每层都是体验优化，不替代服务端鉴权：

| 层次 | 控制对象 | 实现方式 |
|---|---|---|
| 路由级 | 能否进入某页面 | 路由守卫检查登录、资料门、工作空间 |
| 页面级 | 页面内区块显隐 | 服务端返回当前用户对该对象的"能力清单"，前端据此渲染 |
| 组件级 | 按钮/操作可用性 | PermissionGuard 组件根据能力标识控制显隐与禁用 |

**能力清单：** 页面加载数据时，服务端同时返回当前用户对该对象的能力清单（如 `canEdit`、`canSubmit`、`canApprove`、`canCancel`）。前端据此控制 UI，但每次操作提交时服务端重新校验。

**高风险操作：** 以下操作需要二次确认 + 10 分钟内重新认证（PRD-OPT-047）：
- 正式删除
- 权限模板发布
- 数据保留策略发布
- 强制结束联合活动
- 强制停用社团

### 4.6 通知与消息中心

#### 4.6.1 站内信（P-NTF-01）

- 通知列表按时间倒序，支持按社团、业务类型筛选。
- 每条通知显示：事件摘要、所属社团、业务对象、当前处理状态、时间。
- 点击通知链接跳转到对应业务详情页，跳转时重新鉴权。
- 通知正文只含理解事件所需的最少信息（US-NTF-01）。
- 重复事件不生成重复通知。

#### 4.6.2 未读提醒

- 导航栏显示未读计数角标。
- 未读数只用于提醒，不代表待处理数量。

#### 4.6.3 通知与待办的关系

- 通知只提醒"发生了什么"。
- 待办从服务端业务对象当前状态读取（个人中心的"待我处理"）。
- 已读通知 ≠ 已完成；未读通知 ≠ 待处理。

### 4.7 错误处理与状态展示

#### 4.7.1 页面状态

每个页面统一登记五种页面状态；业务状态机中的草稿、待处理、已生效等领域状态不替代本表。页面不适用某一状态时必须给出语义理由，不得留空或伪造场景。逐页合同与证据编号见《[页面状态与需求追踪矩阵](页面状态与需求追踪矩阵-v1.0.md)》。

| 状态 | 进入条件 | 展示与恢复 |
|---|---|---|
| normal | 主查询或必要上下文成功返回 | 展示权威当前状态、允许的操作、下一步和必要作用域提示 |
| loading | 首次加载、刷新、筛选、影响预览或提交等待中 | 骨架、局部进度或处理中提示；保持焦点并防止重复提交 |
| empty | 查询成功且有权，但有效结果为零 | 说明空的原因、当前筛选和安全的下一步；不得泄露无权对象存在性 |
| error | 查询失败、依赖不可用、版本冲突、业务拒绝或外部结果不确定 | 展示安全原因和可恢复动作；不确定结果显示处理中，不得伪造成功或无条件重试业务命令 |
| forbidden | 未登录、资料门阻断、对象失权或服务端拒绝授权 | 进入登录、资料门、P-GEN-02 或原页面等价拒绝；不得只靠按钮隐藏充当授权 |

#### 4.7.2 Casdoor 故障降级

根据 SRS-FAIL-001、002：

| 阶段 | 前端行为 |
|---|---|
| 故障前已登录且 < 15 分钟 | 最小白名单模式：可看公开页面、查看本人基础资料、编辑故障前已存在的表单草稿非附件字段；其他操作禁用并提示 |
| 故障 ≥ 15 分钟 | 除公开页面外全部关闭，展示降级页（P-GEN-03） |
| 恢复后 | 正常恢复，提示用户重新操作 |

#### 4.7.3 外部依赖不确定

Casdoor 写入、邮件、文件检查等外部操作可能不确定：

- 统一展示"处理中，请稍后在通知或详情页查看结果"。
- **不展示成功**，不展示失败，不自动重试业务。
- 等待服务端回读确认或后台任务完成后通过通知告知。

### 4.8 响应式适配

| 设备 | 断点 | 适配重点 |
|---|---|---|
| 桌面端 | ≥ 1024px | 多列表格、侧边导航和并列工作区；提供完整业务能力 |
| 平板 | 768-1023px | 折叠次要列、分步或抽屉交互；提供与桌面端相同业务能力 |
| 手机 | < 768px | 单列、卡片、抽屉和底部操作栏；提供与桌面端相同业务能力 |

**移动端约束：**
- 管理工作台在手机上使用卡片、分步预览和固定操作栏承载管理命令，不得删除批量操作、高风险确认或异常处置能力。
- 表单设计器在手机端必须保留创建、编辑、预览、校验和发布所需业务能力；可以采用分步编辑、字段抽屉和明确的桌面端体验建议，但不得以“建议使用桌面端”为由拒绝手机 Web 操作。
- 文件预览在手机端使用安全预览副本；上传必须支持系统文件、拍照或相册入口，并遵守相同检查与授权边界。
- 任何仅桌面可用的例外都必须先有上游明确边界和评审记录；当前没有此类例外。

#### 4.10.4 弹窗模式

**三种弹窗类型：**

| 类型 | 用途 | 组件 | 确认要求 |
|---|---|---|---|
| 确认弹窗 | 普通操作二次确认（如撤回、取消） | ConfirmDialog | 文字确认 |
| 表单弹窗 | 快速填写（如审批驳回填原因） | FormDialog | 表单校验通过 |
| 影响范围确认 | 高风险操作（发布、删除、移除、任命等） | ConfirmScope | 展示影响范围 + 二次确认；高风险需 10 分钟重认证 |

**统一规则：**

- 弹窗不可通过点击遮罩关闭（防止误操作）。
- 影响范围确认弹窗展示：目标社团、影响对象清单、预计通知对象（US-ORG-02）。
- 高风险操作弹窗含 ReauthGuard，10 分钟内未重新认证则拒绝（PRD-OPT-047）。
- 原因必填的操作（驳回、免职、移除、紧急停用等）在弹窗中强制校验原因非空。

#### 4.10.5 批量操作模式

适用于：批量分配面试官、批量安排面试、批量发布结果、批量发邀请（P-ORG-03）。

**统一流程：**

```
选择操作类型 → 固定对象清单 → 预览 → 二次确认 → 逐项执行 → 结果汇总
```

**统一规则：**

| 规则 | 说明 | 来源 |
|---|---|---|
| 单社团单类型 | 一次批次只能属于一个社团和一种操作 | US-ORG-05 |
| 预览冻结 | 确认后冻结输入清单，预览后新增对象不自动纳入 | US-ORG-05 |
| 逐项结果 | 每项独立成功/失败，展示原因 | US-ORG-05 |
| 部分成功 | 成功项保留，失败项可重试；不回滚已成功项 | US-ORG-05 |
| 失败重试 | 仅失败项可重试，沿用原幂等键 | IFC-CMD-004 |

### 4.12 可访问性要求

以下要求来源于 SRS-NFR-040 至 045，是前端必须遵守的验收下限。

| 要求 | 具体规则 | 来源 |
|---|---|---|
| 键盘可操作 | 核心流程（登录、导航、表单、弹窗、表格、错误提示、高风险确认）可仅用键盘完成，不陷入无法退出的交互 | SRS-NFR-044 |

### 5.2 组织与授权模块（ORG）

### 5.11 通用结果与拦截页面（GEN）

通用页面只解释当前导航结果并提供安全恢复动作，不承担业务授权、状态转换或依赖健康判定。

#### P-GEN-01 404 页

**页面用途：** 站内路径未登记或未匹配时展示，不回显未经转义的原始 URL，不把“未找到”解释为业务对象不存在。

**访问权限：** 所有访问者。

**路由：** 框架无关的最终未匹配回退；不提供固定可收藏业务 URL。

**恢复动作：** 返回公开发现入口；已登录用户还可返回 `/me`。不得自动跳转到猜测的相似对象。

#### P-GEN-02 无权限页

**页面用途：** 展示服务端授权拒绝的安全结果、最小原因和支持编号，不泄露对象存在性、他社团信息或内部权限策略。

**访问权限：** 受保护请求被拒绝的已登录用户；匿名访问先走登录入口。

**路由：** `/forbidden`；也允许业务页面以内嵌等价状态呈现，但证据必须映射到 P-GEN-02。

**恢复动作：** 返回上一安全页面、`/me` 或重新选择有权工作空间；不提供客户端“申请绕过”按钮。

#### P-GEN-03 维护/故障降级页

**页面用途：** Casdoor 降级窗口届满、受保护依赖不可确认或计划维护时说明当前不可用范围，不把未知状态伪装为健康或业务失败。

**访问权限：** 所有受影响访问者；公开内容是否继续开放按 SRS 故障边界决定。

**路由：** `/service-unavailable`

**恢复动作：** 提供安全重试、返回公开入口和支持编号；完全不可用时不承诺页面自身能够自动发现或系统外告警。

#### P-GEN-04 资料门拦截页

**页面用途：** 业务写操作因资料未补齐、邮箱未验证或分范围资料门受限时，展示服务端返回的缺失项和允许的补救入口。

**访问权限：** 当前登录用户本人。

**路由：** `/me/profile/required`

**恢复动作：** 进入 `/me/profile` 完成允许的资料或邮箱操作；完成后默认返回 `/me`，不接受外部绝对回跳地址。只读范围继续按服务端结果开放。
