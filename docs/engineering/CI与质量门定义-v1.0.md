> 文档状态：实现准备评审草案；流水线配置已落地（仓库根 `.cnb.yml`，实现明细见 [CI 流水线落地指南](CI流水线落地指南-v1.0.md)），本文件定义流水线阶段与质量门规则，是门禁权威  
> 草案日期：2026-08-14  
> 权威来源：[后端工程约定](后端工程约定-v1.0.md) §8、[测试执行计划](测试执行计划-v1.0.md)、[依赖与版本基线](依赖与版本基线-v1.0.md) §4、[部署运维与恢复手册](../operations/部署运维与恢复手册-v1.0.md)（§14 升级迁移、§18 开源发布）  
> 用途：定义合并前（MR）与发布前的自动/人工质量门；CI 配置本身不属于文档，但阶段、命令与门禁规则以本文为准；配置落地与维护见 [CI 流水线落地指南](CI流水线落地指南-v1.0.md)

## 1. 流水线阶段（MR 触发）

`CI-001`：每次 MR（含推送更新）运行以下阶段，任一失败阻断合并：

| 阶段 | 内容 | 门禁 |
|---|---|---|
| 1. 安装 | 前后端 `npm ci`（锁文件驱动；锁文件缺失/漂移失败） | 通过 |
| 2. 类型检查 | `tsc --noEmit`（前后端） | 通过 |
| 3. Lint | ESLint＋格式检查（Prettier 等，按工程约定） | 通过 |
| 4. 单元测试 L1 | 领域规则单测（状态机/校验/幂等/版本） | 通过，覆盖率不设硬性下限但新增代码须有对应用例 |
| 5. 集成测试 L2 | 真实 PG18（扩展/RLS/约束）集成测试 | 通过 |
| 6. 契约测试 L3 | HTTP 级契约（信封/17 类错误码/分页/幂等/脱敏） | 通过 |
| 7. 构建 | 前端生产构建、后端 `nest build`、Worker 入口构建 | 通过 |
| 8. 镜像 | 后端/前端镜像构建（tag 非 latest） | 通过（发布阶段复用） |
| 9. 秘密扫描 | 仓库与构建产物秘密扫描（gitleaks/等效） | 0 命中 |
| 10. 依赖审计 | `npm audit` 关键/高危漏洞门禁；许可证登记表更新检查 | 无关键/高危未处置项 |
| 11. 文档一致性 | 文档链接检查（新增/修改文档的相对链接有效） | 通过 |

`CI-002`：触发策略：

1. MR 到 `main`/`dev`：全量 11 阶段；
2. 纯文档变更（`docs/**`）：阶段 1、9、11 可跳过依赖安装，保留 11（链接）与 9（秘密扫描）；
3. 发布 tag（`v*`）：全量阶段＋发布门（§3）。

## 2. 质量门（合并）

`CI-003`：MR 合并门：

1. CI 全部适用阶段通过；
2. 变更涉及接口端点时：契约测试更新且通过（接口实现规格 §14）；接口清单如有新增端点须登记差异（§13）；
3. 变更涉及表/实体时：数据规格 `DATA-*` 证据入口与实体表草案同步；生产 DDL 不得在 MR 中出现（开发环境迁移受控例外）；
4. 提交 GPG 签名校验通过；
5. 依赖变更：更新锁文件与[依赖与版本基线](依赖与版本基线-v1.0.md)登记表；新依赖许可证通过检查；
6. 证据如实：`TST-*`/`OPS-VER-*`/`FE-GATE-*` 状态标注与实际一致，禁止"未执行"写成"通过"。

## 3. 发布门（生产/真实数据）

`CI-004`（承接治理门禁，门由需求方/治理流程控制，CI 只提供证据）：

1. [首批技术验证清单](首批技术验证清单-v1.0.md) 38 项全部通过（含学校真实 Casdoor 实例验证 `TVER-A-*`）；
2. 测试规格完成定义：306 转换底线用例、`TST-FAIL/NFR/SEC` 相关入口执行通过；
3. `OPS-VER-001~024` 部署/升级/恢复演练通过；
4. 生产 DDL 与迁移评审通过、迁移证据门禁关闭；
5. 秘密扫描、许可证审计、开源发布检查（部署运维手册 §18）通过；
6. 镜像与版本锁定（非 latest）就绪；发布说明含配置变更清单（配置规格 §5）。

## 4. 失败处置与重试

`CI-005`：

1. 阶段失败：修复后重跑完整阶段；不允许跳过失败阶段合并；
2. 偶发失败（网络/服务抖动）：记录后重跑一次，仍失败按真实失败处置；
3. 门禁例外：任何门禁例外必须由需求方显式记录（如 `GOV-CODE-WAIVER-001` 式记录），不得在 CI 中硬编码跳过。

## 5. 与现有证据体系的关系

`CI-006`：CI 是**执行载体**，不是证据本身：流水线日志归档为执行证据，结论仍回填测试规格 `TST-*`、运维手册 `OPS-VER-*` 与首批验证清单 `TVER-*`；CI 通过不等于验收通过（承接 `GOV-CODE-WAIVER-001` 边界）。
