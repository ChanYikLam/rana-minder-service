# RanaMinder 安全实现细则 v1.0（草案）

> 文档状态：实现准备评审草案；机制级实现细节，供开发实施，不改变[安全设计与实现级威胁模型](../specification/安全设计与实现级威胁模型-v1.0.md)与数据规格结论  
> 草案日期：2026-08-14  
> 权威来源：[安全设计与实现级威胁模型](../specification/安全设计与实现级威胁模型-v1.0.md)（`SEC-CTL-001~012`）、[数据模型与约束](../specification/数据模型与约束-v1.0.md)（`DATA-Q-005/006/014`）、[接口实现规格](../specification/接口实现规格-v1.0.md)（§5/§7/§4）、[配置规格](配置规格-v1.0.md)（§3.8）、[部署运维与恢复手册](../operations/部署运维与恢复手册-v1.0.md)（§7 `OPS-CFG-002~005`、§9 RLS）  
> 用途：把安全设计/数据规格的控制目标落地为可实现的机制草案：密钥环与加密、RLS 与连接上下文、增强认证 proof、日志脱敏、内置状态页、错误脱敏；全部实现仍须经 `TVER-E-*` 验证

## 1. 密钥环与加密实现（`DATA-Q-014`、`OPS-CFG-002~004`）

`SEC-IMP-001`：

1. **密钥环形态（草案）**：数据库外的版本化密钥环——一个受保护目录中的版本化密钥文件（`keyring/v1.key`、`v2.key`）＋元数据（版本、激活时间、撤销时间、完整性校验）；路径经配置 `security.keyRingRef` 外置引用；
2. **加密**：数据库托管秘密（SMTP 密码、导出签名键等）用 `AES-256-GCM` 加密后入库存密文＋`AAD`（版本化，绑定对象类型/字段/数据域）；`pgcrypto` 不安装（`DATA-Q-014`）；
3. **引用**：密文记录携带强类型秘密引用（`Ref`），恢复旧备份后按 `OPS-CFG-004` 重新录入或轮换；根密钥丢失/引用不可解析/版本撤销 → 受影响能力失败关闭；
4. **轮换**：新版本激活后新旧版本受控过渡（旧密文可解密、新写入用新版本）；轮换记录审计；失败回滚、撤销验证；
5. **边界**：普通个人业务数据默认不做通用应用层列加密（`DATA-Q-014` 既有结论）；密钥不得进入备份、仓库、镜像、日志。

## 2. RLS 与连接上下文实现（`DATA-Q-005/006`、`SEC-CTL-009`）

`SEC-IMP-002`：

1. **上下文建立**：受保护请求在完成认证与对象/工作空间解析后，于事务边界内设置数据库会话上下文（如 `set_config('app.scope_type', ...)` ＋ `app.scope_id`），**事务结束或请求完成必须清除**；连接池复用禁止残留（`IFC-DATA-003`）；
2. **双模式**：单目标模式（命令/详情/文件/任务）与集合只读模式（登记聚合查询）分离；缺失、非法或污染上下文 → 失败关闭；
3. **策略模板（草案）**：普通社团业务表候选按数据规格逐表评估；策略统一形如"当前会话上下文作用域与行作用域一致才可见/可写"；例外表必须登记原因与等效约束（ADR-005 §2.4）；
4. **身份分离**：普通应用角色无 `BYPASSRLS`；迁移/恢复/受控运维高权限连接与业务连接分离（ADR-014 §2.9）；
5. **验证**：`TVER-B-08` 覆盖连接池残留、伪造作用域、跨域引用、恢复路径。

## 3. 增强认证 proof 实现（`SEC-CTL-007/008`、接口实现规格 `API-AUTH-003`）

`SEC-IMP-003`：

1. `POST /api/auth/reauth` 在最近 10 分钟重新认证与当前 Group 实时核验通过后，签发一次性 `proof`：绑定主体、当前会话、认证时刻、适用命令清单、TTL 10 分钟；**消费即失效**（防重放）；
2. 高风险命令（权限模板发布、保留策略发布/执行、正式删除）校验 `input.reauthProof`：过期、跨主体、不可信或重复使用 → `401 IFC-ERR-002`，命令不执行、不产生成功副作用（`SEC-CTL-002`）；
3. proof 存储：服务端会话内存/受控存储，落库须脱敏与加密（如复用 §1 加密）；日志只记录存在性与时间，不记录证明本身。

## 4. 日志脱敏实现（`OPS-CFG-005`、ADR-011）

`SEC-IMP-004`：

1. 结构化日志在**落盘前**执行字段允许清单过滤：仅允许时间、级别、`supportId`、模块、事件、登记过的脱敏字段；疑似秘密（模式匹配＋登记敏感字段）拒绝或移除，不先写原文再清理；
2. 禁止字段：密码/令牌/私钥/访问密钥、报名正文、内部评语、附件内容、完整联系方式、数据库结构、内部路径、其他社团对象（接口实现规格 §4）；
3. 运行日志与业务审计分离：审计走审计模块不可变持久化；普通脱敏运行日志默认共保留 90 天（最近 30 天在线、后续 60 天压缩归档，`AUD-013`、ADR-011）；
4. 验证：`TVER-E-02` 负向用例（触发错误与秘密字段，断言日志与响应均无泄漏）。

## 5. 内置状态页实现（ADR-011）

`SEC-IMP-005`：

1. 超管只读端点 `GET /api/admin/ops-status`（接口清单 §15.8）返回：应用版本与启动状态、数据库连通性、任务积压/最近异常、Casdoor/邮件/文件检查/通知/备份最近结果与更新时间；
2. 数据来自技术运行事实或可重建摘要（`ops_status_snapshots`），**不成为业务状态、权限、任务执行权威或备份完成证明**；来源过期显示"未知"，不得以最近一次成功伪装当前健康；
3. 访问限制：当前有效超管只读；错误详情、连接信息、路径、版本与秘密最小披露；
4. 不创建机器健康接口、独立监测或系统外运维告警（ADR-011 边界）。

## 6. 错误脱敏实现（`SEC-CTL-002`、接口实现规格 §4/§7）

`SEC-IMP-006`：

1. 全局 ExceptionFilter 统一输出：`code`（17 类）、`message`（安全可披露最小原因）、`supportId`、`fieldErrors`；框架默认错误（NestJS/PostgreSQL/Casdoor SDK）必须转换，禁止泄漏堆栈、SQL、内部路径；
2. `404 IFC-ERR-015` 统一"不存在或不可见"，越界对象伪装 404，禁止探测差异（接口清单 §16 通用语义）；
3. 敏感字段错误（如邮箱验证码）只返回字段级占位错误，不返回正确性提示；
4. 验证：`TVER-E-02`。
