# RanaMinder 后端工程约定 v1.0

> 文档状态：实现准备评审草案  
> 草案日期：2026-08-14  
> 权威来源：[接口实现规格](../specification/接口实现规格-v1.0.md)、[接口契约](../specification/接口契约-v1.0.md)、[安全设计与实现级威胁模型](../specification/安全设计与实现级威胁模型-v1.0.md)、[数据模型与约束](../specification/数据模型与约束-v1.0.md)、[ADR-013](../architecture/ADR-013-Vue与NestJS首版应用技术栈.md)、[部署运维与恢复手册](../operations/部署运维与恢复手册-v1.0.md)  
> 用途：后端编码的通用工程规则（命名、错误、日志、追踪、校验、事务、安全、测试、质量门）；模块内分层规则以 `src/modules/分层实现规范.md` 为准（随实现文档分支合入 main 后生效），本文件不重复其内容  
> 范围：不新增产品行为；与上游冲突时按权威顺序处理

## 1. 代码组织

`ENG-001`：

1. 后端为 NestJS＋TypeScript 模块化单体（ADR-013），一个代码基线、至少两个启动入口：HTTP 应用与后台任务（不监听 HTTP）；
2. 目录结构承接 ADR-002 的 15 个逻辑模块（12 领域＋3 平台支撑）；模块间只通过明确应用命令/查询协作，禁止跨模块直接写他域权威表（ADR-002 §3）；
3. 依赖方向：领域层不依赖基础设施适配；适配器（Casdoor、DB、MinIO、Mail）只被应用/领域层以接口引用；
4. 文件命名：模块内按层分目录（interfaces/application/domain/infrastructure）；类名 PascalCase、常量 SCREAMING_SNAKE、方法 camelCase；表/列命名见[实体与表清单草案](实体与表清单草案-v1.0.md)；
5. 新文件必须落在既有模块边界内；无法归属时先评审模块边界（ADR-002 §5），不得由实现者临时选择。

## 2. 请求/响应与错误处理

`ENG-002`（承接[接口实现规格](../specification/接口实现规格-v1.0.md) §3/§4/§7）：

1. 所有 POST/PUT/DELETE 按统一信封解析（`action/targetId/expectedVersion/idempotencyKey/input`），业务字段只读 `input`；不兼容平铺写法；
2. 错误统一经全局 ExceptionFilter 输出：`{ code: "IFC-ERR-xxx", message, supportId, fieldErrors? }`，HTTP 状态码按 17 类映射表；禁止直接泄漏框架默认错误（NestJS/PostgreSQL 原生错误必须转换）；
3. `supportId` 为安全追踪编号（见 §4），错误响应与日志均携带，便于排障且不泄漏内部细节；
4. 状态机守卫失败与业务拒绝 → `422 IFC-ERR-006`；版本冲突 → `409 IFC-ERR-008` 并携带当前版本数据；幂等冲突 → `409 IFC-ERR-009`；作用域越界 → `403 IFC-ERR-003/004`；不存在或不可见 → `404 IFC-ERR-015`（越界伪装 404，禁止探测）；
5. 错误文案只放安全可披露的最小原因；本地化由前端按 `code` 渲染。

## 3. 运行时校验

`ENG-003`（承接 ADR-013 §2.6）：TypeScript 类型不能代替运行时验证。

1. HTTP 输入、配置文件、Casdoor 回调与回读、后台任务载荷、文件元数据、JSONB 动态答案等跨信任边界数据，使用前必须执行运行时结构、范围与业务前置校验；
2. 校验库选型见[依赖与版本基线](依赖与版本基线-v1.0.md) `DEP-Q-002`；校验错误映射为 `422 IFC-ERR-005`（结构）或 `IFC-ERR-006`（业务前置），字段级错误进 `fieldErrors`；
3. 动态表单答案按表单版本规范化校验（`IFC-DATA-005`），拒绝任意 JSON/JSONPath/秘密字段。

## 4. 日志、追踪与审计

`ENG-004`（承接部署运维手册 §15、安全设计）：

1. 运行日志与业务审计分离：业务审计走审计模块持久化（不可变），运行日志只承载排障信息；
2. 日志格式：结构化 JSON（时间、级别、`supportId`、模块、事件、脱敏字段）；默认保留 30 天（ADR-011）；
3. 脱敏：日志落盘前执行字段允许清单过滤；疑似秘密拒绝或移除；禁止输出密码、令牌、私钥、报名正文、内部评语、附件内容、完整联系方式（`OPS-CFG-005` 语义）；
4. 追踪：每个请求/任务生成 `supportId`（请求链路经 `X-Trace-Id` 传播）；后台任务继承来源请求/意图的追踪关联；`supportId` 不得替代幂等键（`IFC-GEN-006`）；
5. 业务审计：关键变化（状态、权限、删除、配置发布、导出、纠错）必须落审计事实，含操作者、对象、旧/新值摘要、来源；审计不可覆盖。

## 5. 事务、任务与幂等

`ENG-005`（承接 ADR-003/004、接口实现规格 §8/§11）：

1. 8 类事务边界按 `IFC-TX-001~008` 落点实现：本地原子事实（状态、历史、审计、必要通知）同一事务；外部副作用（Casdoor/文件/邮件/导出）提交前先持久化意图与任务；
2. 任务模型：权威库持久任务＋租约＋至少一次执行；执行前重新检查状态、版本、权限与前置条件（旧任务不得复活旧业务）；
3. 幂等：命令端点按 `idempotencyKey` 语义摘要去重；同键同摘要返回原结果；同键异参 `409 IFC-ERR-009`；重试沿用原键；
4. 并发：乐观锁 `expectedVersion`/`previewVersion` 校验后提交；单胜者竞争在同一事务边界裁决；
5. 外部结果不确定：返回 `202 IFC-ERR-013`，先可信回读再决定成功/重试/补偿，不得假成功（ADR-004 §2.7）。

## 6. 安全编码

`ENG-006`（承接安全设计与威胁模型、ADR-005）：

1. 受保护操作按 `IFC-GEN-005` 九步授权顺序失败关闭：认证→登记操作→作用域解析→可信 Casdoor 事实→角色/字段/状态叠加→增强认证→数据库上下文→前置条件→才执行；
2. 作用域上下文（RLS）由服务端在完成认证与对象解析后建立，按事务设置并可靠清除；缺失/污染失败关闭；客户端工作空间仅提示（`IFC-DATA-003`）；
3. 普通应用角色无 RLS 绕过能力；迁移/恢复高权限与业务连接分离（ADR-014）；
4. 秘密：配置秘密经统一配置边界与版本化密钥环引用（`DATA-Q-014`）；业务代码不得自行扫描路径、重复解析秘密或把原值写入错误信息；
5. 依赖注入边界：Controller/Guard/Pipe 不承载业务规则；领域规则在领域/应用层，入口只做传输适配。

## 7. 测试约定

`ENG-007`（承接测试规格与验收追踪）：

1. 单元测试：领域层规则不经入口可验证（状态机、校验、幂等、版本）；
2. 集成测试：模块协作、事务边界、任务领取/租约、数据库约束；
3. 契约测试：按[接口实现规格](../specification/接口实现规格-v1.0.md) §14 五类用例逐端点落地（正常/拒绝/同键重放/同键异参/版本冲突/失权/脱敏）；
4. 编号：测试用例关联 `TST-*`/`TST-IFC-*` 入口编号，执行结果回填测试规格，不得冒充通过；
5. 负向优先：跨模块写入绕过、连接上下文残留、伪造作用域、旧任务复活、恢复重放等负向场景必须覆盖（ADR-002/003/004/005 各自要求）。

## 8. Git 与质量门

`ENG-008`：

1. 提交规范：`type: 摘要（详情）`，type ∈ `feat|fix|docs|chore|refactor|test`；提交 GPG 签名（项目已启用 `commit.gpgsign`）；
2. 分支规范：功能/文档分支从 `main` 或 `dev` 拉出，命名 `feat/`、`fix/`、`docs/` 前缀；合入走 MR（仓库 `-/pulls`）；
3. 合入门（`GOV-CODE-WAIVER-001` 豁免后仍有效的门禁）：类型检查通过、lint 通过、单元/契约测试通过、秘密扫描无命中、无未登记依赖、`TST-*`/`OPS-VER-*`/`FE-GATE-*` 证据如实标注；
4. 生产发布门：真实数据启用门与发布门保持关闭，直到[首批技术验证清单](首批技术验证清单-v1.0.md)对应项补齐证据。

## 9. 环境差异

`ENG-009`：开发/测试/生产三环境差异只允许发生在配置与运行方式层（[开发环境搭建指南](开发环境搭建指南-v1.0.md)、[配置规格](配置规格-v1.0.md)）：

1. 业务规则、状态机、事务、授权、审计在所有环境一致；
2. 开发环境可放宽：秘密占位、热重载、实体同步、mock 服务；不得放宽：授权/RLS/审计/脱敏/任务持久化；
3. 生产环境强制：镜像锁定、配置只读挂载、受控迁移、备份与恢复门（部署运维手册）。
