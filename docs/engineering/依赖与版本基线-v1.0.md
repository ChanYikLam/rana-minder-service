## 1. 定位与锁定规则

`DEP-001`：ADR-013 §2.2 要求"具体 Node.js、Vue、NestJS 和 TypeScript 版本不得在 ADR 中写成永久版本；在首批代码验证前必须按当时仍受支持的版本形成可复现锁定，记录兼容性、安全支持期和升级策略"。本文承接该要求：

1. **锁定时机**：首批技术验证（[首批技术验证清单](首批技术验证清单-v1.0.md)）启动前，按本表候选版本复核（npm registry 当前版本、安全公告、支持期剩余），更新本表"锁定值"列并生成锁文件；
2. **锁定载体**：前端 `package-lock.json`、后端 `package-lock.json`（或等价锁文件）；数据库/中间件版本以部署清单（docker-compose 镜像 tag）锁定；
3. **浮动禁止**：生产与正式测试环境不得使用 `latest`/浮动 tag；开发环境可使用受控范围（如 `^`）但升级须回归；
4. **升级策略**：补丁版本按月评估、安全公告驱动；小版本升级走受控迁移流程（部署运维手册 §14）；主版本升级必须重新过首批验证清单的对应项并更新本表；
5. **安全支持期门槛**：运行时（Node）必须处于 Active 或 Maintenance LTS；数据库必须处于官方支持期内；不满足即升级或列入延期风险登记。

## 4. 依赖供应链与许可证（发布门禁，开发期维护）

`DEP-003`：项目采用 MIT；发布前必须完成第三方依赖、素材和复制代码许可证审计（需求事实 13.5）：

1. 依赖引入规则：新增依赖必须登记（名称、版本、许可证、用途、维护状态），优先官方随附/维护活跃/许可证兼容（MIT/Apache-2.0/BSD）依赖；
2. 秘密扫描：CI 与发布前对仓库、镜像、发布物执行秘密扫描（承接 ADR-010）；
3. 漏洞监控：启用 npm audit / 等价机制，安全公告驱动补丁升级；
4. 许可证清单随发布包提供；禁止传染性许可证（GPL/AGPL）依赖进入发布产物，特殊情况须需求方确认。
