# RanaMinder 开发环境搭建指南 v1.0

> 文档状态：实现准备评审草案  
> 草案日期：2026-08-14  
> 权威来源：[部署运维与恢复手册](../operations/部署运维与恢复手册-v1.0.md)（§5 环境与数据权威、§7 外置配置、§13 标准部署）、[ADR-010](../architecture/ADR-010-单文件外置配置与Docker只读挂载.md)、[ADR-006](../architecture/ADR-006-PostgreSQL主数据库与动态表单混合存储方向.md)、[依赖与版本基线](依赖与版本基线-v1.0.md)、[首批技术验证清单](首批技术验证清单-v1.0.md)  
> 用途：让新成员在**一台开发机**上搭建可运行的前后端与全部依赖服务（PostgreSQL 18、MinIO、Casdoor v3.108.0、Mailpit），并完成登录→浏览→报名→管理的最小冒烟路径  
> 范围：仅覆盖开发/测试环境；生产部署、备份、恢复与安全基线以部署运维手册为准；真实配置与秘密绝不进入仓库

## 1. 前置要求

| 项 | 要求 | 说明 |
|---|---|---|
| Docker Desktop / Podman | 20.10+ 或等效 | 依赖服务容器化运行 |
| Node.js | 24 LTS（[依赖与版本基线](依赖与版本基线-v1.0.md)锁定值） | 前端与后端共用 |
| npm | 随 Node LTS | 锁文件驱动 |
| 磁盘/内存 | ≥ 8 GB 内存、≥ 20 GB 空闲磁盘 | 三容器 + 构建产物 |
| 网络 | 可访问 npm registry 与镜像仓库 | 首次拉取 |

## 2. 依赖服务（docker-compose.dev.yml）

开发环境统一编排以下服务（**开发专用**，端口与生产不同；生产拓扑见部署运维手册 §13）：

| 服务 | 镜像 tag | 端口（本机） | 用途 |
|---|---|---|---|
| `postgres` | `postgres:18`（按基线锁定值） | `5432` | 权威数据库；启用 `pg_trgm`、`btree_gist` 扩展与 `uuidv7()`（内置） |
| `minio` | `minio/minio:latest`（开发用，生产锁定 tag） | `9000`（API）、`9001`（控制台） | S3 兼容对象存储；三个私有 Bucket（`DATA-Q-012`） |
| `casdoor` | `casbin/casdoor:v3.108.0` | `8000` | 学校既有版本精确兼容基线（`DATA-Q-013`） |
| `mailpit` | `axllent/mailpit` | `8025`（UI）、`1025`（SMTP） | 本地邮件捕获，替代真实 SMTP |

**数据库初始化**（启动后执行一次，或作为 init 脚本）：

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS btree_gist;
-- uuidv7() 为 PostgreSQL 18 内置函数，无需扩展
-- 验证：SELECT uuidv7(), word_similarity('软件','软件协会');
```

**MinIO Bucket 初始化**（每个隔离部署环境三个私有 Bucket：`待检查`、`权威原件`、`临时派生`，见 `DATA-Q-012`）：使用 `mc` 或应用启动自检创建，全部默认私有、服务端高熵随机对象键、只写一次。

**Casdoor v3.108.0**：导入开发用 Organization/Group 种子（虚构学校数据，禁止真实数据）；验证登录、Claims、Group 读写、写后可见性——**这是首批技术验证的固定靶场**（见[首批技术验证清单](首批技术验证清单-v1.0.md) §A）。

## 3. 配置文件（开发环境）

1. 复制 `config.example.yaml` 为开发配置（路径由后端启动参数指定，如 `CONFIG_FILE=./config.dev.yaml`）；
2. 开发配置允许使用本地占位秘密（如 `db_password: dev-only`、`casdoor_client_secret: dev-only`），**仅限开发环境**；正式/测试环境必须遵守 ADR-010 真实秘密不进仓库、占位符不可用规则；
3. 字段级定义见[配置规格](配置规格-v1.0.md)；开发环境与正式环境的差异（数据库名、Casdoor 地址、MinIO 端点、邮件指向 Mailpit）见配置规格 §6。

## 4. 后端启动（HTTP 应用 + 后台任务）

```bash
# 1. 安装依赖（pnpm 锁文件驱动）
pnpm install --frozen-lockfile
# 2. 迁移/实体同步（开发环境受控执行；生产 DDL 门保持关闭）
npm run migration:run        # 或开发期实体同步，见数据迁移文档
# 3. 启动 HTTP 应用（开发热重载）
npm run start:dev            # 监听 http://localhost:3000
# 4. 启动后台任务单元（独立入口，见启动入口文档）
npm run start:worker:dev     # 任务领取/租约/通知/导出/对账
```

启动判定：HTTP 入口与 Worker 入口均完成配置加载、依赖就绪检查后才开放（见启动入口文档与部署运维手册 §8）；任一必需依赖（PostgreSQL/Casdoor/MinIO）不可用且不在降级白名单时失败关闭。

## 5. 前端启动

```bash
npm ci
npm run dev                  # 开发服务器，代理 /api 到后端
```

前端接口适配器按[接口实现规格](../specification/接口实现规格-v1.0.md)与[接口清单-HTTP端点-v1.0](../specification/接口清单-HTTP端点-v1.0.md)对接后端；开发期可回退 mock 层，但**契约回归必须跑后端真实端点**（见 §7）。

## 6. 最小冒烟路径（开发环境验收）

按顺序执行，全部通过视为开发环境就绪：

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 访问 Casdoor `http://localhost:8000` 登录种子账号 | 登录页正常、Claims 返回 |
| 2 | 前端 `http://localhost:5173` 点击登录 | 跳转 Casdoor→回调→`GET /api/auth/session` 建立会话 |
| 3 | `GET /api/explore/clubs` | 返回种子社团目录（仅启用社团） |
| 4 | 申请端提交报名草稿→提交 | `POST /api/activity/recruitment/:activityId/apply` 返回 `{code:0}` |
| 5 | 管理端发布活动→查看报名列表 | 状态机转换正常、通知事实生成 |
| 6 | 上传文件→检查→下载 | `POST /api/files/upload` 后真实检查任务完成，下载签发短时地址 |
| 7 | 导出任务 | `POST /api/org/:clubId/exports` → 轮询 status → 下载 |
| 8 | 后台任务日志 | Worker 正常领取任务、租约与幂等记录可见 |

冒烟路径与[首批技术验证清单](首批技术验证清单-v1.0.md)的验证项对应；真实数据启用前不得用真实学生数据冒烟。

## 7. 契约回归要求

1. 每次接口变更后，前端契约测试对后端真实端点回归（错误码 17 类、信封、分页、幂等、版本）；
2. mock 层仅作开发占位，**契约以[接口实现规格](../specification/接口实现规格-v1.0.md)与接口契约为准**；
3. 306 条转换的逐行端点映射按接口实现规格 §14 在实现期核对。

## 8. 常见问题

| 现象 | 排查 |
|---|---|
| `CREATE EXTENSION pg_trgm` 失败 | 确认 postgres 镜像为 18 系列（官方随附扩展）；检查镜像 tag |
| Casdoor 登录回调失败 | 核对 `config` 中 Casdoor 地址/端口、应用回调 URL（开发为前端 dev server） |
| 文件上传后一直 `checking` | 检查 Worker 是否启动；文件检查任务未领取时状态不推进（`IFC-FIL-002/003`） |
| 通知未收到 | 检查 Mailpit UI `http://localhost:8025`；kill-switch 是否开启 |
| 时区/截止计算异常 | 服务端平台时区与 `deadline` 半开区间语义（`IFC-QRY-009`），确认配置 `school.timezone` |

## 9. 边界与差异提示

1. 开发环境≠生产环境：开发可放宽秘密占位、热重载、实体同步；生产必须镜像锁定、只读挂载、受控迁移（部署运维手册 §13/§14）；
2. 开发环境同样必须遵守：数据域/RLS 上下文、任务持久化、审计、脱敏日志（安全设计与接口实现规格 §4）——**不允许以"开发环境"为由绕过业务边界**；
3. 本指南不改变代码开工门状态；`OPS-VER-*`、`TST-*`、`FE-GATE-*` 证据仍以实际执行为准。
