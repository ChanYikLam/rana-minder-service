# RanaMinder 实体与表清单草案 v1.0

> 文档状态：实现准备评审草案；**物理表、字段清单、Policy、DDL 和迁移仍未冻结**（[数据模型与约束](../specification/数据模型与约束-v1.0.md)明确），本文件只建立表族清单与约束落点，不编写 DDL/字段级定义  
> 草案日期：2026-08-14  
> 权威来源：[数据模型与约束](../specification/数据模型与约束-v1.0.md)（`DATA-Q-001~014`）、[ADR-002](../architecture/ADR-002-逻辑模块与状态机唯一责任基线.md)、[ADR-014](../architecture/ADR-014-单数据库与统一应用业务Schema.md)、[接口清单-HTTP端点-v1.0](../specification/接口清单-HTTP端点-v1.0.md)（端点→表族对照）  
> 用途：开发环境实体/迁移实施前的表族规划与开发顺序；字段级冻结与生产 DDL 仍须实现评审后按数据规格执行（开发/测试环境实现已获豁免授权，生产迁移门关闭）

## 1. 定位与规则

`TBL-001`：

1. 单个 PostgreSQL 数据库＋统一应用业务 Schema（ADR-014）；不按社团/模块拆库拆 Schema；
2. 每张权威表归属且仅归属一个写入责任模块（ADR-002）；跨模块读取经应用命令/查询，不直接写他域表；
3. 通用列族（草案）：稳定 UUIDv7 主键、模块权威对象版本列、作用域列（普通社团 `club_id`/联合域引用/平台域）、幂等键列、任务引用列、不可变历史关联列、审计关联列；名称 snake_case，历史表后缀 `_history`/`_log`；
4. 动态表单：固定业务骨架强类型关系表，动态答案 JSONB（`DATA-Q-007` 规范化）；核心业务字段绝不埋入 JSONB（ADR-006 §2.2）；
5. 正式数据不自动删除；物理删除仅经正式删除清单（`DATA-Q-011`、`IFC-TX-007`）。

## 2. 通用支撑表族（先于领域表实施）

| 表族（草案名） | 职责 | 关键约束 |
|---|---|---|
| `tasks`（权威任务） | 持久任务信封：类型、载荷引用、租约、尝试、可执行时间、幂等依据、状态、失败摘要、结果引用 | ADR-004；`IFC-DATA-007` 至少一次 |
| `outbox`/`intents`（业务意图） | 外部副作用意图：来源业务、目标、版本、幂等键、收口状态 | `IFC-TX-003/004/005` 提交后可恢复执行 |
| `idempotency_records` | 幂等键→语义摘要→原结果引用 | `IFC-GEN-006`；保留期受控清理（`DATA-Q-011`） |
| `audit_logs` | 不可变业务审计：操作者、对象、动作、旧/新值摘要、来源、追踪编号 | 审计不可覆盖；运行日志不替代 |
| `schema_migrations` | 单一迁移登记表（自定义 runner＋单表账本，消除 ORM 双账本） | 数据迁移文档；`DATA-Q-*` 证据门禁 |
| `deletion_manifests`（删除清单） | 正式删除范围、步骤状态、幂等依据；恢复后重放 | `IFC-TX-007`、`DATA-Q-011/012` |
| `sync_cursors`（对账水位） | Casdoor 对账游标、事件收件、新鲜度 | `DATA-Q-013`、ADR-009 |

## 3. 领域表族清单（草案，15 模块）

### 3.1 身份与资料（identity）

| 表族（草案名） | 职责 | 要点 |
|---|---|---|
| `users` | 本地稳定主体：学号、账号状态、降级/恢复 | 外部账号状态以 Casdoor 为权威（`IFC-DATA-008`） |
| `profiles` | 资料字段、白名单版本、`syncStatus` | 乐观锁版本列；字段白名单（`IDN-*`） |
| `profile_sync_events` | 资料同步意图/冲突/尝试历史 | 不可变历史；第三值冲突处置 |

### 3.2 组织与授权（organization）

| 表族（草案名） | 职责 | 要点 |
|---|---|---|
| `clubs`（社团空间） | 接入映射、状态（向导/启用/停用/同步异常/待重接）、只读标志、冻结区间 | 作用域根；`SRS-SM-ORG-001` |
| `group_mappings` | Casdoor Group 映射（社团/部门/职位）、用途、版本 | `SRS-SM-ORG-002`；映射版本竞争 |
| `appointments`（预约命令） | 任命/调岗/免职命令：目标、计划时间、状态、失败原因 | `SRS-SM-ORG-003`；`btree_gist` 时间占用约束候选 |
| `batch_jobs`（受控批量） | 批次预览快照、冻结目标、逐项结果、审计引用 | `IFC-TX-006` |
| `positions`/`departments` | 部门/职位定义（来源于 Group 配置） | 配置版本；当前发布指针 |

## 4. 关键约束落点（实施时逐项证明）

| 约束 | 落点 | 证据门禁 |
|---|---|---|
| UUIDv7 主键 | 全部权威表 | `DATA-Q-002` |
| 普通社团作用域一致性 | `clubs` 关联表复合外键/唯一约束；跨域引用阻止 | `DATA-Q-003/005` |
| 选择性 RLS | 普通社团业务表候选清单在数据规格逐表标注；例外记录原因 | `DATA-Q-005` |
| 时间占用约束 | `btree_gist` 排除约束（面试/预约/人员占用） | `DATA-Q-010` |
| 任务信封与租约 | `tasks`/`outbox` 与业务表原子提交 | `DATA-Q-004`、ADR-004 |
| 不可变历史 | `*_history` 表只追加 | `DATA-Q-003` |
| 动态答案 JSONB 规范化 | `form_submissions` 版本化结构校验 | `DATA-Q-007` |
| 正式删除清单重放 | `deletion_manifests` 覆盖数据库/对象存储/索引/导出 | `DATA-Q-011/012` |

## 5. 实施顺序建议

1. **通用支撑表**（§2）：`schema_migrations` → `audit_logs` → `tasks`/`outbox`/`idempotency_records` → `deletion_manifests`/`sync_cursors`；
2. **基础域**：identity（users/profiles）→ organization（clubs/group_mappings）→ config；
3. **核心业务域**：recruitment → joint → invitation → membership（相互依赖最重）；
4. **支撑域**：form → file → notification → audit → stat-export → read-model/job/ops 投影；
5. 每批表实施时更新数据规格对应 `DATA-*` 证据入口；生产 DDL 与迁移在实现评审与证据门禁通过前保持关闭。
