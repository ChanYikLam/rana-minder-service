## 1. 定位与文件契约

`CFG-001`（承接 `OPS-CFG-001`）：

1. 官方部署：部署者在部署项目目录复制 `config.example.yaml` 并填写为一个本地 `config.yaml`（或等价单文件），以**只读方式挂载**到容器固定受控位置（如 `/app/config/config.yaml`，绝对路径待实现确认）；
2. 真实配置不得进入源码仓库、镜像、示例、测试夹具、截图、日志或公开发布物；仓库只保留字段结构完整、秘密留空或使用明确无效占位符的示例配置；
3. 应用通过统一配置读取边界加载并校验；业务模块不得自行扫描任意路径或重复解析秘密（ADR-010 §2.7）；
4. 正式环境缺少必要配置、仍使用无效占位符或结构无法解析时，**不得以半配置状态继续提供业务服务**。

## 2. 顶层结构（草案）

```yaml
# config.yaml 顶层段（草案，字段名待实现评审确认）
server:        # HTTP 与任务入口
environment:   # dev | test | prod（正式/开发差异判定）
database:      # PostgreSQL 连接与扩展
casdoor:       # Casdoor 集成（登录、管理 API、服务账号）
storage:       # S3 兼容对象存储（三个 Bucket）
mail:          # SMTP 渠道（开发指向 Mailpit）
notifications: # 通知渠道开关、模板、kill-switch 初始状态
security:      # 加密、密钥环引用、TLS 策略、增强认证
logging:       # 日志级别、保留、字段允许清单
school:        # 学校平台时区、学年起点、默认值
obs:           # 内置状态页与观测开关（ADR-011 最小观测）
backup:        # 备份目录/脚本参数（承接部署运维手册 §16）
```

## 3. 字段级定义（草案）

> 约定：`必填`＝正式环境缺失即启动失败；`秘密`＝落入脱敏与秘密处理规则（`OPS-CFG-005`）；`Ref` 结尾字段＝外置版本化密钥引用（`DATA-Q-014`，不写明文）。

### 3.1 server

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `server.httpPort` | int | 否 | `3000` | HTTP 应用监听端口 |
| `server.workerEnabled` | bool | 否 | `true` | 当前进程是否承担后台任务（独立入口时由入口决定） |
| `server.trustProxy` | bool | 否 | `false` | 反向代理场景按部署手册 §13 受控开启 |

### 3.2 environment

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `environment.name` | enum | 是 | — | `dev \| test \| prod`；`prod` 触发正式环境强制约束（HTTPS、占位符拒绝、最小观测） |

### 3.3 database

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `database.host` | string | 是 | — | PostgreSQL 主机（拆分部署时可为独立节点） |
| `database.port` | int | 否 | `5432` | — |
| `database.name` | string | 是 | — | 单数据库（ADR-014 统一应用业务 Schema） |
| `database.user` | string | 是 | — | 普通应用角色（无 RLS 绕过） |
| `database.passwordRef` | string(Ref) | 是 | — | 密码外置引用 |
| `database.migrationUser` | string | 否 | — | 迁移专用最小高权限角色（与业务连接分离，ADR-014） |
| `database.pool` | object | 否 | 默认 | 连接池上限、空闲回收（默认值待实现确认） |

## 4. 秘密与占位符规则（承接 `OPS-CFG-002~005`）

1. `Ref` 结尾字段引用外置密钥文件路径或密钥管理器标识，**不在配置文件中出现明文**；
2. 根密钥引用不可解析、版本被撤销或完整性无法确认 → 受影响能力失败关闭并进入恢复（`OPS-CFG-004`）；
3. 示例配置使用明确无效占位符（如 `CHANGE_ME`），正式环境检测到占位符即启动失败；
4. 日志、错误、状态页、通知、任务载荷不得输出任何秘密原值或可还原派生值；
5. 数据库托管秘密（如 SMTP 密码、导出签名键）经服务端应用层 `AES-256-GCM`＋版本化 AAD 保存，密钥来自密钥环（`DATA-Q-014`）。

## 5. 校验与启动判定（承接 `OPS-CFG-001` 与配置加载文档）

1. 启动时校验：结构（未知字段拒绝）、环境标识、必填项、引用可解析、版本兼容、互斥条件（如 `webhookEnabled` 与降级路径）、正式环境 HTTPS；
2. 缺失必需项/占位符/解析失败 → 启动阻断，保留脱敏证据；
3. 配置版本兼容：发布说明列出新增/废弃/重命名/默认值变化；升级前保留受保护副本并执行兼容检查（ADR-010 §2.9）。
