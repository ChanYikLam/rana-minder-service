# RanaMinder 合成测试数据规格 v1.0

> 文档状态：实现准备评审草案  
> 草案日期：2026-08-14  
> 权威来源：[测试规格与验收追踪](../specification/测试规格与验收追踪-v1.0.md)（§4 合成测试数据与证据合同、§10 容量口径）、`test/测试目录文档.md`（`SynDataBuilder` 组件）、[接口清单-HTTP端点-v1.0](../specification/接口清单-HTTP端点-v1.0.md)（角色枚举）、[首批技术验证清单](首批技术验证清单-v1.0.md)（`TVER-F-*` 性能容量门禁）  
> 用途：定义 `SYN-DATA-*` 虚构数据集的结构、规模、标识与可复现性合同，支撑测试规格完成定义第 2 条"合成数据、角色、作用域、状态、版本、时钟和依赖条件**可复现**"，并作为 `SynDataBuilder` 生成器的输入规格  
> 范围：不新增产品行为；所有数据完全虚构，禁止真实学生信息、令牌、密钥与真实附件正文

## 1. 定位与边界（承接测试规格 §4.1）

`SYND-001`：

1. 只使用完全虚构的学校、社团、人员、活动、学号、域名、邮箱、手机号、文件和外部对象标识；数据集统一 `SYN-DATA-*` 标识；
2. 敏感字段扫描使用 `SYN-SENSITIVE-MARKER-*` 标记；标记不得具备认证、签名、解密或访问能力；
3. 不得保存、复制或输出真实令牌、密钥、证书、服务账号、完整外部响应、学校敏感配置、真实学生信息或真实附件正文；
4. 外部响应证据只保存允许字段、摘要、状态分类、时间、指纹和脱敏哈希；
5. 性能、容量、期限和保留期直接继承上游数值；测试不得自行增加限流阈值、验证码、封禁期限或新用户行为；
6. 数据集版本与生成器版本绑定；同一版本号必须生成**完全相同**的数据快照（确定性种子＋固定算法）。

## 2. 数据集标识与版本

`SYND-002`：

| 数据集 | 用途 | 规模 | 版本标识 |
|---|---|---|---|
| `SYN-DATA-CORE-*` | 功能/契约/故障测试固定场景集 | 小而全（§3） | `SYN-DATA-CORE-v1` |
| `SYN-DATA-CAP-*` | 性能/容量测试样本集 | 上游容量口径（§4） | `SYN-DATA-CAP-v1` |
| `SYN-DATA-FUZZ-*` | 负向/畸形输入样本 | 按用例需求 | `SYN-DATA-FUZZ-v1` |

版本规则：数据集版本变更（结构/规模/分布）必须生成新版本号并在测试执行记录的环境指纹中登记；同一版本内对象标识（学号/账号/社团 ID）稳定，跨版本不承诺稳定。

## 3. 固定场景数据集 `SYN-DATA-CORE-v1`（功能测试）

### 3.1 学校与组织

| 对象 | 规模 | 覆盖要点 |
|---|---|---|
| 学校 | 1 所虚构学校（如"云麓大学"，全部名称虚构） | 平台时区固定（如 `Asia/Shanghai`）、学年起点 9 月 |
| 学院/年级 | 3 个学院、4 个年级 | 资格筛选（colleges/grades）覆盖 |
| 社团 | 8 个启用 + 1 个停用 + 1 个向导未完成 + 1 个同步异常只读 | `SRS-SM-ORG-001` 全状态覆盖；含 1 个强制停用标志社团 |
| 部门/职位 | 每社团 2~4 部门、3~4 职位层级 | 部门负责人数据范围、职位层级限制（干事/副部长/部长/副负责人） |
| Casdoor Group | 按社团/部门/职位映射，含 1 个异常 Group | 对账差异、重绑、修复场景 |

### 3.2 人员与角色矩阵

| 角色 | 数量 | 账号要点 |
|---|---|---|
| `super_admin` | 1 | 增强认证与特权审计场景 |
| `club_leader` | 8（每启用社团 1） | 最后一名负责人场景额外预留 1 社团仅 1 负责人 |
| `hr` | 4 | 无 `club:email:config` 差异验证 |
| `department_leader` | 6 | 仅本部门数据范围、越界 404 伪装 |
| `interviewer` | 8 | 默认职能＋临时任务（`ORG-037` 折算权限） |
| `member` | 30 | 多社团/多部门/多职位并存、辞职/移除候选 |
| `applicant` | 24 | 报名、草稿、撤回、恢复窗口候选 |
| `candidate`（非成员） | 12 | 常规入社邀请候选 |

边界账号（每类至少 1）：账号禁用（`disabled: true`）、邮箱未验证、资料门未完成、15 分钟降级白名单内账号、服务账号（仅后端）。

### 3.3 普通招新数据（`SRS-SM-REC-001~005` 全状态覆盖）

| 对象 | 数量 | 覆盖要点 |
|---|---|---|
| 招新活动 | 6 | draft/in_progress/paused/completed/cancelled/force_completed 各 1；archived 1 |
| 报名通道 | 每活动 1 | not_open/open/paused/closed 四态；截止快捷范围（今日/3 日/7 日）边界 |
| 报名申请 | 每活动 6~10 | draft/submitted/revision_requested/revised/exited/adjustment_overdue/identity_anomaly/not_qualified/accepted 全覆盖；志愿越界、重复志愿、调剂 |
| 部门路径 | 按申请 | pending/evaluating/hold/decided/waitlist/published；`labelSetBy` 作者 |
| 轮次/时段 | 每活动 1~2 轮、每轮 4~6 时段 | 容量满、时间重叠（含结束=开始不算重叠边界）、选时截止已过 |
| 面试记录 | 每轮若干 | pending_selection/scheduled/leave/late/absent/in_progress/completed/invalidated；`skipReason` |
| 评价 | 按申请 | 首评前隔离（`peerViewLocked`）、多作者、已发布/未发布 |
| 邀请 | 按录取决定 | pending_acceptance/accepted/rejected/withdrawn/expired；`casdoorSync` 四态 |

### 3.4 联合活动数据（`SRS-SM-JNT-001~006` 全状态覆盖）

| 对象 | 数量 | 覆盖要点 |
|---|---|---|
| 联合活动 | 3 | draft/confirmed/published（invite_phase）/closed 覆盖；1 个 20 社团上限规模样本（容量口径） |
| 参与社团关系 | 每活动 4~8 | invited/accepted/confirm_pending/locked/force_suspended；名单锁定、退出拒绝 |
| 联合通道 | 每活动 1 | first_open/open/paused/extend/closed/reopen |
| 联合申请 | 每活动 6 | draft/submitted/archived；`consented` 证据、`volunteerClubIds` |
| 联合面试 | 按申请 | 各态＋`reviewFlag`（面试作废待复核）＋冻结剩余时长 |
| 参与社团结论 | 申请人×社团 | pending/evaluating/invite_pending/accepted_locked/archived；改判历史、跨社互见 |
| 联合邀请 | 按结论 | admit/join 两类；`reviewFlag=true` 接受拒绝场景 |

### 3.5 成员、表单、文件、通知、纠错、导出与配置

| 域 | 覆盖要点 |

### 3.6 敏感标记样本

`SYND-003`：每个应脱敏字段类别提供明确标记样本，供 `SensitiveMarkerHelper` 断言：

| 类别 | 标记样本（示例） | 断言目标 |
|---|---|---|
| 报名正文 | `SYN-SENSITIVE-MARKER-APPLICATION-BODY-001` | 日志/错误/审计无泄漏 |
| 内部评语 | `SYN-SENSITIVE-MARKER-REVIEW-001` | 无权者不可见、日志无泄漏 |
| 附件内容 | `SYN-SENSITIVE-MARKER-ATTACHMENT-001` | 错误响应/下载 URL 不泄漏 |
| 联系方式 | `SYN-SENSITIVE-MARKER-CONTACT-001`（手机/邮箱） | 最小披露 |
| 令牌/密钥 | `SYN-SENSITIVE-MARKER-SECRET-001` | 日志落盘前拒绝/移除（`OPS-CFG-005`） |

## 4. 容量样本数据集 `SYN-DATA-CAP-v1`（性能/容量测试）

`SYND-004`：按测试规格 §10 容量口径（`TST-NFR-001/005/016..019`）生成：

| 维度 | 规模 | 生成规则 |
|---|---|---|
| 社团 | 100 | 均匀分布；含 2 个停用/异常社团 |
| 账号 | 50,000 | 学号/邮箱确定性伪随机（种子固定） |
| 单活动申请 | 2,000 | 单社团单活动峰值；含各状态比例 |
| 联合活动参与社团 | 20 | 上限样本；1 个 |
| 并发负载 | 500 同时在线 | 读/写/搜索/统计/受理型操作比例按性能测试基线版本化记录（`TST-NFR-005`） |
| 名称搜索样本 | 社团/活动/部门/职位名 ≥ 2,000 | 中文子串/错别字近似候选分层命中分布 |
| 文件样本 | 1,000+（元数据）/ 少量真实字节 | 附件平均大小按基准记录，不新增产品承诺 |

生成要求：确定性种子、分布可复现；负载模型版本、并发曲线、读写比例作为执行参数显式记录，不得硬编码为产品行为（`TST-NFR-005` 特别边界）。

## 5. 标识与虚构规则

`SYND-005`：

| 项 | 规则 |
|---|---|
| 学号 | 虚构段（如 `2026` 前缀＋序号），不与任何真实学校编码冲突 |
| 邮箱 | `@syn.example`（或等价保留域）；学校/社团域名 `*-syn.example` |
| 手机号 | 保留号段（如 `19900000000` 起递增） |
| 姓名 | 虚构人名表（确定性轮询），不映射真实学生 |
| 对象标识 | 权威 UUIDv7 由数据库生成（`DATA-Q-009`）；`SYN-` 前缀仅用于数据集/标记标识，不进入业务主键 |
| 外部标识 | Casdoor Group/账号使用 `syn-` 前缀虚构标识 |

## 6. 可复现性合同（完成定义第 2 条落地）

`SYND-006`：

1. 生成器输出契约：数据集版本、对象总数、关系总数、各状态计数（断言表）、边界样本清单；
2. 每次生成后运行一致性校验：对象数/关系数/状态分布与版本声明一致；不一致视为生成器缺陷；
3. 黄金快照：`SYN-DATA-CORE-v1` 生成后保存校验和（含数据与生成器版本），回归测试引用快照；
4. 环境指纹：执行记录登记数据集版本＋生成器版本＋校验和（测试规格 §4.2）；
5. 变更规则：结构/规模/分布变化 → 新版本号；旧版本数据仅用于历史证据，不静默改写。

## 7. 数据生命周期

`SYND-007`：

1. 生成：测试装配时按需生成（`SynDataBuilder`），不预置入生产数据库；
2. 使用：仅限隔离测试环境（开发环境指南 §2 靶场）；禁止进入生产/预演真实环境；
3. 清理：测试结束清理临时对象与上传文件；正式测试库保留黄金快照数据供回归；
4. 泄漏处置：发现真实数据或标记外泄 → 判"失败"并按测试规格 §4.2 记录，不删除失败证据。
