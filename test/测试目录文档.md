## 核心职责

承载跨模块集成测试、端到端（E2E）HTTP 测试、故障注入与恢复演练脚本，以及全测试共享的合成数据生成器、测试辅助工具与 NestJS 应用上下文装配。本目录只放"需要跨模块或跨子系统协作"的测试入口；单模块领域规则与纯函数单元测试归各模块 `domain/` 旁的 `.spec.ts`，不放入本目录。

- **逐行状态机验证**：29 个状态机、306 条转换、1,836 个固定六分面入口（NOM/AUT/STA/VER/CON/REV）的集成级验证（TST-SM-001~029）。
- **事务边界验证**：8 类事务边界的原子性、失败关闭、幂等与恢复（TST-TX-001~008）。
- **故障注入与恢复**：13 条故障规则的故障注入、失败关闭与恢复重放（TST-FAIL-001~013）。
- **非功能验收**：54 条 NFR 的性能、容量、可用性、保留期与恢复演练（TST-NFR-001~054）。
- **安全控制验证**：26 个威胁、38 个控制目标、38 个负向证据入口（TST-SEC-THR-_/CTL-_/VER-*）。

关键不变量：

- 测试数据只使用完全虚构的 `SYN-DATA-*` 数据集；不得保存、复制或输出真实令牌、密钥、真实学生信息或真实附件正文。
- 追踪编号用于关联技术执行（请求→任务→外部调用），业务幂等键用于识别同一业务意图，两者不得混同，也不得包含个人信息或秘密。
- 执行状态只允许：未执行 / 通过 / 失败 / 阻塞 / 不适用。正式 `TST-*` 入口仍全部为"未执行"；当前已落地的工程冒烟测试：`test/integration/pg18.spec.ts`（L2 冒烟，1 用例）、`test/contract/transmission-contracts.spec.ts`（L3 冒烟，2 用例）、read-model L1 单测（74 用例）。

## 使用与准入规则

- **可以放进来**：跨模块集成测试、E2E HTTP 测试、后台任务端到端测试、故障注入与恢复演练脚本、合成数据生成器、测试共享夹具与辅助工具、NestJS 测试上下文装配。
- **禁止放进来**：单模块领域规则单元测试（归各模块 `domain/*.spec.ts`）、纯函数工具测试（归 `src/common/*.spec.ts`）、真实学生数据或真实外部凭据。
- **测试数据边界**：只使用虚构的 `SYN-DATA-*` 数据集；敏感字段扫描使用 `SYN-SENSITIVE-MARKER-*` 标记，标记不得具备认证、签名、解密或访问能力。
- **证据合同**：每次执行记录至少保留测试入口与版本、环境指纹、数据与前置状态、操作与故障、预期与实际、关联标识（追踪编号/幂等键/尝试编号）、脱敏证据与结论。
- **失败处理**：任一已确认阈值不满足、证据不完整、出现禁止副作用、越权、泄密、假成功或静默丢失时判"失败"；不得用失败样本换取统计达标。
- **恢复处理**：失败证据不得被成功重跑覆盖；恢复后重新核对前置状态并建立独立执行记录；备份任务成功不代替恢复通过。

## 核心逻辑摘要

- **状态机测试（TST-SM-***）**：每条转换行生成 6 个固定分面入口--`NOM`（规范路径）、`AUT`（无权/错误作用域）、`STA`（状态不匹配）、`VER`（版本不匹配）、`CON`（并发单胜者）、`REV`（执行中失权）；条件分面 `FLT/TMO/UNK/RTY/CMP/RCV` 按副作用与外部依赖逐行判定。
- **事务边界测试（TST-TX-***）**：每类边界验证本地原子事实、失败关闭、业务幂等、并发、必要通知/审计、跨系统真实状态、适用补偿与恢复；不得把外部系统伪装为 PostgreSQL 分布式原子事务。
- **故障注入（TST-FAIL-***）**：每项至少一次可信故障注入、一次失败关闭验证、一次恢复验证；故障无法安全注入时记"阻塞"，不得用文档审阅代替执行。
- **业务场景家族**：正常、拒绝、撤回、取消、过期、失权、并发、版本冲突、故障、超时、结果不确定、重试、补偿、恢复、强制处置、归档、越权共 17 类，每类对应稳定测试入口与最低验证目标。
- **测试五态**：未执行（尚无完整执行与证据）、通过（实际结果满足全部上游标准且证据完整）、失败（至少一个标准不满足或出现禁止副作用）、阻塞（环境/依赖无法执行）、不适用（有明确上游依据和评审记录，不得隐藏缺测）。

## 典型调用链

`TestAppFactory` 装配 NestJS 测试上下文（注入模拟 Casdoor/邮件/存储适配器或指向隔离测试环境）-> `SynDataBuilder` 生成虚构数据集并校验对象数、关系数与活动边界 -> `StateMachineTestMatrix` 按目标转换行 × 分面发起参数化测试 -> 应用命令经 Controller/用例/领域状态机/适配器执行 -> `FaultInjector` 在指定点注入故障（数据库宕机/Casdoor 超时/外部结果不确定）-> `ConcurrencyTestHelper` 编排并发竞争验证单胜者 -> `EvidenceCollector` 收集执行记录（追踪编号/幂等键/版本/租约/脱敏日志与审计摘要/状态快照）-> `SensitiveMarkerHelper` 断言无敏感泄露 -> 记录结论为未执行/通过/失败/阻塞/不适用。
